# 任务视图页面需求文档

版本：v1.0

日期：2026-06-16

适用范围：桥梁施工自动排程系统实际工程化版本

面向对象：产品经理、前端研发、后端研发、测试工程师、计划工程师

## 1. 功能模块核心定位

### 1.1 模块定位

任务视图页面是排程求解前的任务网络核验与局部排程配置页面。系统在接入桥梁结构参数、工艺工效库、工艺逻辑、资源配置和里程碑配置后，应先生成求解前任务图，再由用户在任务视图中核验任务识别、工程量、工期计算、工艺工效、资源候选和前置关系。

任务视图包括结构物核验、构件工艺选择、工效分组选择、任务生成规则核对和工艺逻辑关系核验。页面不负责录入完整结构物主数据，结构物几何参数仍以项目结构参数服务数据为准。

### 1.2 当前页面效果和业务场景

页面标题为“任务视图”，副标题为“调用 OR-Tools CP-SAT 前核验结构物识别、工期计算和工艺逻辑关系”。页面顶部提供文件选择、导入 Excel、按墩号/按工艺切换、生成或刷新任务视图等操作。

典型业务场景：

* 计划工程师导入或接入桥梁结构参数后，生成求解前任务图，检查桥梁、工区、幅别、墩台、构件和任务是否完整。
* 技术负责人按施工方案调整部分任务或构件工艺，例如将指定墩位桩基由旋挖钻调整为人工挖孔。
* 技术负责人切换工效分组，核验工程量口径、工期计算表达式和资源候选是否符合现场组织方案。
* 技术负责人查看前置关系数量、逻辑关系和时间间隔，判断任务网络能否进入模拟求解。

### 1.3 模块边界

任务视图应覆盖：

* 结构参数接入后的任务图生成和刷新。
* 任务清单展示、筛选、分组、展开和收起。
* 排程相关局部配置，包括管控级别、工艺和工效分组。
* 工期、工程量、资源候选和前置关系核验。
* 任务图生成诊断和影响求解结果的失效提示。

任务视图不覆盖：

* 不录入完整桥梁、墩台、构件尺寸等结构物主数据。
* 不维护工艺工效库、工艺逻辑库、资源池和里程碑模板的全量配置。
* 不执行 CP-SAT 求解；求解动作仍在模拟求解模块完成。

## 2. 数据定义

### 2.1 主数据对象

| 数据对象 | 说明 | 页面用途 |
| --- | --- | --- |
| `ScenarioInput` | 项目排程场景输入，聚合项目结构、工艺工效、逻辑规则、资源、里程碑和求解配置 | 任务视图的输入上下文 |
| `ProjectModel` | 项目结构主数据，包含项目、桥梁、工区、下部结构和上部结构 | 提供桥梁 / 工区、幅别、墩号、构件来源 |
| `ProcessTemplate` | 工艺模板及默认工效配置 | 提供任务工艺选项、资源类型和默认工期规则 |
| `ProductivityOption` | 工效分组 | 提供工程量口径、工期算法、工效值和单位 |
| `LogicRule` | 下部结构或顺序施工逻辑规则 | 生成任务前后置关系 |
| `UpperStructureLogicRule` | 上部结构逻辑规则 | 生成上部结构任务前后置关系 |
| `ResourcePool` | 项目资源池 | 判断任务候选资源是否可用，并显示资源配置 |
| `GeneratedScheduleInput` | 已生成的求解前任务图 | 页面展示任务、资源、前置关系和诊断 |

### 2.2 任务与关系对象

| 数据对象 | 字段 | 说明 |
| --- | --- | --- |
| `Task` | `id`, `name` | 任务唯一标识和任务名称 |
| `Task` | `bridge_id`, `work_section_id`, `structure_id` | 任务所属桥梁、工区和结构物 |
| `Task` | `component_id`, `component_type` | 任务来源构件和构件类型 |
| `Task` | `control_level` | 管控级别，用于后续求解策略和展示 |
| `Task` | `process_name`, `productivity_rule_id` | 当前选用工艺和工效规则 |
| `Task` | `quantity`, `quantity_label` | 工程量数值和展示文本 |
| `Task` | `duration_days` | 生成任务时计算出的工期，最小为 1 天，结果向上取整 |
| `Task` | `compatible_resource_types` | 可匹配的资源类型 |
| `PrecedenceLink` | `predecessor_id`, `successor_id` | 前置任务和后续任务 |
| `PrecedenceLink` | `relationship`, `lag_days` | 逻辑关系类型和滞后天数 |
| `PrecedenceLink` | `source_rule_id`, `severity` | 关系来源规则和严重等级 |
| `TaskOverride` | `method_id`, `productivity_option_id` | 任务级工艺和工效覆盖配置 |

### 2.3 枚举、状态、单位和标签

| 类别 | 值 | 展示或含义 |
| --- | --- | --- |
| 幅别 | `left`, `right`, `none` | 左幅、右幅、无幅别 |
| 管控级别 | `control`, `normal` | 控制性工程、普通工程 |
| 逻辑关系 | `FS`, `SS`, `FF`, `SF` | 完成到开始、开始到开始、完成到完成、开始到完成 |
| 候选前置策略 | `all`, `first_available` | 所有候选均满足、按候选顺序选择第一个可用前置 |
| 工期算法 | `units_per_day`, `days_per_unit`, `fixed_days` | 按日完成量、按单位耗时、固定工期 |
| 工程量来源 | `pile_length_m`, `pier_height_m`, `deck_length_m`, `count` | 桩长、墩高、桥面长度、构件数量 |
| 诊断等级 | `info`, `warning`, `error` | 正常、提醒、严重偏差 |

构件类型应使用统一中文标签展示，包括桩基、承台、扩大基础、地系梁、中系梁、墩身、盖梁、桥台、制梁、架梁、现浇连续梁、现浇箱梁、钢箱梁和桥面系。

### 2.4 页面表格字段

任务清单表格应展示以下列：

| 列 | 说明 | 交互要求 |
| --- | --- | --- |
| 管控级别 | 任务所属结构物或任务的管控级别 | 可编辑时显示下拉选择；不可编辑时显示标签 |
| 桥梁 / 工区 | 桥梁名称和工区名称 | 只读 |
| 幅别 | 左幅、右幅或无幅别 | 只读标签 |
| 墩号 / 结构物 | 墩台号、跨组或结构物名称 | 只读 |
| 构件 | 构件类型中文标签 | 只读标签 |
| 任务名称 | 生成后的任务名称 | 只读 |
| 工艺 | 当前选用施工工艺 | 多个可选工艺时显示下拉选择 |
| 工效 | 当前选用工效分组 | 多个可选工效时显示下拉选择 |
| 工程量 | 工程量摘要 | 只读 |
| 工期 | 计算后的工期天数 | 只读 |
| 工期计算 | 工程量、工效和工期之间的计算表达式 | 只读，内容较长时应可完整查看 |
| 资源配置 | 任务候选资源类型或资源池标签 | 只读 |
| 前置 | 前置任务数量 | 有前置时可查看明细，无前置时显示 0 |

## 3. 默认数据初始化

### 3.1 初始化原则

实际工程中，任务视图应基于项目级数据初始化。项目创建或首次进入排程模块时，系统应把工艺工效模板、工艺逻辑模板、资源模板和里程碑模板初始化为项目级配置，并与项目结构参数组合为 `ScenarioInput`。

结构物主数据应由后端完成文件解析、字段标准化、结构层级映射和数据质量检查，再写入或更新当前项目的标准结构模型。

### 3.2 默认数据清单

| 数据 | 初始化来源 | 项目级归属 |
| --- | --- | --- |
| 桥梁、工区、墩台、构件和上部结构 | 项目结构参数服务或结构参数导入文件 | 项目结构主数据 |
| 工艺工效库 | 系统工艺工效模板 | 项目可调整配置 |
| 工艺逻辑规则 | 系统逻辑模板 | 项目可调整配置 |
| 资源池和资源日历 | 系统资源模板或项目资源方案 | 项目可调整配置 |
| 里程碑 | 合同节点、强控节点或项目计划模板 | 项目可调整配置 |
| 任务工艺和工效覆盖 | 用户在任务视图中的局部调整 | 项目排程方案配置 |

### 3.3 数据归属和持久化

任务视图中的管控级别、构件工艺、工效分组和任务覆盖配置应保存为项目级排程方案配置。保存后，用户再次进入同一项目和同一方案时，应看到上次确认后的配置。

结构物尺寸、墩台编号、跨径表达式和构件数量属于结构主数据，不应在任务视图中直接修改。若发现结构主数据错误，用户应回到结构参数源头修正。

## 4. 页面功能交互

### 4.1 进入页面

用户进入排程系统后，可从功能导航打开“任务视图”，根据当前项目状态展示以下状态之一：

* 正在加载项目场景：展示加载状态。
* 尚未生成任务图：展示空态，提示“尚未生成求解前任务图”和“生成后可按墩号或工艺核验任务、工期和前置关系。”
* 已生成任务图：展示筛选区、分组切换和任务清单。

### 4.2 任务图生成

用户点击“生成任务视图”或“刷新任务视图”时，系统应基于当前 `ScenarioInput` 生成 `GeneratedScheduleInput`。生成或刷新任务视图只负责生成任务、逻辑关系、资源候选和诊断，不执行 CP-SAT 求解。

### 4.3 筛选和分组

任务图生成后，页面应展示两个筛选输入：

| 筛选项 | 占位提示 | 匹配范围 |
| --- | --- | --- |
| 结构物 | 桥梁、工区、幅别、墩号、任务 | 桥梁名称、工区名称、幅别、墩台号、结构物名称、任务名称 |
| 工艺 / 构件 | 工艺名称或构件类型 | 工艺名称、构件中文标签 |

筛选只影响页面展示，不改变任务图和排程输入。

任务视图应支持两种分组方式：

* 按墩号：按桥梁 / 工区展开，墩号从小到大展示，组内按工序顺序排列。
* 按工艺：按构件类型和工艺聚合，组内仍按桥梁 / 工区、墩号、工序排序。

每个分组应支持展开和收起，并显示任务统计摘要，例如结构物数量、任务数量和工期合计。

### 4.4 查看任务清单

任务清单应以表格展示。用户应能够在不进入求解结果页的情况下，核验以下内容：

* 任务是否覆盖项目内应排程的结构物和构件。
* 同一桥梁、工区、幅别下墩台任务顺序是否符合施工认知。
* 工艺和工效是否符合施工方案。
* 工程量和工期计算是否符合工效规则。
* 资源配置是否能映射到当前资源池。
* 前置关系是否来自正确的工艺逻辑规则。

### 4.5 编辑管控级别、工艺和工效

当任务来源于可编辑的结构物时，管控级别应显示为下拉选择。用户可在控制性工程和普通工程之间切换。管控级别参与求解策略或优先级计算时，变更后应标记当前任务图和求解结果需要刷新。

当某个构件类型存在多个可选工艺时，工艺列应显示下拉选择。用户切换工艺后，系统应自动选中该工艺的默认工效分组，并更新后续任务生成所需的工艺和资源类型。

当当前工艺存在多个工效分组时，工效列应显示下拉选择。用户切换工效后，系统应重新计算该任务的工程量口径、工期和工期计算表达式。

工艺和工效调整应写入项目排程方案配置：

* 若任务能回溯到结构构件，应优先写入构件的工艺和工效配置。
* 若任务为聚合任务、上部结构生成任务或不能回溯到单一构件，应写入任务级覆盖配置。

### 4.6 查看前置关系

前置列应显示当前任务的前置任务数量。数量为 0 时，显示 0；数量大于 0 时，用户可查看前置明细。

前置明细应包含：

* 前置任务幅别。
* 前置任务墩台号。
* 前置构件名称。
* 逻辑关系类型和滞后天数，例如 `FS+3`。

前置明细用于核验工艺逻辑，不用于直接编辑逻辑规则。若用户需要调整逻辑关系，应进入工艺逻辑模块维护规则后重新生成任务视图。

## 5. 前后端能力

### 5.1 查询和初始化能力

后端需提供项目排程场景查询能力，返回当前项目和方案的标准 `ScenarioInput`。若项目首次进入排程模块，后端应完成系统模板到项目级配置的初始化。

前端需在进入页面时加载项目排程场景，并根据是否已有有效任务图决定展示空态或任务清单。

### 5.2 结构参数接入能力

后端需支持从项目结构参数服务或导入文件中获取结构参数，并统一映射为标准项目结构模型。结构参数接入应返回标准场景、导入摘要、质量检查结果和告警信息。

前端需负责文件选择、导入提交、导入过程状态、错误展示和导入成功后的页面刷新。

### 5.3 任务图生成能力

后端需根据 `ScenarioInput` 生成 `GeneratedScheduleInput`，包括任务清单、前后置关系、可用资源、里程碑和诊断信息。任务图生成阶段不执行求解器。

前端需根据返回结果渲染任务视图，并在生成失败时展示错误信息。若返回诊断中存在严重偏差，页面应明确提示该任务图暂不适合进入求解。

### 5.4 保存能力

实际工程版本应支持保存任务视图中的项目级配置变更，包括管控级别、构件工艺、构件工效和任务级覆盖配置。保存成功后，后续生成任务和求解均应使用最新配置。

保存能力应与项目、方案和用户权限绑定，避免不同项目或不同方案之间互相污染。

## 6. 联动规则

### 6.1 上游输入

任务视图依赖以下上游数据：

* 项目结构参数：决定任务来源、桥梁 / 工区、幅别、墩号、构件和工程量基础。
* 工艺工效库：决定可选工艺、工效分组、资源类型和工期计算方式。
* 工艺逻辑库：决定任务前后置关系。
* 资源配置：决定任务是否有可用资源候选。
* 里程碑配置：随任务图进入求解输入，用于后续求解评价。

### 6.2 下游影响

任务视图输出的任务图是模拟求解模块的输入。以下变更会影响下游求解：

* 重新接入结构参数。
* 修改管控级别。
* 修改任务或构件工艺。
* 修改任务或构件工效。
* 修改工艺工效库、工艺逻辑库、资源配置、里程碑或计划开始日期。

发生上述变更后，旧任务图、旧求解结果和旧方案对比结果不得继续作为当前方案展示。系统应要求用户重新生成任务视图或重新求解。

### 6.3 任务生成规则

生成任务图时，系统应：

1. 遍历项目内纳入排程范围的桥梁、工区、结构物和构件。
2. 跳过未启用或不在当前排程范围内的构件。
3. 按构件工艺配置、任务覆盖配置和工艺库默认值匹配施工工艺。
4. 按工效配置、任务覆盖配置和工艺默认工效匹配工效分组。
5. 根据工效工程量来源计算任务工程量。
6. 根据工期算法计算任务工期，最小为 1 天。
7. 根据工艺和资源配置生成候选资源类型。
8. 根据工艺逻辑规则生成前后置关系。
9. 汇总生成诊断信息。

工艺匹配优先级：

1. 任务级覆盖配置。
2. 构件 `method_id`。
3. 当前构件类型的默认工艺。
4. 当前构件类型第一个可用工艺。

工效匹配优先级：

1. 任务级覆盖配置。
2. 构件 `productivity_option_id`。
3. 当前工艺的默认工效分组。
4. 当前工艺第一个可用工效分组。

### 6.4 工期计算规则

工期计算应使用统一的工程量口径和工效单位：

| 工效单位示例 | 工期算法 | 工程量来源 |
| --- | --- | --- |
| `m/天` | 按日完成量计算 | 桩长、墩高或桥面长度 |
| `根/天` | 按日完成量计算 | 构件数量 |
| `天/根` | 按单位耗时计算或固定工期 | 构件数量 |
| `天/m` | 按单位耗时计算 | 桩长、墩高或桥面长度 |
| `天/节` | 按单位耗时计算 | 墩身节段数量或由墩高换算的节段数 |

页面应展示可读的工期计算表达式，帮助用户判断工程量、工效和工期之间的关系。

### 6.5 前置关系规则

同一墩台内默认逻辑应覆盖以下关系：

* 承台在同一墩台全部桩基完成后施工。
* 地系梁在同一墩台全部桩基完成后施工。
* 墩身优先以承台为前置；无承台时按规则回退到地系梁或桩基。
* 中系梁在墩身完成后施工。
* 盖梁以墩身、中系梁为前置。
* 桥台台身优先以承台为前置；无承台时回退到桩基或扩大基础。

跨墩台、上部结构和连续梁等关系应由对应逻辑规则生成。若找不到前置任务，应形成诊断，不应静默忽略。

## 7. 校验与异常处理

### 7.1 导入校验

结构参数导入时应校验：

* 文件格式是否符合要求。
* 桥梁、工区、幅别、墩台和构件是否可识别。
* 数量、长度、高度等关键工程量是否可解析。
* 同一结构物或构件是否存在冲突数据。

导入失败时，页面应展示错误信息，并保留当前有效项目数据，不应产生半更新状态。

### 7.2 任务生成校验

任务生成时应校验：

* 构件是否缺少可匹配工艺。
* 工效分组是否缺少工程量来源或工效值。
* 工程量是否小于等于 0。
* 资源池中是否缺少任务需要的资源类型。
* 工艺逻辑是否找不到前置或后续任务。

严重错误应阻止或标记求解不可用；提醒类问题应允许用户继续查看任务图，但需要在进入求解前明确提示。

### 7.3 交互状态

导入、生成或刷新任务图期间，相关按钮和下拉控件应禁用，避免重复提交或在生成过程中修改配置。操作完成后应恢复可用状态。

若筛选条件下没有任务，任务清单区域应展示空结果提示。空结果不代表任务图为空，用户可清空筛选条件恢复展示。

## 8. 验收标准

### 8.1 页面展示验收

* 打开任务视图时，能看到页面标题“任务视图”和求解前核验说明。
* 未生成任务图时，页面展示“尚未生成求解前任务图”的空态。
* 生成任务图后，页面展示结构物筛选、工艺 / 构件筛选、按墩号 / 按工艺切换和任务清单。
* 任务清单表头包含管控级别、桥梁 / 工区、幅别、墩号 / 结构物、构件、任务名称、工艺、工效、工程量、工期、工期计算、资源配置和前置。
* 分组标题能显示任务数量和工期合计。

### 8.2 任务生成验收

* 用户点击生成任务视图后，系统生成任务清单、前后置关系、资源候选和诊断信息，且不执行 CP-SAT 求解。
* 任务按桥梁 / 工区、墩号和工序顺序稳定排序。
* 按工艺分组时，同一构件类型和工艺的任务聚合展示，组内仍保持桥梁 / 工区、墩号、工序排序。
* 工期计算表达式能解释工程量、工效和工期结果。

### 8.3 编辑联动验收

* 用户切换工艺后，任务后续生成使用新工艺、默认工效和对应资源类型。
* 用户切换工效后，任务工程量口径、工期和工期计算表达式随之更新。
* 用户修改管控级别后，项目排程方案中对应结构物或任务的管控级别更新。
* 修改工艺、工效、管控级别或结构参数后，旧求解结果不再作为当前方案结果展示。
* 重新导入结构参数后，旧任务覆盖配置不会错误套用到新结构。

### 8.4 前置关系验收

* 有前置任务时，前置列显示数量，并可查看前置任务的幅别、墩台号、构件名称、逻辑关系和滞后天数。
* 无前置任务时，前置列显示 0。
* 工艺逻辑规则调整后，重新生成任务视图能反映新的前置关系。

### 8.5 异常验收

* 导入非法文件时，页面展示错误信息，当前有效任务图和项目数据不被破坏。
* 缺少工艺、工程量无效、资源缺失或前置任务缺失时，系统生成明确诊断。
* 生成或导入过程中重复点击按钮不会产生重复任务或不一致状态。
