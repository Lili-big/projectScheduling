# 精排目标函数算法需求文档

版本：v3.7
日期：2026-07-04
适用模块：桥梁施工 CP-SAT 精排求解、模拟求解页面、精排结果诊断
文档性质：算法 / 规则交底文档

## 1. 文档目标

本文档说明精排求解中目标函数的业务含义、指标边界、计算口径、输出字段和验收口径，供产品、算法、前后端和测试对齐使用。

本版本聚焦当前已经实际应用的 7 个目标项：

1. 软控制节点迟延
2. 控制链总时差不足风险
3. 控制链衔接空档风险
4. 总工期
5. 资源路径连续性
6. 资源空闲
7. 同类资源工作量均衡

本文只描述当前目标函数和结果诊断口径，不新增接口、字段、算法目标、约束或前端交互；本版本更新资源路径连续性中同幅跨墩跳跃罚分口径。

## 2. 业务背景

桥梁施工精排的核心目标不是只求一个最短工期，而是在控制节点、控制链风险、资源组织、结构连续施工和整体完工跨度之间做有优先级的综合取舍。

业务上需要回答三类问题：

| 问题 | 精排需要给出的答案 |
| --- | --- |
| 关键节点能否守住 | 控制节点是否迟延、迟延多少天、哪些前序任务造成风险 |
| 资源组织是否可施工 | 同类资源是否严重偏载、是否长时间闲置、同一资源是否频繁切换路径 |
| 施工节奏是否可复核 | 整体完工跨度是否偏长、普通任务分布是否需要作为诊断复核 |

因此，目标函数只负责把可以量化并参与求解的偏好转成惩罚项；诊断指标负责解释排程结果中的业务风险；展示指标负责让用户理解方案状态和可复核数据。

## 3. 算法位置与数据流

精排求解入口为后端 CP-SAT 排程流程。前端在模拟求解页面读取目标项配置、权重和诊断结果，用于展示“为什么得到这个方案”。

```mermaid
flowchart LR
    A["任务、依赖、资源、里程碑"] --> B["构建硬约束"]
    B --> C["构建 7 个目标项"]
    C --> D["CP-SAT 求解"]
    D --> E["排程结果"]
    E --> F["目标拆解和诊断输出"]
    F --> G["前端精排结果展示"]
```

核心输出字段包括：

| 字段 | 用途 |
| --- | --- |
| `objective_terms_used` | 本次实际启用的目标项清单 |
| `objective_weights` | 本次目标项权重 |
| `objective_breakdown` | 目标函数惩罚值和解释性汇总 |
| `control_priority_analysis` | 控制节点、控制链风险诊断 |
| `normal_balance_metrics` | 普通任务时间分布兼容诊断；本期不作为目标函数项 |
| `resource_organization_analysis` | 资源工作量、闲置、路径组织诊断 |
| `continuity_metrics` | 连续性、跳墩、跳幅、方向反转等复核指标 |

## 4. 硬约束、目标函数项、诊断指标的边界

### 4.1 硬约束

硬约束是必须满足的规则，不能通过增加目标函数惩罚来违反。

| 规则 | 说明 |
| --- | --- |
| 工序依赖 | 任务之间的 FS、SS、FF、SF 等逻辑关系必须满足 |
| 资源容量 | 同一资源在同一时间不能执行超过容量允许的任务 |
| 固定任务 | 已锁定的任务时间或资源必须保持 |
| 日期窗口 | 任务计划时间不得违反输入中的硬性时间边界 |
| 硬里程碑 | 精排中 `mode = "hard"` 的里程碑必须不晚于目标日期，不能通过权重折中晚点 |
| 同组最大参与设备数 | 资源配置中的 `same_structure_parallel_limit` 控制同一资源池下同一结构、同一构件、同一工艺最多由几台设备或班组参与；`0` 或空值表示不额外限制 |
| 必要前置数据 | 缺少任务、资源或依赖时不能生成有效精排结果 |

### 4.2 目标函数项

目标函数项是可被求解器最小化的软偏好。当前版本目标项数量固定为 7 项。

| 目标项 ID | 页面名称 | 默认权重 | 进入目标函数的惩罚值 |
| --- | --- | ---: | --- |
| `control_node_late` | 软控制节点迟延 | 1000000000 | 软控制节点晚于目标日期的迟延天数 |
| `control_buffer_risk` | 控制链总时差不足风险 | 5000000 | 控制链剩余缓冲低于必要缓冲的不足天数 |
| `risk_related_control_wait` | 控制链衔接空档风险 | 1000000 | 已存在控制链缓冲风险时，相关前后任务之间超过依赖要求的等待天数 |
| `makespan_and_soft_milestone` | 总工期 | 10000 | 项目从计划开始到最后任务完成的跨度 |
| `resource_path_continuity` | 资源路径连续性 | 3000 | 同一资源相邻任务的同幅墩号间隔罚分与左右幅切换罚分 |
| `resource_idle` | 资源空闲 | 1000 | 单个资源活跃跨度内未施工的空闲天数 |
| `resource_workload_balance` | 同类资源工作量均衡 | 100 | 同类资源中最大工作量与最小工作量的差值 |

### 4.3 诊断指标

诊断指标用于解释结果，不单独进入目标函数。典型诊断包括：

| 诊断内容 | 说明 |
| --- | --- |
| 同结构同工艺拆分 | 用于复核同一结构、同一构件、同一工艺是否被多个资源承担；该信息来自排程结果诊断，不再作为目标函数项 |
| 跳墩、跳幅 | 说明同一资源施工位置是否出现大跨度跳跃；其中相邻任务左右幅切换会合并进入资源路径连续性目标项 |
| 方向反转 | 说明同一资源是否在排序路径上频繁折返 |
| 跨侧跳转 | 说明同一资源是否在左右幅或不同侧之间切换 |
| 控制链风险明细 | 说明哪些任务影响控制节点缓冲 |
| 资源利用率 | 说明资源在活跃窗口内的利用程度 |

同结构同工艺拆分、跳墩、方向反转和跨侧跳转明细是复核输出，不是单独目标项。其中，同一资源相邻任务的左右幅切换已经合并进入 `resource_path_continuity`，但不会作为独立目标项出现。它们可以帮助用户判断结果是否需要调整资源配置、权重或约束。同结构同工艺是否允许多设备参与，应通过资源配置中的 `same_structure_parallel_limit` 硬约束表达。

### 4.4 展示指标

展示指标面向页面阅读，不等同于目标函数项。典型展示包括计划状态、总工期、工作项数量、资源 / 里程碑数量、诊断标签和方案说明。

`weighted_objective` 是解释性加权汇总，用于展示各目标项在同一方案下的综合量级，不承诺与求解器内部原始目标值逐项完全等价。

## 5. 目标函数整体口径

求解器在满足硬约束的前提下，最小化各目标项的加权惩罚：

```text
综合惩罚 =
  软控制节点迟延天数 × 软控制节点迟延权重
+ 控制链缓冲不足天数 × 控制链总时差不足风险权重
+ 风险控制链额外等待天数 × 控制链衔接空档风险权重
+ 项目总工期天数 × 总工期权重
+ 资源路径连续性罚分 × 资源路径连续性权重
+ 资源空闲天数 × 资源空闲权重
+ 同类资源工作量差异天数 × 同类资源工作量均衡权重
```

权重体现业务优先级。权重越高，求解器越倾向于优先压低该项惩罚；但最终结果仍受硬约束、可用资源、任务依赖和求解时间共同影响。

## 6. 目标函数指标解释

### 6.1 指标总览

| 目标项 | 解决的问题 | 惩罚触发场景 | 主要结果字段 | 权重 |
| --- | --- | --- | --- | ---: |
| 软控制节点迟延 | 软控制节点不能晚 | 软控制里程碑晚于目标日期 | `control_priority_analysis`、`objective_breakdown.control_lateness_days`、`objective_breakdown.soft_control_lateness_penalty` | 1000000000 |
| 控制链总时差不足风险 | 控制链不能把余量耗尽 | 任务完成后剩余缓冲低于必要缓冲 | `control_priority_analysis`、`objective_breakdown.control_buffer_risk_penalty` | 5000000 |
| 控制链衔接空档风险 | 有风险的控制链不能无故等待 | 风险任务的前后衔接超过依赖要求 | `control_priority_analysis`、`objective_breakdown.risk_related_control_wait_penalty` | 1000000 |
| 总工期 | 控制整体完工跨度 | 项目最终完成时间变晚 | `objective_breakdown.objective_days`、`weighted_objective` | 10000 |
| 资源路径连续性 | 同一资源尽量沿同幅邻近墩号推进，减少左右幅切换 | 同一资源相邻任务同幅墩号间隔较大，或发生左右幅切换 | `resource_organization_analysis`、`objective_breakdown.resource_path_continuity_penalty` | 3000 |
| 资源空闲 | 资源进场后尽量连续作业 | 资源活跃窗口内出现未施工空档 | `resource_organization_analysis`、`objective_breakdown.resource_idle_penalty` | 1000 |
| 同类资源工作量均衡 | 同类型资源不要一忙一闲 | 同类资源工作量差距变大 | `resource_organization_analysis`、`objective_breakdown.resource_workload_balance_penalty` | 100 |

### 6.2 软控制节点迟延

| 项目 | 说明 |
| --- | --- |
| 业务含义 | 对允许晚点但业务上仍需优先保障的控制节点设置最高软目标，尽量压低其晚点天数。 |
| 解决的问题 | 防止求解器为了资源均衡、路径连续或普通任务顺滑，牺牲控制层级节点的目标日期。 |
| 何时产生惩罚 | 当节点是软控制节点，且实际完成日期晚于目标日期时产生惩罚。 |
| 计算方式 | 先计算每个软控制节点“实际完成日期 - 目标日期”的晚点天数；没有晚点则记为 0；多个软控制节点的晚点天数累加。目标贡献 = 软控制节点迟延天数 × 软控制节点迟延权重。硬里程碑不进入该项。 |
| 数值解释 | 数值为 0 表示软控制节点未晚点；数值越大表示控制目标偏离越多。由于权重最高，正常情况下应优先压低。 |
| 展示/诊断字段 | `control_priority_analysis` 展示控制对象、状态、影响任务；`objective_breakdown.control_lateness_days` 和 `objective_breakdown.soft_control_lateness_penalty` 展示软控制节点迟延。 |
| 权重 | 默认 `1000000000`。 |
| 验收口径 | 软控制节点晚点时应进入 `control_node_late` 加权目标；硬里程碑不可用该权重折中晚点，必须作为硬约束满足，否则精排不可行或进入既有失败处理。 |

### 6.3 控制链总时差不足风险

| 项目 | 说明 |
| --- | --- |
| 业务含义 | 控制链上的任务即使没有直接晚点，也要保留必要缓冲，避免后续轻微波动就击穿控制节点。 |
| 解决的问题 | 只看最终节点是否晚点会忽略“马上就要晚”的隐性风险。本指标把总时差不足提前暴露出来。 |
| 何时产生惩罚 | 当任务完成后距离控制节点安全完成时间的剩余缓冲小于必要缓冲时产生惩罚。 |
| 计算方式 | 对控制链任务计算“距离控制节点安全完成时间还剩多少缓冲”。如果实际剩余缓冲小于业务要求的必要缓冲，不足的天数计入风险。目标贡献 = 控制链缓冲不足天数 × 控制链总时差不足风险权重。 |
| 数值解释 | 数值为 0 表示控制链缓冲满足要求；数值越大，表示可用总时差被消耗越多，抗扰动能力越差。 |
| 展示/诊断字段 | `control_priority_analysis` 中展示风险状态、剩余缓冲、必要缓冲；`objective_breakdown.control_buffer_risk_penalty` 展示累计风险天数。 |
| 验收口径 | 用户应能识别哪些控制链任务缓冲不足，以及不足天数是否随权重提高而下降。 |

### 6.4 控制链衔接空档风险

| 项目 | 说明 |
| --- | --- |
| 业务含义 | 对已经存在缓冲风险的控制链，进一步压缩前后任务之间不必要的等待。 |
| 解决的问题 | 有些方案控制节点尚未晚点，但关键路径附近任务之间留了空档，导致风险集中在后段。 |
| 何时产生惩罚 | 当后续任务属于有缓冲风险的控制链，且前后任务实际间隔超过依赖关系要求时产生惩罚。 |
| 计算方式 | 只看已经存在缓冲风险的控制链。系统按工艺依赖要求先确定前后任务之间允许的最小间隔，再计算实际间隔超过最小间隔的等待天数。目标贡献 = 风险控制链额外等待天数 × 控制链衔接空档风险权重。 |
| 数值解释 | 数值为 0 表示风险控制链上没有额外等待；数值越大，表示有风险链路的衔接越松散。 |
| 展示/诊断字段 | `control_priority_analysis` 展示风险链路和相关任务；`objective_breakdown.risk_related_control_wait_penalty` 展示累计等待惩罚。 |
| 验收口径 | 当控制链已经风险较高时，提高该权重应能优先减少风险链路上的无效等待。 |

### 6.5 同类资源工作量均衡

| 项目 | 说明 |
| --- | --- |
| 业务含义 | 同类型资源的工作量尽量接近，避免一部分资源超负荷、另一部分资源利用不足。 |
| 解决的问题 | 在资源数量固定时，单纯追求工期可能导致任务集中给少数资源，现场出现忙闲不均。 |
| 何时产生惩罚 | 同一资源类型下，不同资源承担的任务工期总量存在差异时产生惩罚。 |
| 计算方式 | 系统按资源类型分组，统计同类中每个资源承担的工作天数。取同类资源中最大工作天数与最小工作天数的差值作为工作量差异。目标贡献 = 同类资源工作量差异天数 × 同类资源工作量均衡权重。 |
| 数值解释 | 数值为 0 表示同类资源工作量完全一致；数值越大，表示同类资源之间分工越不均衡。 |
| 展示/诊断字段 | `resource_organization_analysis` 展示资源类型、各资源工作量、均衡状态；`objective_breakdown.resource_workload_balance_penalty` 展示目标项惩罚。 |
| 验收口径 | 同类资源数量充足时，应能看到任务更均匀地分配到同类资源上。 |

### 6.6 资源空闲

| 项目 | 说明 |
| --- | --- |
| 业务含义 | 资源一旦进场，应尽量减少中间长时间停等，提高资源连续利用率。 |
| 解决的问题 | 防止某个班组或设备在首个任务和最后一个任务之间出现大量空档，造成进退场、等待和协调成本。 |
| 何时产生惩罚 | 某资源在活跃窗口内存在未承接任务的空闲天数时产生惩罚。 |
| 计算方式 | 对每个资源，系统从该资源第一个任务开始到最后一个任务完成形成“资源活跃窗口”。活跃窗口内没有承接任务的天数计为空闲天数。目标贡献 = 资源空闲天数 × 资源空闲权重。 |
| 数值解释 | 数值为 0 表示资源活跃期间连续作业；数值越大，表示资源等待或断续越明显。 |
| 展示/诊断字段 | `resource_organization_analysis` 展示资源利用率、最大空档、空闲状态；`objective_breakdown.resource_idle_penalty` 展示目标项惩罚。 |
| 验收口径 | 提高该权重后，同一资源的长空档应减少；若无法减少，应能由依赖、里程碑或资源冲突解释。 |

### 6.7 资源路径连续性

| 项目 | 说明 |
| --- | --- |
| 业务含义 | 同一资源尽量按同一幅内相邻或邻近墩号推进，减少在左右幅之间来回切换。 |
| 解决的问题 | 防止同一设备或班组刚完成一个位置后，被排到同幅相隔很远的墩号，或频繁从左幅切到右幅，增加现场组织和转场解释成本。 |
| 何时产生惩罚 | 对同一资源按计划时间排序后，只比较相邻两项任务：同幅但墩号不相邻时产生墩号间隔罚分；左右幅发生切换时产生换幅罚分。 |
| 计算方式 | 资源路径连续性罚分 = 同幅相邻任务墩号间隔罚分 + 左右幅切换罚分。同幅墩号间隔罚分按“相邻两项任务墩号差值”计算；例如左幅 1# 墩后接左幅 4# 墩，罚分为 3；左幅 4# 墩后接左幅 3# 墩，罚分为 1。左右幅切换罚分按相邻两项任务从左幅到右幅、或从右幅到左幅的切换次数计算，每次切换记 1。目标贡献 = 资源路径连续性罚分 × 资源路径连续性权重。 |
| 数值解释 | 数值为 0 表示同一资源相邻任务没有同幅墩号空档，也没有左右幅切换；数值越大，表示同一资源的空间推进越不连续。 |
| 展示/诊断字段 | `resource_organization_analysis` 展示资源使用、空闲和路径相关统计；`continuity_metrics` 展示跳墩、跳幅、方向反转、路径组切换等复核信息；`objective_breakdown.resource_path_continuity_penalty` 展示目标项惩罚。 |
| 验收口径 | 目标项只按“同幅相邻任务墩号间隔罚分 + 左右幅切换罚分”计算；路径组切换、方向反转等仍可作为诊断信息展示，不应被描述为独立目标项或本目标项的额外求解期罚分。 |

### 6.8 总工期

| 项目 | 说明 |
| --- | --- |
| 业务含义 | 在优先满足硬约束、软控制节点、控制缓冲和资源组织目标后，仍要尽量缩短项目整体完工跨度。 |
| 解决的问题 | 防止方案虽然关键节点和资源组织可接受，但整体完工明显偏晚。 |
| 何时产生惩罚 | 项目最终完成时间变晚时产生惩罚；普通软里程碑迟延不进入该目标项。 |
| 计算方式 | 项目总工期从项目计划开始日期算到最后一个任务完成日期。目标贡献 = 项目总工期天数 × 总工期权重。普通软里程碑迟延只做诊断展示，不加到总工期目标里。内部 ID 仍保留 `makespan_and_soft_milestone` 以兼容既有配置。 |
| 数值解释 | 数值越小表示整体完工越早。该目标权重低于控制链和资源组织目标，避免抢占关键节点和施工组织优先级。 |
| 展示/诊断字段 | `objective_breakdown.objective_days` 和结果统计展示总工期；`objective_breakdown.soft_milestone_penalty` 仅作为普通软里程碑诊断展示，不参与该目标项加权。 |
| 权重 | 默认 `10000`。 |
| 验收口径 | 加权汇总中该项应按“项目总工期天数 × 总工期权重”计算；普通软里程碑迟延只展示，不增加总工期目标贡献。 |

## 7. 指标树与输出口径

### 7.1 目标函数项

目标函数项只包括 7 个实际参与求解的指标。前端目标配置、`objective_terms_used` 和 `objective_weights` 应与下表一致。

| 顺序 | ID | 名称 |
| ---: | --- | --- |
| 1 | `control_node_late` | 软控制节点迟延 |
| 2 | `control_buffer_risk` | 控制链总时差不足风险 |
| 3 | `risk_related_control_wait` | 控制链衔接空档风险 |
| 4 | `makespan_and_soft_milestone` | 总工期 |
| 5 | `resource_path_continuity` | 资源路径连续性 |
| 6 | `resource_idle` | 资源空闲 |
| 7 | `resource_workload_balance` | 同类资源工作量均衡 |

### 7.2 诊断指标

诊断指标用于解释和复核结果，不能被当作新增目标项。

| 字段 | 诊断内容 |
| --- | --- |
| `control_priority_analysis` | 控制节点状态、风险任务、剩余缓冲、必要缓冲、影响路径 |
| `resource_organization_analysis` | 资源工作量、资源空闲、资源路径组、路径空缺、利用率 |
| `continuity_metrics` | 同结构同工艺拆分复核、跳墩、跳幅、跨侧跳转、方向反转；其中相邻任务换幅会进入资源路径连续性罚分，其余明细用于复核 |
| `normal_balance_metrics` | 普通任务时间分布、前后期集中程度；本期仅作兼容诊断，不作为目标项 |

### 7.3 前端展示指标

前端展示指标用于帮助用户快速阅读方案。

| 指标 | 说明 |
| --- | --- |
| 计划状态 | 例如最优、可行、未求解、不可行 |
| 总工期 | 当前方案从计划开始到最后任务完成的天数 |
| 工作项 | 本次排入计划的任务数量 |
| 资源 / 里程碑 | 当前数据中的资源和里程碑数量 |
| 精排诊断 | 控制风险、资源风险、连续性风险和普通任务分布复核摘要 |

展示指标可以引用目标项和诊断指标，但不得把展示标签反向解释为求解器的新目标。

## 8. 典型解释案例

### 8.1 控制链风险高但控制节点未晚点

如果控制节点目标日期尚未被突破，但关键前序任务已经把缓冲压缩到必要缓冲以下，`control_buffer_risk` 会产生惩罚。

业务解释：方案现在看起来没有晚点，但抗扰动能力不足；后续任何小延误都可能导致控制节点失守。

### 8.2 资源工作量均衡但资源空闲较高

如果两个同类资源最终承担的总天数接近，`resource_workload_balance` 可能较低；但其中一个资源中间等待很久，`resource_idle` 仍会较高。

业务解释：资源分得比较平均，但施工节奏不连续，需要看依赖、作业面或路径是否造成断档。

### 8.3 跳墩很多但路径目标项不一定很高

跳墩、方向反转等是连续性诊断口径。左右幅切换既会作为连续性明细展示，也会按相邻任务换幅次数进入 `resource_path_continuity`；当前目标函数只把同一资源相邻任务的同幅墩号间隔和左右幅切换纳入路径连续性罚分。

业务解释：跳墩诊断提醒用户复核现场合理性，但不能直接等同于目标函数惩罚。若后续要把跳墩纳入目标，需要另行定义新目标项、权重和验收标准。

## 9. 前后端职责边界

| 模块 | 职责 |
| --- | --- |
| 后端求解 | 构建硬约束、目标函数项和诊断统计，输出排程结果和目标拆解 |

## 10. 异常与兼容口径

| 场景 | 处理口径 |
| --- | --- |
| 目标项未启用 | 不进入本次目标函数，但字段可用于展示配置状态 |
| 权重为空或非法 | 使用默认权重或后端校验口径处理，结果中应能看到实际权重 |
| 资源数量不足 | 硬约束仍要满足；目标函数只能在可行范围内优化 |
| 硬里程碑无法满足 | 硬里程碑作为精排硬约束，不通过目标权重折中；若无可行解，应展示不可行或进入既有失败/回退处理 |
| 软控制节点迟延 | 返回可行方案时，应展示软控制节点迟延和影响任务，并计入最高权重目标 |
| 诊断指标异常高 | 不代表求解失败，应结合目标项惩罚、权重和硬约束判断 |
| 旧配置包含 `normal_balance` | 后端兼容接收但过滤该目标项，不进入 `objective_terms_used`、`objective_weights` 或加权目标 |
