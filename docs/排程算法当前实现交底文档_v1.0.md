# 排程算法当前实现交底文档

版本：v1.0

日期：2026-07-08

适用范围：桥梁施工排程 Demo 的任务生成、固定资源最短工期、固定工期最少资源、资源成本优化、目标函数、资源约束和结果诊断

面向对象：产品、算法研发、后端研发、前端研发、测试、计划工程师

文档性质：算法 / 规则交底文档

## 1. 文档目标

本文档用一份材料说明当前排程算法如何运行。读者应能从本文理解：

- 用户点击求解后，系统如何从 `ScenarioInput` 生成 `ScheduleInput`。
- 固定资源最短工期入口如何得到主排程结果。
- CP-SAT 中哪些规则属于硬约束，哪些目标进入加权目标函数，哪些字段用于诊断和展示。
- 当前资源未达到业务目标时，系统如何给出资源增量建议和候选方案。
- 固定工期最少资源、资源成本优化与主排程入口的关系。

本文聚焦当前实现口径，避免记录版本差异和迭代过程。

## 2. 系统链路位置

核心数据链路如下：

```text
ScenarioInput
  -> GeneratedScheduleInput / ScheduleInput
  -> ScheduleResult
  -> ScenarioSolveResult / ScenarioAlternativeResult
```

主要入口：

| 能力 | API | 后端编排 | 求解器能力 |
| --- | --- | --- | --- |
| 生成任务图 | `POST /api/generate-schedule-input` | `generate_schedule_input_from_scenario()` | 无 CP-SAT 求解 |
| 固定资源最短工期 | `POST /api/solve-scenario` | `solve_scenario()` | `solve_control_priority_schedule()` |
| 固定工期最少资源 | `POST /api/solve-min-resources` | `solve_min_resources_scenario()` | `solve_min_resources_schedule()` |
| 固定工期最低资源成本 | `POST /api/solve-resource-cost` | `solve_resource_cost_scenario()` | `solve_resource_cost_schedule()` |
| 方案对比 | `POST /api/compare-scenarios` | `compare_scenarios()` | 读取已有结果指标 |

当前固定资源主入口直接使用当前资源数量展开命名资源，进入完整目标函数求解。求解结果是否能作为业务成功方案，由 `stats.target_achievement` 判定。

## 3. 输入对象与前置条件

### 3.1 场景输入

`ScenarioInput` 是前端提交给后端的业务场景，包含：

| 输入 | 来源 | 对排程的作用 |
| --- | --- | --- |
| 项目结构 `project` | 项目参数页、Excel 导入、本地默认场景 | 生成桥梁、工区、墩台、构件和上部结构任务 |
| 工艺工效库 `process_library` | 工艺工效库页 | 选择构件工艺、计算工程量和工期、给出默认资源类型 |
| 工艺逻辑 `logic_rules` | 工艺逻辑页 | 生成同结构内和跨结构的 `PrecedenceLink` |
| 上部结构逻辑 `upper_structure_logic_rules` | 工艺逻辑页 | 生成现浇箱梁、现浇连续梁相关任务和前后置 |
| 资源池 `resource_pools` | 资源配置页 | 展开命名资源，提供当前数量、最大数量、成本和并行规则 |
| 里程碑 `milestones` | 里程碑页 | 评价合同、强控和内部节点目标 |
| 求解策略 `schedule_strategy` | 模拟结果页 / 默认配置 | 控制目标项开关、权重、普通工程窗口和工作面上限 |
| 求解时限 `time_limit_seconds` | 场景配置 | 控制单次求解预算 |

### 3.2 任务生成

任务生成由 `generate_schedule_input_from_scenario()` 完成：

1. 遍历项目桥梁、工区、结构物和构件。
2. 为启用构件匹配工艺模板和工效分组。
3. 依据工程量来源和工期算法计算 `duration_days`。
4. 生成下部结构任务、现浇箱梁任务、现浇连续梁任务。
5. 生成同结构内工艺前后置、跨墩台顺序前后置和上部结构前后置。
6. 按当前资源数量展开命名资源。
7. 为任务匹配当前启用且受限的资源类型。
8. 输出 `GeneratedScheduleInput`，同时给出任务数、逻辑数、资源数和连续梁任务数。

生成阶段发现错误级诊断时，固定资源主入口返回 `MODEL_INVALID`，求解器不会运行。

## 4. 当前固定资源主流程

用户点击“固定资源条件下，推算最短工期”后，后端执行：

```text
生成 ScheduleInput
  -> 使用当前 ResourcePool.quantity 展开命名资源
  -> 完整目标函数求解
  -> 计算 target_achievement
  -> 按业务目标状态返回主结果或资源建议
```

### 4.1 主结果判定

固定资源主结果来自 `solve_control_priority_schedule()`。求解后系统补充固定资源元数据：

| 情况 | 主结果来源 | 展示口径 |
| --- | --- | --- |
| 得到可行排程且业务目标达成 | `current_resources_control_priority_balanced` | 当前资源已满足目标 |
| 得到可行排程但业务目标未达成 | `current_resources_target_failed` | 保留当前资源排程，并输出资源增量建议 |
| 求解时限内无法确认 | `target_unconfirmed` | 当前预算内未确认目标状态 |
| 当前资源、工艺逻辑或资源覆盖无法形成物理可行排程 | `physical_infeasible` | 当前输入需要检查资源、逻辑或任务覆盖 |

业务目标状态写入 `stats.target_achievement` 和 `objective_breakdown.target_achievement`：

| 字段 | 说明 |
| --- | --- |
| `business_success` | 强制节点迟延天数和固定工期超期天数均为 0 时为 `true` |
| `target_status` | 目标状态枚举，例如 `met`、`current_resources_target_failed`、`candidate_resources_target_met`、`physical_infeasible`、`unconfirmed` |
| `hard_milestone_late_days` | 强制里程碑累计迟延天数 |
| `fixed_duration_overrun_days` | 固定工期目标超期天数 |
| `failure_reasons` | 目标未达成或未确认原因 |
| `evaluated_at_source` | 当前判定基于当前资源、候选资源或最大资源 |

### 4.2 当前资源未达成目标时

当前资源已有可查看排程但业务目标未达成时，系统保留主结果的任务、资源分配、里程碑结果和目标函数拆解，并运行资源建议：

1. 计算不考虑资源排队的工艺逻辑关键路径。
2. 使用资源池最大数量生成最大资源场景。
3. 调用固定工期最少资源能力搜索候选资源数量。
4. 将候选资源数量代入完整目标函数复排。
5. 候选复排通过 `target_achievement` 验证后，作为 `alternative_results` 返回。

资源建议状态写入 `resource_recommendation_status`：

| 状态 | 含义 |
| --- | --- |
| `not_needed` | 当前资源已满足目标 |
| `critical_path_unknown` | 关键路径无法计算 |
| `critical_path_infeasible` | 工艺逻辑理论最短路径已经突破目标 |
| `max_resource_generation_error` | 最大资源场景生成失败 |
| `recommended_resources_verified` | 推荐资源数量得到验证，并返回候选排程 |
| `resource_upper_bound_infeasible` | 最大资源上限仍无法满足目标 |
| `resource_recommendation_unresolved` | 求解预算内未得到可验证推荐 |
| `unconfirmed` | 当前资源求解状态未确认 |
| `physical_infeasible` | 当前资源、施工规则或资源覆盖无法形成可行排程 |

## 5. CP-SAT 硬约束

硬约束用于定义排程必须满足的施工规则。目标函数权重不能牺牲这些约束。

| 约束 | 当前实现 |
| --- | --- |
| 任务工期 | 每个任务建立开始、结束变量，结束时间等于开始时间加 `duration_days` |
| 工艺逻辑 | `PrecedenceLink` 支持 `FS`、`SS`、`FF`、`SF` 和 `lag_days` |
| 命名资源唯一分配 | 有受限候选资源的任务在候选命名资源中 `ExactlyOne` |
| 命名资源互斥 | 同一命名资源上的可选任务区间添加 `NoOverlap` |
| 普通工程时间窗口 | 普通任务受 `normal_earliest_start_offset`、`normal_latest_finish_offset` 控制 |
| 普通工程工作面 | 同一工区普通任务受 `max_parallel_normal_per_work_section` 控制 |
| 同结构资源绑定 | 启用 `same_structure_resource_binding` 的资源池，按结构、构件、工艺和资源组限制同组资源参与数 |
| 连续梁班组占用 | 现浇连续梁按跨组占用连续梁班组，班组数量限制可并行跨组数量 |
| 连续梁专项顺序 | 0 号块、标准段、边跨直线段、边跨合龙、中跨合龙按现浇连续梁规则添加硬约束 |

### 5.1 命名资源分配

命名资源精排使用 `_build_named_resource_assignment_model()`：

1. 按任务兼容资源类型找到候选命名资源。
2. 对普通任务建立 `任务-资源` 选择变量。
3. 任务必须选择一个候选资源。
4. 被选择后生成该资源上的可选区间。
5. 每个资源的所有区间使用 `NoOverlap`，保证同一设备或班组同一时间只能承担一个任务。

同结构资源绑定启用时，系统按“结构物 + 构件类型 + 工艺 + 资源组”聚合任务，并控制同组任务可使用的命名资源数量。

### 5.2 容量模型

容量模型用于固定工期最少资源、资源成本优化和部分资源建议测算。它按资源池容量建立 `Cumulative`：

```text
同一资源池同一时间占用量 <= 该资源池选择数量
```

容量模型输出资源数量候选；需要形成最终可查看候选方案时，系统再用候选资源数量运行完整目标函数复排。

### 5.3 现浇连续梁班组

现浇连续梁任务使用 `cast_in_place_continuous_beam_team` 资源类型。系统按 `bridge_id + work_section_id + group_index` 形成跨组身份：

| 字段 | 含义 |
| --- | --- |
| `span_group_id` | 连续梁跨组标识 |
| `bridge_id` | 所属桥梁 |
| `work_section_id` | 所属工区 / 左右幅 |
| `group_index` | 同一工区内连续梁组序号 |

连续梁跨组占用写入 `stats.continuous_beam_team_spans`。当班组数量为 1 时，跨组串行；班组数量为 2 时，最多两个跨组并行。任务结果保留原任务粒度，并补充 `continuous_span_*` 字段用于前端解释班组占用。

## 6. 当前目标函数

当前完整目标函数由 4 个可配置目标项组成：

| 目标项 ID | 名称 | 默认权重 | 原始罚分来源 |
| --- | --- | ---: | --- |
| `control_node_late` | 控制节点迟延 | 10,000,000,000 | 软控制节点迟延、放松目标下的强制节点迟延、固定工期超期 |
| `makespan_and_soft_milestone` | 总工期 | 5,000,000 | 项目整体完工跨度 |
| `resource_path_continuity` | 资源路径连续性 | 50,000 | 同一资源路径中的空间跳跃、左右幅切换、机械钻机墩组路径罚分 |
| `resource_idle` | 资源空闲 | 50,000 | 同一资源两次任务之间的中途空档 |

目标函数按下式计算：

```text
加权目标值 =
控制节点迟延天数 × 控制节点迟延权重
+ 总工期天数 × 总工期权重
+ 资源路径连续性罚分 × 资源路径连续性权重
+ 资源空闲罚分 × 资源空闲权重
```

后端在 `objective_breakdown.objective_contributions` 输出每个目标项的配置、原始罚分和加权贡献。`weighted_objective` 等于所有 `weighted_contribution` 之和。

### 6.1 目标项启用与建模状态

`schedule_strategy.objective_terms` 控制目标项是否启用和权重。后端输出：

| 字段 | 说明 |
| --- | --- |
| `objective_weights` | 本次有效权重，关闭目标项时有效权重为 0 |
| `objective_terms_used` | 用户配置和有效权重 |
| `objective_modeling_gates` | 目标项在本次模型中是否实际建模 |
| `objective_contributions` | 展示用目标贡献表 |

目标项关闭后，相关软目标变量和路径模型会跳过；任务工期、前后置、命名资源互斥、普通工作面、连续梁硬约束仍照常执行。

### 6.2 强制节点与目标达成

固定资源主入口使用放松目标模式求解。强制里程碑的迟延会进入控制节点迟延目标项，并同时进入 `target_achievement`。因此：

- CP-SAT 状态 `OPTIMAL` 或 `FEASIBLE` 表示求解器找到了当前模型下的可行排程。
- `target_achievement.business_success` 表示该排程是否满足业务目标。
- 前端展示成功、失败、未确认时，应优先使用 `target_achievement`。

## 7. 资源路径连续性与机械钻机墩组

资源路径连续性用于让同一资源尽量沿相近墩台、相同幅别、稳定方向推进。

### 7.1 普通资源路径

系统按每个命名资源的实际任务顺序计算路径：

1. 按资源分组任务。
2. 按计划开始、完成和空间位置排序。
3. 比较相邻任务的桥梁、工区、幅别、墩台序号、构件类型和工艺。
4. 形成同幅跳墩、左右幅切换、跨幅跳墩、方向反复等诊断。
5. 在目标项启用时，将可建模的路径跳跃转为目标函数罚分。

诊断字段写入 `stats.continuity_metrics` 和 `stats.resource_organization_analysis`。

### 7.2 机械钻机墩组

旋挖钻、回旋钻和冲击钻桩基任务会进入机械钻机墩组建模：

1. 按资源组、结构物、构件类型和工艺形成墩组。
2. 同一墩组原任务使用同一台对应工艺的命名钻机。
3. 求解器对墩组路径建立轻量排序偏好，优先同幅邻近推进。
4. 结果展开回原始桩基任务，任务 ID、结构归属、构件类型和工艺保持原粒度。
5. 诊断写入 `stats.drill_group_refinement`。

人工挖孔桩按普通班组资源处理。

### 7.3 连续性评分

`continuity_score` 是结果诊断评分，计算口径为：

```text
连续性扣分 =
同结构同工艺拆分次数 × 8
+ 跳墩次数 × 4
+ 左右幅切换次数 × 2
+ 跨幅跳墩次数 × 6
+ 方向反复次数 × 4

连续性评分 = max(0, 100 - 连续性扣分)
```

该评分用于解释排程质量。真正进入目标函数的是 `resource_path_continuity` 罚分。

## 8. 普通工程诊断

普通工程会区分控制链相关任务和普通任务：

| 分类 | 处理 |
| --- | --- |
| 控制工程、关键工程、控制链前置 | 纳入控制优先分析 |
| 有启用受限资源候选的普通任务 | 参与资源路径、资源空闲和资源组织诊断 |
| 无启用受限资源候选的普通任务 | 输出按周/月分布诊断 |

当前 `normal_balance_metrics` 用于展示普通任务数量、已配置资源普通任务数量、未配置资源普通任务数量、时间桶分布和诊断评分。该指标作为结果解释，不进入当前 4 项加权目标函数。

## 9. 固定工期最少资源

固定工期最少资源能力用于回答：“在目标工期或强制里程碑约束下，每类资源建议投入多少？”

流程：

1. 确定目标工期：优先使用可匹配强制里程碑；没有强制里程碑时使用 `fallback_target_days`。
2. 使用最大资源数量做硬目标预检。
3. 做资源下界诊断，识别单资源池理论下界突破上限的场景。
4. 用容量模型搜索资源池数量组合。
5. 用搜索出的资源数量运行完整目标函数复排。
6. 通过硬节点和固定工期目标校验候选结果。
7. 输出推荐资源数量、复排来源和目标达成状态。

关键输出：

| 字段 | 含义 |
| --- | --- |
| `recommended_resource_counts` | 每个资源池当前数量、推荐数量、新增数量和上限 |
| `capacity_model_group_counts` | 容量模型选出的资源池数量 |
| `capacity_precheck_status` | 最大资源硬目标预检状态 |
| `capacity_verification_status` | 容量模型候选是否通过校验 |
| `reoptimization_attempts` | 完整目标函数复排尝试 |
| `recommended_schedule_source` | 推荐方案来源 |
| `target_achievement` | 候选资源目标达成状态 |

## 10. 资源成本优化

资源成本优化用于回答：“在固定工期约束下，选择哪些增量资源成本最低？”

输入来自资源池成本配置：

| 成本字段 | 含义 |
| --- | --- |
| `cost_type` | 无成本、月租、一次性采购 |
| `incremental_unit_cost` | 单个新增资源成本 |
| `billing_period_days` | 月租类资源的计费周期天数 |
| `current_quantity` | 当前资源数量 |
| `max_quantity` | 可增配上限 |

求解流程：

1. 使用最大资源做固定工期可行性预检。
2. 以资源数量选择变量和资源成本项建立容量模型。
3. 月租资源按活跃天数折算成本；一次性采购按新增数量计算固定成本。
4. 最小化资源增量成本。
5. 输出推荐资源数量、成本明细、里程碑结果和业务解释。

关键输出：

| 字段 | 含义 |
| --- | --- |
| `selected_resource_costs` | 每个资源池的选择数量、新增数量和成本 |
| `resource_incremental_cost` | 资源增量成本 |
| `soft_milestone_penalty` | 软节点延误成本 |
| `total_cost` | 展示综合成本 |
| `business_explanation` | 面向用户的成本解释 |
| `schedule_source` | `resource_cost_capacity_model` |

## 11. 结果字段解释

`ScheduleResult` 是前后端展示的统一结果对象：

| 字段 | 展示含义 |
| --- | --- |
| `status` | CP-SAT 求解状态 |
| `objective_days` | 项目总工期天数 |
| `plan_start_date` / `plan_finish_date` | 计划起止日期 |
| `tasks` | 带起止日期和资源信息的任务清单 |
| `resource_allocations` | 资源泳道占用 |
| `milestone_results` | 里程碑目标、实际日期和迟延 |
| `validation` | 生成、求解和诊断消息 |
| `stats` | 前端展示和诊断统计 |
| `objective_breakdown` | 目标函数、来源、资源建议和业务判定元数据 |

前端展示主结果时应同时读取：

- `result.status`
- `result.objective_days`
- `result.milestone_results`
- `result.stats.target_achievement`
- `result.stats.schedule_source` 或 `objective_breakdown.schedule_source`
- `result.objective_breakdown.objective_contributions`
- `result.stats.continuity_metrics`
- `result.stats.continuous_beam_team_spans`
- `alternative_results`

## 12. 验收标准

1. 生成任务图时，任务数、前后置数、资源数和连续梁任务数可从 `source_summary` 读取。
2. 当前资源主入口返回完整目标函数结果，主结果来源和业务目标状态写入 `schedule_source` 与 `target_achievement`。
3. 前端判断当前资源是否达成目标时，优先使用 `target_achievement.business_success`。
4. 目标函数配置区展示 4 个目标项：控制节点迟延、总工期、资源路径连续性、资源空闲。
5. `weighted_objective` 等于 `objective_contributions` 的加权贡献求和。
6. 关闭资源路径连续性目标后，路径建模状态为未启用，命名资源互斥和施工硬约束继续生效。
7. 机械钻机桩基墩组结果保持原任务粒度，并输出 `drill_group_refinement` 诊断。
8. 连续梁班组数量限制跨组并行数量，并输出 `continuous_beam_team_spans`。
9. 当前资源未达成目标时，主结果保留当前资源排程，并输出资源建议状态。
10. 推荐资源候选方案必须经过完整目标函数复排，并通过 `target_achievement` 校验。
11. 固定工期最少资源输出推荐数量、容量模型状态、复排尝试和目标达成状态。
12. 资源成本优化输出资源成本明细、总成本和业务解释。
13. 输入变更后，前端应清空或标记已有任务图、求解结果和方案对比结果失效。
