# 现浇连续梁结构排程 PRD 算法

版本：v1.8
日期：2026-06-30  
适用范围：桥梁施工自动排程系统工程化 MVP 版本  
面向对象：产品、研发、测试、计划工程师

## 1. 需求背景

现浇连续梁、连续刚构等结构通常是桥梁上部结构中的控制性工程，直接影响“下部及现浇结构完成”、架梁前置条件、关键线路和节点履约判断。

系统本期目标不是完整还原连续梁专项施工组织，而是先建立一个可计算、可解释、可排程的 MVP 模型，使计划工程师能够判断：

- 当前连续梁结构数据是否能生成排程任务；
- 当前工效与连续梁班组配置下，连续梁何时完成；
- 连续梁是否影响关键节点；
- 增加或减少连续梁班组后，节点结果如何变化。

## 2. MVP 原则

本期遵循“能落地、可解释、少资源类型、先跑通主链路”的原则。

### 2.1 本期只做

| 类别 | MVP 口径 |
|---|---|
| 结构对象 | 现浇连续梁、连续刚构等上部现浇连续结构 |
| 任务拆解 | 按联、主墩 T 构、0 号块、左侧标准段、右侧标准段、边跨连续段、边跨合龙段、中跨合龙段生成任务 |
| 标准段口径 | 标准段按悬臂方向拆为“左侧标准段、右侧标准段”两个聚合求解任务；不再拆为单个标准块任务 |
| 工期计算 | 工期来自工艺工效库；左/右标准段工期均按标准块循环数 × 单循环工效计算 |
| 工艺逻辑 | 支持下部前置、0 号块、左/右标准段同步、边跨合龙、中跨合龙和合龙顺序 |
| 连续施工 | 左/右标准段均视为连续施工任务，连续性通过聚合任务持续时间表达 |
| 同步控制 | 同一 T 构的左侧标准段与右侧标准段必须同步开始、同步完成，作为 CP-SAT 硬约束 |
| 合龙控制 | 边跨合龙和中跨合龙两侧前置完成时间差均默认不得超过 7 天；具备合龙条件后尽早开始 |
| 资源类型 | 只维护“连续梁班组”一种资源 |
| 资源锁定 | 连续梁班组按 T 构施工包锁定，不支持按单个标准块释放或流转 |
| 输出结果 | 输出任务计划、连续梁班组占用、节点结果、资源不足和逻辑限制原因 |

### 2.2 本期不做

| 非范围 | 说明 |
|---|---|
| 标准块级求解 | 不生成单个标准块任务参与 CP-SAT 求解；不维护单个标准块之间的开始/完成时间 |
| 标准块级连续硬约束 | 不生成单个标准块级连续施工约束；左右同步在“左侧标准段/右侧标准段”聚合任务之间表达 |
| 多类专项资源 | 除连续梁班组外，不单独维护其他连续梁专项资源类型 |
| 单块资源释放 | 连续梁班组不按单个标准块释放或流转 |
| 资源转移过程建模 | 不显式生成拆除、运输、安装等转移任务 |
| 复杂线形/监控计算 | 不处理线形、应力、温控、体系转换细节计算 |
| 自动优化施工方案 | 不自动给出复杂施工组织措施，只输出资源与节点测算结果 |
| 全量连续梁专项设计校核 | 本期只服务进度排程，不替代专项施工方案和施工监控 |

> MVP 统一口径：本期资源只考虑“连续梁班组”；标准段按左/右悬臂方向分别生成聚合任务。左侧标准段与右侧标准段同步开始、同步完成；不再下钻到单个标准块级任务。

## 3. 需求目标

| 目标 | 产品要求 |
|---|---|
| 补齐结构物范围 | 系统应在桥梁结构参数中纳入现浇连续梁、连续刚构等上部现浇连续结构 |
| 完成结构物分解 | 系统应把一联连续梁拆解为主墩 T 构、0 号块、左侧标准段、右侧标准段、边跨连续段、边跨合龙段和中跨合龙段 |
| 统一工期计算 | 所有连续梁任务工期必须来自工艺工效库，结构参数只提供工程量和分解依据 |
| 表达标准段连续施工 | 左/右标准段分别聚合为连续施工任务，不允许算法把单个标准块拆散穿插排程 |
| 表达标准段同步施工 | 同一 T 构的左侧标准段与右侧标准段必须同步开始、同步完成，作为求解硬约束 |
| 表达合龙同步 | 边跨合龙和中跨合龙的两侧前置完成时间差均默认不得超过 7 天，作为逻辑硬约束 |
| 表达合龙及时性 | 合龙段必须等待两侧条件满足；具备合龙条件后，通过目标函数惩罚等待时间，推动尽早开始 |
| 约束资源占用 | 连续梁班组应按 T 构施工包锁定，不能按单个标准块自由释放 |
| 纳入节点判断 | “下部及现浇结构施工完成”类节点应包含现浇连续梁任务，不得只按下部结构判断 |
| 输出可解释结果 | 算法输出应能解释任务来源、工期来源、前置来源、班组占用、里程碑是否满足及异常原因 |

## 4. 关键业务定义

| 名称 | 定义 | MVP 产品口径 |
|---|---|---|
| 现浇连续梁 | 跨越多个支点、现场现浇施工、需要按 T 构和合龙过程控制的上部结构 | 包含现浇连续箱梁、连续刚构等同类结构 |
| 联 | 连续梁排程的基本分组单位 | 同一联内跨号连续、结构类型一致、共享主墩和合龙顺序 |
| 主墩 T 构 | 以主墩为中心向两侧悬臂推进的连续梁施工单元 | 每个主墩生成一个 T 构施工链 |
| T 构施工包 | 一个主墩 T 构从 0 号块到左/右标准段均完成的连续施工范围 | 连续梁班组默认按该施工包锁定 |
| 0 号块 | 主墩 T 构起始块 | 每个主墩 T 构生成 1 个任务 |
| 标准段 | 0 号块完成后的标准块连续施工集合 | 本期按悬臂方向拆为左侧标准段、右侧标准段两个聚合求解任务 |
| 标准块循环数 | 左/右标准段内部的标准块循环数量 | 用于计算左/右标准段工期；不生成单个标准块级求解任务 |
| 悬臂端 | T 构左/右标准段完成后的合龙前置端点 | 本期取对应方向标准段完成时间作为该合龙方向的 ready 时间 |
| 边跨连续段 | 边跨直线段或边跨现浇段 | 每联左右边跨各生成 1 个任务 |
| 边跨合龙段 | 边跨连续段与相邻 T 构悬臂端满足条件后的合龙段 | 每联左右边跨各生成 1 个任务 |
| 中跨合龙段 | 相邻两个主墩 T 构之间的合龙段 | 相邻主墩之间各生成 1 个任务 |
| 连续梁班组 | 本期唯一参与连续梁排程的受限资源 | 可配置数量、启停和成本；不再拆分其他资源类型 |
| 下部完成锚点 | 上部现浇任务使用的墩台下部结构完成口径 | 不直接取同一墩台的全部下部任务；先选定一个完成层级，再取该层级的最晚完成时间 |
| 下部及现浇结构完成 | 计划节点口径 | 包含下部结构、现浇箱梁、现浇连续梁；不包含简支梁架梁、钢箱梁、桥面系 |

## 5. 输入数据要求

| 数据项 | 必填 | 用途 | 缺失处理 |
|---|---|---|---|
| 项目、桥梁、工区或幅别 | 是 | 确定连续梁所属范围和任务展示层级 | 缺失时不允许生成任务 |
| 结构类型 | 是 | 判断是否为现浇连续梁 | 缺失时按未知上部结构处理 |
| 结构编码 | 建议必填 | 提高识别准确性，避免与现浇箱梁混淆 | 缺失时允许按名称兜底识别 |
| 联编号 | 是 | 将跨级数据聚合为同一联 | 缺失时按跨号单独成联，并提示复核 |
| 跨号 | 是 | 联内排序、推断主墩和生成支座范围 | 缺失时不允许生成该跨任务 |
| 支座范围 | 是 | 关联边界墩台、主墩下部结构和任务命名 | 缺失时允许生成任务，但下部前置关系提示缺失 |
| 跨径 | 建议必填 | 展示、校核和后续扩展 | 缺失时不影响本期任务生成，但提示数据不完整 |
| 主墩编号 | 强烈建议 | 决定 T 构数量和左/右标准段生成范围 | 缺失时按跨号推断；仍无法推断则跳过该联任务 |
| 标准块循环数 | 强烈建议 | 计算左/右标准段持续时间 | 缺失时按项目默认循环数生成，并提示复核 |
| 中跨合龙顺序 | 可选 | 决定多个中跨合龙段的先后关系 | 缺失时默认按边到中策略 |
| 控制级别 | 可选 | 标识关键连续梁，影响结果展示和控制优先级 | 缺失时连续梁默认按控制性结构处理 |
| 连续梁班组数量 | 是 | 作为连续梁资源容量 | 缺失时默认 1 个连续梁班组并提示复核 |
| 合龙同步窗口 | 可选 | 判断边跨/中跨合龙两侧前置完成时间是否接近 | 本期默认 7 天 |
| 合龙等待惩罚优先级 | 可选 | 控制具备合龙条件后尽早开始的优化优先级 | 默认高于资源成本和总工期优化 |

## 6. 总体产品算法流程

1. 接收正式结构物参数，按桥梁、工区、幅别整理上部结构。
2. 识别现浇连续梁，并按联编号聚合同一联内的跨。
3. 对每一联连续梁做数据校验，确认跨号、支座范围、主墩、标准块循环数和合龙顺序。
4. 将一联连续梁拆解为排程任务。
5. 为每个任务匹配工艺、工效和连续梁班组资源。
6. 根据连续梁业务规则生成工艺逻辑、合龙逻辑和资源锁定逻辑。
7. 将连续梁任务纳入任务视图、资源配置和里程碑评估。
8. 求解后输出计划日期、连续梁班组占用、里程碑结果和诊断信息。

## 7. 结构物分解算法

### 7.1 联分组

系统应在同一桥梁、同一工区或幅别内按联编号聚合连续梁。联内跨号应按从小到大排序。若工程化数据只提供联级数据，系统应在进入排程前展开为跨级数据，并保留联编号、跨径组合、起止跨号和主墩信息。

产品要求：

- 同一联连续梁必须形成一个父级结构物。
- 父级结构物用于查看和筛选，不作为单独求解任务。
- 子任务必须能追溯到所属桥梁、工区或幅别、联、主墩或合龙位置。

### 7.2 主墩判断

| 步骤 | 规则 |
|---|---|
| 1 | 若结构参数提供主墩编号，直接采用并去重排序 |
| 2 | 若未提供主墩编号，且联内至少有 2 跨，则按联内最小跨号到最大跨号之间的支点推断主墩 |
| 3 | 若无法得到主墩，则该联不生成连续梁任务，并输出“未识别到主墩”的告警 |

### 7.3 求解层任务拆解

对每一联连续梁，设主墩 T 构数量为 N，标准块循环数为 S。S 用于计算每个 T 构左/右标准段工期。

| 任务类型 | 生成规则 | 数量 |
|---|---|---:|
| 0 号块 | 每个主墩 T 构生成 1 个 | N |
| 左侧标准段 | 当 S 大于 0 时，每个主墩 T 构生成 1 个左侧聚合任务 | N |
| 右侧标准段 | 当 S 大于 0 时，每个主墩 T 构生成 1 个右侧聚合任务 | N |
| 边跨连续段 | 每联左、右边跨各生成 1 个 | 2 |
| 边跨合龙段 | 每联左、右边跨各生成 1 个 | 2 |
| 中跨合龙段 | 每两个相邻主墩 T 构之间生成 1 个 | N - 1 |

MVP 说明：

- 标准段不再作为单个 T 构总任务求解，而是按悬臂方向拆为左侧标准段、右侧标准段两个聚合任务。
- 左/右标准段持续时间均按 `标准块循环数 × 单循环工效` 计算。
- 左/右标准段必须同步开始、同步完成，作为 CP-SAT 硬约束。
- 系统不生成单个标准块任务，也不维护单个标准块的开始/完成时间。
- 连续梁班组按 T 构施工包锁定，不按单个标准块释放或流转。

示例：一联连续梁有 2 个主墩，标准块循环数为 18 时，求解层生成 2 个 0 号块、2 个左侧标准段、2 个右侧标准段、2 个边跨连续段、2 个边跨合龙段、1 个中跨合龙段。

### 7.4 命名与展示

| 任务 | 命名要求 |
|---|---|
| 0 号块 | “左幅连续梁 4#墩 T 构-0 号块” |
| 左侧标准段 | “左幅连续梁 4#墩 T 构-左侧标准段 18 个循环” |
| 右侧标准段 | “左幅连续梁 4#墩 T 构-右侧标准段 18 个循环” |
| 边跨连续段 | “左幅连续梁左边跨-边跨连续段” |
| 边跨合龙段 | “左幅连续梁左边跨-边跨合龙段” |
| 中跨合龙段 | “左幅连续梁 4#墩-5#墩-中跨合龙” |

子任务名称不应依赖“第几联”作为唯一识别信息。联级范围应在父级结构物中展示。

## 8. 工艺工效与工期计算

### 8.1 工效配置

| 连续梁构件 | 默认工艺 | 默认工效口径 | 默认资源 |
|---|---|---|---|
| 0 号块 | 0 号块施工 | 固定工期，默认 120 天 / 块 | 连续梁班组 |
| 左/右标准段 | 标准段施工 | 按标准块循环数计算，默认 10 天 / 循环 | 连续梁班组 |
| 边跨连续段 | 直线段施工 | 固定工期，默认 35 天 / 段 | 连续梁班组 |
| 边跨合龙段 | 合龙段施工 | 固定工期，默认 30 天 / 段 | 连续梁班组 |
| 中跨合龙段 | 合龙段施工 | 固定工期，默认 30 天 / 段 | 连续梁班组 |

产品要求：

- 默认工效只作为系统初始化值，项目可按实际施工组织调整。
- 左/右标准段默认使用“单循环工效”，不是固定总工期。
- 修改标准段单循环工效后，重新生成任务视图或重新求解时，左/右标准段应按最新工效计算。
- 结构参数中不得直接写死任务工期。

### 8.2 工期计算规则

| 任务类型 | 工程量来源 | 工期算法 |
|---|---|---|
| 0 号块 | 1 块 | 固定工期 |
| 左/右标准段 | 标准块循环数 S | S × 单循环工效，向上取整且不少于 1 天 |
| 边跨连续段 | 1 段 | 固定工期 |
| 边跨合龙段 | 1 段 | 固定工期 |
| 中跨合龙段 | 1 段 | 固定工期 |

说明：

- 左/右标准段分别聚合为任务，算法不再计算每个标准块的单独开始/完成时间。
- 左/右标准段完成时间分别作为该 T 构左/右悬臂端 ready 时间，用于对应边跨合龙和中跨合龙前置匹配。
- 连续梁班组资源按 T 构施工包占用，不按标准块重复占用。

### 8.3 工期示例

| 条件 | 计算结果 |
|---|---|
| 标准块循环数 18，单循环工效 10 天 / 循环 | T 构左/右标准段任务工期均为 180 天 |
| 标准块循环数 18，用户选择快速工效 5 天 / 循环 | T 构左/右标准段任务工期均为 90 天 |
| 0 号块默认工效 120 天 / 块 | 每个 0 号块任务工期 120 天 |
| 合龙段默认工效 30 天 / 段 | 每个边跨或中跨合龙任务工期 30 天 |

## 9. 工艺逻辑算法

### 9.1 基础前后置关系

| 逻辑名称 | 前置对象 | 后置对象 | 产品规则 |
|---|---|---|---|
| 连续梁 0 号块前置 | 对应主墩下部完成锚点 | 主墩 T 构 0 号块 | 系统先在对应主墩内选定下部完成锚点，0 号块不得早于该锚点完成 |
| 连续梁边跨连续段前置 | 对应边跨墩台下部完成锚点 | 边跨连续段 | 系统先在边跨支座内选定下部完成锚点，边跨连续段不得早于该锚点完成 |
| 连续梁标准段前置 | 同一 T 构 0 号块 | 同一 T 构左/右标准段 | 左/右标准段不得早于 0 号块完成 |
| 连续梁边跨合龙 | 边跨连续段、相邻 T 构边跨侧标准段 | 边跨合龙段 | 边跨合龙必须等待边跨连续段与相邻 T 构对应侧标准段满足前置条件 |
| 连续梁中跨合龙 | 相邻两个 T 构面向同一合龙口的标准段 | 中跨合龙段 | 中跨合龙必须等待相邻 T 构对应侧标准段满足前置条件 |
| 边跨先于中跨合龙 | 左右边跨合龙段 | 中跨合龙段 | 默认中跨合龙不得早于边跨合龙 |
| 中跨合龙顺序 | 前序中跨合龙段 | 后序中跨合龙段 | 按配置的合龙顺序推进 |

### 9.2 下部完成锚点选择规则

业务规则：

> 连续梁 0 号块和边跨连续段的“下部前置”应表达为对应墩台下部结构已经完成。系统不得把同一墩台下的桩基、承台、墩身、盖梁等全部历史下部任务同时作为 0 号块前置；应先确定一个“下部完成锚点”，再用该锚点约束上部现浇任务开始。

选择口径：

| 场景 | 下部完成锚点选择顺序 | 产品规则 |
|---|---|---|
| 主墩 T 构 0 号块 | 盖梁 → 墩身 → 中系梁 → 承台 → 地系梁 / 扩大基础 → 桩基 | 按倒序优先级查找，取到第一个存在的完成层级即停止；若主墩不设盖梁，通常取墩身完成 |
| 边跨支座为墩 | 盖梁 → 墩身 → 中系梁 → 承台 → 地系梁 / 扩大基础 → 桩基 | 边跨连续段只以前述锚点为下部前置，不追加更早层级任务 |
| 边跨支座为台 | 台身 → 承台 → 扩大基础 → 桩基 | 取到第一个存在的完成层级即停止 |

补充说明：

- 若任务图生成前尚无排程完成日期，应按上表倒序优先级选择锚点。
- 若系统已有可比较的计划完成日期，也可在候选下部层级中取实际最晚完成的下部结构作为锚点；两种方式的目标都是表达“对应墩台下部结构最终完成”。
- 同一完成层级内存在多个任务时，例如多根桩基，锚点完成时间取该层级最晚完成时间；任务图可用同层级全部任务或聚合完成点表达。
- 取到锚点层级后不得继续追加更早层级任务。例如同一主墩已取“墩身完成”作为 0 号块前置时，不应再把该墩桩基、承台任务同时列为 0 号块前置。
- 任务视图的前置明细应展示被选中的锚点来源，便于用户核验“为什么 0 号块等待该下部任务完成”。

约束口径：

```text
lower_finish_anchor(墩台) = max(end(被选中完成层级内的任务))
start(0号块) >= lower_finish_anchor(对应主墩)
start(边跨连续段) >= lower_finish_anchor(对应边跨墩台)
```

### 9.3 左/右标准段聚合施工与同步规则

业务规则：

> 标准段按悬臂方向拆为左侧标准段、右侧标准段两个聚合任务。每个聚合任务内部不再拆单个标准块；同一 T 构的左/右标准段应同步施工，保持同一节拍完成。

MVP 实现：

- 每个主墩 T 构生成 1 个左侧标准段任务、1 个右侧标准段任务。
- 左/右标准段任务开始不得早于 0 号块完成。
- 左/右标准段工期均按 `标准块循环数 × 单循环工效` 计算。
- 左侧标准段与右侧标准段必须同步开始、同步完成。
- CP-SAT 不生成单个标准块连续施工硬约束。

约束口径：

```text
start(左侧标准段) >= end(0号块)
start(右侧标准段) >= end(0号块)
duration(左侧标准段) = 标准块循环数 × 单循环工效
duration(右侧标准段) = 标准块循环数 × 单循环工效
start(左侧标准段) = start(右侧标准段)
end(左侧标准段) = end(右侧标准段)
```

说明：

- 左/右标准段已经分别代表一侧悬臂的连续施工集合，因此不需要再用 `start(i+1) = end(i)` 表达单个标准块连续。
- 左/右同步在“左侧标准段、右侧标准段”两个聚合任务之间表达，不下钻到 `左 i#标准块` 与 `右 i#标准块`。
- 后续若进入精排版本，需要展示或控制每个标准块时，再扩展标准块级任务与同步约束。

### 9.4 边跨合龙同步与及时开始规则

业务规则：

> 边跨合龙的两侧前置工作包括边跨连续段和相邻 T 构边跨侧标准段。两侧前置完成时间应尽可能同步，本期默认完成时间差不得超过 7 天，作为逻辑硬约束；两侧均完成后，边跨合龙段应尽早开始。

MVP 参数：

| 参数 | 含义 | 默认口径 |
|---|---|---|
| 合龙同步窗口 | 边跨合龙两侧前置完成时间的最大允许偏差 | 7 天 |
| 合龙等待惩罚优先级 | 两侧具备合龙条件后，等待合龙开始的惩罚权重 | 高于资源成本和总工期优化 |

产品规则：

- 左边跨合龙前置为左边跨连续段和最左侧主墩 T 构左侧标准段。
- 右边跨合龙前置为右边跨连续段和最右侧主墩 T 构右侧标准段。
- 边跨连续段完成时间与对应边跨侧标准段完成时间差不得超过 7 天。
- 该同步窗口本期作为硬约束处理；若当前前置、资源和顺序条件下无法满足，应返回不可行诊断或提示调整班组、工效、前置时间或合龙顺序。
- 两侧前置均完成后，系统计算“边跨合龙等待时间”，并在目标函数中设置高优先级惩罚，推动边跨合龙段尽早开始。

约束口径：

```text
abs(end(边跨连续段) - end(相邻T构边跨侧标准段)) <= 7天
start(边跨合龙段) >= end(边跨连续段)
start(边跨合龙段) >= end(相邻T构边跨侧标准段)
边跨合龙等待 = start(边跨合龙段) - max(end(边跨连续段), end(相邻T构边跨侧标准段))
```

其中 `边跨合龙等待` 进入目标函数高优先级惩罚，不再单独设置“边跨最大等待”参数。

### 9.5 中跨合龙同步与及时开始规则

业务规则：

> 中跨合龙的两侧前置工作为相邻两个 T 构面向同一合龙口的标准段。两侧标准段完成时间应尽可能同步，本期默认完成时间差不得超过 7 天，作为逻辑硬约束；两侧均完成后，中跨合龙段应尽早开始。

MVP 实现：

- T_i 与 T_{i+1} 之间的中跨合龙，左侧前置为 T_i 的右侧标准段。
- T_i 与 T_{i+1} 之间的中跨合龙，右侧前置为 T_{i+1} 的左侧标准段。
- 两侧标准段完成时间差不得超过 7 天。
- 中跨合龙段必须等待两侧标准段均完成后才能开始。
- 两侧均完成后，系统计算“中跨合龙等待时间”，并在目标函数中设置高优先级惩罚，推动中跨合龙段尽早开始。
- 中跨合龙仍受合龙顺序和连续梁班组容量约束。

约束口径：

```text
abs(end(左侧T构右侧标准段) - end(右侧T构左侧标准段)) <= 7天
start(中跨合龙段) >= end(左侧T构右侧标准段)
start(中跨合龙段) >= end(右侧T构左侧标准段)
中跨合龙等待 = start(中跨合龙段) - max(end(左侧T构右侧标准段), end(右侧T构左侧标准段))
```

### 9.6 合龙段等待优化规则

业务规则：

> 合龙段不是普通后置任务。边跨或中跨两侧前置工作均完成后，即视为具备合龙条件；系统应在满足资源容量、合龙顺序和里程碑约束的前提下，尽量减少合龙等待时间。

MVP 实现：

- 合龙段开始时间必须晚于两侧前置任务完成时间。
- 系统计算两侧前置完成时间的较晚值，作为合龙具备条件时间。
- 合龙等待时间不再设置独立最大等待阈值，而是作为目标函数中的高优先级惩罚项。
- 合龙等待惩罚优先级高于资源成本和总工期优化，低于硬约束和硬里程碑可行性判断。

统一计算口径：

```text
ready_time(合龙段) = max(end(前置A), end(前置B))
wait(合龙段) = start(合龙段) - ready_time(合龙段)
wait(合龙段) >= 0
```

## 10. 资源配置算法

### 10.1 资源类型

现浇连续梁任务本期只使用“连续梁班组”一种资源。

| 资源类型 | 用途 | 默认约束 |
|---|---|---|
| 连续梁班组 | 0 号块、左/右标准段、边跨连续段、边跨合龙段、中跨合龙段施工 | T 构内按施工包锁定；边跨连续段和合龙段按任务占用 |

MVP 要求：

- 资源配置页只维护连续梁班组数量、是否启用、成本信息。
- 求解结果只输出连续梁班组占用情况。
- 固定工期最少资源推荐只推荐连续梁班组数量。
- 文档、页面和诊断说明中不再引入其他连续梁专项资源类型。

### 10.2 T 构级资源锁定

业务规则：

> 连续梁班组一旦分配给某个主墩 T 构，应持续服务该 T 构施工包，直到该 T 构左/右标准段均完成后才允许释放，不能按标准段内部标准块自由释放。

T 构施工包默认范围：

```text
T 构施工包 = 0 号块 + 左侧标准段 + 右侧标准段
```

不允许出现：

```text
10#T构左/右标准段未全部完成 → 连续梁班组转去11#T构 → 再回到10#T构
```

允许出现：

```text
10#T构施工包完成 → 连续梁班组释放 → 11#T构施工包开始
```

### 10.3 资源占用口径

| 任务类型 | 资源占用口径 |
|---|---|
| 0 号块 | 纳入所属 T 构施工包占用 |
| 左/右标准段 | 纳入所属 T 构施工包占用 |
| 边跨连续段 | 按任务占用连续梁班组 |
| 边跨合龙段 | 按任务占用连续梁班组 |
| 中跨合龙段 | 按任务占用连续梁班组 |

说明：

- T 构施工包和其内部任务不能重复占用资源；求解时只按 T 构施工包占用连续梁班组。
- 左/右标准段用于表达 T 构两侧悬臂端完成和合龙前置，不单独重复占用连续梁班组容量。
- 边跨连续段、边跨合龙段、中跨合龙段作为独立任务占用连续梁班组。
- 若连续梁班组数量为 1，则同一时间只能存在一个资源占用对象。
- 若连续梁班组数量为 2，则同一时间最多允许两个资源占用对象并行。

### 10.4 资源推荐

| 资源规则 | 产品要求 |
|---|---|
| 默认资源池 | 项目初始化应至少有 1 个连续梁班组 |
| 最大可增配数量 | 若项目未配置上限，系统应按连续梁 T 构数量和默认上限取较大值 |
| 资源停用 | 资源停用后，连续梁任务保留，但求解应输出资源配置诊断 |
| 资源推荐 | 固定工期最少资源推荐只评估连续梁班组增配 |
| 成本优化 | 若连续梁班组配置了成本，资源成本优化只计算连续梁班组成本 |

## 11. CP-SAT 约束编译口径

### 11.1 变量

每个求解任务生成以下变量：

```text
start_i：任务开始时间
end_i：任务完成时间
duration_i：任务持续时间
interval_i：任务时间区间
```

每个 T 构生成一个资源占用包：

```text
TBlockPackage_j.start = start(0号块_j)
TBlockPackage_j.end = max(end(左侧标准段_j), end(右侧标准段_j))
TBlockPackage_j.interval = [start, duration, end]
```

每个合龙口生成两侧前置端点：

```text
边跨合龙前置 = 边跨连续段完成时间、相邻T构边跨侧标准段完成时间
中跨合龙前置 = 相邻两个T构面向同一合龙口的标准段完成时间
```

每个需要下部前置的连续梁任务先生成下部完成锚点：

```text
lower_finish_anchor(墩台) = max(end(被选中完成层级内的任务))
```

### 11.2 硬约束

| 约束 | CP-SAT 表达口径 |
|---|---|
| 下部前置 | `start(0号块) >= lower_finish_anchor(对应主墩)` |
| 边跨连续段前置 | `start(边跨连续段) >= lower_finish_anchor(对应边跨墩台)` |
| 标准段前置 | `start(左侧标准段) >= end(0号块)` 且 `start(右侧标准段) >= end(0号块)` |
| 左右标准段同步 | `start(左侧标准段) = start(右侧标准段)` 且 `end(左侧标准段) = end(右侧标准段)` |
| 边跨合龙前置 | `start(边跨合龙) >= end(边跨连续段)` 且 `start(边跨合龙) >= end(相邻T构边跨侧标准段)` |
| 边跨合龙同步 | `abs(end(边跨连续段) - end(相邻T构边跨侧标准段)) <= 7天` |
| 中跨合龙前置 | `start(中跨合龙) >= end(左侧T构右侧标准段)` 且 `start(中跨合龙) >= end(右侧T构左侧标准段)` |
| 中跨合龙同步 | `abs(end(左侧T构右侧标准段) - end(右侧T构左侧标准段)) <= 7天` |
| 合龙顺序 | 后序合龙开始不得早于前序合龙完成 |
| 连续梁班组容量 | 对 T 构施工包、边跨连续段、边跨合龙段、中跨合龙段统一施加容量约束 |
| T 构资源锁定 | T 构施工包未完成前，所属连续梁班组不得流转到其他 T 构施工包 |
| 已完成实际锁定 | 已完成任务锁定实际开始、实际完成时间 |

不再生成以下单个标准块级硬约束：

```text
start(同侧 i+1#标准块) = end(同侧 i#标准块) + 标准块间隔
start(左 i#标准块) = start(右 i#标准块)
end(左 i#标准块) = end(右 i#标准块)
```

原因：MVP 中只生成左/右标准段两个聚合任务，不生成单个标准块任务；左右同步在左/右标准段聚合任务之间表达。

### 11.3 合龙等待优化项

合龙同步窗口本期作为硬约束，不进入超限惩罚。合龙段具备条件后的等待时间作为优化项进入目标函数。

| 优化项 | 计算口径 | 处理方式 | 输出 |
|---|---|---|---|
| 边跨合龙等待 | `start(边跨合龙段) - max(end(边跨连续段), end(相邻T构边跨侧标准段))` | 目标函数高优先级惩罚 | 输出等待天数 |
| 中跨合龙等待 | `start(中跨合龙段) - max(end(左侧T构右侧标准段), end(右侧T构左侧标准段))` | 目标函数高优先级惩罚 | 输出等待天数 |
| 目标合龙日期 | `end(合龙段) - 目标日期` | 若配置为硬节点则作为硬约束；若配置为软节点则进入延期惩罚 | 输出延期天数 |
| 里程碑日期 | `节点实际完成日期 - 目标日期` | 若配置为硬节点则作为硬约束；若配置为软节点则进入延期惩罚 | 输出延期天数 |

合龙等待变量约束：

```text
ready_time = max(end(前置A), end(前置B))
wait = start(合龙段) - ready_time
wait >= 0
```

若同步硬约束导致模型不可行，系统应输出不可行原因，例如“边跨合龙两侧前置完成时间差超过 7 天且无法调整”或“中跨合龙两侧对应标准段完成时间差超过 7 天且无法调整”。

### 11.4 目标函数优先级

目标函数不应只追求总工期最短，应优先保证连续梁关键节点合理。

建议优先级：

```text
1. 满足工艺逻辑、资源容量、T构资源锁定、边跨/中跨7天同步窗口等硬约束
2. 最小化硬节点或关键合龙节点延期
3. 最小化里程碑延期
4. 最小化合龙等待时间
5. 最小化连续梁班组增配成本
6. 最小化总工期
```

说明：边跨/中跨同步窗口不作为惩罚项处理，而是进入硬约束；合龙等待时间作为高优先级优化项处理。

## 12. 里程碑节点算法

### 12.1 节点范围

项目、桥梁或工区级“下部及现浇结构施工完成”节点应匹配以下任务：

- 下部结构任务：桩基、承台、扩大基础、系梁、墩身、盖梁、桥台等。
- 上部现浇任务：现浇箱梁。
- 上部现浇任务：现浇连续梁。

该节点不匹配：

- 简支梁架梁任务。
- 钢箱梁现场任务。
- 桥面系任务。
- 未生成排程任务的结构参数对象。

### 12.2 节点日期计算

| 节点事件 | 计算口径 |
|---|---|
| 完成节点 | 取节点范围内所有匹配任务的最晚完成日期 |
| 开始节点 | 取节点范围内所有匹配任务的最早开始日期 |
| 未匹配任务 | 节点状态为未评估，并输出节点无匹配任务提示 |
| 硬节点延期 | 输出延期状态，固定工期求解和资源推荐应按硬节点目标判断可行性 |
| 软节点延期 | 输出延期天数和延期成本，不强制阻断求解 |

只要节点范围内存在现浇连续梁任务，该任务未完成时，节点不得判定完成。

## 13. 算法输出

### 13.1 任务图输出

| 输出项 | 内容 |
|---|---|
| 连续梁父级结构物 | 桥梁、工区或幅别、支座范围、联信息 |
| 连续梁子任务 | 0 号块、左侧标准段、右侧标准段、边跨连续段、边跨合龙段、中跨合龙段 |
| 标准段信息 | 标准块循环数、单循环工效、左/右标准段开始/完成时间、是否同步 |
| 工程量 | 0 号块数量、标准块循环数、边跨/合龙段数 |
| 工艺工效 | 当前工艺、工效分组、工效值、工期计算口径 |
| 任务工期 | 每个任务的计划工期 |
| 前置关系 | 下部完成锚点、0 号块至左/右标准段、左右标准段同步、边跨合龙、中跨合龙、合龙顺序 |
| 资源 | 连续梁班组数量、是否启用、占用口径 |
| 数据诊断 | 主墩缺失、标准块循环数缺失、支座无法匹配、工艺缺失、连续梁班组缺失等 |

### 13.2 求解结果输出

| 输出项 | 内容 |
|---|---|
| 排程计划 | 每个连续梁任务的开始日期、完成日期、持续天数 |
| 资源占用 | 连续梁班组分配、占用起止日期、是否存在容量冲突 |
| 标准段结果 | 各 T 构左/右标准段开始、完成时间、同步状态及工期来源 |
| 边跨同步结果 | 边跨连续段完成时间、相邻 T 构边跨侧标准段完成时间、是否满足 7 天硬约束 |
| 中跨同步结果 | 相邻两个 T 构面向同一合龙口的标准段完成时间、是否满足 7 天硬约束 |
| 总工期 | 项目或方案计划完成日期和总天数 |
| 里程碑结果 | 目标日期、实际日期、延期天数、节点状态 |
| 合龙诊断 | 两侧前置完成时间、是否满足 7 天同步硬约束、合龙等待时间 |
| 资源建议 | 为满足固定工期或硬节点建议增加的连续梁班组数量 |
| 诊断说明 | 数据、工效、逻辑、资源、里程碑不可行原因 |
| 对比指标 | 不同连续梁班组数量下的连续梁完成日期和节点满足情况 |

结果输出应明确说明连续梁是否处于关键影响链路。若增加连续梁班组仍无法满足节点，系统应提示受工艺顺序、下部结构前置或合龙逻辑限制，不能只给出“继续增加班组”的建议。

## 14. 异常处理

| 异常场景 | 系统处理 |
|---|---|
| 正式结构物参数未返回上部结构 | 显示“当前无上部现浇结构”；若项目存在架梁前置要求，应提示结构参数缺失 |
| 结构编码缺失但名称包含“连续”或“刚构” | 按现浇连续梁识别，同时输出需复核提示 |
| 结构类型为现浇箱梁但跨径组合呈连续梁特征 | 可作为连续梁候选提示，不应直接覆盖正式结构编码 |
| 联编号缺失 | 按跨号单独成联，并提示联信息缺失 |
| 主墩缺失且无法推断 | 跳过该联连续梁任务生成，输出明确告警 |
| 标准块循环数缺失 | 按项目默认标准块循环数生成，并提示计划工程师复核 |
| 支座范围无法匹配下部结构 | 生成任务，跳过无法建立的下部前置关系，输出告警 |
| 同一墩台存在多类下部任务 | 按下部完成锚点选择规则取一个完成层级，不把所有下部任务全部追加为连续梁前置 |
| 工艺配置缺失 | 不生成对应任务或标记生成失败，并提示维护工艺工效库 |
| 连续梁班组缺失或停用 | 任务保留，求解输出资源配置诊断 |
| 合龙同步硬约束不可满足 | 输出不可行原因，提示调整班组、工效、前置时间或合龙顺序 |
| 合龙节点不可满足 | 输出延期或不可行原因，资源推荐应判断增加连续梁班组是否仍有意义 |

## 16. 验收标准

| 编号 | 验收场景 | 预期结果 |
|---|---|---|
| AC-01 | 工程项目返回一联现浇连续梁，包含联编号、跨号、支座范围和主墩 | 系统生成连续梁父级结构物，并在任务视图下展示连续梁子任务 |
| AC-02 | 一联连续梁有 2 个主墩，标准块循环数为 18 | 生成 2 个 0 号块、2 个左侧标准段、2 个右侧标准段、2 个边跨连续段、2 个边跨合龙段、1 个中跨合龙段 |
| AC-03 | 一联连续梁有 4 个主墩，标准块循环数为 2 | 生成 4 个 0 号块、4 个左侧标准段、4 个右侧标准段、2 个边跨连续段、2 个边跨合龙段、3 个中跨合龙段 |
| AC-04 | 标准段单循环工效为 10 天、标准块循环数为 18 | 每个 T 构左/右标准段任务工期均为 180 天 |
| AC-05 | 用户把某联标准段单循环工效改为 5 天 | 该联 T 构左/右标准段工期均更新为 90 天 |
| AC-06 | 查看标准段求解任务 | 系统展示左侧标准段、右侧标准段两个聚合任务，不生成单个标准块求解任务 |
| AC-06A | 同一 T 构左/右标准段存在多个可行排法 | CP-SAT 必须输出左/右标准段同步开始、同步完成的排程 |
| AC-06B | 同一主墩存在桩基、承台、墩身，且不设盖梁 | 0 号块前置只取该主墩墩身完成锚点，不把桩基、承台等历史下部任务全部列为前置 |
| AC-06C | 同一主墩同时存在盖梁和墩身 | 默认取盖梁作为 0 号块下部完成锚点；取到后不再追加墩身、承台、桩基等前置 |
| AC-07 | 连续梁班组数量为 1，10#T构施工包未完成 | 该班组不得被分配到 11#T构施工包 |
| AC-08 | 连续梁班组数量从 1 调整为 2 后重新求解 | 连续梁任务排布、班组占用和里程碑日期按新班组数量重新计算 |
| AC-09 | 边跨连续段完成时间与相邻 T 构边跨侧标准段完成时间差超过 7 天 | 不得输出违反同步窗口的可行排程；应调整排程满足 7 天约束，无法满足时输出不可行诊断 |
| AC-10 | 中跨相邻两个 T 构面向同一合龙口的标准段完成时间差超过 7 天 | 不得输出违反同步窗口的可行排程；应调整排程满足 7 天约束，无法满足时输出不可行诊断 |
| AC-11 | 两侧前置已完成且存在多个可行合龙开始时间 | 目标函数应优先选择合龙等待时间更短的方案，并输出合龙等待天数 |
| AC-12 | 桥级“下部及现浇结构施工完成”目标早于连续梁合龙完成日期 | 里程碑显示延期，延期天数按连续梁实际完成日期计算 |
| AC-13 | 连续梁缺少主墩且无法推断 | 不生成该联连续梁任务，输出“未识别到主墩”类告警 |
| AC-14 | 固定工期最少资源推荐场景中连续梁导致硬节点延期 | 推荐结果只评估连续梁班组增配；若增配无效，应说明受工艺关键路径限制 |
| AC-15 | 结果页查看连续梁资源占用 | 只展示连续梁班组占用，不展示其他连续梁专项资源 |

## 17. 测试建议

测试数据至少覆盖：

| 测试数据 | 覆盖目的 |
|---|---|
| 单联双主墩连续梁 | 验证基础任务拆解、标准段工期、边跨和中跨合龙 |
| 单联四主墩连续梁 | 验证多 T 构、多中跨合龙和合龙顺序 |
| 现浇箱梁 + 现浇连续梁 + 简支梁混合桥 | 验证结构识别边界和里程碑范围 |
| 主墩缺失、标准块循环数缺失、支座缺失的数据 | 验证异常提示和跳过规则 |
| 连续梁班组 1 个与多个的对比方案 | 验证班组约束对工期和节点结果的影响 |
| 边跨连续段完成时间与相邻 T 构边跨侧标准段相差超过 7 天 | 验证边跨同步窗口和不可行诊断 |
| 相邻 T 构面向同一合龙口的标准段完成时间差过大 | 验证中跨合龙 7 天同步硬约束和不可行诊断 |

自动化测试应覆盖：

- 连续梁结构识别和分组。
- 主墩推断和无法推断时的告警。
- 任务数量、任务名称和父子展示关系。
- 0 号块下部完成锚点选择：有盖梁取盖梁，无盖梁取墩身；取到一个完成层级后不再追加更早下部层级。
- 标准段按悬臂方向生成左侧标准段、右侧标准段两个聚合任务。
- 左/右标准段均按 `标准块循环数 × 单循环工效` 计算工期。
- 不生成标准块级连续施工硬约束。
- 左/右标准段同步开始、同步完成作为硬约束；不生成单个标准块级同步约束。
- 连续梁班组按 T 构施工包锁定，不按标准块流转。
- 边跨连续段与相邻 T 构边跨侧标准段完成时间差默认不超过 7 天，作为硬约束；无法满足时输出不可行诊断。
- 中跨相邻 T 构面向同一合龙口的标准段完成时间差默认不超过 7 天，作为硬约束；无法满足时输出不可行诊断。
- 合龙段具备条件后尽早开始，等待时间进入目标函数高优先级惩罚。
- 连续梁班组资源限制和资源推荐。
- “下部及现浇结构施工完成”节点包含现浇连续梁，不包含简支梁架梁。

## 18. MVP 一致性检查

交付前需要检查：

1. 文档中连续梁资源只出现“连续梁班组”。
2. 页面配置项只要求维护连续梁班组数量、启停和成本。
3. 资源推荐结果只推荐连续梁班组增配。
4. 标准段按悬臂方向拆为左侧标准段、右侧标准段两个聚合求解任务，不拆成单个标准块任务。
5. 左/右标准段必须同步开始、同步完成，作为 CP-SAT 硬约束。
6. 不存在单个标准块级连续施工硬约束；左右同步只在左/右标准段聚合任务之间表达。
7. 连续梁班组不能在一个 T 构施工包未完成前流转到其他 T 构。
8. 边跨合龙和中跨合龙的两侧前置完成时间差默认均不得超过 7 天，并作为硬约束。
9. 合龙段不是普通后置任务，必须输出两侧完成时间、是否满足 7 天同步硬约束和合龙等待时间。
10. 0 号块和边跨连续段的下部前置必须先选下部完成锚点，不能把同一墩台所有下部历史任务全部挂为前置。
