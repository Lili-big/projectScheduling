# 现浇连续梁结构排程 PRD 算法

版本：v1.2

日期：2026-06-26

适用范围：桥梁施工自动排程系统工程化版本

面向对象：产品、研发、测试、计划工程师

## 1. 需求背景

工程项目排程中，现浇连续梁不是普通上部结构展示信息，而是影响下部结构完成口径、架梁前置条件、关键线路和资源投入判断的控制性结构。若系统只识别下部结构，或只把连续梁作为桥梁参数展示，将导致“下部及现浇结构施工完成”节点被提前判定，资源投入测算缺失连续梁班组，关键线路也无法反映连续梁T构的真实制约。

工程项目应基于正式结构物参数服务获取现浇连续梁数据。系统需要把结构参数、工艺工效、工艺逻辑、资源配置和里程碑节点放入同一条计算链路，使计划工程师能够判断：当前资源下连续梁何时完成，是否影响桥梁控制节点，以及调整工效或连续梁班组后节点结果如何变化。

## 2. 需求目标


| 目标           | 产品要求                                                                              |
| -------------- | ------------------------------------------------------------------------------------- |
| 补齐结构物范围 | 系统应在桥梁结构参数中纳入现浇连续梁、连续刚构等上部现浇连续结构                      |
| 完成结构物分解 | 系统应把一联连续梁拆解为主墩 T 构、0 号块、标准段、边跨连续段、边跨合龙段和中跨合龙段 |
| 统一工期计算   | 所有连续梁任务工期必须来自工艺工效库，结构参数只提供工程量和分解依据                  |
| 形成工艺逻辑   | 连续梁任务应自动继承下部前置、T 构施工顺序、边跨合龙、中跨合龙和合龙顺序规则          |
| 纳入节点判断   | “下部及现浇结构施工完成”类节点应包含现浇连续梁任务，不得只按下部结构判断            |
| 输出可解释结果 | 算法输出应能解释任务来源、工期来源、前置来源、资源占用、里程碑是否满足及异常原因      |

产品实现原则：

- 结构参数只负责描述连续梁位置、联、跨、主墩、节段数量和合龙顺序，不直接决定任务工期。
- 工期必须由结构工程量和工艺工效共同计算，且可被项目级工效配置覆盖。
- 工艺逻辑必须由业务规则生成，不依赖用户手工补齐连续梁内部前后置关系。
- 里程碑判断必须基于生成后的任务范围，不能只按结构参数对象是否存在判断。
- 求解结果必须可解释到结构分解、工效选择、资源占用和节点偏差。

## 3. 本期范围

本期纳入：

- 正式结构物参数服务中现浇连续梁数据的接收、校验和标准化。
- 现浇连续梁按联、主墩 T 构、节段类型生成排程任务。
- 现浇连续梁工艺工效库、任务视图、工艺逻辑、资源配置、里程碑结果联动。
- 固定资源最短工期、固定工期最少资源、资源成本优化等求解结果中体现连续梁影响。

4. 关键业务定义


| 名称               | 定义                                                            | 产品口径                                                             |
| ------------------ | --------------------------------------------------------------- | -------------------------------------------------------------------- |
| 现浇连续梁         | 跨越多个支点、现场现浇施工、需要按 T 构和合龙过程控制的上部结构 | 包含现浇连续箱梁、连续刚构等同类结构                                 |
| 联                 | 连续梁排程的基本分组单位                                        | 同一联内跨号连续、结构类型一致、共享主墩和合龙顺序                   |
| 主墩 T 构          | 以主墩为中心向两侧悬臂施工的连续梁施工单元                      | 每个主墩生成一个 T 构施工链                                          |
| 0 号块             | 主墩 T 构起始块                                                 | 每个主墩 T 构生成 1 个任务                                           |
| 标准段             | 主墩0#块完成后的挂篮循环施工的标准块集合                        | 本期按“标准块数量”生成一个批量任务                                 |
| 边跨连续段         | 边跨直线段或边跨现浇段                                          | 每联左右边跨各生成 1 个任务                                          |
| 边跨合龙段         | 边跨与 T 构完成后的合龙段                                       | 每联左右边跨各生成 1 个任务                                          |
| 中跨合龙段         | 相邻两个主墩 T 构之间的合龙段                                   | 相邻主墩之间各生成 1 个任务                                          |
| 下部及现浇结构完成 | 计划节点口径                                                    | 包含下部结构、现浇箱梁、现浇连续梁；不包含简支梁架梁、钢箱梁、桥面系 |

## 5. 输入数据要求

工程项目应由正式结构物参数服务提供连续梁数据。系统接收后应标准化为排程可消费的结构物数据。


| 数据项                 | 必填     | 用途                                     | 缺失处理                                   |
| ---------------------- | -------- | ---------------------------------------- | ------------------------------------------ |
| 项目、桥梁、工区或幅别 | 是       | 确定连续梁所属范围和任务展示层级         | 缺失时不允许生成任务                       |
| 结构类型               | 是       | 判断是否为现浇连续梁                     | 缺失时按未知上部结构处理                   |
| 结构编码               | 建议必填 | 提高识别准确性，避免与现浇箱梁混淆       | 缺失时允许按名称兜底识别                   |
| 联编号                 | 是       | 将跨级数据聚合为同一联                   | 缺失时按跨号单独成联，并提示复核           |
| 跨号                   | 是       | 联内排序、推断主墩和生成支座范围         | 缺失时不允许生成该跨任务                   |
| 支座范围               | 是       | 关联边界墩台、主墩下部结构和任务命名     | 缺失时允许生成任务，但下部前置关系提示缺失 |
| 跨径                   | 建议必填 | 展示、校核和后续专项扩展                 | 缺失时不影响本期任务生成，但提示数据不完整 |
| 主墩编号               | 强烈建议 | 决定 T 构数量和 0 号块、标准段数量       | 缺失时按跨号推断；仍无法推断则跳过该联任务 |
| 标准块数量             | 强烈建议 | 计算标准段任务工程量和工期               | 缺失时按默认挂篮循环数生成，并提示复核     |
| 中跨合龙顺序           | 可选     | 决定多个中跨合龙段的先后关系             | 缺失时默认按边到中策略                     |
| 控制级别               | 可选     | 标识关键连续梁，影响结果展示和控制优先级 | 缺失时连续梁默认按控制性结构处理           |

识别优先级：


| 优先级 | 识别条件                                           | 产品结果                           |
| ------ | -------------------------------------------------- | ---------------------------------- |
| 1      | 结构编码明确为现浇连续梁                           | 识别为现浇连续梁                   |
| 2      | 结构类型包含“连续”或“刚构”                     | 识别为现浇连续梁                   |
| 3      | 结构类型包含“现浇”和“箱梁”，但不满足连续梁条件 | 识别为现浇箱梁                     |
| 4      | 简支梁、T 梁等其他类型                             | 本期仅保留结构参数，不生成架梁任务 |

## 6. 总体产品算法流程

系统生成连续梁排程时应按以下产品流程执行：

1. 接收正式结构物参数，按桥梁、工区、幅别整理上部结构。
2. 识别现浇连续梁，并按联编号聚合同一联内的跨。
3. 对每一联连续梁做数据校验，确认跨号、支座范围、主墩、标准块数量和合龙顺序。
4. 将一联连续梁拆解为可排程任务。
5. 为每个任务匹配工艺、工效和候选资源，并计算任务工期。
6. 根据上部结构工艺逻辑生成前后置关系。
7. 将连续梁任务纳入任务视图、资源配置和里程碑评估。
8. 求解后输出计划日期、资源占用、里程碑结果和诊断信息。

流程完成后，系统应能够回答三类研发交付问题：连续梁拆成了哪些任务、每个任务工期如何计算、这些任务如何影响资源占用和控制节点。

## 7. 结构物分解算法

### 7.1 联分组

系统应在同一桥梁、同一工区或幅别内按联编号聚合连续梁。联内跨号应按从小到大排序。若工程化数据只提供联级数据，系统应在进入排程前展开为跨级数据，并保留联编号、跨径组合、起止跨号和主墩信息。

产品要求：

- 同一联连续梁必须形成一个父级结构物，任务视图中显示为“幅别 + 起止支座范围 + 现浇连续梁”。
- 父级结构物用于查看和筛选，不作为单独求解任务。
- 子任务必须能追溯到所属桥梁、工区或幅别、联、主墩或合龙位置。

### 7.2 主墩判断

系统按以下顺序确定主墩：


| 步骤 | 规则                                                                              |
| ---- | --------------------------------------------------------------------------------- |
| 1    | 若结构参数提供主墩编号，直接采用并去重排序                                        |
| 2    | 若未提供主墩编号，且联内至少有 2 跨，则按联内最小跨号到最大跨号之间的支点推断主墩 |
| 3    | 若无法得到主墩，则该联不生成连续梁任务，并输出“未识别到主墩”的告警              |

示例：一联跨号为 1、2、3、4，未提供主墩时，系统推断主墩为 1#、2#、3#墩。

### 7.3 任务拆解

对每一联连续梁，设主墩 T 构数量为 N，标准块数量为 S。


| 任务类型   | 生成规则                                       | 数量  |
| ---------- | ---------------------------------------------- | ----- |
| 0 号块     | 每个主墩 T 构生成 1 个                         | N     |
| 标准段     | 当 S 大于 0 时，每个主墩 T 构生成 1 个批量任务 | N     |
| 边跨连续段 | 每联左、右边跨各生成 1 个                      | 2     |
| 边跨合龙段 | 每联左、右边跨各生成 1 个                      | 2     |
| 中跨合龙段 | 每两个相邻主墩 T 构之间生成 1 个               | N - 1 |

当 S 大于 0 时，连续梁任务总数为：2N + 2 + 2 + (N - 1)。当 S 等于 0 时，不生成标准段任务，任务总数为：N + 2 + 2 + (N - 1)。

示例：


| 场景       | 主墩数量 | 标准块数量 | 应生成任务                                                              |
| ---------- | -------- | ---------- | ----------------------------------------------------------------------- |
| 单联双主墩 | 2        | 18         | 2 个 0 号块、2 个标准段、2 个边跨连续段、2 个边跨合龙段、1 个中跨合龙段 |
| 单联四主墩 | 4        | 2          | 4 个 0 号块、4 个标准段、2 个边跨连续段、2 个边跨合龙段、3 个中跨合龙段 |

### 7.4 命名与展示


| 任务       | 命名要求                              |
| ---------- | ------------------------------------- |
| 0 号块     | “左幅连续梁 4#墩 T 构-0 号块”       |
| 标准段     | “左幅连续梁 4#墩 T 构-标准段 18 块” |
| 边跨连续段 | “左幅连续梁 4#墩 T 构-边跨连续段”   |
| 边跨合龙段 | “左幅连续梁 4#墩 T 构-边跨合龙段”   |
| 中跨合龙段 | “左幅连续梁 4#墩-5#墩-中跨合龙 1”   |

子任务名称不应依赖“第几联”作为唯一识别信息，避免同一页面中联编号、跨号和墩号混淆。联级范围应在父级结构物中展示。

## 8. 工艺工效与工期计算

### 8.1 工效配置

系统应在工艺工效库中提供现浇连续梁的默认工艺模板，并允许用户按项目维护工效分组。


| 连续梁构件 | 默认工艺   | 默认工效口径               | 默认资源   |
| ---------- | ---------- | -------------------------- | ---------- |
| 0 号块     | 0 号块施工 | 固定工期，默认 120 天 / 块 | 连续梁班组 |
| 标准段     | 标准块施工 | 按块计算，默认 10 天 / 块  | 连续梁班组 |
| 边跨合龙段 | 合龙段施工 | 固定工期，默认 30 天 / 段  | 连续梁班组 |
| 中跨合龙段 | 合龙段施工 | 固定工期，默认 30 天 / 段  | 连续梁班组 |
| 边跨连续段 | 直线段施工 | 固定工期，默认 35 天 / 段  | 连续梁班组 |

产品要求：

- 默认工效只作为系统初始化值，项目可按实际施工组织调整。
- 用户可在任务视图中对单个连续梁任务选择工艺或工效分组。
- 修改工效后，重新生成任务视图或重新求解时应按最新工效计算。
- 结构参数中不得直接写死任务工期。

### 8.2 工期计算规则


| 任务类型   | 工程量来源   | 工期算法                             |
| ---------- | ------------ | ------------------------------------ |
| 0 号块     | 1 块         | 固定工期                             |
| 标准段     | 标准块数量 S | S × 单块工效，向上取整且不少于 1 天 |
| 边跨连续段 | 1 段         | 固定工期                             |
| 边跨合龙段 | 1 段         | 固定工期                             |
| 中跨合龙段 | 1 段         | 固定工期                             |

标准段必须按标准块数量计算工期。即使历史工效模板曾被配置为固定工期，系统也应在连续梁标准段场景中按“块数 × 单块工效”计算，避免 18 块标准段只被计算成 1 个固定工期。

### 8.3 任务工期示例


| 条件                                      | 计算结果                         |
| ----------------------------------------- | -------------------------------- |
| 标准块数量 18，单块工效 10 天 / 块        | 标准段工期 180 天                |
| 标准块数量 18，用户选择快速工效 5 天 / 块 | 标准段工期 90 天                 |
| 0 号块默认工效 120 天 / 块                | 每个 0 号块任务工期 120 天       |
| 合龙段默认工效 30 天 / 段                 | 每个边跨或中跨合龙任务工期 30 天 |

## 9. 工艺逻辑算法

连续梁任务应自动生成以下前后置关系。默认关系为完成后开始，默认间隔为 0 天；用户在工艺逻辑页修改关系类型或间隔后，重新生成任务图应生效。


| 逻辑名称             | 前置对象                      | 后置对象         | 产品规则                                          |
| -------------------- | ----------------------------- | ---------------- | ------------------------------------------------- |
| 连续梁 0 号块前置    | 对应主墩下部完成任务（按照盖梁、墩身、桥台、承台的倒序排列，取到一个即终止）          | 主墩 T 构 0 号块 | 0 号块不得早于主墩下部结构完成                    |
| 连续梁边跨连续段前置 | 对应边跨墩台下部完成任务      | 边跨连续段       | 边跨连续段不得早于边跨支座下部完成                |
| 连续梁 T 构顺序      | 同一 T 构 0 号块              | 同一 T 构标准段  | 标准段不得早于 0 号块开始或完成，按配置关系执行   |
| 连续梁边跨合龙       | 边跨连续段、相邻 T 构完成任务 | 边跨合龙段       | 边跨合龙必须等待边跨连续段和相邻 T 构满足前置条件 |
| 连续梁中跨合龙       | 相邻两个 T 构完成任务         | 中跨合龙段       | 中跨合龙必须等待相邻两个 T 构满足前置条件         |
| 边跨先于中跨合龙     | 左右边跨合龙段                | 中跨合龙段       | 默认中跨合龙不得早于边跨合龙                      |
| 中跨合龙顺序         | 前序中跨合龙段                | 后序中跨合龙段   | 按配置的合龙顺序推进                              |

合龙顺序规则：


| 配置       | 产品行为                                           |
| ---------- | -------------------------------------------------- |
| 未配置     | 默认按边到中推进；左右对称的中跨可同一层级施工     |
| 从左到右   | 中跨合龙从小跨号向大跨号依次推进                   |
| 从右到左   | 中跨合龙从大跨号向小跨号依次推进                   |
| 自定义层级 | 同一层级可并行，后续层级等待前序层级完成           |
| 非法配置   | 忽略非法项，未覆盖的中跨按默认顺序补齐，并提示复核 |

若某个下部支座无法匹配到对应下部完成任务，系统仍可生成连续梁任务，但应跳过无法建立的前置关系并输出告警，避免静默生成错误关键线路。

## 10. 资源配置算法

现浇连续梁任务默认使用“连续梁班组”资源。资源为受限资源时，同一班组同一时间只能施工一个连续梁任务；班组数量增加后，求解结果应允许更多连续梁任务并行。


| 资源规则       | 产品要求                                                                              |
| -------------- | ------------------------------------------------------------------------------------- |
| 默认资源池     | 项目初始化应至少有 1 个连续梁班组                                                     |
| 最大可增配数量 | 若项目未配置上限，系统应按连续梁 T 构数量和默认上限取较大值，保证资源推荐有可探索空间 |
| 资源停用       | 资源停用后，连续梁任务保留，但求解应输出资源配置诊断                                  |
| 资源推荐       | 固定工期最少资源推荐应把连续梁班组纳入可增配范围                                      |
| 成本优化       | 若连续梁班组配置了成本，资源成本优化应计算连续梁班组增配成本                          |

## 11. 里程碑节点算法

### 11.1 节点范围

项目、桥梁或工区级“下部及现浇结构施工完成”节点应匹配以下任务：

- 下部结构任务：桩基、承台、扩大基础、系梁、墩身、盖梁、桥台等。
- 上部现浇任务：现浇箱梁。
- 上部现浇任务：现浇连续梁。

该节点不匹配：

- 简支梁架梁任务。
- 钢箱梁现场任务。
- 桥面系任务。
- 未生成排程任务的结构参数对象。

### 11.2 节点日期计算


| 节点事件   | 计算口径                                                     |
| ---------- | ------------------------------------------------------------ |
| 完成节点   | 取节点范围内所有匹配任务的最晚完成日期                       |
| 开始节点   | 取节点范围内所有匹配任务的最早开始日期                       |
| 未匹配任务 | 节点状态为未评估，并输出节点无匹配任务提示                   |
| 硬节点延期 | 输出延期状态，固定工期求解和资源推荐应按硬节点目标判断可行性 |
| 软节点延期 | 输出延期天数和延期成本，不强制阻断求解                       |

只要节点范围内存在现浇连续梁任务，该任务未完成时，节点不得判定完成。若连续梁数据缺失导致任务未生成，系统应通过数据质量告警提示用户，不得把该桥误判为“只有下部结构需要完成”。

## 12. 算法输出

系统在生成任务图、执行求解和展示结果时，应输出以下内容。

### 12.1 任务图输出


| 输出项           | 内容                                                         |
| ---------------- | ------------------------------------------------------------ |
| 连续梁父级结构物 | 桥梁、工区或幅别、支座范围、联信息                           |
| 连续梁子任务     | 0 号块、标准段、边跨连续段、边跨合龙段、中跨合龙段           |
| 工程量           | 0 号块数量、标准块数量、段数                                 |
| 工艺工效         | 当前工艺、工效分组、工效值、工期计算口径                     |
| 任务工期         | 每个任务的计划工期                                           |
| 前置关系         | 下部前置、T 构顺序、合龙顺序、关系类型、间隔天数             |
| 候选资源         | 连续梁班组及资源是否启用                                     |
| 数据诊断         | 主墩缺失、标准块数量缺失、支座无法匹配、工艺缺失、资源缺失等 |

任务图输出应面向计划复核展示，不暴露底层接口字段或程序内部标识。用户看到的核心信息应是结构归属、任务名称、工程量、工效、工期、前置关系和资源。

### 12.2 求解结果输出


| 输出项     | 内容                                                 |
| ---------- | ---------------------------------------------------- |
| 排程计划   | 每个连续梁任务的开始日期、完成日期、持续天数         |
| 资源占用   | 连续梁班组分配、占用起止日期、是否存在资源冲突       |
| 总工期     | 项目或方案计划完成日期和总天数                       |
| 里程碑结果 | 目标日期、实际日期、延期天数、节点状态               |
| 资源建议   | 为满足固定工期或硬节点建议增加的连续梁班组数量       |
| 诊断说明   | 数据、工效、逻辑、资源、里程碑不可行原因             |
| 对比指标   | 不同方案下连续梁任务完成日期、资源投入和节点满足情况 |

结果输出应明确说明连续梁是否处于关键影响链路。若增加连续梁班组仍无法满足节点，系统应提示受工艺顺序、下部结构前置或合龙逻辑限制，不能只给出“继续增加资源”的建议。

## 13. 异常处理


| 异常场景                                 | 系统处理                                                               |
| ---------------------------------------- | ---------------------------------------------------------------------- |
| 正式结构物参数未返回上部结构             | 显示“当前无上部现浇结构”；若项目存在架梁前置要求，应提示结构参数缺失 |
| 结构编码缺失但名称包含“连续”或“刚构” | 按现浇连续梁识别，同时输出需复核提示                                   |
| 结构类型为现浇箱梁但跨径组合呈连续梁特征 | 可作为连续梁候选提示，不应直接覆盖正式结构编码                         |
| 联编号缺失                               | 按跨号单独成联，并提示联信息缺失                                       |
| 主墩缺失且无法推断                       | 跳过该联连续梁任务生成，输出明确告警                                   |
| 标准块数量缺失                           | 按默认挂篮循环数生成，并提示计划工程师复核                             |
| 支座范围无法匹配下部结构                 | 生成任务，跳过无法建立的下部前置关系，输出告警                         |
| 工艺模板缺失                             | 不生成对应任务或标记生成失败，并提示维护工艺工效库                     |
| 连续梁班组缺失或停用                     | 任务保留，求解输出资源配置诊断                                         |
| 硬里程碑不可满足                         | 输出延期和不可行原因，资源推荐应判断增加资源是否仍有意义               |

## 14. 前后端职责


| 角色 | 职责                                                                                                 |
| ---- | ---------------------------------------------------------------------------------------------------- |
| 后端 | 接收并标准化正式结构物参数，完成连续梁识别、分组、任务拆解、工期计算、逻辑关系、里程碑匹配和诊断输出 |
| 前端 | 在任务视图、工艺工效库、工艺逻辑、资源配置、里程碑和结果页展示连续梁相关信息，并支持筛选、复核和配置 |
| 测试 | 覆盖结构识别、任务数量、工期计算、逻辑关系、资源并行、节点延期和异常提示                             |
| 产品 | 确认正式结构物参数字段、主墩来源、标准块数量来源、节点业务口径和本期非范围                           |

## 15. 验收标准


| 编号  | 验收场景                                                     | 预期结果                                                                     |
| ----- | ------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| AC-01 | 工程项目返回一联现浇连续梁，包含联编号、跨号、支座范围和主墩 | 系统生成连续梁父级结构物，并在任务视图下展示连续梁子任务                     |
| AC-02 | 一联连续梁有 2 个主墩，标准块数量为 18                       | 生成 2 个 0 号块、2 个标准段、2 个边跨连续段、2 个边跨合龙段、1 个中跨合龙段 |
| AC-03 | 一联连续梁有 4 个主墩，标准块数量为 2                        | 生成 15 个连续梁任务，其中中跨合龙段为 3 个                                  |
| AC-04 | 标准块工效为 10 天 / 块、标准块数量为 18                     | 标准段任务工期为 180 天                                                      |
| AC-05 | 用户把某个标准段改选为 5 天 / 块工效                         | 该标准段工期更新为 90 天，同联其他未改任务保持原工效                         |
| AC-06 | 用户将“连续梁 0 号块前置”关系改为开始后开始、间隔 4 天     | 重新生成任务图后，对应前置关系按新关系和 4 天间隔生效                        |
| AC-07 | 边跨墩台下部任务未完成                                       | 对应边跨连续段不得判定可开始                                                 |
| AC-08 | 连续梁班组数量从 1 调整为 2 后重新求解                       | 连续梁任务排布、资源占用和里程碑日期按新资源数量重新计算                     |
| AC-09 | 桥级“下部及现浇结构施工完成”目标早于连续梁合龙完成日期     | 里程碑显示延期，延期天数按连续梁实际完成日期计算                             |
| AC-10 | 连续梁缺少主墩且无法推断                                     | 不生成该联连续梁任务，输出“未识别到主墩”类告警                             |
| AC-11 | 正式结构物参数同时包含现浇箱梁、现浇连续梁和简支梁           | 现浇箱梁生成箱梁任务，现浇连续梁生成连续梁任务，简支梁本期不生成架梁任务     |
| AC-12 | 固定工期最少资源推荐场景中连续梁导致硬节点延期               | 推荐结果应评估连续梁班组增配；若增加资源无效，应说明受工艺关键路径限制       |

## 16. 测试建议

测试数据至少覆盖：


| 测试数据                             | 覆盖目的                                     |
| ------------------------------------ | -------------------------------------------- |
| 单联双主墩连续梁                     | 验证基础任务拆解、标准段工期、边跨和中跨合龙 |
| 单联四主墩连续梁                     | 验证多 T 构、多中跨合龙和合龙顺序            |
| 现浇箱梁 + 现浇连续梁 + 简支梁混合桥 | 验证结构识别边界和里程碑范围                 |
| 主墩缺失、标准块缺失、支座缺失的数据 | 验证异常提示和跳过规则                       |
| 连续梁班组 1 个与多个的对比方案      | 验证资源约束对工期和节点结果的影响           |

自动化测试应覆盖：

- 连续梁结构识别和分组。
- 主墩推断和无法推断时的告警。
- 任务数量、任务名称和父子展示关系。
- 标准段按块数计算工期。
- 用户修改工效分组后的任务工期变化。
- 上部结构逻辑关系和间隔天数生效。
- 连续梁班组资源限制和资源推荐。
- “下部及现浇结构施工完成”节点包含现浇连续梁，不包含简支梁架梁。
