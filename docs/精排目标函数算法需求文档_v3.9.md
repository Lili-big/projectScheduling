# 精排目标函数算法需求文档

版本：v3.9

日期：2026-07-04

适用模块：桥梁施工 CP-SAT 精排求解、模拟求解页面、精排结果诊断

文档性质：算法 / 规则交底文档

## 1. 文档目标

本文档说明精排求解中目标函数的业务含义、计算口径、输出字段和验收口径，供产品、算法、后端、前端和测试对齐使用。

本版本重点更新精排失败最佳努力口径，并保留普通工程处理口径：

| 普通工程类型 | 本次优化口径 |
| --- | --- |
| 已配置受限资源的普通工程 | 不做时间均摊，优先通过资源连续施工目标减少窝工 |
| 未配置受限资源的普通工程 | 进入低优先级时间均衡目标，避免短时间集中施工 |

一句话概括：有资源看连续，没资源看均衡；控制节点、控制缓冲、资源连续和总工期始终优先于普通工程均衡。

当严格精排在当前求解时限内没有返回可用结果时，系统可以进入最佳努力精排：只把强制里程碑和固定工期上限从硬约束转为最高优先级软目标，继续遵守资源和施工硬约束，返回当前资源下可复核的最合理方案。

## 2. 算法在系统链路中的位置

用户点击“固定资源条件下，推算最短工期”后，如果当前资源能够满足强制节点，系统会进入命名资源精排。严格精排在满足硬约束的前提下，比较不同可行排程的综合惩罚，选择惩罚更低的方案。若严格精排失败，系统可追加一次最佳努力精排，把强制节点和固定工期作为高优先级软目标处理。

```mermaid
flowchart LR
  A["任务、前置、资源、里程碑"] --> B["硬约束校验"]
  B --> C["控制节点和控制缓冲目标"]
  C --> D["资源组织目标"]
  D --> E["未配置资源普通工程均衡目标"]
  E --> F{"严格精排是否可用"}
  F -- "可用" --> G["输出严格精排和诊断"]
  F -- "不可用" --> H["放松强制节点/固定工期目标"]
  H --> I["输出最佳努力精排和目标迟延诊断"]
```

前端仍只展示和配置原有目标项；未配置资源普通工程均衡是后端固定低优先级目标，不恢复为前端可编辑目标。

## 3. 输入与前置条件

| 输入 | 业务含义 | 本算法用途 |
| --- | --- | --- |
| 工作项管控级别 | 普通、关键、控制 | 只允许普通工程进入普通工程均衡判断 |
| 控制链归属 | 是否影响控制工程或控制节点 | 控制链上的普通前置工作不进入普通工程均衡 |
| 兼容资源类型 | 工作项需要哪些资源类型 | 判断工作项是否可能被受限资源约束 |
| 启用的受限资源候选 | 当前资源配置中可分配给该工作项的命名资源 | 判断普通工程属于“已配置资源”还是“未配置资源” |
| 普通工程统计桶 | 按周或按月 | 用于统计未配置资源普通工程是否集中施工 |
| 普通工程最早开始 / 最晚完成偏移 | 普通工程允许展开的时间窗口 | 统计桶在该窗口内展开 |
| 强制里程碑 | 必须满足的目标节点 | 严格精排中是硬约束；最佳努力分支中转为最高优先级软目标 |
| 固定工期上限 | 固定工期或 fallback target | 严格精排中是硬约束；最佳努力分支中转为最高优先级软目标 |

“没有配置资源”的落地口径是：该普通工作没有启用的受限兼容资源候选。它可能完全没有资源类型，也可能写了资源类型但当前资源池未配置、未启用或不是受限资源。

## 4. 目标函数分层

精排目标按优先级处理。越靠前的目标权重越高，普通工程均衡不会为了好看而牺牲控制链或资源连续施工。

| 优先层 | 目标 | 业务解释 |
| --- | --- | --- |
| 最高层 | 最佳努力目标迟延 | 仅在最佳努力分支启用，强制节点迟延和固定工期超期越大，惩罚越大 |
| 第 1 层 | 软控制节点迟延 | 控制节点越晚，惩罚越大 |
| 第 2 层 | 控制链总时差不足风险 | 控制链剩余缓冲低于必要缓冲会产生惩罚 |
| 第 3 层 | 控制链衔接空档风险 | 控制链已有风险时，前后任务空等会产生惩罚 |
| 第 4 层 | 总工期 | 总完工时间越长，惩罚越大 |
| 第 5 层 | 资源路径连续性 | 同一资源跳墩、换幅会产生惩罚 |
| 第 6 层 | 资源空闲 | 同一资源活跃窗口内停等越多，惩罚越大 |
| 第 7 层 | 同类资源工作量均衡 | 同类资源干活差距越大，惩罚越大 |
| 固定低优先级 | 未配置资源普通工程均衡 | 未配置资源普通工程短时间集中施工会产生惩罚 |

未配置资源普通工程均衡的默认权重为 10，低于同类资源工作量均衡、资源空闲、资源路径连续性和总工期。

### 4.1 最佳努力分支的目标放松口径

最佳努力分支不是降低施工可执行性，而是在严格目标无法满足或无法在当前时限内求得可用结果时，把目标偏差显式纳入目标函数。

| 项目 | 严格精排 | 最佳努力精排 |
| --- | --- | --- |
| 强制里程碑 | `event <= target` 硬约束 | `max(0, event - target)` 进入最高优先级软目标 |
| 固定工期 | `makespan <= target_days` 硬约束 | `max(0, makespan - target_days)` 进入最高优先级软目标 |
| 资源互斥 | 必须满足 | 必须满足 |
| 同结构同工序资源绑定 | 必须满足 | 必须满足 |
| 工艺依赖和工作面 | 必须满足 | 必须满足 |

最佳努力目标迟延的权重不低于普通资源均衡、资源空闲、资源路径连续和普通工程均衡。前端必须把该结果展示为“最佳努力精排”，并说明不代表目标已满足。

## 5. 普通工程差异化均衡算法

### 5.1 第一步：确定普通工程参与范围

系统先找出“普通工程任务”，但不是所有普通工程都会进入均衡目标。

纳入普通工程判断的任务必须同时满足：

| 条件 | 说明 |
| --- | --- |
| 管控级别为普通 | 控制工程和关键工程不参与 |
| 不属于控制链 | 如果普通任务是控制任务的前置影响项，也不参与 |

例如：

| 工作项 | 管控级别 | 是否控制链前置 | 是否进入普通工程均衡判断 |
| --- | --- | --- | --- |
| 左幅 1#墩桩基 | 普通 | 否 | 是 |
| 10#墩盖梁 | 控制 | 是 | 否 |
| 10#墩桩基前置 | 普通 | 是 | 否 |

### 5.2 第二步：区分“有资源”和“没资源”

普通工程再分成两类：

| 类型 | 判断方式 | 后续优化方式 |
| --- | --- | --- |
| 已配置受限资源普通工程 | 至少有一个启用的受限兼容资源候选 | 走资源连续施工目标 |
| 未配置受限资源普通工程 | 没有启用的受限兼容资源候选 | 走普通工程时间均衡目标 |

例如当前资源配置里启用了 1 台“旋挖钻 1”，左幅 1#墩桩基兼容旋挖钻，那么它就是“已配置资源普通工程”。如果“普通附属工作”填写了“附属班组”，但资源池里没有启用该班组，它就是“未配置资源普通工程”。

### 5.3 第三步：已配置资源普通工程不做时间均摊

已配置资源普通工程的核心问题是资源利用率，不是时间平均分布。系统会通过以下目标影响它们：

| 目标 | 计算口径 | 业务含义 |
| --- | --- | --- |
| 资源空闲 | 资源从第一项工作到最后一项工作之间，没有施工的天数 | 空闲越少，窝工越少 |
| 资源路径连续性 | 同一资源相邻工作之间的同幅墩号间隔和左右幅切换 | 跳墩、换幅越少，路径越连续 |
| 同类资源工作量均衡 | 同类资源最大工作量与最小工作量差值 | 多台同类资源负荷更均衡 |

真实案例：

| 资源 | 工作顺序 | 资源路径罚分说明 |
| --- | --- | --- |
| 旋挖钻 1 | 左幅 1#墩桩基 -> 左幅 4#墩桩基 -> 右幅 4#墩桩基 | 左幅 1# 到左幅 4# 的墩号间隔罚分为 3；左幅切到右幅罚分为 1；合计 4 |

该 4 分进入“资源路径连续性”目标，不进入“未配置资源普通工程均衡”目标。

### 5.4 第四步：未配置资源普通工程按时间桶统计工作量

未配置资源普通工程没有命名资源可用来判断连续施工，因此系统按周或按月统计它们的施工工作量。

计算步骤：

1. 确定统计桶：如果配置为按周，系统每 7 天作为一个桶；如果配置为按月，系统每 30 天作为一个桶。
2. 确定统计窗口：从普通工程允许开始时间开始，到普通工程最晚完成时间结束；如果未配置最晚完成时间，则使用本次排程可用的求解窗口。
3. 统计实际工作量：每个桶内，把该桶开始施工的未配置资源普通工程工期相加。
4. 计算理想工作量：把未配置资源普通工程总工期平均分到所有统计桶。
5. 计算偏差：某个桶的实际工作量高于理想上限或低于理想下限，都会产生偏差。
6. 汇总罚分：所有桶的偏差合计，就是未配置资源普通工程均衡罚分。

业务公式：

```text
未配置资源普通工程均衡罚分 =
所有统计桶“实际工作量与理想工作量偏差”的合计
```

```text
未配置资源普通工程均衡目标贡献 =
未配置资源普通工程均衡罚分 × 10
```

### 5.5 第五步：真实数据案例

假设项目计划从 2026-01-01 开始，有 6 个未配置资源普通工程，每个工期 2 天，允许在 3 周内施工。

| 工作项 | 工期 | 资源状态 |
| --- | ---: | --- |
| 普通附属工作 1 | 2 天 | 无启用受限资源 |
| 普通附属工作 2 | 2 天 | 无启用受限资源 |
| 普通附属工作 3 | 2 天 | 无启用受限资源 |
| 普通附属工作 4 | 2 天 | 无启用受限资源 |
| 普通附属工作 5 | 2 天 | 无启用受限资源 |
| 普通附属工作 6 | 2 天 | 无启用受限资源 |

总工作量为 12 天，分到 3 周，理想状态是每周 4 天工作量。

集中施工方案：

| 周次 | 实际工作量 | 理想工作量 | 偏差 |
| --- | ---: | ---: | ---: |
| 第 1 周 | 12 天 | 4 天 | 8 |
| 第 2 周 | 0 天 | 4 天 | 4 |
| 第 3 周 | 0 天 | 4 天 | 4 |

均衡罚分为 16，目标贡献为 160。

均匀施工方案：

| 周次 | 实际工作量 | 理想工作量 | 偏差 |
| --- | ---: | ---: | ---: |
| 第 1 周 | 4 天 | 4 天 | 0 |
| 第 2 周 | 4 天 | 4 天 | 0 |
| 第 3 周 | 4 天 | 4 天 | 0 |

均衡罚分为 0，目标贡献为 0。

如果项目同时有一个 30 天的控制工程决定总工期，那么这 6 个普通工作分散到 3 周不会拉长总工期，系统会优先选择更均匀的方案。反过来，如果为了均匀施工会导致控制节点迟延或总工期变长，高优先级目标会压过该低权重均衡目标。

## 6. 输出字段和展示口径

### 6.1 目标拆解

| 字段 | 业务含义 |
| --- | --- |
| `unconfigured_normal_balance_penalty` | 未配置资源普通工程均衡罚分 |
| `unconfigured_normal_balance_weight` | 固定低优先级权重，当前为 10 |
| `unconfigured_normal_balance_score` | 面向展示的均衡评分 |
| `normal_balance_penalty` | 兼容字段，当前等于未配置资源普通工程均衡罚分 |
| `normal_balance_score` | 兼容评分字段，当前表示未配置资源普通工程均衡评分 |
| `relaxed_hard_milestone_lateness_days` | 最佳努力分支中强制里程碑迟延天数合计 |
| `fixed_duration_overrun_days` | 最佳努力分支中固定工期超期天数 |
| `target_relaxation_penalty` | 强制节点迟延和固定工期超期的未加权合计 |
| `best_effort_refinement` | 最佳努力精排元数据，包含严格失败原因、放松目标和最佳努力分值 |

### 6.2 诊断指标

`normal_balance_metrics` 用于解释普通工程分布，核心口径如下：

| 字段 | 业务含义 |
| --- | --- |
| `normal_task_count` | 本次可按普通工程口径处理的普通任务数，不含控制链普通前置 |
| `configured_resource_normal_task_count` | 已配置受限资源普通工程数量 |
| `unconfigured_resource_normal_task_count` | 未配置受限资源普通工程数量 |
| `bucket_loads` | 未配置资源普通工程按周/月的工作量分布 |
| `balance_penalty` | 均衡罚分 |
| `balance_weight` | 均衡权重 |
| `balance_score` | 均衡评分，分数越高表示越均匀 |

## 7. 验收标准

1. 已配置旋挖钻、模板班组等受限资源的普通工程，不计入未配置资源普通工程均衡罚分。
2. 已配置资源普通工程仍能产生资源空闲、资源路径连续性或同类资源工作量均衡目标贡献。
3. 未配置资源普通工程按周/月统计实际工作量，并输出桶分布、罚分和评分。
4. 6 个 2 天未配置资源普通任务在 3 周窗口内，集中施工方案罚分高于均匀施工方案。
5. 控制链普通前置任务不进入普通工程均衡，也不会被普通工程最早开始窗口拖后。
6. `objective_weights` 和 `objective_terms_used` 不恢复废弃的 `normal_balance` 可配置目标项。
7. 严格精排失败但最佳努力精排可用时，结果来源必须区分为 `current_resources_best_effort_refinement` 或 `minimum_resources_best_effort_refinement`。
8. 最佳努力结果必须输出强制节点迟延或固定工期超期诊断，且前端不得展示为目标已满足。
9. 前端构建通过，旧结果中没有新增字段时仍能正常展示。

## 8. 交付边界

- 本次不新增用户可编辑目标项。
- 本次不改变严格精排中的硬里程碑、资源互斥、工序依赖和普通工程工作面并行上限。
- 最佳努力分支只在严格精排失败后启用，不替代严格精排成功结果。
- 本次不要求 Netlify 演示 API 完整复刻 CP-SAT 精排目标，只要求不要输出与 Python 主链路冲突的目标解释。
