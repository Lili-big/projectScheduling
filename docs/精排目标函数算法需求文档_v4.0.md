# 精排目标函数算法需求文档

版本：v4.0

日期：2026-07-06

适用模块：桥梁施工 CP-SAT 精排求解、模拟求解页面、精排结果诊断

文档性质：算法 / 规则交底文档

## 1. 文档目标

本文档说明精排求解中目标函数的业务含义、可配置项、结果贡献和只读诊断边界，供产品、算法、后端、前端和测试对齐使用。

本版本在 v3.9 基础上重点补充：后端实际参与精排目标函数的指标必须在前端完整展示并支持配置；求解结果必须展示每个目标项的原始罚分、有效权重和加权贡献；连续性评分、跳跃、换向、普通工程均衡评分等解释性指标作为只读诊断，不作为独立权重项。

## 2. 算法链路位置

用户点击“固定资源条件下，推算最短工期”后，系统直接进入命名资源精排。严格精排在满足施工硬约束的前提下，根据目标函数综合惩罚选择更优方案。若当前资源严格精排失败或不满足硬里程碑，主结果保持失败语义并进入资源增量建议，不再追加当前资源最佳努力精排，也不回退展示池级最短工期。最少资源候选方案的精排失败兜底可继续使用最佳努力口径。

目标函数配置只影响软目标权重，不改变任务工期、前后置、资源兼容、命名资源互斥、工作面、同结构同工序、硬里程碑等硬约束。

对于旋挖钻、回旋钻和冲击钻桩基任务，`resource_path_continuity` 不再直接为每台钻机连接全部候选桩基任务或候选墩组。资源配置页已移除“同墩同工艺最多设备数”参数，旧字段不再作为并行上限参与求解；三类机械钻资源默认按同墩同工艺聚合为内部墩组，并由求解器显式约束同一墩组原任务使用同一台对应工艺的命名资源。系统先在粗排阶段使用相邻换机和 `1-0-1` 洞洞式跳墩作为轻量软惩罚；再在细排阶段固定粗排得到的墩组资源分配，只对每台钻机实际分配到的墩组建立路径排序。该聚合只影响求解内部节点，最终结果仍展开为原任务。人工挖孔桩不进入该聚合，仍可由多个人工挖孔班组并行。

当 `resource_path_continuity` 被关闭时，系统不得构建上述跳墩软惩罚或细排路径排序；资源互斥、工艺前后置、同结构同工艺并行上限和硬里程碑仍作为硬约束执行。

## 3. 前端可配置目标项

前端目标函数配置区必须展示下表全部可配置项。旧场景缺少新增项时，后端自动补齐默认配置。

| 目标项 ID | 名称 | 默认权重 | 适用范围 | 业务含义 |
| --- | --- | ---: | --- | --- |
| `control_node_late` | 软控制节点迟延 | 1,000,000,000 | 控制优先 / 综合精排 | 软控制节点晚于目标日期的天数 |
| `target_relaxation` | 目标放松迟延 | 1,000,000,000 | 最佳努力精排 | 强制节点迟延和固定工期超期，仅目标放松分支生效 |
| `control_buffer_risk` | 控制链总时差不足风险 | 5,000,000 | 控制优先 / 综合精排 | 控制链任务距离最晚安全完成时间的余量风险 |
| `risk_related_control_wait` | 控制链衔接空档风险 | 1,000,000 | 控制优先 / 综合精排 | 已存在风险的控制链前后任务之间的可压缩空档 |
| `makespan_and_soft_milestone` | 总工期 | 10,000 | 控制优先 / 综合精排 | 项目整体完工跨度 |
| `resource_path_continuity` | 资源路径连续性 | 3,000 | 控制优先 / 综合精排 | 同一资源相邻任务的同幅邻近推进程度 |
| `resource_idle` | 资源空闲 | 1,000 | 控制优先 / 综合精排 | 单个资源两次任务之间的中途停等 |

兼容旧配置时：

- 缺少 `target_relaxation` 时，继承 `control_node_late` 的启用状态和权重，保证旧场景中最佳努力迟延目标与原行为一致。
- 旧配置或旧结果中如果仍包含 `resource_slot_balance`，后端保留兼容解析和调试字段；前端目标函数配置区和结果贡献表不再展示该项。
- 旧配置中如果仍传入 `resource_workload_balance`，后端按废弃目标项兼容忽略，不再作为有效目标项补齐或参与求解。
- 旧配置中如果仍传入 `unconfigured_normal_balance`，后端按废弃目标项兼容忽略，不再作为有效目标项补齐或参与求解。

## 4. 目标函数贡献口径

后端结果必须输出 `objective_breakdown.objective_contributions`，每个目标项一行，包含：

| 字段 | 含义 |
| --- | --- |
| `term_id` | 目标项 ID |
| `label` | 前端展示名称 |
| `enabled` | 用户配置是否启用 |
| `active` | 本次求解分支是否实际参与目标函数 |
| `configured_weight` | 用户配置或默认权重 |
| `effective_weight` | 本次进入目标函数的有效权重 |
| `raw_penalty` | 未乘权重的罚分 |
| `weighted_contribution` | 加权贡献 |
| `applies_to` | 适用分支 |
| `notes` | 继承父项、分支不适用等说明 |

`weighted_objective` 必须等于所有 `weighted_contribution` 的求和。旧字段如 `target_relaxation_penalty`、`resource_slot_balance_penalty` 可继续保留，用于兼容旧页面和调试。`resource_workload_balance`、`unconfigured_normal_balance` 和 `normal_balance_penalty` 不再作为当前目标贡献输出。

## 5. 只读诊断边界

以下指标用于解释排程质量，不作为独立目标函数配置项：

| 诊断指标 | 展示口径 | 是否可配置 |
| --- | --- | --- |
| `continuity_score` | 资源路径连续性总体评分 | 否 |
| `jump_pier_count` | 同一资源路径中的跳墩次数 | 否 |
| `side_switch_count` | 左右幅切换次数 | 否 |
| `direction_reversal_count` | 施工方向反复次数 | 否 |
| `normal_balance_score` / `normal_balance_metrics` | 普通工程时间桶分布、已配置 / 未配置资源普通工程数量、峰值 / 低谷和诊断评分 | 否 |
| `resource_workload_balance` 相关工作量统计 | 同类资源活跃天数、最大/最小工作量和工作量差异 | 否 |
| `path_group_diagnostics` | 路径组实际施工序列 | 否 |
| `drill_group_refinement` | 桩基钻机墩组两阶段精排状态、粗排墩组数、细排节点/弧数、弧减少比例、跳墩惩罚和回退原因 | 否 |

如果未来希望把某个诊断指标变成可配置优化目标，必须先在后端目标函数中建立独立罚分项，再进入前端目标项目录。

## 6. 验收口径

- 前端目标函数配置区展示 7 个可配置目标项。
- 用户调整任一目标项后，请求配置、后端有效权重和结果贡献表保持一致。
- 前端目标函数配置区和结果贡献表均不展示“资源槽位均衡”“同类资源工作量均衡”和“未配置资源普通工程均衡”。
- 严格精排中 `target_relaxation` 可见但显示为不适用或 0 贡献；最佳努力精排中显示迟延 / 超期贡献。
- 只读诊断指标在结果页可见，但不提供启用开关和权重输入。
- 桩基钻机墩组两阶段精排不新增前端可配置目标项；其粗排跳墩偏好和细排路径弧均归属于 `resource_path_continuity` 的启用状态。
- 关闭 `resource_path_continuity` 时，路径节点、路径弧、相邻换机惩罚和洞洞式跳墩惩罚应为 0 或未评估状态。
- 旧场景缺少新增目标项时仍可求解，并按兼容规则补齐默认值。
