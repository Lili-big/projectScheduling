# 施工工艺及工效库需求文档

版本：v1.1

日期：2026-06-15

适用范围：桥梁自动排程系统工程化版本

面向对象：产品、前端研发、后端研发、测试

## 1. 功能模块核心定位

### 1.1 模块定位

施工工艺及工效库是排程系统的基础配置模块，用于维护“构件类型 -> 施工工艺 -> 工效分组 -> 默认资源”的规则库。

该模块的核心价值不是展示工艺资料，而是为后续任务生成、工期计算、资源自动匹配提供统一的数据来源。

工程化产品目标是“系统默认模板 + 项目级配置副本”：系统内置默认工艺工效数据，项目首次创建或首次进入排程配置时，将默认数据初始化为该项目自己的工艺库副本。用户后续增删改应作用于当前项目副本，不影响系统默认模板和其他项目。

项目参数页、任务生成、排程求解均应引用本模块维护的数据：

- 项目构件选择施工工艺时，从工艺库中选择匹配构件类型的工艺模板。
- 项目构件未指定工效分组时，使用该工艺模板下的默认工效分组。
- 生成任务时，系统根据工艺模板的默认资源匹配资源池。
- 计算工期时，系统根据工效分组中的工期算法、工程量来源、工效值和单位计算。

### 1.2 当前页面效果

当前页面名称为“施工工艺及工效库”，副标题为“工艺模板按构件类型和适用工艺维护，关键资源由工艺规则自动匹配”。

页面采用表格形式展示，表头为：

| 列名 | 页面含义 | 当前交互 |
| --- | --- | --- |
| 构件 | 展示工艺适用构件类型 | 只读标签，如桩基、承台、扩大基础、地系梁、墩身 |
| 工艺名称 | 展示施工工艺名称 | 当前页面只读 |
| 工效分组 | 维护该工艺下的一个或多个工效分组 | 支持编辑分组名、工效值、单位、节高、默认分组、新增、删除 |
| 默认资源 | 展示该工艺默认匹配资源 | 当前页面只读，展示资源池标签 |

页面右上角提供“保存”按钮：

- 当工艺工效库没有变更时，按钮置灰不可点击。
- 当用户编辑工效分组后，按钮可点击。
- 保存中展示加载状态。
- 保存成功后，使用后端返回的工艺库刷新页面数据，并清空未保存状态。

### 1.3 模块边界

本模块本期负责：

- 展示后端返回的标准化工艺工效库。
- 将系统默认工艺工效数据初始化为可持久化数据。
- 支持工效分组的新增、编辑、删除、设为默认。
- 支持桩基工效单位切换，并自动联动工期算法和工程量来源。
- 支持墩身分节施工工艺的单位切换和标准节高配置。
- 支持保存工艺工效库，并在刷新后保留修改。

本模块本期不负责：

- 在页面上新增或删除整条施工工艺模板。
- 在页面上编辑构件类型、工艺名称、默认资源。
- 直接编辑资源池数量、日历、成本等资源配置。
- 在本页面展示排程结果或任务实例。
- 做复杂的适用条件筛选，如地层、桩径、桥型条件自动推荐。

## 2. 数据定义

### 2.1 施工工艺模板

施工工艺模板对应后端 `ProcessTemplate`、前端 `ProcessTemplate`。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 工艺模板稳定 ID，保存和任务引用使用 |
| `component_type` | string | 是 | 构件类型 |
| `process_name` | string | 是 | 页面展示的工艺名称 |
| `method_id` | string \| null | 否 | 工艺方法 ID，用于项目构件匹配，如桩基工艺 |
| `duration_method` | string | 是 | 当前默认工效分组对应的工期算法 |
| `quantity_source` | string | 是 | 当前默认工效分组对应的工程量来源 |
| `productivity_value` | number | 是 | 当前默认工效分组对应的工效值，必须大于 0 |
| `productivity_unit` | string | 是 | 当前默认工效分组对应的工效单位 |
| `resource_type` | string | 是 | 默认资源类型 |
| `productivity_options` | ProductivityOption[] | 是 | 工效分组列表 |
| `applicability` | object | 否 | 扩展字段，当前可保留来源、适用条件等信息 |
| `is_default` | boolean | 是 | 是否为该构件类型下默认施工工艺 |

产品规则：

- 一个构件类型可以有多个施工工艺。
- 一个构件类型建议有一个默认施工工艺。
- 一个施工工艺必须至少有一个工效分组。
- 一个施工工艺必须且只能有一个默认工效分组。
- 工艺模板上的 `duration_method`、`quantity_source`、`productivity_value`、`productivity_unit` 必须与默认工效分组保持一致。

### 2.2 工效分组

工效分组对应后端 `ProductivityOption`、前端 `ProductivityOption`。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 工效分组稳定 ID |
| `name` | string | 是 | 分组名称，页面可编辑，如默认工效、工效分组2、软岩地层 |
| `duration_method` | string | 是 | 工期算法 |
| `quantity_source` | string | 是 | 工程量来源 |
| `productivity_value` | number | 是 | 工效值，必须大于 0 |
| `productivity_unit` | string | 是 | 工效单位 |
| `standard_section_height_m` | number \| null | 否 | 标准节高，当前用于墩身天/节类工效 |
| `is_default` | boolean | 是 | 是否为该工艺下默认分组 |

产品规则：

- 新增分组时，默认复制当前默认工效分组的算法、工程量来源、工效值、单位和节高。
- 新增分组默认命名为“工效分组N”，其中 N 为当前分组数量 + 1。
- 新增分组默认不是默认分组。
- 删除默认分组时，如果仍有其他分组，系统自动将剩余第一条分组设为默认。
- 当只剩一个工效分组时，删除按钮置灰，不允许删除。

### 2.3 构件类型

当前工艺库支持以下构件类型：

| 字段值 | 页面标签 |
| --- | --- |
| `pile` | 桩基 |
| `cap` | 承台 |
| `spread_foundation` | 扩大基础 |
| `ground_tie_beam` | 地系梁 |
| `middle_tie_beam` | 中系梁 |
| `pier_body` | 墩身 |
| `cap_beam` | 盖梁 |
| `abutment_body` | 桥台 |
| `precast_beam` | 制梁 |
| `beam_erection` | 架梁 |
| `cast_in_place_continuous_beam` | 现浇连续梁 |
| `cast_in_place_box_beam` | 现浇箱梁 |
| `steel_box_beam` | 钢箱梁 |
| `bridge_deck_system` | 桥面系 |

页面排序按上述构件顺序展示。同一构件下按后端返回顺序展示；墩身默认将爬模施工排在墩身工艺前列。

### 2.4 工期算法

| 字段值 | 页面标签 | 计算方式 |
| --- | --- | --- |
| `units_per_day` | 按日完成量计算 | `ceil(工程量 / 工效值)` |
| `days_per_unit` | 按单位耗时计算 | `ceil(工程量 * 工效值)` |
| `fixed_days` | 固定工期 | `ceil(工效值)` |

通用规则：

- 工期计算结果最小为 1 天。
- 不同单位下的工效值不能直接比较大小，必须结合算法和工程量来源解释。
- 页面中的算法字段不单独编辑，由单位选择或后端数据决定。

### 2.5 工程量来源

| 字段值 | 页面标签 | 说明 |
| --- | --- | --- |
| `count` | 构件数量 | 桩基按 1 根，其他构件通常按 1 个、1 片、1 块、1 联 |
| `pile_length_m` | 桩长 | 用于桩基按长度计算 |
| `pier_height_m` | 墩高 | 用于墩身按高度或分节计算 |
| `deck_length_m` | 桥面长度 | 用于桥面系按长度计算 |

### 2.6 默认资源

默认资源通过工艺模板的 `resource_type` 关联资源池展示。

当前页面只展示默认资源标签，不提供编辑入口。展示逻辑如下：

- 桩基优先根据工艺模板 ID 或 `method_id` 匹配资源类型。
- 非桩基优先根据构件类型匹配默认资源类型。
- 找到资源池时展示资源池 `label`，如旋挖钻、冲击钻、人工挖孔班组、承台模板、墩柱模板。
- 找不到资源池标签时，兜底展示资源类型编码。

## 3. 默认数据初始化

### 3.1 初始化原则

系统应将当前页面已有的工艺工效数据作为默认初始化数据。

初始化后的数据应进入后端工艺库持久化结构。工程化版本中，用户后续修改的应是当前项目的工艺库副本，不应只依赖前端写死数据，也不应直接改动系统默认模板。

当前实现中：

- 默认库由后端 `historical_default_process_library()` 提供。
- 加载场景时通过 `load_process_library()` 读取持久化工艺库。
- 如未配置数据库，则使用默认库作为降级数据。
- 如已配置数据库但表中为空，后端应写入默认库后再返回。
- 保存时通过 `PUT /api/process-library` 持久化完整 `process_library`。

当前代码中的 `GET /api/process-library`、`PUT /api/process-library` 尚未携带 `projectId`，更接近 demo 或全局工艺库实现。正式多项目版本建议扩展为项目级接口，或在后端仓储层按 `project_id` 做数据隔离。

## 4. 页面功能交互

### 4.1 进入页面

用户进入页面后，前端展示当前 `scenario.process_library`。

数据加载链路：

1. 前端请求默认场景。
2. 后端读取或初始化工艺工效库。
3. 前端导入项目参数后，将后端返回的 `scenario.process_library` 渲染到页面。

页面展示要求：

- 构件列使用标签样式展示。
- 工艺名称只读展示。
- 每个施工工艺占一行。
- 每行工效分组区域可展示多条分组。
- 默认分组使用高亮背景和“默认分组”标识。
- 非默认分组展示“设为默认”按钮。
- “新增”按钮只展示在该工艺最后一条工效分组上。

### 4.2 编辑工效分组名称

用户可直接编辑分组名称输入框。

规则：

- 修改后页面进入未保存状态。
- 保存时名称不能为空。
- 同一工艺下是否允许重名由后端校验策略决定；产品建议不允许重名，避免项目参数页选择时混淆。

### 4.3 编辑工效值

用户可编辑工效值输入框。

规则：

- 输入类型为数字。
- 最小值为 0.1。
- 步长为 0.1。
- 保存时工效值必须大于 0。
- 修改默认分组的工效值后，工艺模板上的默认工效值同步变化。

### 4.4 编辑工效单位

不同构件的单位交互不同。

桩基工艺支持单位下拉：

| 单位 | 自动算法 | 自动工程量来源 | 示例含义 |
| --- | --- | --- | --- |
| m/天 | `units_per_day` | `pile_length_m` | 每天完成多少米桩长 |
| 根/天 | `units_per_day` | `count` | 每天完成多少根桩 |
| 天/根 | `days_per_unit` | `count` | 每根桩需要多少天 |
| 天/m | `days_per_unit` | `pile_length_m` | 每米桩长需要多少天 |

墩身分节施工工艺支持单位下拉：

适用工艺：

- `method_id = climbing_form`
- `method_id = sliding_form`
- `method_id = turnover_form`
- 或工艺名称包含爬模、滑模、翻模

可选单位：

| 单位 | 自动算法 | 自动工程量来源 | 页面额外字段 |
| --- | --- | --- | --- |
| 天/节 | `days_per_unit` | `pier_height_m` | 显示标准节高输入框 |
| m/天 | `units_per_day` | `pier_height_m` | 不显示标准节高 |

其他工艺单位当前只读，以文本标签展示。

### 4.5 编辑标准节高

当墩身分节施工工效单位为“天/节”时，页面展示标准节高输入框。

规则：

- 默认节高为 4.5m/节。
- 用户可编辑标准节高。
- 最小值为 0.1。
- 步长为 0.1。
- 单位切换到“m/天”时，不展示标准节高，保存数据可置空。

计算规则：

- 先按 `ceil(墩高 / 标准节高)` 得到节数。
- 再按 `ceil(节数 * 天/节工效值)` 得到工期。
- 计算结果最小为 1 天。

### 4.6 新增工效分组

用户点击某工艺最后一条分组右侧“新增”按钮，系统在该工艺下追加一条工效分组。

新增规则：

- 新分组复制当前默认分组的数据。
- 新分组 ID 前端临时生成，格式类似 `{process.id}-option-{timestamp}`。
- 新分组名称为“工效分组N”。
- 新分组 `is_default = false`。
- 新增后页面进入未保存状态。

### 4.7 删除工效分组

用户点击“删除”按钮删除当前工效分组。

规则：

- 当该工艺只有一个分组时，删除按钮置灰。
- 当删除非默认分组时，直接删除。
- 当删除默认分组且仍有剩余分组时，系统自动将剩余第一条设为默认分组。
- 删除后页面进入未保存状态。

### 4.8 设置默认分组

用户点击“设为默认”按钮，将当前分组设为默认分组。

规则：

- 当前工艺下所有其他分组自动取消默认。
- 被设为默认的分组展示“默认分组”标识。
- 工艺模板上的 `duration_method`、`quantity_source`、`productivity_value`、`productivity_unit` 同步为新的默认分组值。
- 设置默认后页面进入未保存状态。

### 4.9 保存

用户点击右上角“保存”按钮后，前端提交当前完整工艺库。

保存规则：

- 保存接口为全量保存，不是单行局部保存。
- 保存成功后，前端使用后端返回的标准化工艺库覆盖本地 `scenario.process_library`。
- 保存成功后，清空未保存状态。
- 保存成功后，已生成任务、求解结果、方案对比结果应失效，需要重新生成或重新求解。
- 保存失败时，页面保留用户当前未保存数据，并展示错误信息。

## 5. 前后端接口

当前代码已提供无项目 ID 的工艺库接口。工程化多项目版本建议在接口路径或请求上下文中加入项目 ID，例如 `/api/projects/{projectId}/process-library`，以保证每个项目拥有独立工艺库副本。

### 5.1 查询工艺工效库

```http
GET /api/process-library
```

用途：

- 独立读取当前持久化工艺工效库。
- 返回标准化后的 `ProcessTemplate[]`。

### 5.2 保存工艺工效库

```http
PUT /api/process-library
```

请求体：

```json
{
  "process_library": []
}
```

返回：

```json
[]
```

返回值为后端校验、迁移、排序后的 `ProcessTemplate[]`。

保存要求：

- `process_library` 不能为空。
- 后端应校验每条工艺至少有一个工效分组。
- 后端应确保每条工艺只有一个默认工效分组。
- 后端应确保工艺模板默认字段与默认工效分组一致。
- 后端应持久化 `productivity_options`。
- 当前数据库表为 `process_relationships`，以 `process_id` 作为冲突更新键。
- 保存时，前端传入列表中不存在的旧工艺记录会被后端删除。

### 5.3 默认场景加载

```http
GET /api/demo-scenario
```

用途：

- 返回包含 `process_library` 的完整场景。
- 场景中的工艺库应来自持久化数据；无持久化数据时应使用默认工艺库初始化。

## 6. 排程联动规则

### 6.1 任务生成时选择工艺

生成任务时，系统按构件匹配施工工艺：

- 构件有 `method_id` 时，优先匹配工艺模板的 `id` 或 `method_id`。
- 构件没有 `method_id` 时，优先使用该构件类型下 `is_default = true` 的工艺。
- 如没有默认工艺，则使用该构件类型下第一条工艺。
- 如找不到工艺，生成错误提示“构件没有匹配的工艺模板”。

### 6.2 任务生成时选择工效分组

生成任务时，系统按构件选择工效分组：

- 构件有 `productivity_option_id` 时，优先使用该分组。
- 找不到指定分组时，使用该工艺默认分组。
- 构件未指定分组时，使用该工艺默认分组。

生成的任务规则 ID 格式为：

```text
{process.id}:{productivity_option.id}
```

### 6.3 工期计算

任务工期由工程量和工效分组共同决定。

通用公式：

| 算法 | 公式 |
| --- | --- |
| `units_per_day` | `ceil(quantity / productivity_value)` |
| `days_per_unit` | `ceil(quantity * productivity_value)` |
| `fixed_days` | `ceil(productivity_value)` |

特殊规则：

- 桩基 `count` 工程量按 1 根计算。
- 桩基 `pile_length_m` 工程量按桩长计算。
- 墩身 `天/节` 先按标准节高换算节数，再乘以天/节工效。
- 现浇连续梁标准块强制按 `days_per_unit + count` 计算。

### 6.4 资源匹配

任务生成后，系统根据工艺资源类型匹配资源池：

- 受限资源池启用且数量大于 0 时，任务使用该资源类型作为候选资源。
- 对关键资源构件，如果对应资源池不可用，则不生成候选受限资源。
- 默认资源变化会影响后续重新生成任务后的资源约束。

## 7. 校验与异常处理

### 7.1 前端校验

前端应至少保证：

- 只剩一个工效分组时不能删除。
- 切换单位后，自动更新算法和工程量来源。
- 同一工艺下始终只有一个默认分组。
- 默认分组变化时，同步工艺模板默认字段。
- 保存按钮只在存在未保存变更时可点击。

### 7.2 后端校验

后端应至少保证：

- `process_library` 非空。
- `productivity_value > 0`。
- `standard_section_height_m > 0`，如果有值。
- 无分组时自动补一个“默认工效”分组。
- 多个分组同时标记默认时，仅保留第一个默认。
- 没有默认分组时，将第一条分组设为默认。
- 墩身分节施工工艺中，`天/节` 自动对应 `days_per_unit + pier_height_m`，`m/天` 自动对应 `units_per_day + pier_height_m`。

### 7.3 异常提示

异常场景建议：

| 场景 | 产品提示 |
| --- | --- |
| 保存失败 | 工艺工效库保存失败，请检查网络或后端配置 |
| 后端数据库未配置 | 未配置工艺库持久化数据库，当前使用默认数据 |
| 工效值不合法 | 工效值必须大于 0 |
| 分组名称为空 | 工效分组名称不能为空 |
| 构件找不到工艺 | 构件没有匹配的工艺模板 |

## 8. 验收标准

### 8.1 页面验收

- 页面标题、说明文案、表头与当前页面一致。
- 表格按构件顺序展示工艺模板。
- 每条工艺至少展示一个工效分组。
- 默认分组高亮展示并显示“默认分组”。
- 非默认分组显示“设为默认”按钮。
- 每条工艺只有最后一个分组显示“新增”按钮。
- 默认资源列展示资源池中文标签。

### 8.2 工效分组验收

- 用户可编辑分组名称。
- 用户可编辑工效值。
- 用户可新增工效分组，新分组复制当前默认分组。
- 用户可删除非唯一分组。
- 删除默认分组后，剩余第一条自动成为默认分组。
- 用户可将任意非默认分组设为默认。
- 保存并刷新后，分组数据仍然存在。

### 8.3 单位联动验收

- 桩基单位可选 m/天、根/天、天/根、天/m。
- 桩基选择 m/天 后，算法为按日完成量计算，工程量来源为桩长。
- 桩基选择根/天 后，算法为按日完成量计算，工程量来源为构件数量。
- 桩基选择天/根 后，算法为按单位耗时计算，工程量来源为构件数量。
- 桩基选择天/m 后，算法为按单位耗时计算，工程量来源为桩长。
- 爬模、滑模、翻模可选天/节和 m/天。
- 选择天/节时显示标准节高，默认 4.5m/节。
- 选择 m/天时不显示标准节高。

### 8.4 保存验收

- 未修改时保存按钮置灰。
- 修改任意分组后保存按钮可点击。
- 点击保存后调用 `PUT /api/process-library`。
- 保存成功后使用接口返回值刷新页面。
- 保存成功后保存按钮恢复置灰。
- 保存失败时保留当前编辑内容并展示错误。

### 8.5 排程联动验收

- 修改默认工效后，未指定工效分组的构件重新生成任务时使用新默认值。
- 修改工效单位后，重新生成任务时按新算法计算工期。
- 修改墩身标准节高后，重新生成任务时按新节数计算工期。
- 保存工艺库后，已生成任务和求解结果失效，需要重新生成或求解。
- 任务 `productivity_rule_id` 可追溯到具体工艺和工效分组。

## 9. 后续扩展建议

以下能力不纳入本期验收，但建议在设计时预留：

- 新增、删除、停用整条施工工艺模板。
- 编辑默认资源，支持从资源池选择。
- 工效分组按适用条件筛选，如地层、桩径、墩高区间、施工季节。
- 项目级工艺库和系统级模板库分离，支持项目重置为系统默认。
- 工艺库版本管理，支持回滚、复制和跨项目复用。
- 多人编辑冲突控制，保存时引入版本号或更新时间校验。
