# AI资源配置与排程优化助手验证说明

日期：2026-07-14

适用范围：AI 资源配置方案生成、严格固定资源单阶段 CP-SAT 求解、三种业务状态、逐步指标对比、独立推荐解释和本地回退验证。

## 1. Demo 闭环

1. 进入前端 Demo。
2. 导入项目数据或使用默认项目场景。
3. 打开「AI资源助手」。
4. 点击「生成三方案」，系统生成工程画像和三张资源方案卡。
5. 用户检查或调整资源数量。
6. 分别点击三张方案卡中的「求解经济方案」「求解平衡方案」「求解抢工方案」；每次只调用对应方案的 CP-SAT，并立即展示该方案结果。
7. 查看逐步补全的指标对比表、整体计划、资源利用和控制墩专项视图。
8. 三套方案都完成后，点击「生成LLM推荐」；系统基于完整结果先确定推荐结论，再生成解释。

## 2. 方案生成口径

- LLM 根据工程画像、约束提示和参考样例一次性输出经济、平衡、抢工三套资源配置。
- 原 A/B/C 数量只作为参考样例，不作为固定方案。
- 外部 LLM 未配置或调用失败时，系统使用本地回退样例生成三方案。
- 桩机按资源类型分别配置，例如旋挖钻、回旋钻、冲击钻和人工挖孔班组分别给数量。

## 3. 指标来源

| 指标 | 来源 |
| --- | --- |
| 总工期、预计完工日期、求解状态 | CP-SAT 求解结果 |
| 控制墩释放、连续梁开工、资源利用率、平均等待、最大等待 | 基于 CP-SAT 任务和资源分配结果派生 |
| 转场惩罚 | 复用现有连续性诊断，MVP 阶段为诊断口径 |
| 成本估算 | 演示默认单价估算，仅用于横向比较 |

### 3.1 严格固定资源求解

- 每个 AI 方案严格使用 LLM 推荐或用户调整后的 `quantity` 展开命名资源。
- 每个 AI 单方案只执行一次固定资源求解，并把最长 15 秒预算完整配置给该次求解。经济、平衡、抢工三套方案分别独立获得 15 秒；该预算只作用于 LLM 推荐或用户调整资源后的 CP-SAT 排程，不修改 LLM 调用超时或通用模拟求解时限。
- 唯一阶段按 `[最大目标延期, 总工期]` 严格字典序求解，不构建资源空闲或连续性目标。最大延期减少 1 天始终优先于任意总工期差异。
- 累计资源空闲和连续性在最终排程完成后计算，仅作为施工组织诊断，不参与目标函数、重试或结果采用判断。
- 新结果保留 `optimization_stages` 兼容外壳：`selected_stage=primary`，`secondary.attempted=false`，`secondary.skipped_reason=not_applicable`。历史两阶段结果和基准快照仍按原字段解析，但不会触发新的第二阶段求解。
- 工期是否证明最优读取唯一阶段的求解状态；`FEASIBLE` 表示已有排程但尚未证明最优。
- 目标延期时保留当前排程和延期信息，不进入最大资源、最少资源、资源压力搜索或候选复排。
- 人工挖孔、冲击钻、回旋钻等工艺工作量为 0 时，对应资源保持为 0，不自动补足。
- 通用「模拟求解」入口仍保留原有资源增量候选能力，不受 AI 严格规则影响。

### 3.2 三种用户可见主状态

| 主状态 | 含义 | 是否参与推荐 |
| --- | --- | --- |
| 工期目标已满足 | 已有可行排程且所有可评估工期目标无延期 | 是 |
| 工期目标未满足 | 已有排程但至少一个工期目标延期；保留排程 | 否 |
| 当前资源未获得可行排程 | 当前没有可用排程，可能是限时未确认或已证明不可行 | 否 |

页面同时保留求解器状态和状态原因：已证明最优但延期显示“已证明延期”，`FEASIBLE + 目标延期` 显示“尚未证明不存在更优排程”；`UNKNOWN` 无排程不得表述为资源一定不足。缺少可评估工期目标时不生成三态，显示“缺少工期目标，无法评估”。旧 `met`、`not_met`、`unconfirmed`、`infeasible` 字段继续保留用于历史兼容，但不再作为页面主状态。

### 3.3 最大延期口径

页面主摘要使用：

```text
最大延期天数 = max(每个强制里程碑延期天数, 固定总工期超期天数)
```

例如强制里程碑延期为 `[0, 12, 5]` 天、固定总工期超期为 `8` 天，页面显示“最大延期 12 天”。原强制里程碑累计延期仍为 `17` 天，固定总工期超期和逐里程碑明细保持不变；该展示口径不修改 CP-SAT 目标函数。

## 4. 推荐解释边界

- 推荐结论先由系统基于求解指标和轻量规则确定。
- AI 只解释推荐证据、风险和边际收益。
- 外部大模型不得改写 `recommended_scenario_id`。
- 只有主状态为“工期目标已满足”的方案进入推荐候选集；历史结果缺少新字段时兼容旧 `met`，没有满足目标方案时不输出正式推荐方案。

## 5. 本地配置

复制 `.local.env.example` 为 `.local.env` 后，优先配置统一的 `PROCESS_NL_LLM_*`。AI 资源助手默认复用这套配置，不需要再复制一份模型参数。

```text
PROCESS_NL_LLM_PROVIDER=openai_compatible
PROCESS_NL_LLM_ENDPOINT=https://api.example.com/v1/chat/completions
PROCESS_NL_LLM_MODEL=your-model
PROCESS_NL_LLM_API_KEY=
PROCESS_NL_LLM_TEMPERATURE=0
PROCESS_NL_LLM_RESPONSE_FORMAT=json_object
```

默认 `local` 可完成完整演示闭环，不需要真实密钥。

如 AI 资源助手确需使用不同模型，可再单独填写 `AI_RESOURCE_ASSISTANT_*` 覆盖项；留空时继续复用 `PROCESS_NL_LLM_*`。

## 6. 验证命令

```powershell
.\.venv\Scripts\python.exe -m pytest backend\tests\test_ai_resource_scheduling_assistant.py -q
.\.venv\Scripts\python.exe -m pytest backend\tests\test_scheduler.py -q
npm.cmd run build
```

通过标准：

- 三方案生成、资源调整、单方案求解、逐步指标对比和独立推荐解释可形成闭环。
- 每个 AI 单方案的 `solver_call_count` 固定为 1，`resource_expansion_attempted` 始终为 `false`。
- 新结果的 `optimization_stages.total_budget_seconds=15.0`，唯一阶段的 `configured_budget_seconds=15.0`；历史结果继续保留求解时记录的 30 秒、60 秒或其他原始预算，通用模拟求解继续使用原场景时限。
- 新结果固定选择 `primary`，第二阶段标记为不适用；累计资源空闲和连续性诊断变好或变差均不参与结果采用判断。
- 单方案求解请求不调用推荐解释；只有用户点击「生成LLM推荐」才调用外部模型或本地解释。
- 三种主状态、证明原因、目标缺失、工作流失效和 LLM 失败均有明确展示，旧四状态结果可兼容读取。
- 页面延期摘要使用单项目标最大值，累计延期和逐里程碑明细保持原口径。
- 演示成本和转场惩罚均标识来源，不进入 CP-SAT 硬约束。
