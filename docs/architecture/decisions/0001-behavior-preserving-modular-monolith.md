# ADR-0001：行为保持型模块化单体

- 状态：accepted
- 日期：2026-07-16
- 规格：`specs/042-repo-architecture-modernization/`

## 背景

后端路由、153 个模型、场景编排和 CP-SAT 求解集中在四个大文件；前端状态、结果展示、202 个类型导出、40 个 API 和样式也集中在少数热点。维护单一能力需要进入无关全局文件，文档又无法稳定指向真实所有权。

## 决策

保留一个 FastAPI + React 的模块化单体，按 HTTP、contracts、scheduling、assistants、girder_planning、plan_control 和前端 features 划分所有权。旧公开文件成为兼容 façade；每批迁移先有契约/行为测试，再移动实现，并可独立回退。

042 不改变 API、业务规则、算法目标、共享 JSON、存储路径、启动命令或依赖。物理资产迁移另设逐文件清单和用户二次确认。

## 被拒绝方案

- 微服务拆分：当前部署、数据和团队边界不足以抵消分布式复杂度。
- 一次性重写：无法提供可靠行为等价和逐批回退。
- 只改目录不设门禁：会隐藏重复实现、循环依赖和文档漂移。
- 保持大文件只补文档：不能解决修改范围和所有权问题。

## 影响

- 正向：单能力修改更局部，入口可定位，兼容风险可自动检查。
- 成本：迁移期存在 façade 和新旧路径并存；每批必须维护基线与回退记录。
- 后续：删除旧入口、升级依赖或拆独立服务都必须另立规格。
