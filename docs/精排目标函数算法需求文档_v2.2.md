# 精排目标函数算法需求文档

版本：v2.2 收敛版

日期：2026-06-30

适用范围：当前资源已通过固定资源满足分支验证，能够满足强制节点后，系统生成命名资源级详细施工计划的精排阶段。

面向对象：产品、算法研发、后端研发、前端研发、测试、计划工程师。

## 1. 需求背景

在固定资源满足分支中，系统先判断当前资源数量是否能够满足强制里程碑，并生成一版可行的固定资源参考排程。该阶段解决的是“当前资源够不够、强制节点能不能保住”的问题。

当当前资源已经满足强制节点后，用户仍需要一版更适合现场讨论、资源泳道展示、施工组织复核和月计划拆解的详细排程。此时排程目标不应继续单纯追求“所有任务越早越好”或“最短总工期”，而应在可行前提下平衡以下目标：


| 目标           | 业务价值                                                               |
| -------------- | ---------------------------------------------------------------------- |
| 控制节点保住   | 关键桥梁、现浇连续梁、架梁通道、合龙等控制对象不能影响节点兑现         |
| 控制链留缓冲   | 控制链任务不需要无差别提前，但不能压线或侵蚀节点缓冲                   |
| 普通工程可穿插 | 普通任务在不影响控制节点时应正常推进，避免资源闲置和计划过度保守       |
| 普通工程有节奏 | 普通任务不能全部抢早或全部堆到后期，应符合工区、工作面和月计划节奏     |
| 资源路径可解释 | 用户能看懂某台设备或班组为什么这样走，哪些跳墩是合理跨越，哪些需要关注 |

本需求面向正式研发交付，从业务目标、算法规则和验收口径重新定义精排能力。它与《固定资源满足分支详细排程算法文档》配合使用，作为固定资源已满足后的精排补充文档。

## 2. 需求目标

精排阶段的核心目标是：

> 在施工逻辑、资源互斥、强制节点等基础约束满足的前提下，优先保障关键节点和控制性工程；控制链任务只有在缓冲不足时才产生惩罚；普通工程允许穿插并保持均衡推进；资源路径按业务路径组输出可解释诊断。

本期需要达成以下结果：


| 编号 | 目标                 | 说明                                                           |
| ---- | -------------------- | -------------------------------------------------------------- |
| 1    | 明确精排入口         | 精排只在当前资源已满足强制节点后执行                           |
| 2    | 明确控制目标来源     | 控制目标来自任务控制属性和现浇连续梁规则识别                   |
| 3    | 明确缓冲不足才惩罚   | 控制链不再因“没有最早完成”被惩罚，只有缓冲不足才产生风险惩罚 |
| 4    | 明确加权目标         | 精排采用加权目标函数表达优先级，不宣称严格字典序优化           |
| 5    | 新增路径组口径       | 路径组用于资源路径评价和跳墩解释，本期暂不增加转场目标惩罚     |
| 6    | 明确输出指标业务含义 | 先让产品、计划工程师和测试理解每个指标解决什么问题             |
| 7    | 增加可测试验收标准   | 研发和测试可直接按场景验证算法行为                             |

## 3. 与固定资源满足分支的关系

《固定资源满足分支详细排程算法文档》负责定义固定资源求解的主流程，本文档只定义其中“当前资源满足强制节点后”的精排规则。


| 环节                     | 固定资源满足分支文档                 | 本文档                                 |
| ------------------------ | ------------------------------------ | -------------------------------------- |
| 用户入口                 | 定义用户点击固定资源推算后的整体链路 | 不重复定义入口                         |
| 当前资源是否满足强制节点 | 由池级固定资源快排判断               | 使用其判断结果作为前置条件             |
| 当前资源不满足强制节点   | 进入资源不足和资源建议分支           | 不处理                                 |
| 当前资源满足强制节点     | 进入命名资源级详细排程               | 定义精排目标函数、控制目标、指标和验收 |
| 精排失败                 | 回退固定资源参考排程                 | 输出精排失败原因和回退说明             |

精排阶段不得重新承担“资源是否足够”的主判断职责。资源够不够由上游固定资源满足分支先判断；精排只负责在当前资源已满足强制节点的前提下，选择更适合施工组织表达的命名资源级详细排程。

## 4. 适用范围与非范围

### 4.1 本期范围


| 范围               | 说明                                                         |
| ------------------ | ------------------------------------------------------------ |
| 命名资源级详细排程 | 将资源池能力落到具体设备、模板、班组等命名资源               |
| 控制目标识别       | 根据任务控制属性和现浇连续梁规则识别控制性工程               |
| 控制链识别         | 从控制目标沿施工逻辑向前追溯关键前置任务                     |
| 控制缓冲风险       | 计算控制链任务是否侵蚀关键节点缓冲                           |
| 普通工程穿插       | 普通任务在不影响控制目标时可以正常施工                       |
| 普通工程均衡       | 普通任务在施工窗口内按空间顺序、工区节奏和工作面能力均衡推进 |
| 路径组诊断         | 按业务路径组解释资源路径、跳墩、跳幅和方向反转               |
| 输出指标口径       | 输出业务主指标、诊断指标和技术辅助指标的业务含义             |
| 验收标准           | 覆盖控制、普通、路径组、回退和指标展示场景                   |

### 4.2 本期非范围


| 非范围                     | 说明                                                             |
| -------------------------- | ---------------------------------------------------------------- |
| 当前资源不满足强制节点     | 由资源不足和资源建议分支处理                                     |
| 动态重排和实际锁定         | 属于后续重排能力                                                 |
| 成本最优资源方案           | 属于资源成本优化模型                                             |
| 真实转场时间建模           | 本期只做路径组诊断，不增加转场目标惩罚                           |
| 材料供应、交地、便道、审批 | 应作为外部条件或工作面约束输入，不由目标函数替代                 |
| 现场执行失控               | 天气、队伍、审批、材料异常需要记录，但不是精排目标函数单独能解决 |
| 严格分阶段优化             | 本期采用加权目标；如需严格字典序优化，应另行定义                 |

## 5. 核心概念


| 概念             | 定义                                                   | 用途                                 |
| ---------------- | ------------------------------------------------------ | ------------------------------------ |
| 里程碑评价范围   | 用来判断某个节点是否完成的一组任务                     | 计算节点实际日期、是否迟延和剩余余量 |
| 控制目标         | 本期真正需要优先保障的关键任务、关键工点或控制性结构物 | 作为控制优先的起点                   |
| 控制链           | 从控制目标沿施工逻辑向前追溯得到的前置任务链条         | 判断关键前置是否影响控制目标         |
| 最晚安全完成时间 | 某任务不影响后续控制目标或节点兑现的最晚完成边界       | 判断是否压线                         |
| 必要缓冲         | 业务要求控制目标或控制链保留的最小安全余量             | 判断缓冲是否不足                     |
| 控制缓冲风险     | 实际排程未保留必要缓冲所产生的风险                     | 作为精排惩罚项                       |
| 普通工程         | 未被识别为控制目标或控制链关键任务的常规施工任务       | 可穿插、需均衡推进                   |
| 路径组           | 用于评价资源路径连续性的业务分组                       | 判断跳墩、跳幅、方向反转是否合理     |
| 实际可施工序列   | 路径组内实际存在该工艺任务的施工对象顺序               | 判断是否真实跳墩                     |
| 加权目标         | 将多个目标项按权重求和形成的优化目标                   | 表达优先级，但不是严格字典序优化     |

关键原则：

> 里程碑评价范围不等于控制目标。

例如，里程碑要求“某桥下部结构全部完成”时，系统可以用该桥范围内的桩基、承台、墩柱、盖梁等任务判断节点是否完成，但不能因此把该范围内所有任务都自动提升为控制目标。

## 6. 精排前置条件

进入精排前，系统必须已经满足以下条件：


| 条件                 | 说明                                                           |
| -------------------- | -------------------------------------------------------------- |
| 当前资源满足强制节点 | 上游固定资源满足分支已判断强制里程碑无迟延                     |
| 任务已生成           | 已形成可排程任务，并包含工期、工艺、结构物、资源类型等基础信息 |
| 施工逻辑已生成       | 前后置、搭接、技术间歇等逻辑关系可用于排程                     |
| 资源池已展开         | 需要形成可分配的命名资源                                       |
| 强制节点已定义       | 业主节点、架梁节点、交通转换节点、合龙节点等可用于可行性判断   |
| 任务控制属性已输出   | 结构物参数生成任务时，应明确任务属于控制性工程还是普通工程     |

精排只在可行计划之间排序，不允许用目标函数替代施工逻辑、资源互斥、强制节点等基础约束。

## 7. 控制目标识别规则

### 7.1 控制目标来源

本期控制目标只来自以下两类：


| 来源         | 规则                                               | 说明                                                                             |
| ------------ | -------------------------------------------------- | -------------------------------------------------------------------------------- |
| 任务控制属性 | 算法输出的结构物参数中，任务已明确标记为控制性工程 | 这是“用户指定”的工程化口径，即上游结构物参数或任务生成结果已经明确任务控制属性 |
| 规则识别     | 现浇连续梁默认识别为控制性工程                     | 本期仅支持现浇连续梁规则识别                                                     |

本期不支持控制性目标的设置。仅在算法预留入口参数。

### 7.2 不作为控制目标来源的内容


| 内容                       | 处理口径                                   |
| -------------------------- | ------------------------------------------ |
| 里程碑评价范围内的全部任务 | 仅用于判断节点是否完成，不自动成为控制目标 |
| 普通桥梁下部结构全量任务   | 不因属于某个节点范围而自动成为控制目标     |
| 求解器临时判断的瓶颈任务   | 可作为诊断输出，不作为本期控制目标来源     |
| 用户未确认的经验规则       | 不进入本期自动识别                         |

### 7.3 现浇连续梁控制性工程规则

当结构物参数中存在现浇连续梁时，系统应将该现浇连续梁识别为控制性工程，并将其相关排程任务作为控制目标或控制链重点对象。


| 对象                                                   | 处理口径                             |
| ------------------------------------------------------ | ------------------------------------ |
| 现浇连续梁整体结构                                     | 识别为控制性工程                     |
| 0号块、标准节段、边跨现浇段、合龙段等任务              | 纳入控制目标或控制链分析             |
| 与现浇连续梁前置相关的墩身、临时固结、支架、挂篮等任务 | 按施工逻辑追溯进入控制链             |
| 非现浇连续梁的普通墩、普通梁、普通工序                 | 不因同桥或同评价范围自动成为控制目标 |

## 8. 控制链识别与缓冲规则

### 8.1 控制链识别

系统应从控制目标出发，沿施工逻辑向前追溯，得到保障控制目标所需的前置任务链条。

示例：

```text
现浇连续梁合龙
<- 标准节段施工
<- 0号块完成
<- 主墩墩身完成
<- 承台完成
<- 桩基完成
```

控制链用于判断关键前置是否影响控制目标，不表示链上所有任务都必须越早完成越好。

### 8.2 最晚安全完成时间

系统应为控制目标和控制链任务计算最晚安全完成时间。


| 对象                           | 最晚安全完成时间来源                             |
| ------------------------------ | ------------------------------------------------ |
| 直接关联硬里程碑的控制目标     | 不晚于硬里程碑目标日期                           |
| 直接关联软控制里程碑的控制目标 | 不晚于软控制目标日期，允许迟延但产生高优先级风险 |
| 控制链前置任务                 | 根据后续控制任务开始时间、施工逻辑和必要缓冲反推 |
| 无明确节点约束的控制目标       | 结合后续施工逻辑和总工期目标推导，不能无约束抢早 |

### 8.3 缓冲不足才惩罚

本期明确采用以下目标口径：

> 控制链任务不因“没有尽早完成”而被惩罚；只有当任务完成时间侵蚀必要缓冲、接近最晚安全完成时间或影响控制节点时，才产生控制缓冲风险惩罚。

建议计算口径：

```text
剩余缓冲天数 = 最晚安全完成时间 - 当前计划完成时间
缓冲风险天数 = max(0, 必要缓冲天数 - 剩余缓冲天数)
```


| 场景                             | 处理口径                 |
| -------------------------------- | ------------------------ |
| 控制链任务远早于最晚安全完成时间 | 不继续奖励无限提前       |
| 控制链任务保留足够必要缓冲       | 风险为 0                 |
| 控制链任务接近最晚安全完成时间   | 产生缓冲风险             |
| 控制链任务超过硬节点最晚边界     | 当前精排方案不可接受     |
| 控制链任务影响软控制节点         | 产生软控制迟延和缓冲风险 |

### 8.4 普通任务让位规则

普通任务可以穿插，但不能抢占关键窗口。


| 场景                                     | 系统行为                           |
| ---------------------------------------- | ---------------------------------- |
| 普通任务穿插后控制链仍有足够缓冲         | 允许普通任务正常施工               |
| 普通任务导致控制链缓冲不足               | 普通任务应让位，或产生明确风险诊断 |
| 普通任务导致硬节点不可满足               | 该精排方案不可接受                 |
| 普通任务不影响控制目标但改善普通工程节奏 | 可优先保留                         |

## 9. 硬里程碑与软控制里程碑

### 9.1 硬里程碑

硬里程碑是必须满足的节点，包括业主强制节点、架梁节点、交通转换节点、贯通节点、合龙节点等。

硬节点口径：

> 不是“尽量不晚”，而是“不能晚”。

算法要求：


| 要求               | 说明                                                                           |
| ------------------ | ------------------------------------------------------------------------------ |
| 作为硬约束         | 精排结果不得晚于硬里程碑目标日期                                               |
| 不进入迟延罚分抵消 | 不能通过其他目标收益抵消硬节点迟延                                             |
| 输出余量           | 展示实际完成日期、目标日期和剩余缓冲                                           |
| 不满足时回退或诊断 | 当前资源满足分支中，若命名资源精排无法满足硬节点，应回退上游可行结果并说明原因 |

### 9.2 软控制里程碑

软控制里程碑是希望尽量满足但允许迟延的节点，如内部管理节点、月度计划节点、季度计划节点等。本期不涉及软里程碑。

算法要求：


| 要求         | 说明                             |
| ------------ | -------------------------------- |
| 可迟延       | 不直接导致方案不可行             |
| 高优先级惩罚 | 迟延天数高于普通均衡和路径诊断   |
| 输出影响     | 展示迟延天数、影响对象和可能原因 |

## 10. 普通工程均衡规则

普通工程均衡的业务口径是：

> 普通工程不是越早越好，而是应在可施工窗口内，按照空间顺序、工区节奏和工作面能力均衡推进。

系统应避免两种极端：


| 极端                 | 问题                           |
| -------------------- | ------------------------------ |
| 普通任务全部抢早开工 | 造成资源、工作面和现场组织混乱 |
| 普通任务全部压到后期 | 后期集中爆量，月计划不可执行   |

普通工程均衡应低于控制节点和控制缓冲风险。当普通工程均衡与控制缓冲冲突时，控制缓冲优先。


| 规则                     | 说明                                                       |
| ------------------------ | ---------------------------------------------------------- |
| 普通任务有施工窗口       | 受最早开始、最晚完成、最大提前完成窗口约束                 |
| 普通任务受工作面能力限制 | 同桥梁、同工区、同作业面不能无限铺开                       |
| 普通任务按空间顺序均衡   | 尽量符合墩台顺序、工区顺序和月计划节奏                     |
| 控制链普通前置需重新归属 | 一旦普通任务被追溯为控制链前置，应按控制链缓冲规则判断风险 |

## 11. 路径组与资源路径诊断

### 11.1 路径组定义

本期新增路径组口径，用于资源路径评价和结果解释。路径组不能全项目混算，应按业务维度划分。


| 维度     | 示例                                               |
| -------- | -------------------------------------------------- |
| 结构物   | 某座桥、某座隧道、某段路基                         |
| 作业区域 | 工区、施工段、作业面                               |
| 幅别     | 左幅、右幅、全幅                                   |
| 资源类型 | 旋挖钻、模板、挂篮、班组、架桥机                   |
| 工艺类型 | 桩基、墩柱、盖梁、现浇梁、架梁                     |
| 施工方向 | 顺里程、逆里程、主墩向两侧、两端向中间、自定义顺序 |

### 11.2 实际可施工序列

跳墩判断应基于路径组内实际存在的施工对象序列，而不是简单按原始墩号判断。


| 场景                                     | 判断                                   |
| ---------------------------------------- | -------------------------------------- |
| 人工挖孔桩只有 4#、7# 墩有任务，4# 到 7# | 不算跳墩                               |
| 旋挖钻桩 1# 到 7# 都有任务，4# 到 7#     | 算跳墩                                 |
| 左幅和右幅分别独立施工                   | 不应混在同一序列判断跳墩               |
| 跨桥、跨工区转移                         | 应作为路径组切换诊断，不直接等同于跳墩 |

### 11.3 路径连续性目标边界

本期路径组用于结果诊断和资源连续性解释。算法可对明显不连续行为加入轻量路径连续惩罚，但不建模真实转场时间。


| 内容           | 本期处理                                                                     |
| -------------- | ---------------------------------------------------------------------------- |
| 跳墩次数       | 输出诊断；本期不逐次建模为独立罚分                                           |
| 跳幅次数       | 输出诊断；本期不逐次建模为独立罚分                                           |
| 方向反转次数   | 输出诊断；本期不逐次建模为独立罚分                                           |
| 路径组切换次数 | 输出诊断；路径组过多可进入轻量连续惩罚                                       |
| 路径连续惩罚   | 采用轻量近似项，主要惩罚同一资源跨路径组过多、同一路径组内施工位置分布不连续 |
| 真实转场时间   | 本期不做                                                                     |

这意味着，路径组诊断可以告诉用户“资源路径是否顺、哪里发生跳转、跳转是否合理”。路径连续惩罚不能牺牲硬节点、控制缓冲和主要资源组织目标。

当前路径连续惩罚为轻量近似项，不等同于完整转场模型。目标函数重点处理两类不连续：


| 近似项           | 业务含义                                               | 当前处理                                 |
| ---------------- | ------------------------------------------------------ | ---------------------------------------- |
| 路径组过多       | 同一资源跨桥梁、工区、幅别、资源类型或工艺路径过多     | 作为目标惩罚，减少不必要路径组切换       |
| 路径组内空间空缺 | 同一路径组内资源施工位置跨度大，中间存在未覆盖施工对象 | 作为目标惩罚，推动资源路径更集中、更连续 |

跳墩、跳幅、方向反转等逐次 transition 指标本期主要用于诊断展示和人工复核，暂不逐项建模为独立目标罚分。后续如需精细控制，应单独设计转场时间、转场成本或逐次跳转罚分。

## 12. 同结构同工艺连续性与并行配置

同结构同工艺连续性不应按资源类型在算法中硬编码，应由资源配置字段决定。


| 配置字段                          | 业务含义                                                           | 求解规则                                   |
| --------------------------------- | ------------------------------------------------------------------ | ------------------------------------------ |
| `same_structure_resource_binding` | 同一结构物、同一构件类型、同一工艺是否绑定同一命名资源             | 为 true 时，相关任务必须分配给同一命名资源 |
| `same_structure_parallel_limit`   | 同一结构物、同一构件类型、同一工艺在同一资源池内允许的最大并行数量 | 有值时，相关任务并行数量不得超过该上限     |
| `parallel_rule_description`       | 前端展示的并行施工说明                                             | 只读解释，不直接参与求解                   |

默认资源模板应按以下口径初始化，求解器只读取配置字段，不按类型编码写死规则。


| 资源 / 工艺            | 本期业务口径                                     |
| ---------------------- | ------------------------------------------------ |
| 挂篮                   | 强连续，应尽量绑定连续梁节段或 T 构推进          |
| 爬模                   | 强连续，应尽量绑定高墩连续爬升                   |
| 架桥机                 | 强连续，应按架梁路径推进                         |
| 特殊模板               | 优先连续，减少频繁倒用                           |
| 墩柱模板、盖梁模板     | 弱连续，可作为组织偏好                           |
| 旋挖钻、回旋钻、冲击钻 | 默认配置为同结构同工艺绑定同一资源，并行上限为 1 |
| 人工挖孔班组           | 默认不设置同结构同工艺额外并行上限               |
| 未配置并行规则的资源   | 不施加同结构同工艺绑定或并行限制                 |

命名资源级精排应执行绑定和并行上限约束；固定资源容量快排至少应执行并行上限约束，避免高估同结构同工艺可并行能力。

## 13. 加权目标函数口径

本期精排采用加权目标函数表达业务优先级。

重要说明：

> 加权目标表示“不同目标项按权重求和后的综合优化”，不是严格数学意义上的分阶段或字典序优化。

建议目标结构：

```text
Minimize =
  软控制节点迟延惩罚
+ 控制缓冲风险惩罚
+ 风险相关控制链等待惩罚
+ 同类资源工作量不均衡惩罚
+ 资源窝工惩罚
+ 资源路径连续惩罚
+ 总工期和普通软节点惩罚
+ 普通工程均衡惩罚
+ 同结构同工艺连续性偏好
```

目标项说明：


| 目标项                   | 业务含义                                                   | 优先级口径 |
| ------------------------ | ---------------------------------------------------------- | ---------- |
| 软控制节点迟延惩罚       | 软控制节点晚了多少天                                       | 高         |
| 控制缓冲风险惩罚         | 控制链是否侵蚀必要缓冲                                     | 高         |
| 风险相关控制链等待惩罚   | 控制链因资源或前置关系产生的等待是否导致风险               | 中高       |
| 同类资源工作量不均衡惩罚 | 已启用同类资源是否被均衡使用                               | 高         |
| 资源窝工惩罚             | 单个资源从首次施工到末次施工之间是否存在长空档             | 高         |
| 资源路径连续惩罚         | 资源是否跨过多路径组，或同一路径组内施工位置是否分布不连续 | 中高       |
| 总工期和普通软节点惩罚   | 在关键目标满足后控制整体效率                               | 中         |
| 普通工程均衡惩罚         | 避免普通任务抢早或后期堆积                                 | 低         |
| 同结构同工艺连续性偏好   | 减少强连续资源被拆散                                       | 低         |

硬里程碑、施工逻辑和资源互斥是硬约束，不应作为可被其他收益抵消的普通罚分项。

如果后续业务要求“某一层目标绝对不能被低优先级目标影响”，需要改为分阶段求解，或对权重做上界证明。

## 14. 输出指标业务含义

### 14.1 业务主指标

业务主指标用于让计划工程师快速判断当前精排结果是否可用于讨论和复核。


| 指标             | 回答的业务问题                           | 业务口径                                |
| ---------------- | ---------------------------------------- | --------------------------------------- |
| 推荐排程总工期   | 当前推荐详细计划整体持续多久             | 当前精排结果的项目总工期                |
| 最短工期基准     | 和固定资源快排相比，精排是否牺牲了总工期 | 上游池级快排得到的参考总工期            |
| 强制节点状态     | 业主、架梁、交通转换等节点能否保住       | 全部满足 / 存在风险 / 不满足            |
| 控制缓冲状态     | 控制性工程是否压线                       | 正常 / 接近风险 / 缓冲不足 / 已影响节点 |
| 普通工程均衡状态 | 普通任务是否过早集中或后期堆积           | 均衡 / 偏集中 / 后期堆积                |
| 资源路径状态     | 资源路径是否顺向、连续、可解释           | 顺畅 / 有合理跨越 / 有异常跳转          |

### 14.2 诊断指标

诊断指标用于解释为什么排成这样，以及哪些地方需要人工复核。


| 指标               | 回答的业务问题                         | 业务口径                                           |
| ------------------ | -------------------------------------- | -------------------------------------------------- |
| 控制缓冲风险天数   | 哪些控制任务已经压线                   | 必要缓冲与剩余缓冲的差值                           |
| 控制链等待天数     | 哪些关键工作在等资源或等前置           | 控制链相邻任务之间超出逻辑间隔的等待               |
| 软控制节点迟延天数 | 哪些内部目标没有完全满足               | 实际完成日期晚于目标日期的天数                     |
| 普通工程均衡偏差   | 普通任务是否按节奏展开                 | 实际任务分布与目标节奏的偏差                       |
| 同类资源工作量差值 | 已启用同类资源是否分配均衡             | 同类资源最大工作量减最小工作量                     |
| 资源窝工天数       | 单个资源施工是否连续                   | 资源驻场跨度减实际工作天数，或相邻任务正向空档合计 |
| 最大空档天数       | 哪些资源存在长时间空闲                 | 单个资源相邻任务之间的最大空档                     |
| 真实跳墩次数       | 资源是否跳过路径组内实际存在的施工对象 | 排除中间无该工艺任务后的跳墩                       |
| 跳幅次数           | 资源是否频繁左右幅切换                 | 同一路径组内左右幅切换次数                         |
| 方向反转次数       | 资源是否反复折返施工                   | 同一路径组内施工方向反转次数                       |
| 同工艺拆分次数     | 高连续性资源是否被拆散使用             | 同结构同工艺任务被多个资源承担的次数               |

### 14.3 技术辅助指标

技术辅助指标用于研发和测试复核，不建议作为业务主展示。


| 指标         | 用途                                       |
| ------------ | ------------------------------------------ |
| 求解状态     | 判断是否找到可行解或最优解                 |
| 加权目标值   | 研发测试复核目标函数效果                   |
| 各目标项贡献 | 判断哪个目标项主导了本次排程               |
| 回退原因     | 精排失败时说明为什么回退到固定资源参考排程 |
| 求解耗时     | 评估工程性能和超时风险                     |

## 15. 结果解释口径

精排结果不应只输出一个目标值，应能解释用户最关心的问题。


| 解释内容         | 用户能理解的问题                                 |
| ---------------- | ------------------------------------------------ |
| 强制节点是否满足 | 业主节点、架梁节点、交通转换节点能不能保住       |
| 控制目标来源     | 为什么这些任务被当成控制性工程                   |
| 控制缓冲风险     | 哪些控制任务接近最晚安全完成时间                 |
| 普通任务穿插     | 为什么普通任务可以插在控制链之间                 |
| 普通任务让位     | 为什么某些普通任务被延后                         |
| 普通工程均衡     | 普通任务是否形成月计划可执行节奏                 |
| 资源路径诊断     | 某台设备或班组是否跳墩、跳幅或反向               |
| 跳墩原因         | 是真实跳墩，还是中间没有该工艺任务               |
| 方案来源         | 当前是命名资源精排结果，还是固定资源参考排程回退 |

## 16. 前后端职责

### 16.1 后端职责


| 职责                     | 说明                                                   |
| ------------------------ | ------------------------------------------------------ |
| 接收上游固定资源满足结果 | 确认当前资源已满足强制节点后进入精排                   |
| 识别控制目标             | 根据任务控制属性和现浇连续梁规则识别                   |
| 追溯控制链               | 沿施工逻辑生成控制链                                   |
| 计算最晚安全完成时间     | 为控制目标和控制链任务计算节点边界                     |
| 计算控制缓冲风险         | 按必要缓冲判断是否惩罚                                 |
| 读取资源并行规则         | 从资源配置读取同结构绑定和并行上限，不按资源类型硬编码 |
| 计算资源组织目标         | 输出工作量均衡、窝工、利用率和路径连续诊断             |
| 构建加权目标函数         | 使用加权目标表达优先级                                 |
| 生成命名资源排程         | 分配具体设备、模板、班组                               |
| 输出业务指标和诊断       | 返回主指标、诊断指标和技术辅助指标                     |
| 处理精排失败             | 回退固定资源参考排程并说明原因                         |

### 16.2 前端职责


| 职责                     | 说明                                             |
| ------------------------ | ------------------------------------------------ |
| 展示精排主结果           | 甘特图、资源泳道、里程碑结果使用主结果           |
| 展示业务主指标           | 总工期、强制节点状态、控制缓冲状态、普通均衡状态 |
| 展示诊断信息             | 控制链等待、缓冲风险、资源路径诊断               |
| 区分方案来源             | 标识当前结果是命名资源精排还是回退结果           |
| 避免技术指标干扰业务用户 | 技术辅助指标可折叠或放在研发诊断区               |

## 17. 异常与回退


| 异常场景               | 处理方式                                       |
| ---------------------- | ---------------------------------------------- |
| 精排未找到可行解       | 回退固定资源满足分支的参考排程                 |
| 精排超时               | 回退固定资源参考排程，并输出超时原因           |
| 控制目标为空           | 输出诊断，按普通工程均衡和资源路径诊断生成结果 |
| 现浇连续梁识别失败     | 输出规则识别诊断，不能静默按普通任务处理       |
| 路径组信息不足         | 输出路径组缺失诊断，资源路径指标降级展示       |
| 部分里程碑无法匹配任务 | 输出里程碑匹配诊断，不影响其他可匹配节点计算   |

## 18. 验收标准


| 编号 | 场景                                                 | 预期结果                                                                       |
| ---- | ---------------------------------------------------- | ------------------------------------------------------------------------------ |
| 1    | 上游固定资源快排判断强制节点无迟延                   | 系统进入命名资源级精排                                                         |
| 2    | 上游固定资源快排判断强制节点迟延                     | 不进入本文档定义的精排分支，进入资源不足和资源建议分支                         |
| 3    | 任务生成结果中某任务标记为控制性工程                 | 该任务被识别为控制目标，并输出控制来源                                         |
| 4    | 结构物参数中存在现浇连续梁                           | 现浇连续梁被识别为控制性工程                                                   |
| 5    | 某桥下部结构只是里程碑评价范围                       | 该桥全部下部结构任务不自动成为控制目标                                         |
| 6    | 控制链任务早于最晚安全完成时间且保留足够缓冲         | 不因“没有更早完成”产生控制缓冲风险惩罚                                       |
| 7    | 控制链任务接近最晚安全完成时间，剩余缓冲小于必要缓冲 | 产生控制缓冲风险，并输出风险天数                                               |
| 8    | 控制链任务超过硬节点最晚边界                         | 当前精排方案不可接受，需回退或重新求解                                         |
| 9    | 普通任务穿插后不影响控制缓冲                         | 普通任务允许穿插施工                                                           |
| 10   | 普通任务导致控制缓冲不足                             | 普通任务应让位，或结果中输出明确风险诊断                                       |
| 11   | 普通任务全部抢早造成工作面过度铺开                   | 普通工程均衡指标应识别异常                                                     |
| 12   | 普通任务全部堆到后期                                 | 普通工程均衡指标应识别后期堆积                                                 |
| 13   | 使用加权目标函数求解                                 | 文档和结果解释中不得表述为严格字典序优化                                       |
| 14   | 人工挖孔桩仅 4#、7# 墩有任务，资源从 4# 到 7#        | 不计为真实跳墩                                                                 |
| 15   | 旋挖钻桩 1# 到 7# 均有任务，资源从 4# 到 7#          | 计为真实跳墩                                                                   |
| 16   | 左右幅分别独立形成路径组                             | 不应把左右幅任务混在同一可施工序列判断跳墩                                     |
| 17   | 资源发生跳墩、跳幅或方向反转                         | 输出诊断和人工复核信息；本期不逐项建模为独立目标罚分                           |
| 18   | 精排成功                                             | 输出推荐排程总工期、强制节点状态、控制缓冲状态、普通工程均衡状态和资源路径状态 |
| 19   | 精排失败或超时                                       | 回退固定资源参考排程，并输出回退原因                                           |
| 20   | 前端展示结果                                         | 能区分当前结果是命名资源精排结果还是固定资源参考排程回退结果                   |
| 21   | 用户配置 6 个旋挖钻且任务量充足                      | 精排按 6 个资源参与求解，并尽量均衡各资源工作量                                |
| 22   | 同一资源存在长时间空档                               | `resource_idle_penalty` 增加，并在资源组织分析中输出空闲天数和最大空档         |
| 23   | 旋挖钻、回旋钻或冲击钻同墩同工艺多桩任务             | 默认绑定同一资源，并行上限为 1                                                 |
| 24   | 人工挖孔班组同墩多桩任务                             | 默认不设置同结构同工艺额外并行上限                                             |
| 25   | 同样的资源类型未配置并行规则字段                     | 求解器不得仅按资源类型编码施加同结构同工艺并行限制                             |

## 19. 交付边界

本 PRD 定义的是固定资源满足后的精排目标函数和结果解释口径。研发实现时应先保证：

1. 控制目标来源清晰。
2. 控制链缓冲风险可计算。
3. 加权目标函数口径一致。
4. 普通工程穿插和均衡不破坏控制缓冲。
5. 路径组诊断可解释。
6. 输出指标能支撑产品展示和测试验收。

后续若需要严格字典序优化、真实转场时间、资源成本最优或动态重排，应单独立项。
