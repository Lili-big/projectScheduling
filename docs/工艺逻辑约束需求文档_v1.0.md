# 工艺逻辑约束需求文档

版本：v1.0

日期：2026-06-16

适用范围：桥梁自动排程系统工程化版本

面向对象：产品、前端研发、后端研发、测试

## 1. 功能模块核心定位

### 1.1 模块定位

工艺逻辑约束是排程系统的基础规则配置模块，用于维护“任务之间谁先谁后、间隔多久、以何种时间关系约束”的工艺逻辑规则。

该模块的核心价值不是展示工艺说明，而是为任务生成和排程求解提供可计算的前后置约束。系统生成任务视图和求解排程时，应将本模块维护的规则转换为任务之间的 `PrecedenceLink`，并进入求解器约束。

工程化产品目标是“系统默认规则模板 + 项目级配置”：系统内置默认工艺逻辑规则，新项目创建或首次进入排程配置时，将默认规则初始化为当前项目自己的工艺逻辑配置。用户后续修改只影响当前项目，不影响系统默认模板和其他项目。

### 1.2 当前页面效果

当前页面标题为“工艺逻辑约束”，副标题为“维护任务之间谁先谁后；逻辑关系和时间间隔会进入排程求解”。

页面主体为“规则配置”表格，顶部展示规则统计：

- 规则总数。
- 当前适用规则数。
- 暂未适用规则数。

当前页面右侧展示提示“修改后重新生成任务视图”，用于提醒用户规则修改后既有任务视图和排程结果需要重新生成。

表格列如下：

| 列名 | 页面含义 | 当前交互 |
| --- | --- | --- |
| 规则名称 | 展示规则来源标签和规则名称 | 只读；下部结构为蓝色标签，桥梁上部为绿色标签 |
| 适用结构物 | 展示该规则约束的后续任务或目标结构 | 只读 |
| 前置工序 | 展示该规则要求的前置任务来源 | 只读 |
| 匹配规则 | 展示前置任务匹配策略 | 只读 |
| 逻辑关系 | 展示并编辑任务时间关系 | 下拉选择，支持 `FS`、`SS`、`FF`、`SF` |
| 时间间隔 | 展示并编辑前后任务间隔 | 数字输入，单位为自然日 |
| 使用范围 | 展示当前项目中该规则匹配到的对象数量 | 只读 |
| 规则说明 | 展示规则业务说明和任务生成说明 | 只读 |

### 1.3 模块边界

本模块本期负责：

- 展示项目级工艺逻辑规则。
- 展示下部结构规则和桥梁上部规则，并用来源标签区分。
- 支持编辑规则的逻辑关系和时间间隔。
- 支持编辑后立即保存当前项目工艺逻辑配置。
- 支持根据当前项目结构计算规则适用范围。
- 支持将工艺逻辑规则用于任务生成和排程求解。
- 支持在规则变化后使旧任务视图、求解结果和方案对比结果失效。

本模块本期不负责：

- 在页面新增或删除工艺逻辑规则。
- 在页面编辑规则名称、适用结构物、前置工序、匹配规则和规则说明。
- 在页面直接编辑构件、工艺工效、资源池和里程碑。
- 在本页面展示完整任务视图、甘特图或求解结果。
- 维护系统默认规则模板。默认模板应由后台规则库或管理后台维护。

## 2. 数据定义

### 2.1 下部结构工艺逻辑规则

下部结构工艺逻辑规则对应 `LogicRule`，用于描述同一墩台或同一结构序列内的构件任务前后置关系。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 规则稳定 ID，用于保存、展示、生成前后置关系和追踪来源 |
| `scope` | string | 是 | 规则作用范围，本期主要支持 `same_structure`，可扩展 `structure_sequence` |
| `structure_type` | string \| null | 否 | 适用结构类型；为空表示不限制结构类型 |
| `to_component` | string | 是 | 后续任务对应的构件类型 |
| `predecessor_candidates` | string[] | 是 | 候选前置构件类型列表，至少 1 项 |
| `predecessor_strategy` | string | 是 | 前置匹配策略，支持 `all`、`first_available` |
| `relationship` | string | 是 | 逻辑关系，支持 `FS`、`SS`、`FF`、`SF` |
| `lag_days` | number | 是 | 时间间隔，单位为自然日，必须大于等于 0 |
| `severity` | string | 是 | 规则严重级别，本期默认 `error` |
| `note` | string | 否 | 规则说明，页面只读展示 |

### 2.2 桥梁上部工艺逻辑规则

桥梁上部工艺逻辑规则对应 `UpperStructureLogicRule`，用于描述现浇箱梁、连续梁等上部结构现场任务与下部结构完成任务、上部内部任务之间的前后置关系。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 规则稳定 ID |
| `relationship` | string | 是 | 逻辑关系，支持 `FS`、`SS`、`FF`、`SF` |
| `lag_days` | number | 是 | 时间间隔，单位为自然日，必须大于等于 0 |
| `severity` | string | 是 | 规则严重级别，本期默认 `error` |
| `note` | string | 否 | 规则说明，页面只读展示 |

桥梁上部规则的规则名称、适用结构物、前置工序、匹配规则和任务生成说明由系统规则定义提供；项目级配置仅保存用户可调整的逻辑关系和时间间隔等配置项。

### 2.3 前后置关系输出

任务生成后，工艺逻辑规则应转换为 `PrecedenceLink`。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 前后置关系稳定 ID |
| `predecessor_id` | string | 是 | 前置任务 ID |
| `successor_id` | string | 是 | 后续任务 ID |
| `relationship` | string | 是 | 从规则继承的逻辑关系 |
| `lag_days` | number | 是 | 从规则继承的时间间隔 |
| `source_rule_id` | string | 是 | 来源规则 ID，用于页面追踪和诊断 |
| `severity` | string | 是 | 来源规则严重级别 |

### 2.4 枚举定义

逻辑关系枚举：

| 枚举 | 含义 | 约束说明 |
| --- | --- | --- |
| `FS` | Finish to Start | 前置任务完成后，后续任务才可开始 |
| `SS` | Start to Start | 前置任务开始后，后续任务才可开始 |
| `FF` | Finish to Finish | 前置任务完成后，后续任务才可完成 |
| `SF` | Start to Finish | 前置任务开始后，后续任务才可完成 |

前置匹配策略：

| 枚举 | 页面展示 | 说明 |
| --- | --- | --- |
| `all` | 所有前置都要完成 | 候选前置工序中存在的任务全部作为前置 |
| `first_available` | 按顺序回退 | 按候选列表顺序查找，使用第一个存在的前置工序 |
| 系统生成 | 按结构自动生成 | 根据桥梁上部结构和下部完成任务自动派生前后置关系 |

## 3. 默认数据初始化

### 3.1 初始化原则

系统应内置默认工艺逻辑规则模板。项目首次创建或首次进入排程配置时，系统应将默认规则初始化为当前项目的项目级工艺逻辑配置。

初始化后的项目级配置应满足：

- 项目配置与系统默认模板分离。
- 用户修改当前项目规则后，不影响其他项目。
- 系统默认模板后续升级时，不应无提示覆盖用户已修改的项目配置。
- 当前项目刷新、重新进入或重新生成任务时，应读取项目级最新工艺逻辑配置。

## 4. 页面功能交互

### 4.1 进入页面

用户进入“工艺逻辑约束”页面后，系统应：

- 查询当前项目的项目级工艺逻辑配置。
- 若项目尚未初始化工艺逻辑配置，则使用系统默认规则模板初始化项目配置。
- 根据当前项目结构物、构件和上部结构参数计算每条规则的使用范围。
- 按下部结构规则在前、桥梁上部规则在后的顺序展示统一规则表。
- 展示规则总数、当前适用规则数和暂未适用规则数。

### 4.2 查看规则

规则表应完整展示下部结构规则和桥梁上部规则。

展示规则：

- 下部结构规则展示“下部结构”标签。
- 桥梁上部规则展示“桥梁上部”标签。
- 使用范围大于 0 时，展示“适用 N 个结构物 / 联 / T构 / 边跨 / 中跨”等文本。
- 使用范围等于 0 时，展示“当前无适用对象”。
- 规则说明应同时说明业务前后置含义；桥梁上部规则可补充任务生成说明。

### 4.3 编辑逻辑关系

用户可在“逻辑关系”列编辑规则关系。

交互要求：

- 下拉选项固定为 `FS`、`SS`、`FF`、`SF`。
- 用户选择新关系后，系统立即保存当前项目该规则的关系配置。
- 保存成功后，页面保留新值，并以新值参与后续任务生成和求解。
- 保存失败时，页面应展示明确错误提示；用户当前操作值可保留在页面中，刷新后以服务端项目配置为准。

### 4.4 编辑时间间隔

用户可在“时间间隔”列编辑时间间隔。

交互要求：

- 输入框仅允许非负数字，单位固定为自然日。
- 用户输入负数、空值或非法字符时，系统应按 0 处理或提示校验错误，不能提交负数。
- 时间间隔保存为整数自然日；如输入小数，系统应按产品统一规则转换为整数，并在前端展示转换后的值。
- 用户修改时间间隔后，系统立即保存当前项目该规则的间隔配置。
- 保存成功后，页面保留新值，并以新值参与后续任务生成和求解。

### 4.5 编辑即保存

本页面采用编辑即保存。

保存要求：

- 每次修改逻辑关系或时间间隔后，系统应保存当前项目对应规则配置。
- 保存操作只影响当前项目，不影响系统默认模板和其他项目。
- 保存过程中应避免用户误以为旧任务视图已经自动更新。
- 保存成功后，应将已生成任务视图、求解结果和方案对比结果标记为失效。
- 保存失败时，应展示错误信息，不允许静默失败。
- 若用户连续快速编辑，系统可做防抖或合并提交，但最终服务端项目配置必须与页面最新值一致。

### 4.6 只读项

本期以下内容只读：

- 规则名称。
- 规则来源。
- 适用结构物。
- 前置工序。
- 匹配规则。
- 使用范围。
- 规则说明。

如需新增、删除规则或调整匹配策略，应作为后续规则库管理能力建设。

## 5. 前后端能力

### 5.1 查询能力

后端应支持查询当前项目工艺逻辑配置。

查询返回应满足：

- 包含下部结构规则配置。
- 包含桥梁上部规则配置。
- 包含规则稳定 ID、逻辑关系、时间间隔、严重级别和说明。
- 对缺失规则具备补全能力，确保项目配置能随系统规则模板升级获得新增规则的默认配置。
- 返回数据应经过标准化处理，保证前端可以直接渲染。

### 5.2 初始化能力

后端应支持项目级初始化。

初始化规则：

- 新项目没有项目级工艺逻辑配置时，从系统默认规则模板初始化。
- 初始化后形成项目级配置副本。
- 后续用户修改只写入项目级配置。
- 系统默认模板升级时，新增规则可按默认值补入项目配置；已被用户修改的规则不得被覆盖。

### 5.3 保存能力

后端应支持保存用户修改后的项目级工艺逻辑配置。

保存规则：

- 仅允许保存可编辑字段：`relationship`、`lag_days`，以及必要的项目级配置元数据。
- 后端应校验 `relationship` 是否属于 `FS`、`SS`、`FF`、`SF`。
- 后端应校验 `lag_days` 大于等于 0。
- 后端应校验规则 ID 存在于系统可识别规则集中。
- 保存成功后返回标准化后的项目级规则配置。
- 保存失败时返回明确错误原因，便于前端提示用户。

### 5.4 前端职责

前端应负责：

- 渲染规则配置表。
- 展示规则统计、来源标签、使用范围和只读说明。
- 处理逻辑关系和时间间隔编辑。
- 触发编辑即保存。
- 根据后端返回结果刷新当前规则值。
- 在规则变化后标记旧任务视图、求解结果和方案对比结果失效。
- 展示保存失败、校验失败等错误提示。

### 5.5 后端职责

后端应负责：

- 维护系统默认规则模板。
- 初始化项目级工艺逻辑配置。
- 查询和保存项目级配置。
- 校验规则字段合法性。
- 根据项目结构和规则配置生成 `PrecedenceLink`。
- 将 `PrecedenceLink` 提供给任务生成、排程求解、校验诊断和规则追踪。

## 6. 联动规则

### 6.1 上游输入

本模块依赖以下上游输入：

- 项目桥梁、工区、幅别、墩台和构件清单。
- 下部结构构件是否启用。
- 上部结构类型、跨号、支座范围、连续梁分组、主墩配置和合龙顺序。
- 任务生成所需的工艺工效库。

当上游结构参数变化时，系统应重新计算每条规则的使用范围。

### 6.2 下部结构规则生成

下部结构规则用于同一墩台内任务关系生成。

生成规则：

- 系统按结构物分组查找任务。
- 当规则的 `structure_type` 不为空时，仅匹配对应结构类型。
- 当结构物中不存在 `to_component` 对应任务时，该规则对该结构物不生效。
- `all` 策略应将候选前置工序中存在的任务全部作为前置。
- `first_available` 策略应按候选前置工序顺序查找，使用第一个存在的前置工序。
- 若存在后续任务但找不到前置任务，系统应输出诊断信息。

### 6.3 桥梁上部规则生成

桥梁上部规则用于上部现场任务与下部完成任务、上部内部任务之间的关系生成。

生成规则：

- 现浇箱梁任务应以前跨组覆盖范围内墩台完成任务为前置。
- 连续梁0号块任务应以对应主墩完成任务为前置。
- 连续梁边跨连续段应以对应边跨墩台完成任务为前置。
- 同一 T 构内，0号块和标准段应按顺序生成前后置关系。
- 边跨合龙段应以边跨连续段和相邻 T 构完成为前置。
- 中跨合龙段应以相邻两个 T 构完成为前置。
- 中跨合龙默认等待左右边跨合龙段完成。
- 多个中跨合龙段应按配置顺序推进。

### 6.4 结果失效规则

用户修改任意规则的逻辑关系或时间间隔后：

- 当前已生成任务视图应失效。
- 当前求解结果应失效。
- 当前方案对比结果应失效。
- 用户需要重新生成任务视图或重新求解，才能看到规则修改后的结果。
- 页面应明确提示“修改后重新生成任务视图”。

### 6.5 求解约束

任务生成得到的 `PrecedenceLink` 应进入排程求解。

求解时应满足：

- 关系类型按 `relationship` 执行。
- 时间间隔按 `lag_days` 执行。
- `severity = error` 的规则为必须满足的硬约束。
- 求解结果诊断应能提示工艺逻辑是否满足。
- 当工艺逻辑导致不可行时，系统应给出可理解的诊断信息。

## 7. 校验与异常处理

### 7.1 字段校验

| 场景 | 校验规则 |
| --- | --- |
| 逻辑关系为空 | 不允许保存，提示用户选择逻辑关系 |
| 逻辑关系不在枚举内 | 不允许保存，提示逻辑关系不合法 |
| 时间间隔为空 | 按 0 处理或提示必填 |
| 时间间隔为负数 | 按 0 处理或提示不能小于 0 |
| 时间间隔为非法字符 | 不允许保存，提示请输入自然日数字 |
| 规则 ID 不存在 | 不允许保存，提示规则不存在或已被系统更新 |

### 7.2 保存异常

| 场景 | 产品提示 |
| --- | --- |
| 保存失败 | 工艺逻辑配置保存失败，请稍后重试 |
| 网络异常 | 网络异常，当前修改尚未确认保存 |
| 服务端校验失败 | 工艺逻辑配置不合法，请检查后重试 |
| 项目无权限 | 当前账号无权修改该项目工艺逻辑配置 |

### 7.3 生成异常

| 场景 | 处理方式 |
| --- | --- |
| 后续任务存在但前置任务不存在 | 生成诊断提示，说明对应结构物和规则 |
| 规则匹配不到任何对象 | 页面展示“当前无适用对象”，不作为错误 |
| 工艺逻辑形成不可满足约束 | 求解结果返回不可行，并提示检查工艺逻辑 |
| 上部结构缺少主墩或跨组信息 | 不生成对应上部规则关系，并输出诊断提示 |

## 8. 验收标准

### 8.1 页面展示验收

- 进入页面后，能看到“工艺逻辑约束”标题和对应副标题。
- 规则配置区能展示规则总数、当前适用规则数和暂未适用规则数。
- 表格列完整展示：规则名称、适用结构物、前置工序、匹配规则、逻辑关系、时间间隔、使用范围、规则说明。
- 下部结构规则展示“下部结构”标签。
- 桥梁上部规则展示“桥梁上部”标签。

### 8.2 默认规则验收

- 新项目初始化后，应包含 6 条下部结构默认规则。
- 新项目初始化后，应包含 8 条桥梁上部默认规则。
- 默认逻辑关系均为 `FS`。
- 下部结构默认时间间隔分别为 3、2、5、0、3、5 自然日。
- 桥梁上部默认时间间隔均为 0 自然日。

### 8.3 编辑保存验收

- 修改任意规则的逻辑关系后，系统立即保存当前项目配置。
- 修改任意规则的时间间隔后，系统立即保存当前项目配置。
- 刷新页面后，已保存的逻辑关系和时间间隔仍然保留。
- 修改当前项目规则不会影响其他项目。
- 保存失败时，页面出现明确错误提示，不静默丢失用户操作。
- 输入非法或负数时间间隔时，系统按 0 处理或提示校验错误，不允许保存负数。

### 8.4 联动验收

- 修改规则后，已生成任务视图失效。
- 修改规则后，已求解结果失效。
- 修改规则后，方案对比结果失效。
- 重新生成任务后，`PrecedenceLink` 使用最新 `relationship` 和 `lag_days`。
- 重新求解后，排程结果满足最新工艺逻辑约束。

### 8.5 诊断验收

- 当前项目中规则没有适用对象时，页面展示“当前无适用对象”。
- 生成任务时找不到前置任务，应返回诊断提示。
- 工艺逻辑不可满足时，求解结果应返回不可行或诊断说明。

## 9. 后续扩展建议

- 支持在页面新增、删除和禁用工艺逻辑规则。
- 支持编辑规则名称、适用结构物、前置工序和匹配规则。
- 支持跨结构物顺序规则配置，例如同一工区内相邻墩台按顺序施工。
- 支持规则模板版本管理，项目可选择同步系统模板新增规则。
- 支持按桥梁、工区、幅别、结构类型筛选规则。
- 支持工艺逻辑影响预览，在保存前展示预计影响的任务数量。
- 支持规则冲突检测，提前发现闭环、不可满足约束和缺失前置任务。
