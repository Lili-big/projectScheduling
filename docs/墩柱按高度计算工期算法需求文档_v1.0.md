# 墩柱按高度计算工期算法需求文档

版本：v1.0

日期：2026-06-25

适用范围：桥梁施工自动排程系统的工艺工法库、工期计算、任务视图和求解前任务生成链路

面向对象：产品、后端研发、前端研发、测试、计划工程师

## 1. 需求背景

当前研发实现墩柱工期时，只覆盖了“单根墩柱固定工期”的模式，例如整体式浇筑按“20 天/个”直接生成任务工期。

实际桥梁排程中，爬模、滑模、翻模等墩柱施工工艺通常不是按单根固定天数计算，而是先根据墩柱高度换算施工节数，再按单节工效计算工期。若系统仍按固定工期处理，会导致高墩和低墩工期相同，后续资源排队、关键节点判断和固定资源最短工期结果失真。

本需求用于指导研发在已实现固定工期模式的基础上，补充墩柱按高度计算工期的算法，并同步更新施工工艺及工效库、任务生成、任务视图、保存校验的相关口径。

## 2. 需求目标

系统应支持同一类墩柱构件根据所选施工工艺和工效分组，使用不同工期算法：


| 场景                       | 目标行为                           |
| -------------------------- | ---------------------------------- |
| 整体式浇筑等固定工期工艺   | 继续按单根墩柱固定天数计算         |
| 爬模、滑模、翻模等分节工艺 | 按墩柱高度、标准节高和单节工效计算 |
| 分节工艺切换为按日完成量   | 按墩柱高度和每日完成米数计算       |

计算结果应进入 `duration_days`，并作为后续任务视图展示、工艺逻辑生成、资源约束求解、里程碑诊断和方案对比的统一工期来源。

## 3. 适用范围

本需求覆盖：

- 施工工艺及工效库中墩柱工艺模板和工效分组。
- 墩柱任务生成时的工程量来源、工效匹配和工期计算。
- 任务视图中的工程量、工期和工期计算表达式展示。
- 工艺工效库保存、刷新、历史默认值升级和校验。

本需求不覆盖：

- 新增完整结构物主数据录入页面。
- 新增整条施工工艺模板的前端创建和删除能力。
- 按地层、桥型、墩高区间自动推荐工效分组。
- 将多根墩柱拆成多条独立可排程任务；本期仍沿用当前墩柱任务颗粒度。

## 4. 规则 / 数据定义

### 4.1 构件和字段口径


| 业务概念    | 系统字段或口径                    | 说明                                                  |
| ----------- | --------------------------------- | ----------------------------------------------------- |
| 墩柱 / 墩身 | `component_type = pier_body`      | 页面可展示“墩柱”或“墩身”，代码口径保持`pier_body` |
| 墩柱高度    | `quantity_source = pier_height_m` | 用于按高度或分节计算工期                              |
| 工期算法    | `duration_method`                 | 支持`fixed_days`、`days_per_unit`、`units_per_day`    |
| 工效值      | `productivity_value`              | 固定天数、单节耗时或每日完成量，取决于工效单位        |
| 工效单位    | `productivity_unit`               | 墩柱本期重点支持`天/个`、`天/节`、`m/天`              |
| 标准节高    | `standard_section_height_m`       | 单节高度，单位为 m/节，仅`天/节` 模式需要             |

### 4.2 墩柱工期模式


| 模式       | 适用工艺示例         | 算法字段        | 工程量来源      | 工效单位 | 公式                                         |
| ---------- | -------------------- | --------------- | --------------- | -------- | -------------------------------------------- |
| 固定工期   | 整体式浇筑           | `fixed_days`    | `count`         | `天/个`  | `ceil(工效值)`                               |
| 按高度分节 | 爬模、滑模、翻模     | `days_per_unit` | `pier_height_m` | `天/节`  | `ceil(ceil(墩柱高度 / 标准节高) * 单节工效)` |
| 按日完成量 | 爬模、滑模、翻模可选 | `units_per_day` | `pier_height_m` | `m/天`   | `ceil(墩柱高度 / 日完成米数)`                |

通用规则：

- 工期计算结果最小为 1 天。
- 所有除法类计算均向上取整。
- `productivity_value` 必须大于 0。
- `standard_section_height_m` 在 `天/节` 模式下必须大于 0。
- 当单位为 `m/天` 时，不使用 `standard_section_height_m`。

### 4.3 默认工艺数据

工艺工法库应至少包含以下墩柱工艺，并用于项目或方案初始化：


| 构件 | 工艺       | 方法 ID            | 默认工效 | 单位    | 算法            | 工程量来源      | 默认单节高度 | 默认资源 |
| ---- | ---------- | ------------------ | -------- | ------- | --------------- | --------------- | ------------ | -------- |
| 墩柱 | 爬模施工   | `climbing_form`    | 7        | `天/节` | `days_per_unit` | `pier_height_m` | 4.5m         | 墩柱模板 |
| 墩柱 | 滑模施工   | `sliding_form`     | 6        | `天/节` | `days_per_unit` | `pier_height_m` | 4.5m         | 墩柱模板 |
| 墩柱 | 翻模施工   | `turnover_form`    | 12       | `天/节` | `days_per_unit` | `pier_height_m` | 4.5m         | 墩柱模板 |
| 墩柱 | 整体式浇筑 | `integral_casting` | 20       | `天/个` | `fixed_days`    | `count`         | -            | 墩柱模板 |

默认规则：

- 爬模、滑模、翻模应被识别为墩柱分节施工工艺。
- 墩柱分节施工工艺的工效分组若使用 `天/节`，应默认补齐 `standard_section_height_m = 4.5`。
- 若旧配置中爬模、滑模、翻模仍保存为 `fixed_days + count + 天/节`，系统应按默认迁移规则升级为 `days_per_unit + pier_height_m + 天/节 + standard_section_height_m`。
- 整体式浇筑继续保留固定工期，不应被自动改为按高度分节计算。

### 4.4 墩柱高度取值

任务生成时，`pier_height_m` 应优先使用结构参数中的单根墩柱高度：

1. 构件属性中的高度字段，如 `height_m`、`heightM`。
2. 构件 `dimensions_m` 中的 `heightM`。
3. 无明确高度字段时，才使用构件 `quantity`。

若导入数据同时存在墩柱根数和单根高度，按高度计算工期时应使用单根高度，不应将“根数 × 高度”作为单根墩柱高度重复放大工期。

示例：


| 输入数据                                  | 按高度计算使用的墩柱高度 | 说明               |
| ----------------------------------------- | ------------------------ | ------------------ |
| 高度 9.2m，数量 1 根                      | 9.2m                     | 正常单根高度       |
| 高度 9.2m，数量 2 根，构件数量字段为 18.4 | 9.2m                     | 优先取单根高度字段 |
| 仅有`quantity = 9.2`，无高度属性          | 9.2m                     | 使用数量兜底       |

## 5. 页面交互 / 用户流程

### 5.1 工艺工效库页面

施工工艺及工效库中，墩柱分节施工工艺应支持以下交互：


| 用户操作                     | 系统行为                                                                                         |
| ---------------------------- | ------------------------------------------------------------------------------------------------ |
| 查看爬模、滑模、翻模工效分组 | 单位可选择`天/节` 或 `m/天`                                                                      |
| 选择`天/节`                  | 自动设置`duration_method = days_per_unit`、`quantity_source = pier_height_m`，展示标准节高输入框 |
| 选择`m/天`                   | 自动设置`duration_method = units_per_day`、`quantity_source = pier_height_m`，不展示标准节高     |
| 编辑标准节高                 | 保存到当前工效分组的`standard_section_height_m`                                                  |
| 新增工效分组                 | 复制当前默认分组的算法、工程量来源、工效值、单位和标准节高                                       |
| 删除默认分组                 | 若仍有其他分组，系统自动将剩余第一条设为默认                                                     |
| 设为默认分组                 | 工艺模板上的默认字段同步为该分组字段                                                             |

标准节高输入要求：

- 默认值为 4.5。
- 允许小数。
- 最小值大于 0；页面建议最小输入限制为 0.1。
- 单位展示为 `m/节`。

### 5.2 任务视图页面

任务视图生成或刷新任务图后，应展示墩柱任务的计算结果：


| 字段     | 展示要求                                             |
| -------- | ---------------------------------------------------- |
| 工艺     | 展示当前墩柱选用工艺，如爬模施工、整体式浇筑         |
| 工效     | 展示当前工效分组，分节工艺需能体现工效值和标准节高   |
| 工程量   | 按当前工效分组的工程量来源展示，按高度时展示墩柱高度 |
| 工期     | 展示计算后的`duration_days`                          |
| 工期计算 | 展示可读表达式，说明高度、节高、节数、工效和结果     |

表达式示例：


| 场景                        | 展示表达式                                      |
| --------------------------- | ----------------------------------------------- |
| 9.2m 墩柱，4.5m/节，7 天/节 | `墩高 9.2m / 4.5m/节 = 3节；3 × 7天/节 = 21天` |
| 9.2m 墩柱，2m/天            | `墩高 9.2m / 2m/天 = 5天`                       |
| 整体式浇筑 20 天/个         | `20天/个 = 20天`                                |

用户在任务视图切换墩柱工艺或工效分组后，系统应重新计算该任务的工程量、工期、资源类型和工期计算表达式。

## 6. 前后端职责

### 6.1 后端职责

后端需保证：

- 工艺工法库默认数据包含墩柱分节施工工艺和标准节高。
- 保存或加载工艺工法库时，校验并归一化墩柱分节工艺的单位、算法、工程量来源和标准节高。
- 任务生成时，根据构件 `method_id`、`productivity_option_id` 和默认工效分组选择实际工期规则。
- 计算 `pier_height_m` 时优先使用单根墩柱高度字段。
- `duration_days` 使用统一算法计算，供 CP-SAT 求解和里程碑诊断直接消费。
- 对缺少墩柱高度、工效值或标准节高的场景输出明确诊断，不静默使用错误结果。

### 6.2 前端职责

前端需保证：

- 工艺工效库页面对墩柱分节工艺展示单位选择和标准节高输入。
- 单位切换时同步更新工期算法、工程量来源和标准节高字段。
- 工效分组新增、删除、设默认时保持默认字段一致。
- 任务视图中切换工艺或工效后，前端临时预览计算结果与后端重新生成结果口径一致。
- 修改工艺工效库、任务工艺或工效分组后，旧任务图、旧求解结果和旧方案对比结果标记为失效。

### 6.3 Netlify 镜像职责

如项目继续保留 Netlify 函数作为部署镜像或演示后端，则 Netlify 实现需同步：

- 默认墩柱工艺数据。
- 墩柱分节工艺的单位归一化规则。
- `天/节` 的分节工期公式。
- `m/天` 的按日完成量公式。
- 墩柱高度取值优先级。

同一 `ScenarioInput` 在本地后端和 Netlify 镜像中应得到一致的墩柱任务 `quantity`、`quantity_label` 和 `duration_days`。

## 7. 异常处理


| 异常场景                     | 系统处理                                                   |
| ---------------------------- | ---------------------------------------------------------- |
| `天/节` 模式缺少标准节高     | 使用默认 4.5m/节补齐；若仍无法补齐，则生成错误诊断         |
| 标准节高小于等于 0           | 不允许保存或生成可用任务，提示标准节高必须大于 0           |
| 工效值小于等于 0             | 不允许保存或生成可用任务，提示工效值必须大于 0             |
| 墩柱高度缺失或小于等于 0     | 任务生成时提示构件缺少有效墩柱高度                         |
| 墩柱工艺单位无法识别         | 保留原有配置，但不自动按分节计算；生成诊断提示复核工效单位 |
| 旧配置中存在多个默认工效分组 | 仅保留第一条默认分组，其余取消默认                         |
| 旧配置中无默认工效分组       | 将第一条工效分组设为默认                                   |

## 8. 验收标准

### 8.1 工艺工法库验收

- 默认工艺库中存在爬模施工、滑模施工、翻模施工和整体式浇筑。
- 爬模施工默认值为 7 天/节，`duration_method = days_per_unit`，`quantity_source = pier_height_m`，`standard_section_height_m = 4.5`。
- 滑模施工默认值为 6 天/节，`duration_method = days_per_unit`，`quantity_source = pier_height_m`，`standard_section_height_m = 4.5`。
- 翻模施工默认值为 12 天/节，`duration_method = days_per_unit`，`quantity_source = pier_height_m`，`standard_section_height_m = 4.5`。
- 整体式浇筑仍为 20 天/个，`duration_method = fixed_days`，`quantity_source = count`。
- 保存并刷新工艺工法库后，墩柱工效分组的单位、工效值、默认分组和标准节高保持不变。

### 8.2 工期计算验收


| 测试场景                                     | 期望结果                           |
| -------------------------------------------- | ---------------------------------- |
| 墩柱高度 9.2m，单节高度 4.5m，爬模 7 天/节   | 节数为 3，工期为 21 天             |
| 墩柱高度 9.2m，单节高度改为 3m，爬模 7 天/节 | 节数为 4，工期为 28 天             |
| 墩柱高度 9.2m，工效切换为 2m/天              | 工期为 5 天                        |
| 整体式浇筑 20 天/个，墩柱高度 9.2m           | 工期仍为 20 天                     |
| 墩柱高度 0 或缺失                            | 生成错误或警告诊断，不输出可信工期 |

### 8.3 任务视图验收

- 生成任务视图后，墩柱任务展示当前工艺、工效分组、工程量、工期和工期计算表达式。
- 分节工艺表达式能展示“墩高 / 标准节高 = 节数；节数 × 单节工效 = 工期”。
- 用户切换墩柱工艺后，系统自动使用新工艺的默认工效分组重新计算。
- 用户切换墩柱工效分组后，工程量口径、工期和表达式同步变化。
- 修改工艺工效库、任务工艺或工效分组后，旧求解结果不得继续作为当前有效结果展示。

## 9. 研发联动清单

研发实现时至少需检查以下位置是否已补齐，避免只在单点实现公式：


| 联动位置              | 需要确认的内容                                                      |
| --------------------- | ------------------------------------------------------------------- |
| 工艺工法库默认数据    | 墩柱分节工艺、默认工效、默认单节高度是否初始化正确                  |
| 工艺工效库保存 / 加载 | 是否保留并校验`productivity_options` 和 `standard_section_height_m` |
| 工效单位归一化        | `天/节`、`m/天` 是否自动映射到正确算法和工程量来源                  |
| 任务生成              | 是否按构件工艺和工效分组生成`duration_days`                         |
| 墩柱高度取值          | 是否优先取单根高度而不是根数乘高度                                  |
| 任务视图              | 是否展示准确工程量、工期和计算表达式                                |
| 结果失效              | 工艺、工效、节高变更后是否要求重新生成任务或重新求解                |
