# 04 · Demo 实现

## 目的

维护路面及桥梁施工排程 Demo 的后端、前端、运行入口、样例、部署配置和独立展示工具。

页面默认进入路面：导入主数据并确认版本 → 配置三类工效、逐层工序条件和机组 → 生成任务 → 固定机组求解。桥梁入口为 `?engineering_domain=bridge`；路面按 `project_id` 保存独立配置，新项目保持待导入空态。

按施工长度（m）及m/天工效排程时，厚度不参与任务生成或求解校验，可留空；未知厚度/密度的吨位仍显示“—”。m2/m3/t计量沿用原厚度校验。启用工序后仍须配置适用机组、数量和转场条件。

支持碎石、水稳、沥青工艺，层间养生通过FS+N维护，不计末尾养生；支持共享机组、配套步骤和实际相邻转场，配套资源按充足考虑，不含天气/温度优化。待移交段纳入任务，严格排在正常段所有任务完成后；可行结果显示需移交日、预计施工完成日及移交前提，不回写真实移交状态。当前客户25段100层，其中4段附条件排程。

固定机组求解采用三种贪心初解＋CP-SAT限时优化，最多8worker（按CPU适配）、seed0、内置LNS，缺省15秒为构造/建模/优化共用预算。页面立即显示合法初解，通过`POST /api/solve-scenario/stream`的NDJSON更新当前最好完整方案，到时保留最好结果；未证明最优则FEASIBLE，无方案才可能UNKNOWN。输入变化和断连取消旧求解，历史/中断结果明确标识；旧同步接口和桥梁行为保持兼容，演示镜像仍不支持路面求解。

结果页支持施工段/工序两级表格与横道：施工段可折叠，仅工序画作业条，工序逻辑箭线可开关；点击工序可查看FS/SS/FF/SF及实际工艺等待。“机组作业与空闲”位于计划图和机组施工顺序之间，每套实际机组一行，共用日期轴；可筛选、查看区间详情、汇总作业/转场/期间空闲并定位最长空闲。期间作业率=作业天数÷首次开工至末次完工天数，期外不计空闲，养生不直接占机组，信息不足时不输出确定空闲结论；不自动判断窝工原因。见[071验证指南](../03-requirements/specs/071-pavement-resource-timeline/quickstart.md)。

“机组施工顺序”采用施工段分格的顺序示意图：左右幅分别按里程递增排列等宽施工段，节点编号和箭头代表实际到访先后，全部编号配工序简名。同段回访向外另起节点；不同施工段的纵向位置、段宽及间距均不表示真实时间或距离。图中不画日期刻度或时间横道，实际日期及转场仍在详情；支持全程/仅当前前后、节点间距和键盘导航。跨幅连线沿分格边界经过中央通道，避免遮挡段名；未知位置仍单列且不跳连。见[072实施记录](../03-requirements/specs/072-pavement-crew-tl-flow/tasks.md)。

求解中的“已等待”为客户端计时，实际计算耗时仍见折叠详情。待移交列“本方案最晚需移交日”要求该日开工前移交，实际日期仍待确认。见[070操作验证](../03-requirements/specs/070-pavement-results-visualization/quickstart.md)。

100任务15秒实测324→310天，缩短14天，计算耗时15.051秒；独立HTTP验收首解0.341秒到达、最终311天，页面验收最终310天。并行搜索有波动，这些都是可行方案，未接入专项下界或证明最优。启动见[根README](../README.md)，验证与限制见[069验收指南](../03-requirements/specs/069-pavement-live-optimization/quickstart.md)及[实施证据](../03-requirements/specs/069-pavement-live-optimization/tasks.md)。
