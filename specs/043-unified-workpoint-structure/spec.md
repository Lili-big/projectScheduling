# 功能规格：统一工点与结构物主数据

**功能目录/分支**：`043-unified-workpoint-structure`

**创建日期**：2026-07-16

**状态**：草稿

**输入**：用户要求放弃历史桥梁结构导入与架梁工点导入的分离交互，统一按照“工点 → 结构物 → 构件参数”维护项目主数据，通过统一 Excel 全量快照导入并进行结构化持久化；一座桥梁、一段路基或一座隧道只维护为一个工点，桥梁结构物区分左右幅；工点类型全面覆盖，但本期排程算法只处理桥梁；采用本地单机结构化存储，不迁移旧数据，只参考旧数据结构和排程映射实现。

## 来源与评审上下文（必填）

- **来源文档**：`AGENTS.md`、`agent.md`、`README.md`、`.specify/memory/constitution.md`、`docs/项目排程系统整体说明_v1.1.md`、`docs/任务视图页面需求文档_v1.0.md`、`specs/041-girder-scheduling-integration/spec.md`、`specs/041-girder-scheduling-integration/data-model.md`，以及当前共享契约、项目结构参数、工点导入、版本仓储和任务生成代码事实。
- **评审结论**：用户已确认采用统一工点主数据、统一 Excel 全量快照、版本确认和本地关系型结构化持久化方案；旧导入交互和旧存储数据不迁移。该变更涉及共享模型、数据导入、持久化、前端维护入口和桥梁排程输入，必须进入完整 Spec Kit 门禁。
- **使用的 Demo/代码事实**：当前 `ProjectModel.bridges` 保存桥梁详细结构，`ProjectDataVersion.workpoints` 另存架梁路线工点；结构参数还存在独立本地 JSON 读写入口，计划管控与项目版本主要写入本地 JSON 仓储；当前页面启动和任务页面仍依赖历史桥梁 Excel 导入；任务生成按桥梁、工区、结构物、构件和上部结构遍历。现状存在两套工点语义、两套导入入口和多处分散持久化边界。
- **不在范围内**：不兼容历史 Excel 模板和历史导入交互；不迁移 `.local-data` 中已有项目、结构或工点数据；不长期双写旧 JSON 和新主数据存储；不在本期为路基、隧道、涵洞、互通、场站、便道等非桥梁工点生成排程任务；不把梁场、架桥机、路线顺序、通行条件和实绩纳入工点主数据；不提供完整的页面逐字段手工录入；不改变现有桥梁排程算法的目标函数、硬约束、软约束、工期规则和资源规则。

## 用户场景与测试（必填）

### 用户故事 1 - 导入统一工点与结构物主数据（优先级：P1）

计划工程师在当前项目中下载统一模板，按工点、结构物和构件参数填写完整项目快照并导入。系统校验层级关系、稳定标识、左右幅、工程量和必填参数，形成可检查的导入草稿，而不是分别导入桥梁结构和架梁工点。

**优先级理由**：统一输入是消除两套工点语义和重复映射的前提，也是后续版本管理、排程和项目数据复用的唯一入口。

**独立测试**：导入一个同时包含桥梁、路基、隧道、涵洞、互通、场站和便道工点的工作簿，其中桥梁包含左右幅墩台、梁跨、连续梁联及构件参数；验证系统形成一个统一层级、保留全部合法对象并准确报告非法行。

**验收场景**：

1. **假设** 工作簿包含一座左右幅桥梁，**当** 用户导入数据，**则** 系统只创建一个桥梁工点，并将左右幅信息保存在该工点下的结构物属性中。
2. **假设** 结构物和构件都引用有效父级标识，**当** 导入完成，**则** 工点、结构物、构件数量及层级关系与工作簿一致。
3. **假设** 某结构物引用不存在的工点，**当** 系统校验导入，**则** 系统定位到工作表、行号和字段，阻止该草稿被确认，且当前有效版本不受影响。
4. **假设** 同一项目中存在重复稳定标识，**当** 系统校验导入，**则** 系统报告重复对象并阻止确认，不按名称或导入顺序静默覆盖。
5. **假设** 用户已经上传并形成阻断批次或可确认草稿，**当** 用户取消该批次，**则** 系统保留批次、问题和取消审计，清理未确认草稿业务数据，当前确认版本不受影响。

---

### 用户故事 2 - 检查差异并确认项目主数据版本（优先级：P1）

计划工程师可以查看导入草稿相对于当前确认版本的新增、修改和删除差异，解决阻断问题后确认新版本。确认版本成为后续方案共享的稳定项目主数据，且不能被原地修改。

**优先级理由**：全量快照只有结合差异预览和不可变版本，才能避免漏行导致静默删除，并保证排程输入可追溯。

**独立测试**：先确认一个项目版本，再导入包含新增工点、修改结构参数和缺失历史结构物的新快照；验证差异分类、删除提示、阻断规则、版本递增和确认后只读语义。

**验收场景**：

1. **假设** 新快照缺少上一确认版本中的结构物，**当** 用户查看导入结果，**则** 系统将其列为待删除差异，未经确认不得从当前有效版本中消失。
2. **假设** 草稿不存在阻断问题，**当** 用户确认版本，**则** 新版本成为当前有效主数据，原确认版本保留可查询且不可被改写。
3. **假设** 草稿仍有父级缺失、重复标识或桥梁幅别非法等阻断问题，**当** 用户尝试确认，**则** 系统拒绝确认并说明受影响对象。
4. **假设** 相同内容被重复导入，**当** 用户再次提交，**则** 系统保存新的 `unchanged` 导入批次并引用已有相同版本，但不创建重复业务版本。

### 用户故事 3 - 统一查看工点和结构物（优先级：P1）

计划工程师在统一的项目主数据页面先查看工点清单，再查看选中工点下的结构物、左右幅和构件参数，并可切换草稿、当前确认版本和历史版本进行核对。

**优先级理由**：统一数据如果仍分散展示，用户无法确认系统是否真正消除了两套工点和结构物维护方式。

**独立测试**：使用包含多类工点和左右幅桥梁的确认版本，验证用户能从单一入口定位任意工点、结构物和构件，且无需进入任务视图或架梁专项导入页。

**验收场景**：

1. **假设** 当前项目存在多种工点，**当** 用户进入项目主数据页面，**则** 页面按稳定顺序展示全部工点及类型、里程和版本状态。
2. **假设** 用户选择一个桥梁工点，**当** 查看结构物明细，**则** 可以区分左幅、右幅和共用结构，并查看墩台、梁跨、连续梁联及构件参数。
3. **假设** 用户选择非桥梁工点，**当** 查看该工点，**则** 系统展示其基础信息和已导入结构物，同时明确当前排程算法暂不处理该工点类型。

---

### 用户故事 4 - 使用统一主数据生成桥梁排程输入（优先级：P1）

计划工程师确认项目主数据后，桥梁排程从当前确认版本读取桥梁工点及其结构物，不再依赖根目录样例 Excel、独立结构参数 JSON 或另行维护的桥梁对象；非桥梁工点保持可见但不进入本期任务生成。

**优先级理由**：统一维护只有真正成为排程输入的唯一来源，才能解决当前数据混乱，而不是再增加一层旁路数据。

**独立测试**：将一个包含桥台、桥墩、简支梁跨、现浇箱梁联和连续梁联的确认版本转换为排程输入，核对任务所属工点、幅别、工区、结构物、构件、工程量和稳定引用，并与既有桥梁任务生成业务不变量比较。

**验收场景**：

1. **假设** 当前确认版本包含合法桥梁结构，**当** 用户生成任务图，**则** 系统使用该版本生成桥梁任务，结构层级和左右幅不丢失。
2. **假设** 当前确认版本同时包含非桥梁工点，**当** 用户生成桥梁任务图，**则** 非桥梁工点不会被误生成桥梁任务，并产生明确的范围说明而非错误。
3. **假设** 当前主数据版本发生变化，**当** 新版本被确认，**则** 基于旧版本的任务图、求解结果、方案比较和计划引用被标记为失效，必须重新生成或重新计算。
4. **假设** 项目没有确认版本，**当** 用户尝试进入正式任务生成或求解，**则** 系统阻止操作并引导用户先完成主数据导入和确认。

### 边界与异常场景

- 一座桥梁、一段路基或一座隧道只对应一个工点；左右幅属于结构物属性，不能通过重复工点表达。
- 桥梁结构物正式数据的幅别必须为左幅、右幅或共用；不适用幅别只允许非桥梁对象或确实无幅别语义的结构物。
- 工点里程起点不得大于终点；展示长度由起止里程计算，导入文件中的长度值仅用于核对，不得成为冲突的第二权威值。
- 工点类型必须能够覆盖桥梁、路基、隧道、涵洞、互通、服务区、场站、便道和其他类型，并允许后续扩展而不破坏已有版本。
- 结构物和构件类型必须保留桥梁排程所需的墩台、梁跨、联、桩基、承台、系梁、墩身、盖梁和上部结构参数；不能把联跨表达式压平为名称或备注。
- 导入过程中发生文件损坏、工作表缺失、字段类型错误、父级缺失或重复提交时，当前确认版本不得发生半更新。
- 新版本中删除仍被方案、计划或实绩引用的对象时，必须形成阻断问题或明确的引用处置结果，不能静默形成悬空引用。
- 服务重启、异常退出或重复提交后，草稿版本、确认版本、导入批次、差异和问题记录必须能够恢复且保持一致。
- 旧数据不迁移；首次启用新能力时，项目没有当前确认版本属于正常空态，用户必须使用新模板创建首个版本。
- 旧数据结构和排程适配逻辑仅作为字段含义与业务规则参考，不形成旧格式兼容、旧数据读取或长期双写承诺。

## 需求（必填）

### 功能需求

- **FR-001**：系统必须将项目主数据统一组织为“项目主数据版本 → 工点 → 结构物 → 构件参数”的单一层级。
- **FR-002**：一座桥梁、一段路基或一座隧道必须只维护为一个工点，左右幅必须作为工点下结构物的属性表达。
- **FR-003**：系统必须为工点、结构物和构件提供项目内稳定标识；名称、排序或里程变化不得导致对象被误识别为新增对象。
- **FR-004**：系统必须支持桥梁、路基、隧道、涵洞、互通、服务区、场站、便道和其他工点类型，并允许后续扩展类型而保持历史版本可读。
- **FR-005**：结构物必须明确所属工点、结构类别、结构类型、幅别、稳定顺序和可选工区属性；构件必须明确所属结构物、构件类型、工程量、单位和结构参数。
- **FR-006**：桥梁结构物必须支持左幅、右幅和共用三种正式幅别语义；不适用幅别不得用于应区分左右幅的正式桥梁结构。
- **FR-007**：桥梁工点必须能够表达桥台、桥墩、简支梁跨、现浇梁联和连续梁/连续刚构联，并保留任务生成所需的下部构件、跨径、支座范围、联跨表达式、主墩和节段参数。
- **FR-008**：系统必须提供统一 Excel 模板，至少包含填写说明、工点信息、结构物信息和构件参数，并通过稳定标识建立父子关系。
- **FR-009**：每次导入必须被解释为当前项目的一份完整主数据快照，不支持按导入顺序静默追加或覆盖当前确认版本。
- **FR-010**：系统必须在导入后展示相对于当前确认版本的新增、修改和删除差异，缺失历史对象必须显示为待删除。
- **FR-011**：系统必须校验必填字段、稳定标识唯一性、父子关系、里程范围、幅别、类型、工程量和桥梁排程必需参数，并将问题定位到文件、工作表、行号和字段。
- **FR-012**：阻断问题未解决前，导入草稿不得转为确认版本；告警可以确认，但必须保留确认时可见的说明。
- **FR-013**：导入失败、校验失败或用户取消已上传批次/草稿时，当前确认版本不得被修改或部分覆盖；取消后必须保留批次审计并清理未确认草稿业务数据。
- **FR-014**：系统必须保存每次导入批次、文件身份、来源位置、校验问题、差异结果、`unchanged` 引用、取消记录和用户确认记录，以支持数据追溯。
- **FR-015**：系统必须以结构化方式持久保存工点、结构物、构件、版本、导入批次、差异和问题；服务重启后所有已保存状态必须可恢复。
- **FR-016**：核心通用字段必须以可查询、可约束的结构化属性保存；只有结构类型特有且无法统一的扩展参数可以作为扩展属性保存。
- **FR-017**：项目主数据版本必须支持草稿、已确认和已替代状态；已确认版本不得原地修改，后续变更必须创建新版本。
- **FR-018**：相同项目、相同内容的重复导入不得生成重复业务版本；每个项目同时只能有一个当前确认版本。
- **FR-019**：系统必须提供统一项目主数据页面，支持查看工点列表、工点基础信息、工点下结构物、结构物构件、导入问题、版本差异和历史版本。
- **FR-020**：统一项目主数据页面必须提供模板下载、完整快照导入、差异预览、草稿确认和当前确认版本导出能力。
- **FR-021**：旧的桥梁结构导入和架梁工点导入入口不得继续作为新主数据维护路径；新页面不得要求用户重复导入或手工建立两类数据映射。
- **FR-022**：梁场、架桥机、路线顺序、通行条件和架梁实绩必须继续归属于方案或实绩数据，只通过稳定工点和结构物引用关联主数据。
- **FR-023**：桥梁任务生成必须只读取当前确认主数据版本中的桥梁工点及结构物，并保持现有桥梁任务业务规则、工期计算和结构逻辑语义不变。
- **FR-024**：非桥梁工点必须能够导入、持久化和查看，但本期不得被误送入桥梁排程；系统必须明确标识其当前排程支持状态。
- **FR-025**：新主数据版本确认后，所有引用旧版本且受结构变化影响的任务图、求解结果、方案比较、计划和专项状态必须失效或要求重新校验。
- **FR-026**：首次启用新能力时，系统不得迁移或自动读取旧 JSON 项目结构、旧项目数据版本或旧导入结果；用户必须通过新模板创建首个主数据版本。
- **FR-027**：系统可以复用旧版本的数据字段、层级含义、稳定引用、版本状态和桥梁任务适配规则，但不得因此形成旧格式兼容、旧存储双写或旧交互保留要求。
- **FR-028**：用户必须能够在不打开原始 Excel 的情况下，从系统中查询当前确认版本的完整工点、结构物和构件数据及其来源。

### 关键实体（涉及数据时填写）

- **项目主数据版本**：某一时点完整的工点、结构物和构件快照，具有项目内递增版本号、状态、稳定指纹、创建与确认记录；确认后不可修改。
- **工点**：项目内独立管理的空间工程对象，包含稳定标识、名称、类型、起止里程、排序及来源；一座桥梁、一段路基或一座隧道只对应一个工点。
- **结构物**：工点下可独立识别、具有结构类型、幅别、位置和顺序、可承载构件并参与任务生成或进度归集的工程实体；桥墩、桥台、梁跨和联属于桥梁结构物。
- **构件参数**：结构物下承载工程量、单位、几何属性、工艺匹配所需参数和扩展属性的最小工程数据对象；桩基、承台、系梁、墩身、盖梁和连续梁节段属于典型构件或参数项。
- **工点类型**：工点的业务分类，首期覆盖桥梁、路基、隧道、涵洞、互通、服务区、场站、便道和其他，并支持未来新增分类。
- **导入批次**：一次完整 Excel 提交及其文件身份、解析状态、统计、来源、问题和目标草稿版本。
- **导入问题**：绑定到工作表、行号、字段和业务对象的校验结果，分为阻断问题和告警。
- **版本差异**：新草稿与当前确认版本之间的新增、修改和删除对象及字段变化，用于用户确认全量快照影响。
- **稳定业务引用**：方案、路线、计划和实绩引用工点或结构物的长期标识，不依赖名称、排序或当次生成的任务 ID。

## 成功标准（必填）

### 可衡量结果

- **SC-001**：计划工程师可以在一个页面和一次统一导入流程内完成项目工点与结构物维护，不需要进入两个导入入口或手工映射桥梁与工点。
- **SC-002**：对包含一座左右幅桥梁的验收样例，系统只保存一个桥梁工点，左右幅结构物归属正确率达到 100%，墩台、梁跨、联和构件参数无丢失。
- **SC-003**：合法工作簿导入后，工点、结构物、构件数量及父子关系与源文件一致率达到 100%；非法父级、重复标识和非法幅别的检出率达到 100%。
- **SC-004**：对包含新增、修改和删除的全量快照，差异分类正确率达到 100%，未经确认的删除对象不会影响当前有效版本。
- **SC-005**：服务重启后，已保存的导入批次、草稿、确认版本、结构化对象、差异和问题记录恢复率达到 100%。
- **SC-006**：已确认版本的原地修改成功次数为 0；每次有效变更都产生可追溯的新版本。
- **SC-007**：相同内容重复导入时，重复业务版本新增数量为 0。
- **SC-008**：桥梁验收样例从统一主数据生成的任务在所属工点、幅别、工区、结构物、构件、工程量和业务前后置关系上与现行有效规则一致率达到 100%。
- **SC-009**：非桥梁工点导入和查询成功率达到 100%，被误生成桥梁排程任务的数量为 0。
- **SC-010**：在包含不超过 500 个工点、10,000 个结构物和 50,000 个构件的参考项目中，用户提交导入后可在 30 秒内看到完整校验和差异结果，且页面保持可继续操作或查看进度。
- **SC-011**：随机抽查不少于 20 个工点及其结构物，用户能够从当前确认版本追溯到导入批次和源工作表位置，追溯成功率达到 100%。
- **SC-012**：新能力启用后，新主数据维护流程对旧结构导入、旧工点导入和旧 JSON 数据的运行时依赖数量为 0。

## 默认假设

- 当前目标是本地单机 Demo，采用本地结构化持久化；持久化技术和表结构在技术计划阶段确定，并为未来多用户存储保留仓储边界。
- 用户具备通过统一 Excel 模板维护完整项目快照的能力；首期页面以导入、查看、校验、差异确认和版本管理为主，不提供完整在线主数据编辑器。
- 当前页面上下文已经确定项目，统一工作簿不需要重复维护项目级基础信息。
- 工点起止里程为长度权威来源，长度为系统计算值；桥梁跨径等结构长度仍按结构物专业字段维护。
- 桥梁正式结构物使用左幅、右幅或共用；非桥梁对象可以使用不适用幅别。
- 工点类型全面覆盖指主数据可以导入、持久化和展示多类工点，不代表所有类型都在本期获得排程算法。
- 桥梁排程继续使用既有工艺、工效、逻辑、资源、里程碑和求解策略；本功能只改变主数据来源和适配方式。
- 旧数据不迁移，旧 Excel 不兼容，旧存储不双写；旧实现只用于核对字段含义、结构规则、稳定引用和桥梁任务生成不变量。
- 对外共享契约继续使用现有 `project_data_version_id` 引用新的项目主数据版本；主数据领域内部使用 `version_id`，不新增并列的 `project_master_version_id`。
- 现有参数助手作为独立辅助入口保留，但移除历史桥梁结构 Excel 导入职责，不承担工点和结构物主数据持久化。
