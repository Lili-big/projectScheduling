# 快速验证：任务结构物参数与工程量拆分

## 1. 前置条件

- 工作目录：仓库根目录。
- 使用当前本地桥梁样例或包含承台尺寸、墩柱形式/柱径/柱数/墩高和上部结构跨径的等价输入。
- 不需要新增依赖或修改 `.local.env`。

## 2. 后端验证

### 2.1 桥梁导入与参数拆分

```powershell
python -m pytest backend/tests/test_bridge_import.py -q
```

重点断言：

- 承台参数为 `6.25m × 1.5m × 1.8m`，工程量为 `1个`。
- 桩基参数包含桩型和桩径，按长度工效时工程量只包含桩长。
- 墩柱参数使用“柱径”，包含结构形式和柱数。
- 新字段可空，旧项目结构数据仍能加载。

### 2.2 平均墩高与工期

```powershell
python -m pytest backend/tests/test_scheduler.py -q -k "pier_body or quantity or structure_parameter"
```

固定样例：

```text
双柱墩：2根 × 10m
平均墩高：10m
标准节高：4.5m/节
每节工期：7天/节
期望节数：3
期望工期：21天
```

还应覆盖：

- 逐柱高度 `[8, 10, 12]` 得到平均值 `10m`。
- 无有效高度时形成明确错误诊断。
- 结构参数摘要变化不影响工期。
- 工效按根与按米切换时工程量标签和工期一致。

### 2.3 历史计划兼容

```powershell
python -m pytest backend/tests/test_plan_control_repository.py backend/tests/test_plan_control_api.py -q
```

断言缺少新字段的项目和计划可读取，历史文件哈希不变。

## 3. 前端与 Netlify 镜像验证

npm.cmd run build
git diff --check

构建必须覆盖前端共享类型和任务视图，不允许新增类型错误。`netlify/demo-functions/api.mts` 当前未配置为发布 Functions，也不在根构建 TypeScript 项目中；需按接口契约静态核对 `ComponentModel`、`UpperStructureComponent`、`Task` 及任务生成逻辑与 FastAPI 一致。

## 4. 页面验证

1. 启动本地 FastAPI 页面并进入“任务视图”。
2. 导入当前桥梁样例，点击“生成/刷新任务视图”。
3. 确认表头顺序为“工效 → 结构物参数 → 工程量 → 工期 → 工期计算”。
4. 检查承台行：参数显示尺寸，工程量显示 `1个`。
5. 检查墩柱行：参数显示结构形式、柱径和柱数；双柱每根 10m 时工程量显示 `10m`。
6. 检查墩柱工期表达式：`10m / 4.5m/节 = 3节；3 × 7天/节 = 21天`。
7. 检查现浇箱梁行：参数包含结构形式、支座范围和跨径组合，工程量为联数。
8. 检查连续梁 0 号块、标准段、边跨连续段和合龙段：参数包含组级结构信息及节段类型，工程量分别为块数或段数。
9. 将桩基工效从按米切换为按根，确认结构参数不变、工程量变为 `1根`、工期表达式更新。
10. 修改工效后确认旧求解结果、三方案对比和推荐按现有规则失效。

## 5. 空态和兼容验证

- 删除一个任务的参数摘要但保留结构化属性：页面应派生摘要。
- 同时缺少摘要和结构化属性：结构物参数显示 `-`，工程量与工期正常。
- 输入不完整尺寸：只显示可用参数，不出现 `0m`、`NaN` 或猜测值。
- 打开旧基准计划：页面不得报错，文件不得被自动修改。
