# 研究结论：任务结构物参数与工程量拆分

## 决策 1：结构参数摘要是展示字段，结构化属性仍是权威来源

- **决策**：为结构构件、上部结构构件和任务增加默认可空的 `structure_parameter_label`，仅用于一致展示；尺寸、形式、柱径、柱数、高度、支座范围和跨径组合仍保存在现有结构化字段和 `properties` 中。
- **理由**：当前 `quantity_label` 被尺寸和工程量共同占用，必须拆开；但只增加一段摘要文本不能替代原始结构数据，也不能参与算法计算。
- **已评估的替代方案**：前端直接解析 `properties`。该方案会在前端、FastAPI 和 Netlify 重复构件映射，并且无法保证下载或其他消费者得到相同摘要，因此不采用。

## 决策 2：`quantity_label` 收敛为当前工效的纯工程量文本

- **决策**：保留 `quantity` 与 `quantity_label` 字段名称以兼容现有接口；新生成任务的 `quantity_label` 只允许出现数值和单位，例如 `20m`、`1根`、`1个`、`8块`、`1段`、`1联`。
- **理由**：`quantity` 已经是工期计算输入，继续保留避免大范围契约迁移；纯工程量文本能让页面展示、工期表达式和进度反馈口径一致。
- **已评估的替代方案**：新增独立 `quantity_unit` 并删除 `quantity_label`。该方案会扩大共享接口和历史快照迁移范围，超出本期“两列拆分”目标，因此不采用。

## 决策 3：平均墩高优先使用结构化高度，不解析旧混合文本

- **决策**：墩柱工程量取值顺序为：逐柱有效高度列表的算术平均值；统一 `height_m`/`heightM`；最后才使用已明确代表单柱高度的构件数值。导入新数据时不再计算 `height × count`。旧导入数据即使 `component.quantity` 是总高度，也优先使用 `properties.height_m` 得到平均高度。
- **理由**：当前导入链路在双柱墩上把统一高度乘以柱数，而 `properties.height_m` 仍保存单柱高度，能在不迁移历史 JSON 的前提下恢复用户确认的平均高度口径。
- **已评估的替代方案**：把历史 `quantity` 除以柱数。该方案无法区分原本已是平均高度的默认场景和历史总高度，存在二次除法风险，因此只把结构化高度作为可靠来源，不根据混合标签推断。

## 决策 4：构件数量工程量使用真实数量，桩基仍按单桩任务计数

- **决策**：工效来源为 `count` 时，桩基单任务取 `1根`；连续梁标准段使用实际块数；现浇箱梁使用联数；连续梁闭合或连续段使用段数；其他按数量生成的下部构件使用构件自身数量和“个”单位。
- **理由**：现有通用逻辑除连续梁外固定返回 1，会掩盖导入数量大于 1 的承台、系梁或盖梁工程量；按构件实际数量更符合规格中的纯工程量定义。
- **已评估的替代方案**：所有非桩任务继续固定 `1个`。该方案不能覆盖导入数据中的真实数量，不采用。

## 决策 5：十类当前任务使用统一映射，未生成类型不启用

- **决策**：本期覆盖八类下部任务与现浇箱梁、现浇连续梁/连续刚构两类上部任务。上部任务在生成时携带结构形式、支座范围、跨径组合和节段类型；预制梁、简支梁架设、钢箱梁和桥面系继续不生成。
- **理由**：用户要求覆盖所有当前实际生成的任务类型，而不是扩大当前排程任务范围。
- **已评估的替代方案**：按 `ComponentType` 枚举全部补齐。该方案会意外启用尚未实现的任务生成，违反范围约束。

## 决策 6：后端生成规范值，前端只处理局部重算和历史回退

- **决策**：FastAPI 任务生成返回规范的参数摘要与纯工程量；前端工效切换复用同一单位映射更新工程量而不改参数摘要；历史任务缺字段时从 `properties` 派生，无法派生显示 `-`。Netlify Demo 采用相同字段和计算顺序。
- **理由**：后端是主要工程化实现，但当前前端会在不重新请求后端的情况下局部切换工效，Netlify 也有独立任务生成镜像，三处必须保持一致。
- **已评估的替代方案**：切换工效后强制重新请求后端。该方案会增加交互延迟并改变现有页面流程，不采用。

## 决策 7：不重写历史快照，不从旧字符串反向迁移

- **决策**：所有新增字段默认可空；历史项目和计划原样读取，不批量重写文件。历史展示使用结构化属性派生，不能派生时显示 `-`；工期始终使用数值和工效规则，不拆分旧 `quantity_label`。
- **理由**：避免不可逆数据迁移和标点、单位、格式差异带来的错误解析，也符合本地计划快照只读兼容要求。
- **已评估的替代方案**：按逗号或中文标点拆分旧文本。该方案脆弱且可能把尺寸误当工程量，不采用。
