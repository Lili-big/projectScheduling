# 实施计划：进度锁定重排三步闭环

**分支/目录**：`040-progress-forecast-closed-loop` | **日期**：2026-07-15 | **规格**：[spec.md](./spec.md)

**输入**：来自 `specs/040-progress-forecast-closed-loop/spec.md` 的功能规格

## 概要

在现有基准计划、进度快照、滚动预测和调整方案能力上补齐可见的三步闭环。第一步增加与后端一致的保存前行级校验和未保存状态；第二步将现有“生成滚动预测”改造为始终可见、按有效快照解锁的“锁定实绩并重排剩余计划”，并明确五类任务的锁定策略；第三步新增结构化关键节点结果，使用历史实绩与未来预测的合并计划重新计算项目完工和强制里程碑，展示按期、临近风险、延期和无法判断，并衔接既有调整方案比选。

## 设计概览

### 三步页面状态

```text
步骤 1 保存实际进度
  ├─ 页面行级校验失败 → 保持填写态，定位错误
  └─ 保存成功 → 有效 ProgressSnapshot，解锁步骤 2

步骤 2 锁定实绩并重排剩余计划
  ├─ 已完成/取消 → 历史事实或显式诊断
  ├─ 进行中/暂停 → 剩余工作与执行约束
  └─ 未开始 → 状态日期之后当前趋势重排

步骤 3 关键节点预警与调整
  ├─ 合并历史实际 + 未来预测
  ├─ 重算项目完工 + 强制里程碑
  └─ 定位任务或进入现有调整方案比选
```

步骤状态不新增持久化实体，由活动计划、当前快照、最新预测、页面未保存变更和请求状态共同推导。这样避免出现“步骤显示完成但底层输入已经变化”的第二套状态源。

### 后端处理

1. 继续由进度快照服务执行最终权威校验；暂停任务缺少恢复日期时允许保存并产生数据质量警告，但预测不得输出确定性未来排程。
2. 滚动预测沿用一次 `solve_schedule`：已完成任务不进入残余网络；进行中任务固定状态日开始的剩余段和原资源；暂停任务遵守恢复日期；未开始任务沿用当前趋势资源顺序。
3. 合并历史实际任务与未来预测任务后，统一重新评估节点，避免只看残余任务导致已完成节点丢失。
4. 节点证据只使用确定性事实：决定节点日期的任务、基准/目标差异、求解诊断、瓶颈资源和数据质量；不生成推测性原因。
5. 保留既有 `risk_status` 和 `risk_evidence` 作为兼容摘要，新增结构化 `critical_nodes` 与 `execution_summary`。

### 前端处理

1. 抽取计划管控专用的进度校验与步骤状态纯函数，复用 039 的本地日期工具并增加 Node 规则测试。
2. 三个步骤始终显示；未满足前置条件时展示原因而不是隐藏整个模块。
3. 任何表格编辑将页面标记为“有未保存变更”，旧预测不再作为当前结论展示；保存成功后清除未保存状态并显式引导第二步。
4. 第二步展示锁定数量摘要和五类任务处理说明，按钮使用业务名称。
5. 第三步使用节点摘要卡和节点表，支持按风险等级排序、定位任务及进入既有调整方案。
6. 将网络不可达、校验失败、修订冲突、求解无解映射为不同的业务提示。
