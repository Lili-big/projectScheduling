# 验证指南：统一目标函数求解与资源分支重构

本指南用于实现完成后的本地验证。当前阶段不执行实现，只定义可复现验证入口和预期结果。

## 前置条件

- 已完成 `tasks.md` 和 `$speckit-analyze`，并获得用户确认进入实现。
- 本地 Python、Node.js、后端依赖和前端依赖按项目现有方式可用。
- 使用本地 FastAPI 后端作为权威求解行为。

## 场景 1：固定资源当前资源达成目标

**输入准备**：

- 使用当前默认资源数量。
- 硬里程碑目标日期可由当前资源按时完成。
- 固定工期目标不存在或不会超期。

**执行**：

- 在前端点击固定资源求工期，或调用 `POST /api/solve-scenario` 的固定资源入口。

**预期结果**：

- 返回 `OPTIMAL` 或 `FEASIBLE` 排程。
- `stats.target_achievement.business_success = true`。
- `hard_milestone_late_days = 0`。
- `fixed_duration_overrun_days = 0`。
- 页面显示目标达成结果和目标函数贡献，不再把“精排/粗排”作为主结果分类。

## 场景 2：固定资源当前资源可排程但目标失败

**输入准备**：

- 当前默认资源数量可以生成施工排程。
- 至少一个硬里程碑晚于目标日期，或固定工期超期。
- 最大资源范围内存在可能达成目标的资源数量。

**执行**：

- 在前端点击固定资源求工期。

**预期结果**：

- 当前资源结果仍包含可查看的 `scheduled_tasks` 和资源分配。
- 当前资源结果的 `business_success = false`。
- `target_status = current_resources_target_failed`。
- 页面展示当前资源失败原因、晚点节点、目标日期、实际日期和晚点/超期天数。
- 系统进入新增资源分支，候选资源数量不低于当前默认数量，不超过最大资源数量。
- 候选资源必须经过完整目标函数复排；候选目标达成时显示推荐资源方案。

## 场景 3：固定资源当前资源物理无可行排程

**输入准备**：

- 设置施工硬规则或资源配置冲突，使 CP-SAT 不能生成物理可行排程。

**执行**：

- 在前端点击固定资源求工期。

**预期结果**：

- `target_status = physical_infeasible`。
- 页面说明没有可展示的物理可行排程。
- 不得把该结果展示为“当前资源可排程但业务失败”。

## 场景 4：固定工期最大资源预检达成目标

**输入准备**：

- 当前默认资源不足以按目标完成。
- 最大资源数量可以达成硬里程碑和固定工期目标。

**执行**：

- 在前端点击固定工期求资源，或调用 `POST /api/solve-min-resources`。

**预期结果**：

- 系统先用最大资源运行硬里程碑和固定工期窗口快速预检。
- 最大资源快速预检通过后，进入候选资源搜索。
- 返回的候选资源数量在当前默认数量和最大资源数量之间。
- 候选资源复排结果目标达成后，页面显示推荐资源方案。

## 场景 5：固定工期最大资源不满足目标

**输入准备**：

- 即使使用最大资源，硬里程碑仍晚点或固定工期仍超期。

**执行**：

- 在前端点击固定工期求资源。

**预期结果**：

- `target_status = max_resources_target_failed`。
- 页面提示“当前最大资源不满足目标”或等价文案。
- 页面尽量展示硬里程碑关键路径晚点天数和固定工期超期天数。
- 不得继续推荐超过最大资源上限的资源数量。

## 场景 6：15 秒预算耗尽或求解未知

**输入准备**：

- 使用规模较大或搜索困难的场景，使完整目标函数或资源搜索在总预算内无法确认。

**执行**：

- 运行固定资源或固定工期求解。

**预期结果**：

- `target_status = unconfirmed`。
- `time_budget_seconds = 15`。
- `time_budget_exhausted = true` 或 `solver_status = UNKNOWN`。
- 页面显示“限时内无法确认”。
- 不得显示“无解”或“最大资源不满足目标”。

## 场景 7：同结构同工艺规则保留

**输入准备**：

- 同一墩号、同一桩基工艺、多个机械钻机候选资源。
- 资源类型覆盖旋挖钻、冲击钻或回旋钻。

**执行**：

- 运行固定资源、固定工期和候选资源复排各一类场景。

**预期结果**：

- 业务成功结果不得违反当前桩基机械钻机同结构同工艺规则。
- 规则不得默认扩展到模板、人工班组或其他未确认资源类型。
- 若目标无法在该硬规则下达成，结果应表现为目标失败或资源上限不足，而不是放松该规则。

## 场景 8：旧结果兼容

**输入准备**：

- 使用缺少 `target_achievement` 的旧结果或旧目标配置。

**执行**：

- 前端加载旧结果，后端接收旧配置并求解。

**预期结果**：

- 旧目标配置可按默认值补齐。
- 前端不得把旧结果误标为新目标达成成功。
- 缺失的固定工期超期字段展示为未评估或兼容状态，而不是强行展示为 0。

## 完成判定

- 后端测试覆盖固定资源成功、当前资源失败、候选资源复排、最大资源不满足、`UNKNOWN` 未确认、15 秒总预算和同结构同工艺规则。
- 前端构建通过，结果页能区分求解器状态和业务目标状态。
- 文档、数据模型和契约中没有未解决占位符。
- 如实现阶段保留 `_solve_capacity_model` 或等价容量模型，`$speckit-analyze` 必须列出保留原因、影响范围和后续删除条件。
