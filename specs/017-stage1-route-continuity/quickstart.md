# 快速验证：第一阶段钻机组路径连续性优化

## 前置条件

- 已安装项目 Python 依赖和 OR-Tools。
- 在仓库根目录执行验证命令。
- 使用可复现的后端测试夹具，不依赖随机起点。

## 验证 1：稀疏同幅可施工序列

**场景**：同幅可施工墩组为 `[1, 2, 4, 7]`，资源连续性开启。

**期望**：
- `1# -> 2#` 惩罚为 0。
- `4# -> 7#` 惩罚为 0。
- `1# -> 4#` 惩罚为 1。
- `1# -> 7#` 不生成第一阶段候选弧。

**验证方式**：

```powershell
python -m pytest backend/tests/test_scheduler.py -k "stage1_route"
```

## 验证 2：跨幅真实墩号窗口

**场景**：左幅和右幅均存在多个可施工墩组。

**期望**：
- 左幅 `4# -> 右幅 4#` 允许，跨幅惩罚为 1。
- 左幅 `4# -> 右幅 5#` 允许，跨幅惩罚为 1。
- 左幅 `1# -> 右幅 4#` 不允许。

## 验证 3：无远距离兜底

**场景**：只有窗口外远距离跳转才能满足硬里程碑。

**期望**：
- 系统不生成窗口外候选弧。
- 结果返回可解释的不可行、当前资源精排失败或资源建议状态。
- 诊断中说明失败来自第一阶段路径窗口或资源连续性约束。

## 验证 4：关闭资源连续性目标

**场景**：同一测试数据中关闭 `resource_path_continuity`。

**期望**：
- 第一阶段空间路径节点、候选弧和惩罚为 0 或未评估。
- 资源互斥、工艺前后置、同墩同工艺单资源和硬里程碑仍生效。

## 验证 5：回归验证

**期望**：
- 现有桩基墩组两阶段精排测试继续通过。
- 固定资源当前方案和最少资源候选二次精排都使用一致窗口规则。

**命令**：

```powershell
python -m pytest backend/tests/test_scheduler.py
```
