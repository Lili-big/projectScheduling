# 功能规格：第一阶段钻机组路径连续性优化

**功能目录/分支**：`017-stage1-route-continuity`

**创建日期**：2026-07-08

**状态**：草稿

**输入**：用户确认在开启资源连续性要求时，第一阶段粗粒度直接尝试对钻机组进行路径优化选择；同幅按可施工序列窗口，跨幅按真实墩号窗口；相邻可施工节点不罚分；不允许为满足硬里程碑临时走远距离跳转。

## 来源与评审上下文（必填）

- **评审结论**：建议调整后推进。该变更会改变 CP-SAT 求解目标、候选路径边界、资源连续性诊断和失败语义，按项目契约必须进入 Spec Kit；未确认 `tasks.md` 与 `$speckit-analyze` 结果前不进入实现。
- **使用的 Demo/代码事实**：
  - 当前固定资源主流程在 `backend/app/scenario.py` 中直接进入 `solve_control_priority_schedule()`，成功来源为 `current_resources_control_priority_balanced`，失败时进入资源建议。
  - 当前 `backend/app/solver.py` 中，机械钻资源在资源连续性目标开启时进入钻机组两阶段精排：第一阶段为粗排，第二阶段固定粗排资源归属后再建路径弧。
  - 当前第一阶段粗排主要使用相邻换机与 `1-0-1` 洞洞式跳墩软惩罚，不直接按同幅/跨幅空间路径窗口选择下一组。
  - 当前第二阶段已有可见可施工序列窗口剪枝思路，但用户要求把路径选择能力前移到第一阶段，并且不允许远距离跳转兜底。
- **不在范围内**：
  - 不改变桩基原任务生成、任务粒度、工期计算和工艺前后置规则。
  - 不改变资源连续性目标项 `resource_path_continuity` 的前端开关和权重配置入口。
  - 不引入真实转场时间、道路成本、设备迁移费用或地图路径。
  - 不改变人工挖孔桩、非机械钻资源和连续梁班组联级占用规则。
  - 不修改 `README.md`，不默认提交 git。

## 用户场景与测试（必填）

### 用户故事 1 - 第一阶段按空间窗口选择钻机组路径（优先级：P1）

计划工程师开启资源连续性目标后，希望系统在第一阶段粗粒度排程时就让每台钻机沿可解释的相近墩组推进，避免粗排把钻机分配到明显跳跃的墩组序列，再依赖第二阶段修正。

**优先级理由**：这是本次变更的核心价值。第一阶段资源归属如果已经严重跳跃，第二阶段固定归属后可优化空间有限，容易返回不连续或回退结果。

**独立测试**：构造左右幅、多个可施工墩组和两台旋挖钻的场景，开启 `resource_path_continuity` 后执行固定资源精排，验证第一阶段候选路径只使用允许窗口内的转移，并且输出可解释的阶段一空间路径诊断。

**验收场景**：

1. **假设** 同一幅可施工墩组序列为 `1#、2#、4#、7#`，**当** 第一阶段为某台钻机构建路径候选，**则** `1# -> 4#` 允许，`1# -> 7#` 不允许。
2. **假设** 左幅 `4#` 和右幅 `4#` 均为可施工墩组，**当** 第一阶段构建跨幅候选，**则** 左右幅 `4# -> 4#` 允许且产生跨幅切换惩罚。
3. **假设** 左幅 `1#` 与右幅 `4#` 之间真实墩号差为 3，**当** 第一阶段构建跨幅候选，**则** 不允许该跨幅转移。

---

### 用户故事 2 - 同幅惩罚按可施工序列距离计算（优先级：P1）

计划工程师希望“间隔”反映当前资源实际可施工任务范围，而不是自然墩号差。旋挖钻只有 `1#、2#、4#、7#` 可施工时，`4# -> 7#` 应视为相邻可施工节点，不应因为自然墩号差为 3 而被罚。

**优先级理由**：如果按自然墩号差计算，稀疏任务场景会误判连续性，导致系统惩罚合理的现场推进顺序。

**独立测试**：构造稀疏可施工墩组序列 `[1, 2, 4, 7]`，验证同幅相邻可施工节点罚分为 0，跳过 1 个可施工节点罚分为 1，并且同幅候选窗口为可施工序列距离 `<= 2`。

**验收场景**：

1. **假设** 可施工序列为 `[1, 2, 4, 7]`，**当** 计算 `1# -> 2#` 或 `4# -> 7#`，**则** 同幅连续性惩罚为 0。
2. **假设** 可施工序列为 `[1, 2, 4, 7]`，**当** 计算 `1# -> 4#`，**则** 可施工序列距离为 2，惩罚为 1。
3. **假设** 可施工序列为 `[1, 2, 4, 7]`，**当** 计算 `1# -> 7#`，**则** 可施工序列距离为 3，第一阶段不允许该候选转移。

---

### 用户故事 3 - 不为硬里程碑放开远距离跳转（优先级：P1）

计划工程师希望资源连续性要求开启后，第一阶段路径窗口是明确约束，不因为硬里程碑压力临时放开远距离跳转；如果窗口内无法形成可行路径，系统应给出失败或资源建议，而不是返回违反连续性要求的路径。

**优先级理由**：这是用户明确确认的失败边界。若系统私下放开窗口，结果看似满足节点但违背资源连续性要求，会削弱排程结果可信度。

**独立测试**：构造只有远距离跳转才能满足硬里程碑的场景，验证第一阶段不生成远距离候选弧，最终返回可解释的不可行/精排失败状态或进入资源建议分支。

**验收场景**：

1. **假设** 第一阶段只有 `1# -> 7#` 远距离跳转才能满足硬里程碑，**当** 资源连续性开启，**则** 系统不得生成该转移作为兜底。
2. **假设** 严格窗口导致当前资源无法得到可行精排，**当** 用户查看结果，**则** 结果应说明失败来自阶段一路径窗口或资源连续性约束，而不是返回一个远跳路径。

---

### 用户故事 4 - 阶段诊断说明候选窗口和惩罚（优先级：P2）

计划工程师查看结果时，需要知道第一阶段为什么选择或拒绝某些钻机组转移，以及同幅序列距离、跨幅墩号差、惩罚和失败原因。

**优先级理由**：本次算法边界更严格，如果缺少诊断，用户会难以区分资源不足、工艺冲突、硬里程碑冲突和路径窗口冲突。

**独立测试**：执行包含允许转移、拒绝转移和不可行窗口的样例，验证诊断字段包含阶段一候选节点数、候选弧数、拒绝原因计数和惩罚合计。

**验收场景**：

1. **假设** `1# -> 7#` 因同幅可施工序列距离为 3 被拒绝，**当** 用户查看诊断，**则** 能看到该拒绝原因归类为同幅窗口超限。
2. **假设** 左幅 `1# -> 右幅 4#` 因跨幅真实墩号差为 3 被拒绝，**当** 用户查看诊断，**则** 能看到该拒绝原因归类为跨幅窗口超限。

### 边界与异常场景

- 当资源连续性目标关闭时，不构建第一阶段空间路径候选，不应用本功能新增窗口约束，保留现有资源互斥、工艺前后置、硬里程碑和同墩同工艺单资源规则。
- 当任务缺少可识别墩号、幅别或桥梁范围时，该任务不得被错误纳入空间路径窗口；系统应输出诊断并按既有可解释失败或降级规则处理。
- 当同一钻机组只有一个可施工墩组时，不需要建立转移弧，惩罚为 0。
- 当跨幅两端真实墩号相同或相差 1 时可作为候选；真实墩号差大于 1 时不可作为候选。
- 当同幅可施工序列稀疏时，窗口距离必须按实际可施工墩组排序后的序号差计算，而不是自然墩号差。
- 当第一阶段路径窗口导致无可行资源归属时，不允许临时放开远距离弧；当前资源结果应保持失败语义并触发已有资源建议或失败诊断。
- 当第二阶段继续运行时，应尊重第一阶段得到的合法资源归属，不得把第一阶段禁止的远距离路径作为无说明兜底重新引入。

## 需求（必填）

### 功能需求

- **FR-001**：系统必须在 `resource_path_continuity` 开启且机械钻机组存在时，为第一阶段粗粒度钻机组建立空间路径候选选择能力。
- **FR-002**：系统必须将第一阶段路径节点限定为机械钻资源可施工的同结构同工艺钻机组，最终排程任务仍保持原任务粒度。
- **FR-003**：系统必须允许任意合法可施工钻机组作为路径起点，不得随机固定一个起点；相同输入应保持可复现的求解语义。
- **FR-004**：系统必须按“同桥梁、同工艺、同幅别、当前资源可施工钻机组”生成同幅可施工序列，并以该序列中的序号差作为同幅窗口距离。
- **FR-005**：系统必须将同幅候选转移允许条件定义为可施工序列距离 `<= 2`。
- **FR-006**：系统必须将同幅连续性惩罚定义为 `max(0, 可施工序列距离 - 1)`；相邻可施工节点惩罚为 0。
- **FR-007**：系统必须将跨幅候选转移允许条件定义为真实墩号差 `<= 1`。
- **FR-008**：系统必须将允许的跨幅切换惩罚定义为 1 次资源路径连续性惩罚。
- **FR-009**：系统不得在第一阶段为满足硬里程碑、缩短工期或避免不可行而临时生成超出窗口的远距离候选转移。
- **FR-010**：系统必须把第一阶段空间路径惩罚归入 `resource_path_continuity` 目标项，并在目标关闭时完全跳过新增路径候选和惩罚。
- **FR-011**：系统必须在第一阶段失败、无候选弧或窗口导致不可行时返回可解释诊断，并保持当前资源精排失败或资源建议的既有结果语义。
- **FR-012**：系统必须在阶段诊断中输出第一阶段路径节点数、候选弧数、拒绝弧原因计数、同幅惩罚、跨幅惩罚和是否因窗口不可行失败。
- **FR-013（历史边界修正）**：常规自动流程不再运行第二阶段细排；系统必须保持资源空闲、硬里程碑、工艺逻辑和命名资源互斥等当前边界，第二阶段相关字段仅作为历史兼容或显式诊断路径保留。
- **FR-014**：系统必须为固定资源当前方案和最少资源候选二次精排复用同一第一阶段路径窗口规则，保证推荐方案与当前方案口径一致。
- **FR-015**：系统必须提供覆盖稀疏可施工序列、跨幅窗口、关闭目标、不可行窗口和诊断输出的自动化验证。

### 关键实体（涉及数据时填写）

- **机械钻机组**：同资源组、同结构物、同构件类型、同施工工艺聚合得到的内部粗粒度节点，适用于旋挖钻、回旋钻和冲击钻资源。
- **可施工序列**：在同桥梁、同工艺、同幅别范围内，当前资源实际可施工的机械钻机组按墩号排序后的序列，用于计算同幅窗口距离。
- **同幅候选转移**：同一幅别内两个机械钻机组之间的第一阶段路径边，必须满足可施工序列距离 `<= 2`。
- **跨幅候选转移**：左右幅之间两个机械钻机组的第一阶段路径边，必须满足真实墩号差 `<= 1`。
- **第一阶段空间路径惩罚**：第一阶段路径中同幅跳过可施工节点和跨幅切换产生的未加权罚分，归属于 `resource_path_continuity`。
- **窗口拒绝诊断**：记录第一阶段候选边因为同幅序列距离超限、跨幅墩号差超限、缺少位置数据等原因被拒绝的诊断信息。

## 成功标准（必填）

### 可衡量结果

- **SC-001**：在可施工序列 `[1, 2, 4, 7]` 的同幅样例中，`1# -> 2#` 和 `4# -> 7#` 的第一阶段同幅惩罚均为 0。
- **SC-002**：在同一同幅样例中，`1# -> 4#` 的第一阶段同幅惩罚为 1，`1# -> 7#` 不生成候选转移。
- **SC-003**：在跨幅样例中，真实墩号差 `<= 1` 的左右幅转移可生成候选且跨幅惩罚为 1；真实墩号差大于 1 的左右幅转移不生成候选。
- **SC-004**：在只有远距离跳转才能满足硬里程碑的样例中，系统不生成远距离兜底候选，并返回可解释失败或资源建议状态。
- **SC-005**：关闭 `resource_path_continuity` 后，第一阶段空间路径节点数、候选弧数和惩罚均为 0 或未评估，原有硬约束仍生效。
- **SC-006**：新增自动化测试覆盖至少 5 类场景：稀疏同幅序列、跨幅窗口、无远跳兜底、目标关闭、诊断输出。
- **SC-007**：现有桩基墩组第一阶段最终排程、固定资源当前方案和最少资源候选精排相关回归测试继续通过；历史二阶段兼容测试不得要求常规自动流程进入第二阶段。

## 默认假设

- 默认“机械钻资源”沿用当前系统已识别的旋挖钻、回旋钻和冲击钻资源类型。
- 默认“幅别”来自现有任务位置解析结果；同一任务无法识别为左右幅时，不参与同幅/跨幅路径窗口。
- 默认同幅可施工序列按当前资源候选范围生成，不把没有该资源候选的墩号计入序列距离。
- 默认第一阶段空间路径优化仍属于 `resource_path_continuity`，不新增前端可配置目标项。
- 默认本次先覆盖 Python 后端主求解链路和测试；前端仅在已有诊断展示需要对齐时做兼容展示。
## 2026-07-08 补充口径：第一阶段作为最终排程

- 当 `resource_path_continuity` 开启且机械钻机组存在时，第一阶段同时承担钻机组路径优化、里程碑、总工期、资源空闲和任务时间落位；第一阶段可行结果即为最终主排程。
- 机械钻机组按墩号、幅别和施工工艺聚合；组内桩基任务必须按桩基序号从小到大连续施工。
- 常规自动求解不再进入第二阶段 `refined` 排程，不再对同一批钻机组重新构造资源路径 circuit。
- 既有第二阶段诊断字段仅作为历史兼容字段保留；新结果的 `drill_group_refinement.status` 应体现第一阶段最终排程语义。
- 本补充口径已写入 FR-013，第二阶段仅保留历史兼容或显式诊断语义。

### 新增成功标准

- **SC-008**：开启 `resource_path_continuity` 且第一阶段可行时，结果状态为可行，`drill_group_refinement.status` 为第一阶段最终排程语义，且不调用第二阶段 `refined` 求解。
- **SC-009**：同一钻机组内存在多个桩基任务且输入顺序与桩号不一致时，最终组内连续施工顺序仍按桩基序号升序。
