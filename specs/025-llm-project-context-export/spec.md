# 功能规格：三方案生成前 LLM 项目信息下载

**功能目录/分支**：`025-llm-project-context-export`

**创建日期**：2026-07-10

**状态**：已实现

**输入**：用户要求在“AI 多方案比选”点击“生成三方案”后，可下载本次实际提供给 LLM 的精简项目上下文 JSON；不涉及 CP-SAT 求解输入。

## 来源与评审上下文（必填）

- **来源文档**：`AGENTS.md`、`agent.md`、`README.md`、`docs/AI资源配置与排程优化助手验证说明.md`、`specs/022-ai-resource-scheduling-assistant/spec.md`、`specs/024-navigation-ai-comparison/spec.md`。
- **评审结论**：用户已明确确认下载口径为当前真正传给三方案生成 LLM 的精简项目上下文，不包含完整 HTTP 请求、原始 `ScenarioInput` 或 CP-SAT 数据。
- **使用的 Demo/代码事实**：当前三方案初始化会先形成工程画像、资源类型、约束提示、参考样例、当前资源池和生成规则，再将该上下文传给 LLM；初始化响应仅返回其中部分信息，页面没有可下载入口；外部 LLM 不可用时会使用本地回退方案。
- **不在范围内**：不修改三方案生成规则、提示词、参考样例、LLM 输出解析和回退策略；不下载 system instruction、输出结构、模型配置、Endpoint、密钥或完整请求体；不覆盖推荐解释输入、方案求解输入、CP-SAT 输入、方案结果下载和服务端留档。

## 用户场景与测试（必填）

### 用户故事 1 - 下载三方案生成依据（优先级：P1）

计划工程师生成经济、平衡、抢工三套资源方案后，可以下载本次实际提供给 LLM 的项目信息，核查模型获得了哪些工程画像、资源需求、约束提示和参考样例。

**优先级理由**：这是本功能唯一的核心价值，直接解决三方案生成输入不可见、难以核查的问题。

**独立测试**：在 AI 多方案比选页面点击“生成三方案”，下载 JSON，并将文件内容与该次生成实际使用的项目上下文逐字段比对。

**验收场景**：

1. **假设** 当前项目可以正常初始化三方案，**当** 用户点击“生成三方案”且接口成功返回，**则** 页面出现“下载本次 LLM 项目信息 JSON”入口。
2. **假设** 下载入口已出现，**当** 用户下载并解析文件，**则** 文件包含本次实际使用的 `project_profile`、`resource_types`、`constraint_hints`、`reference_examples`、`current_resource_pools` 和 `rules`，且内容与 LLM 生成调用使用的上下文一致。
3. **假设** 项目名称包含中文，**当** 用户下载文件，**则** 文件名可识别且 JSON 中中文内容可正常阅读。

---

### 用户故事 2 - 在回退场景核查预备输入（优先级：P2）

当外部 LLM 未配置、调用失败或超时时，计划工程师仍可下载系统已准备的项目上下文，理解本次本地回退原本准备提供给模型的数据。

**优先级理由**：回退场景是当前产品的正式兼容路径，输入核查能力不能只在外部调用成功时存在。

**独立测试**：分别模拟本地 Provider 和外部调用失败回退，确认三方案正常返回后均可下载对应上下文。

**验收场景**：

1. **假设** 外部 LLM 未配置或调用失败但初始化接口通过本地回退成功返回，**当** 用户查看页面，**则** 下载入口仍然可用。
2. **假设** 初始化接口整体失败且没有返回本次上下文，**当** 页面显示失败状态，**则** 不展示或沿用上一轮下载入口。

### 边界与异常场景

- 项目场景变化后，旧上下文入口必须立即失效，不能把上一项目的数据标记为当前输入。
- 用户连续生成三方案时，下载入口必须替换为最新一次成功响应中的上下文。
- 下载内容不得包含 API Key、Authorization、Endpoint、模型名称或其他环境配置值。
- 下载上下文保留当前实际精简口径；不因下载功能额外加入完整结构物、工艺逻辑、工效库或里程碑明细。
- 文件只在当前页面会话中可用，不要求刷新后恢复、长期留档或形成可分享 URL。

## 需求（必填）

### 功能需求

- **FR-001**：系统必须为每次三方案初始化构建唯一的一份 LLM 项目上下文，并让 LLM 调用和下载文件复用同一份数据对象。
- **FR-002**：LLM 项目上下文必须包含 `project_profile`、`resource_types`、`constraint_hints`、`reference_examples`、`current_resource_pools` 和 `rules` 六个分区。
- **FR-003**：三方案初始化成功返回后，系统必须在“AI 多方案比选”页面提供“下载本次 LLM 项目信息 JSON”入口。
- **FR-004**：下载文件必须直接使用初始化响应中的上下文，页面不得依据当前状态重新拼装或推断上下文。
- **FR-005**：下载文件必须是可解析的 UTF-8 JSON，保留可读中文，并以项目名称、三方案上下文标识和生成时间形成可识别文件名。
- **FR-006**：外部 LLM 未配置或调用失败但本地回退成功时，系统仍必须返回并允许下载本次已构建的上下文。
- **FR-007**：初始化接口整体失败时，页面不得展示或沿用上一轮下载入口。
- **FR-008**：再次成功生成三方案时，系统必须用最新上下文替换旧上下文；项目场景变化时必须清除旧上下文。
- **FR-009**：下载内容不得包含 system instruction、输出结构、模型配置、Endpoint、API Key、Authorization 或完整 HTTP 请求体。
- **FR-010**：本功能不得改变现有三方案生成结果、提示词规则、参考样例、回退策略和输出解析行为。
- **FR-011**：系统不得在方案卡、方案详情、模拟求解或 CP-SAT 求解区域增加该下载入口。

### 关键实体（涉及数据时填写）

- **LLM 项目上下文**：三方案生成前提供给模型的精简工程信息，包含工程画像、资源需求、约束提示、参考样例、当前资源池和生成规则。
- **三方案初始化结果**：一次生成经济、平衡、抢工方案的页面会话结果，关联输入指纹、生成来源、上下文和方案列表。
- **下载文件**：当前初始化结果对应的临时 JSON 表达，仅用于用户核查，不作为持久化或再次导入格式。

## 成功标准（必填）

### 可衡量结果

- **SC-001**：每次三方案初始化成功后，用户最多一次点击即可下载本次 LLM 项目信息。
- **SC-002**：下载文件与该次三方案生成实际使用的项目上下文逐字段一致率为 100%。
- **SC-003**：外部 LLM 成功、本地 Provider 回退、外部调用失败回退三种初始化成功场景的下载可用率均为 100%。
- **SC-004**：下载文件中凭据、Endpoint、模型配置和 Authorization 等敏感配置出现次数为 0。
- **SC-005**：项目场景变化或初始化整体失败后，旧下载入口继续可用的次数为 0。

## 默认假设

- 目标用户是需要核查三方案生成依据的计划工程师和算法调试人员。
- “实际输入”指传给三方案生成函数的精简 `context`，不包含 system instruction、任务标识和输出结构。
- 本功能不改变现有上下文信息量，只提高可见性和可下载性。
- 下载链接只在当前页面会话有效，不需要服务端文件存储。
