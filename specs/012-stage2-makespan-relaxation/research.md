# 研究记录：放宽第二阶段工期上限

## 决策 1：移除 `M2 <= M1` 硬约束

- **决策**：第二阶段不再把第一阶段总工期 `M1` 作为硬上限。
- **理由**：`M1` 是第一阶段结果，不是真实业务硬约束。把它作为第二阶段硬上限会导致路径连续性优化只要略微延长总工期就失败或回退。
- **已评估的替代方案**：保留 `M2 <= M1`。该方案保持短工期优先，但无法满足“硬约束范围内优化连续性”的目标。

## 决策 2：不新增线性 `M2 - M1` 求解目标

- **决策**：`M2 - M1` 只作为诊断字段，不作为新的目标函数项。
- **理由**：对第二阶段求解器而言，`M1` 是常数，最小化 `M2 - M1` 与最小化 `M2` 等价。现有总工期目标已经覆盖该优化方向，重复添加会导致总工期被双重计分。
- **已评估的替代方案**：新增 `M2 - M1` 目标。该方案表达直观，但会改变权重比例并削弱资源路径连续性目标。

## 决策 3：保留真实硬约束

- **决策**：硬里程碑、资源互斥、工艺前后置、固定资源分配、未放松的真实固定工期上限不随本次变更放松。
- **理由**：用户要移除的是第一阶段结果派生出的相对工期门槛，不是移除业务硬约束。
- **已评估的替代方案**：统一把硬目标转成罚分。该方案超出当前范围，会改变固定资源排程的硬约束语义。

## 决策 4：接受规则以可行性和真实硬约束为准

- **决策**：第二阶段只要返回 `FEASIBLE` 或 `OPTIMAL`，且未违反真实硬约束，即可被接受；不再因 `M2 > M1` 回退。
- **理由**：接受规则需要与模型约束一致。若模型放开 `M2 <= M1`，但接受逻辑继续检查 `M2 <= M1`，实际行为仍不会改变。
- **已评估的替代方案**：只移除模型硬约束，不改接受逻辑。该方案无效，因为结果仍会被回退。
