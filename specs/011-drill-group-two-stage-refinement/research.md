# 研究记录：桩基钻机墩组两阶段精排

> 当前实现校正（2026-07-08）：后续 `017-stage1-route-continuity` 已取消常规自动第二阶段排程。当前主链路在资源连续性开启且机械钻机组第一阶段可行时直接返回 `stage1_final`；本研究中关于细排模型、细排失败回退和 `stage2_refined` / `stage2_fallback` 的结论仅作为历史兼容或显式二阶段诊断路径说明。

## 决策 1：聚合层仅作为求解内部层

**决策**：机械钻机墩组不替代原 `Task`，只在固定资源精排内部参与资源分配、跳墩偏好和路径细排；最终结果仍展开回原任务。

**理由**：当前前端、API、里程碑诊断、甘特图和测试都围绕原任务粒度工作。用户已明确“聚合后的子任务最终展开回每根桩、每个原任务”。保持输出粒度不变可以降低前端和兼容风险。

**已评估的替代方案**：

- 直接改变任务生成粒度为墩组任务：会破坏现有任务视图和里程碑诊断，不采用。
- 同时输出墩组任务和原任务：会造成前端展示重复和统计口径混乱，不作为第一版。

## 决策 2：聚合 key 沿用当前同结构同工艺资源规则

**决策**：第一版聚合身份使用当前实现等价口径：资源组、`structure_id`、`component_type`、`process_name`。桥梁、工区、幅别和墩号通过当前结构物归属保持区分。

**理由**：当前求解器已有 `_same_structure_resource_rule_key()`，测试也已覆盖同结构同工艺并行上限。沿用该口径能最大程度复用现有数据结构和业务规则。

**已评估的替代方案**：

- 新增显式 `bridge_id/work_area_id/side/pier_no/process_type/drill_group` key：业务表达更完整，但需要先统一所有任务的侧别和墩号字段，风险较高。
- 仅按 `structure_id` 聚合：会混合不同施工工艺或资源组，不满足用户要求。

## 决策 3：粗排不建立路径环路

**决策**：第一阶段粗排只做墩组资源分配、时间、硬约束和轻量连续性偏好，不建立每台桩机候选墩组的全量路径环路。

**理由**：本次需求的根因是当前全量 `AddCircuit` 弧数量随候选节点平方增长。粗排阶段先决定资源分配，可以显著缩小第二阶段路径节点集合。

**已评估的替代方案**：

- 继续在单一模型中使用全量路径环路并调低时间限制：不能解决规模根因。
- 只关闭路径连续性目标：能降规模但丢失桩机路径质量，不满足用户目标。

## 决策 4：粗排跳墩偏好使用相邻换资源和 `1-0-1` 洞洞惩罚

**决策**：粗排阶段按当前存在的墩组序列计算相邻换资源惩罚和 `1-0-1` 洞洞惩罚，作为资源分配层面的轻量软目标。

**理由**：细排固定资源分配后只能优化访问顺序，无法改变明显不连续的资源分配。粗排提前施加轻量偏好，可以减少细排无力修复的跳墩模式。

**已评估的替代方案**：

- 仅在细排做路径距离优化：对资源分配造成的 1-0-1 模式帮助有限。
- 把方向反转和大跨度折返也放进粗排目标：目标变多且解释复杂，第一版先作为诊断。

## 决策 5：细排固定粗排资源分配，只处理实际分配节点

**决策**：第二阶段固定 `group -> resource` 关系，只对每台桩机实际分配到的墩组建立路径排序，并保护粗排总工期和硬里程碑。

**理由**：这是降低路径环路规模的核心机制，也能避免第二阶段推翻粗排的资源可行性。

**已评估的替代方案**：

- 第二阶段允许重新分配资源：路径质量可能更好，但会重新引入大规模资源选择和路径组合问题，不适合作为第一版。
- 第二阶段只做诊断不优化：实现简单，但不能改善访问顺序。

## 决策 6：硬里程碑使用保守组完成口径

**决策**：当硬里程碑命中墩组内任一原任务时，粗排和细排默认要求整个墩组在期限前完成。

**理由**：最终结果需要展开到原任务，若粗排只保护部分子任务，必须引入复杂的子任务偏移约束。第一版采用保守口径可避免展开后违约。

**已评估的替代方案**：

- 精确到组内某一根桩的完成偏移：更不保守，但需要在聚合节点内部建子任务偏移，复杂度高。
- 忽略子任务级硬里程碑：会产生业务错误，不采用。

## 决策 7：目标门控沿用资源路径连续性配置

**决策**：当资源路径连续性目标关闭时，跳墩软惩罚和细排路径排序不建模，诊断显示未启用或未评价；硬约束仍执行。

**理由**：`specs/008-objective-model-gating` 已明确关闭路径连续性时不得产生路径节点和转移弧。本功能必须遵守该门控规则。

**已评估的替代方案**：

- 即使关闭路径连续性也运行两阶段路径细排：违反既有门控语义，不采用。
- 增加新的前端目标项控制两阶段精排：扩大配置面，不属于本期范围。

## 决策 8：细排失败回退粗排展开结果

**决策**：若粗排满足硬约束但细排失败或超时，返回展开后的粗排结果，并通过结果来源和诊断说明路径精修回退。

**理由**：用户需要可检查的当前资源方案。细排只是路径质量优化，不应让已满足硬约束的粗排结果丢失。

**已评估的替代方案**：

- 细排失败则整体失败：用户体验差，也不利于定位资源方案。
- 直接回退到原容量快排：会丢失粗排已完成的墩组资源分配和跳墩优化。

## 决策 9：移除 `same_structure_parallel_limit = 1` 作为机械桩基聚合门槛

**决策**：旋挖钻、冲击钻、回旋钻机械桩基墩组的聚合和组内单资源规则不再依赖 `same_structure_parallel_limit = 1`。除人工挖孔桩外，同一机械桩基墩组内所有原任务默认由一台命名资源负责；人工挖孔桩继续沿用原任务粒度资源分配，可由多个资源并行。

**理由**：用户希望基于 MVP 减少可配置参数对主链路的影响。当前实现把 `same_structure_parallel_limit = 1` 既当作资源业务规则，又当作两阶段粗排触发门槛，导致“是否进入桩基粗排”被资源池配置耦合。移除该门槛后，机械桩基粗排触发条件更直接：资源路径连续性目标启用，且第一阶段精排中存在机械钻机桩基墩组。

**已评估的替代方案**：

- 保留 `same_structure_parallel_limit = 1` 作为触发门槛：与用户本次简化要求冲突，不采用。
- 继续依赖现有同结构并行上限规则间接实现组内单资源：当参数未配置、为 0 或大于 1 时会失效，不采用。
- 将人工挖孔也纳入单资源墩组：会削弱人工挖孔多作业面并行能力，不采用。

## 决策 10：固定资源主链路直接进入第一阶段精排

**决策**：固定资源场景不再把外层池级最短工期排序作为命名资源精排的前置必跑阶段。当前资源可用时，主链路直接进入第一阶段精排；若第一阶段中存在机械钻机桩基墩组且资源路径连续性目标启用，再触发第二阶段路径精排。若第一阶段精排不可行或超时，当前资源主结果保持失败语义，并尝试进入资源建议分支。池级最短工期求解仅保留为资源建议测算或明确标记的内部诊断辅助，不作为当前资源失败后的兜底展示。

**理由**：原链路“池级排序 + 精排”会增加一次求解，并且让用户难以判断真正采用的是哪一层排程结果。MVP 口径下，第一阶段精排已经承担资源分配、硬里程碑、工艺前后置和跳墩偏好，应成为固定资源主入口。

**已评估的替代方案**：

- 完全删除所有基准解计算：需要同步重构控制缓冲、固定工期保护和资源建议路径，风险超过本次 MVP。
- 只改文案不改编排：用户仍会看到池级预排优先，不能解决主链路复杂度问题。
- 保留池级预排但只作为 warm start：仍会产生前置求解成本；本次不作为主路径采用。
- 第一阶段失败后回退展示池级最短工期或当前资源最佳努力：会弱化“命名资源精排失败”的真实信号，不采用。
