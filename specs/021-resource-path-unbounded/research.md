# 研究结论：resource_path_continuity 候选路径无窗口化

> 当前实现校正（2026-07-09）：`resource_path_continuity` 已从当前目标项体系中移除；旧输入字段仅作为废弃兼容字段被忽略。当前目标项为 `control_node_late`、`makespan_and_soft_milestone`、`resource_idle`。第一阶段路径连续性、无窗口候选路径和资源路径罚分均为历史设计，不再建路径 circuit 或产生路径罚分；机械钻组聚合、组内升序和同组同资源保留为基础规则。

## 决策 1：保留机械桩基钻机组聚合

**决策**：继续沿用当前机械钻机组聚合口径，同资源组、同结构物、同构件类型、同施工工艺的机械桩基聚合为一个内部路径节点。

**理由**：用户明确要求保留“钻机组节点”。当前 `_build_drill_group_nodes()` 已具备该能力，并且测试已覆盖原任务 ID 不被虚拟组 ID 替换。

**已评估的替代方案**：
- 按单根桩基生成路径节点：被拒绝，会制造同结构物内部无意义路径跳转。
- 按桥梁或幅别更大粒度聚合：被拒绝，会丢失结构物级资源归属和组内连续施工口径。

## 决策 2：移除距离窗口作为候选弧硬过滤

**决策**：同幅可施工序列距离和跨幅墩号差不再决定候选弧是否生成。只要两个钻机组同桥梁、同资源组、同构件类型、同施工工艺且位置可识别，就允许作为有向候选转移。

**理由**：窗口硬过滤会把可行路径排除在模型外，导致固定资源精排可能因候选不足而不可行或返回质量很差的早停结果。用户要求的是优化目标项，不是保留隐藏硬约束。

**已评估的替代方案**：
- 把同幅窗口从 2 放大到更大值：被拒绝，仍然是硬过滤。
- 失败后再临时放开窗口：被拒绝，会产生两套结果语义且难以解释。
- 保留窗口但降低权重：被拒绝，权重无法恢复被过滤掉的候选路径。

## 决策 3：同幅远距离只保留诊断，不进入罚分

**决策**：同幅仍按当前资源实际可施工序列计算距离，但 `penalty` 固定为 0，不再作为 `resource_path_continuity` 目标项罚分。

**理由**：用户追补要求移除 `resource_path_continuity` 的罚分机制，不再对资源顺序进行罚分。可施工序列距离仍有解释价值，可用于诊断候选路径和验证无窗口候选是否生效。

**已评估的替代方案**：
- 保留递增软罚分：被拒绝，仍会影响目标函数。
- 删除距离诊断：暂不采用，会降低结果解释能力。

## 决策 4：跨幅远距离只保留诊断，不进入罚分

**决策**：跨幅允许任意有效墩号差，继续记录 `cross_side_support_gap`，但 `penalty` 固定为 0。

**理由**：跨幅切换仍是重要诊断信息，但用户要求不再让资源顺序影响目标函数，因此不再区分同墩、邻墩或远距离跨幅的目标罚分。

**已评估的替代方案**：
- 保留基础切幅罚分：被拒绝，仍属于资源顺序罚分。
- 删除跨幅距离诊断：暂不采用，会降低结果解释能力。

## 决策 5：保留非距离合法性过滤

**决策**：缺少位置、桥梁不同、资源组不同、构件类型不同、施工工艺不同的候选仍不得生成。

**理由**：用户要求移除“候选路径窗口”约束，不等于允许跨工艺、跨资源组或缺少空间信息的任意连边。保留合法性过滤能避免目标项表达超出业务含义的路径。

**已评估的替代方案**：
- 所有节点全连接：被拒绝，会破坏资源和工艺语义。
- 对缺少位置的任务使用 sequence_order 兜底：暂不采用，容易把非空间排序误当空间路径。

## 决策 6：诊断字段兼容旧结果但改写语义

**决策**：保留现有 `stage1_route_*` 诊断字段，新增或填充候选模式语义时使用可选字段；旧 `same_side_window_exceeded` 和 `cross_side_gap_exceeded` 兼容字段不再因距离超限增加。

**理由**：前端和历史结果已经围绕 `drill_group_refinement`、`continuity_objective` 消费诊断。可选扩展和零计数比删除字段更安全。

**已评估的替代方案**：
- 删除窗口相关字段：被拒绝，容易破坏旧结果兼容。
- 继续统计“本来会超窗”的数量：暂不采用，容易让用户误以为仍存在窗口拒绝。

## 决策 7：普通资源路径顺序罚分同步移除

**决策**：普通资源路径连续性不再生成同幅跳点和跨幅切换罚分；当前主流程不再因 `resource_path_continuity` 打开普通资源路径顺序建模。

**理由**：用户明确要求移除 `resource_path_continuity` 的罚分机制，不再对资源顺序罚分。若只移除机械钻机组罚分而保留普通资源路径罚分，开启同一目标项时仍可能产生顺序分数，语义不一致。

**已评估的替代方案**：
- 只移除机械钻机组罚分：被拒绝，同一目标项在其他资源上仍会罚分。
- 删除所有诊断字段：暂不采用，兼容风险高。
