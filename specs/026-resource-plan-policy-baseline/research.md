# 研究结论：三方案资源策略基线与 LLM 校验

## 决策 1：采用确定性基线与 LLM 混合生成

- **决策**：后端先计算项目化三方案数量基线，LLM 负责组织策略、依据、风险和受约束的数量调整。
- **理由**：零工作量、上限和三方案单调性属于必须稳定执行的业务规则，不应只依赖提示词遵守。
- **已评估的替代方案**：纯提示词生成无法可靠保证硬规则；完全取消 LLM 会损失方案策略表达价值。

## 决策 2：工作量以生成任务的资源需求为准

- **决策**：通过当前场景生成的任务需求映射汇总资源工作量，不以资源池当前数量或结构物名称直接推断。
- **理由**：任务生成结果已经综合结构参数、工艺选择、工效和工艺逻辑，是“实际使用”的最近事实源。
- **已评估的替代方案**：按资源池数量判断会把预配置但未使用的工艺误判为有工作量；按结构物名称判断无法区分桩基工艺。

## 决策 3：未知资源和超限数量按整体验证失败处理

- **决策**：未知资源、非整数、负数、超原始上限、零工作量非零和单调性违规均形成结构化校验错误，不静默修正为有效 LLM 输出。
- **理由**：静默丢弃会掩盖提示或模型问题；反向扩大 `max_quantity` 会改变用户配置边界。
- **已评估的替代方案**：自动截断可作为确定性回退的内部裁剪，但不能把非法 LLM 草案标记为合法。

## 决策 4：只纠错重试一次

- **决策**：首次非法时把错误摘要连同原上下文发给同一 Provider 重试一次，仍非法立即使用基线。
- **理由**：一次重试兼顾模型自修复机会、时延和调用成本，并确保生成闭环稳定。
- **已评估的替代方案**：无限或多次重试增加不可控耗时；完全不重试降低外部模型可用率。

## 决策 5：保持当前输出 Schema

- **决策**：不引入 `recommended_profile`、对象型 `organization_strategy` 或新的前端字段。
- **理由**：当前前端和解析器依赖现有字段；求解前推荐违反 022 的产品边界。
- **已评估的替代方案**：扩充 Schema 会扩大前后端改动，并混淆资源草案与求解后推荐。

## 决策 6：连续梁使用真实主墩字段

- **决策**：连续梁组关系读取现有 `main_support_indices` / `main_support_refs`，不使用不存在的 `main_support`。
- **理由**：与当前项目模型和上下文构造保持一致，避免专项工作量判断失真。
- **已评估的替代方案**：新增别名字段没有业务收益且会扩大共享契约。
