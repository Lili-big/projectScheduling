# 功能规格：实际进度日期默认赋值

**功能目录/分支**：`039-progress-actual-date-defaults`

**创建日期**：2026-07-14

**状态**：草稿

**输入**：用户要求在更新任务实际进度状态时，结合任务计划时间、状态日期和系统当前日期，自动提供实际开始与实际完成日期的默认建议值；用户确认采用推荐的日期取值口径。

## 来源与评审上下文（必填）

- **来源文档**：`AGENTS.md`、`agent.md`、`README.md`、`docs/基建智能计划管控中枢整体产品方案_v1.0.md`、`specs/027-baseline-progress-forecast/`、`specs/031-progress-quantity-consistency/`。
- **评审结论**：需求成立。默认日期应作为保存前可编辑的建议值，不得由系统在保存时静默制造或覆盖实际事实；用户已确认采用计划日期与日期上限取较早值的口径。
- **使用的 Demo/代码事实**：当前状态切换会同步工程量但不会填充实际日期；进行中、暂停和已完成状态已分别存在实际日期必填校验；活动计划版本已保存逐任务计划起止日期；历史进度采用快照修订和审计记录。
- **不在范围内**：不按完成比例或工效反推日期，不接入外部考勤或现场系统，不新增实际日期来源持久化字段，不修改历史快照、滚动预测算法、CP-SAT、任务工期、资源配置或里程碑规则。

## 澄清记录

### 2026-07-14

- **问题**：实际日期默认值如何同时受计划日期、状态日期和系统当前日期约束？
  **结论**：采用用户确认的推荐口径。日期上限 `cutoff = min(状态日期, 系统当前日期)`；默认实际开始为 `min(计划开始, cutoff)`；已完成任务的默认实际完成为 `max(实际开始, min(计划完成, cutoff))`。
- **问题**：哪些状态生成默认日期？
  **结论**：进行中和暂停仅建议实际开始；已完成建议实际开始与实际完成；未开始清空两项；取消不新增默认日期，并保留已有实际事实。
- **问题**：自动建议是否覆盖人工或历史数据？
  **结论**：只补空值，建议值保存前可编辑；人工修改或历史快照数据不得被自动覆盖。状态日期变化时，仅重算本次页面会话中仍保持自动建议且未人工修改的草稿值。

## 用户场景与测试（必填）

### 用户故事 1 - 状态切换时获得实际日期建议（优先级：P1）

计划工程师在进度反馈页面把任务切换为进行中、暂停或已完成时，系统结合该任务的计划起止日期和当前进度数据截止日期，自动填充合理且不超出数据截止范围的实际日期建议值，减少逐行重复录入。

**优先级理由**：这是本需求的核心价值，可直接消除状态已更新但实际日期仍为空、保存时才被阻断的问题。

**独立测试**：选择具有明确计划起止日期的任务，分别切换为进行中、暂停和已完成，核对实际日期建议值与约定公式一致，并可在保存前修改。

**验收场景**：

1. **假设** 任务计划开始日期不晚于日期上限且实际开始为空，**当** 用户切换为进行中，**则** 实际开始默认等于计划开始日期，实际完成保持为空。
2. **假设** 任务计划开始日期晚于日期上限，**当** 用户切换为进行中，**则** 实际开始默认等于日期上限，用于表达提前开工。
3. **假设** 任务计划起止日期均不晚于日期上限且实际日期为空，**当** 用户切换为已完成，**则** 实际起止日期默认等于计划起止日期。
4. **假设** 任务计划完成日期晚于日期上限，**当** 用户切换为已完成，**则** 实际完成默认等于日期上限且不得早于默认实际开始。
5. **假设** 用户切换为暂停，**当** 实际开始为空，**则** 系统按进行中任务相同口径默认实际开始，实际完成保持为空。

---

### 用户故事 2 - 人工事实和历史快照不被覆盖（优先级：P1）

计划工程师可以修改系统给出的日期建议；已经人工填写或从历史快照加载的实际日期始终优先，状态或状态日期变化不得无提示覆盖这些事实。

**优先级理由**：实际日期属于可审计事实，防止静默覆盖与提供默认值同等重要。

**独立测试**：先修改系统建议日期，再切换状态日期或重新打开历史快照，验证人工值和历史值保持不变；只有仍保持系统建议且未人工修改的草稿随状态日期重算。

**验收场景**：

1. **假设** 实际开始已经由用户填写，**当** 用户把任务从进行中切换为暂停，**则** 系统保留已有实际开始，不重新赋值。
2. **假设** 已完成任务已有人工填写的实际起止日期，**当** 用户重新选择已完成，**则** 系统不覆盖任何已有日期。
3. **假设** 日期字段仍是尚未人工修改的系统建议值，**当** 状态日期变化，**则** 系统按新日期上限重算建议值。
4. **假设** 用户已经修改某个建议日期，**当** 状态日期变化，**则** 该人工值不被重算；若新状态日期使其非法，页面提示并由现有保存校验阻止提交。
5. **假设** 页面加载已保存历史快照，**当** 任务状态和日期被回显，**则** 系统不为缺失或已有日期自动生成新历史事实。

---

### 用户故事 3 - 核查默认值来源并安全保存（优先级：P2）

计划工程师能在任务行看到计划起止日期并理解默认建议的来源；保存时继续执行既有状态日期、日期顺序、状态必填和历史修订规则。

**优先级理由**：默认值必须可解释，避免用户把系统建议误认为已经确认的现场事实。

**独立测试**：核对任务行中的计划起止日期、默认实际日期和状态日期；构造晚于状态日期、完成早于开始等错误，验证保存被阻止且提示可定位到任务。

**验收场景**：

1. **假设** 活动计划存在任务排程，**当** 用户进入进度反馈页面，**则** 每个任务行可核查其计划开始和计划完成日期。
2. **假设** 系统生成了实际日期建议，**当** 用户查看对应日期字段，**则** 页面能区分尚未保存的建议值与已保存实际事实。
3. **假设** 用户把实际日期改为晚于状态日期，**当** 保存进度，**则** 系统阻止保存并指出对应任务。
4. **假设** 用户把实际完成日期改为早于实际开始日期，**当** 保存进度，**则** 系统阻止保存并指出日期顺序错误。

### 边界与异常场景

- 日期上限始终取状态日期和系统当前日期中的较早日期；历史状态日期不得生成晚于该状态日期的实际建议。
- 任务计划开始日期晚于日期上限时，默认实际开始取日期上限；计划完成日期晚于日期上限时，默认实际完成取日期上限。
- 默认实际完成必须不早于实际开始；若计划快照本身日期倒置或缺失，不生成冲突建议并显示可定位提示。
- 未开始状态必须清空实际开始和实际完成；从已完成切换到进行中或暂停时必须清空实际完成。
- 取消状态不新增默认实际日期；已有实际开始事实继续保留，实际完成不自动生成。
- 仅切换筛选条件、分页或刷新展示不得触发默认日期写入。
- 页面刷新前未保存的建议值可以丢失；刷新后只恢复后端已经保存的实际事实。
- 没有活动计划或任务没有可用计划日期时，继续使用现有空态或人工填写路径，不得生成无来源日期。

## 需求（必填）

### 功能需求

- **FR-001**：系统必须从当前活动计划的任务排程中读取逐任务计划开始日期和计划完成日期作为默认建议来源。
- **FR-002**：系统必须定义日期上限为状态日期与系统当前日期中的较早日期。
- **FR-003**：当实际开始为空且任务切换为进行中或暂停时，系统必须将实际开始建议为计划开始日期与日期上限中的较早日期。
- **FR-004**：当实际日期为空且任务切换为已完成时，系统必须按相同规则建议实际开始，并将实际完成建议为计划完成日期与日期上限中的较早日期，且不得早于实际开始。
- **FR-005**：当任务切换为未开始时，系统必须清空实际开始和实际完成日期。
- **FR-006**：当任务从已完成切换为进行中或暂停时，系统必须清空实际完成日期并保留合法的实际开始事实。
- **FR-007**：取消任务不得新增实际日期建议；已经存在的实际开始事实必须保留，实际完成不得自动生成。
- **FR-008**：系统默认建议只能填充空字段，不得覆盖人工输入、已保存进度或历史快照中的实际日期。
- **FR-009**：系统必须允许用户在保存前修改或清空默认建议值，并继续按任务状态执行既有必填校验。
- **FR-010**：系统必须能够区分仍保持系统建议的未保存日期和已被人工修改的日期草稿。
- **FR-011**：状态日期变化时，系统只能重算仍保持系统建议且未人工修改的日期；人工修改值不得被覆盖。
- **FR-012**：历史快照加载、页面筛选、分页和纯展示刷新不得触发新的实际日期默认赋值。
- **FR-013**：任务行必须展示或提供可直接核查的计划开始、计划完成日期，并说明实际日期建议尚未保存且可以修改。
- **FR-014**：任务计划日期缺失、倒置或无法识别时，系统不得生成冲突的实际日期建议，必须允许人工填写并显示原因。
- **FR-015**：保存时必须继续拒绝晚于状态日期的实际日期、早于实际开始的实际完成日期以及不满足相应任务状态必填条件的记录。
- **FR-016**：默认日期只有在用户保存有效进度快照后才成为可审计实际事实；未保存建议不得进入历史快照、滚动预测或调整方案。
- **FR-017**：保存默认日期形成的进度快照必须继续沿用现有修订号、更正原因、字段级审计和预测失效规则。
- **FR-018**：本功能不得修改实际完成比例、实际已完工程量、剩余工程量、实际工效、剩余工期或暂停/取消原因的现有计算和校验口径。
- **FR-019**：本功能不得修改活动计划快照、任务计划日期、任务工期、工艺逻辑、资源配置、里程碑或滚动预测算法。
- **FR-020**：现有不包含日期来源标记的历史进度数据必须继续可读取，不要求迁移或重写。

### 关键实体（涉及数据时填写）

- **任务计划日期**：活动计划版本中某任务已经确认的计划开始和计划完成日期，是默认建议的计划依据。
- **状态日期**：本次进度快照的数据截止日期，也是实际日期允许范围的主要上限。
- **系统当前日期**：用于阻止状态日期或默认建议落到未来日期的环境日期。
- **实际日期建议草稿**：尚未保存、可被用户修改的实际开始或实际完成建议，不属于历史事实。
- **实际进度事实**：用户保存成功后的实际日期，进入进度快照、审计和滚动预测。

## 成功标准（必填）

### 可衡量结果

- **SC-001**：具有有效计划日期的进行中、暂停和已完成任务，首次状态切换后需要手工逐个输入必填实际日期的任务数量减少 100%。
- **SC-002**：计划日期早于、跨越和晚于状态日期三类样例的默认实际日期与约定公式一致率为 100%。
- **SC-003**：人工填写或历史保存的实际日期被默认逻辑覆盖的次数为 0。
- **SC-004**：默认建议晚于状态日期、晚于系统当前日期或实际完成早于实际开始的次数为 0。
- **SC-005**：未开始、进行中、已完成、暂停和取消五种状态转换的日期清空、保留和默认行为均通过自动化或页面验收。
- **SC-006**：用户可以在一次状态切换后直接识别默认日期来源，并在保存前修改建议值。
- **SC-007**：使用默认建议保存的有效进度快照刷新后可原样恢复，且滚动预测读取的日期与保存结果一致。
- **SC-008**：现有历史进度快照无需迁移即可读取，原快照被静默改写的次数为 0。

## 默认假设

- MVP 面向当前单机 Demo 的本地计划工程师，不新增角色权限。
- 正常活动计划中的已排程任务具有稳定的计划开始和计划完成日期。
- 用户选择任务状态表示希望开始录入该状态所需实绩，因此系统可以提供可编辑建议，但不能替代用户确认。
- 页面使用业务本地日期判断系统当前日期，不使用可能跨日的 UTC 日期作为直接业务口径。
- 不新增持久化的“默认生成/人工填写”来源字段；未保存页面草稿可以在当前会话内区分，保存后统一视为用户确认的实际事实。
