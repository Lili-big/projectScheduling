# 契约：实际进度日期默认赋值

## 1. 页面输入来源

| 输入 | 权威来源 | 说明 |
|---|---|---|
| 计划开始/完成 | `active_plan.schedule_result_snapshot.tasks[]` | 通过 `task_id` 关联，只读展示与建议计算 |
| 状态日期 | 页面 `statusDate` | 进度数据截止日期 |
| 系统当前日期 | 浏览器本地日期 | 只用于限制建议值不进入未来 |
| 已有实际日期 | `current_progress_snapshot.entries[]` 或当前草稿 | 优先级高于自动建议 |

## 2. 页面交互契约

### 状态切换

- 进行中、暂停：只为空的实际开始提供建议，实际完成为空。
- 已完成：只为空的实际开始和实际完成提供建议。
- 未开始：清空实际开始和实际完成。
- 取消：不生成日期建议；已有实际开始不覆盖。
- 每个建议字段显示“系统建议”，用户可在保存前修改。

### 状态日期变化

- 使用新的 `min(statusDate, localToday)` 重算仍标记为系统建议的草稿字段。
- 人工修改、历史加载或已保存字段不重算。
- 状态日期为空或无效时不生成新建议，保存仍由现有校验处理。

### 任务行展示

- 在任务名称下显示 `计划：YYYY-MM-DD 至 YYYY-MM-DD`。
- 未找到求解快照任务或计划日期异常时显示 `计划日期不可用`，不伪造日期。
- 筛选、分页和表格滚动不改变建议或事实。

## 3. API 契约

接口继续使用现有进度保存请求，不新增字段：

```json
{
  "plan_version_id": "plan-version-id",
  "status_date": "2026-07-14",
  "entries": [
    {
      "task_id": "task-id",
      "status": "completed",
      "actual_start_date": "2026-07-10",
      "actual_finish_date": "2026-07-14",
      "percent_complete": 100,
      "remaining_days": 0,
      "remaining_days_source": "none",
      "notes": ""
    }
  ],
  "submitted_by": "本地计划工程师"
}
```

“系统建议”来源标记不得进入请求或响应。保存成功返回的日期立即视为已确认事实。

## 4. 错误与兼容契约

- 实际日期晚于状态日期、完成早于开始、状态必填缺失等情况继续由后端返回现有 422 错误。
- 页面不得为通过校验而覆盖人工日期；应展示后端错误并保留用户草稿以便修正。
- 保存接口整体失败时不把建议标记转为已保存事实。
- 历史快照加载不补空日期、不显示为“系统建议”、不修改版本文件。
- 无活动计划时继续显示现有空态，不执行日期建议逻辑。

## 5. 非目标

- 不按完成比例、工程量、工效或任务持续时间反推实际日期。
- 不修改预测、调整方案、计划版本或 CP-SAT 契约。
- 不持久化建议来源，不跨页面刷新保留未保存建议。
