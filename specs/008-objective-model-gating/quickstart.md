# 快速验证：目标指标建模门控

## 后端自动验证

实施后运行：

```powershell
.\.venv\Scripts\python.exe -m pytest backend\tests\test_scheduler.py -q
```

重点期望：

- 只启用 `control_node_late` 时，关闭目标项有效权重为 0。
- 资源路径连续性关闭时，路径节点数和转移弧数为 0。
- 全部资源类目标关闭时，资源组织优化建模跳过，但命名资源互斥仍生效。
- 默认目标配置下，4 个当前目标项仍按当前默认权重参与求解。

## 前端构建验证

实施后运行：

```powershell
npm --prefix frontend run build
```

重点期望：

- 目标函数配置区仍显示 4 个当前目标项。
- 关闭项在结果中显示为未启用或未评价。
- 已启用但罚分为 0 的指标不会被误显示为未启用。

## 手工场景验证

1. 启动本地服务。
2. 导入本地 Excel 案例。
3. 在目标函数配置中只保留“软控制节点总迟延”启用，关闭其他 3 个当前目标项。
4. 运行固定资源求解。
5. 查看结果：
   - `objective_terms_used` 中关闭项 `effective_weight = 0`。
   - 资源空闲、资源路径连续性显示为未启用或未评价。
   - 资源路径连续性建模诊断不再产生路径节点和转移弧。
   - 资源互斥、工艺前后置和硬里程碑仍按原规则执行。

## 回归场景

1. 恢复默认目标配置。
2. 运行同一案例。
3. 确认默认 4 个目标项全部启用，资源路径连续性和资源空闲仍可正常评价。
