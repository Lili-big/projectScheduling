# 研究结论：目标指标建模门控

## 决策 1：以有效权重作为建模门控来源

**决定**：后端使用归一化后的 `objective_weights` 判断目标项是否需要建模。有效权重为 0 的目标项不构建专属优化变量、约束、罚分项和已评价诊断。

**理由**：`objective_weights` 已经体现启用状态、默认合并和兼容过滤，是当前求解器实际使用的权重入口。以它为唯一门控来源可以避免前端状态、请求原始值和求解权重不一致。

**已评估的替代方案**：只在目标函数求和时乘以 0。该方案无法减少模型规模和建模耗时，拒绝。

## 决策 2：资源组织类目标拆分独立建模

**决定**：当前资源组织类目标只包含 `resource_idle`、`resource_path_continuity`，两者分别门控；两个资源目标全关时跳过资源组织类优化建模，只保留资源互斥硬约束。历史 `resource_workload_balance` 不再作为当前可配置目标项建模。

**理由**：统一构建资源组织项会导致关闭路径连续性后仍生成路径节点、转移弧和排序约束。拆分后，用户只启用某个当前资源目标时不会被其他关闭目标拖累。

**已评估的替代方案**：保留统一构建函数，仅返回空目标项。该方案仍可能创建中间变量和约束，拒绝。

## 决策 3：关闭指标显示为未启用或未评价

**决定**：关闭目标项的结果状态不展示为已评价 0 分，而是结合 `objective_terms_used.effective_weight = 0` 表达为未启用或未评价。

**理由**：已评价 0 分表示该指标被计算且无风险；关闭项没有建模，不能让用户误以为系统已优化成功。

**已评估的替代方案**：所有关闭项统一展示 0 分。该方案会造成产品解释歧义，拒绝。

## 决策 4：共享支持数据只为启用目标最小构建

**决定**：如果一个启用目标依赖某类基础信号，只构建启用目标所需的最小支持数据，不把被关闭目标或已废弃目标本身计入罚分或已评价状态。

**理由**：当前实现已移除 `risk_related_control_wait`、`control_buffer_risk` 等旧目标项，但共享支持数据规则仍适用于未来目标或现有目标间的基础数据复用。该规则能兼顾正确性和关闭项不被隐式评价。

**已评估的替代方案**：完全禁止构建任何关闭项相关支持数据。该方案会让部分启用目标缺少必要输入，影响正确性，拒绝。

## 决策 5：最佳努力目标放松作为独立例外

**决定**：严格精排失败后的最佳努力分支，如果需要放松强制里程碑或固定工期目标，仍可构建必要迟延变量并最小化迟延，但必须在最佳努力诊断中说明来源，不混同为用户已关闭的常规目标项。

**理由**：最佳努力分支的目标是返回当前资源下最合理的可用精排方案。如果放松目标后不最小化迟延，结果可能任意偏离目标，失去业务意义。

**已评估的替代方案**：用户关闭 `control_node_late` 后最佳努力也不最小化放松迟延。该方案会破坏最佳努力分支的可信度，拒绝。

## 决策 6：测试以结果元数据和模型诊断证明门控

**决定**：测试既验证用户可见状态，也验证关键模型诊断，例如路径节点数、转移弧数和资源组织状态。

**理由**：本需求的重点是“不建模”，只看最终罚分不足以证明模型规模下降。关键模型诊断可以在不暴露 OR-Tools 内部对象的情况下验证行为。

**已评估的替代方案**：只比较求解耗时。耗时受机器、搜索状态和时间限制影响，不适合作为唯一验收依据，拒绝。
