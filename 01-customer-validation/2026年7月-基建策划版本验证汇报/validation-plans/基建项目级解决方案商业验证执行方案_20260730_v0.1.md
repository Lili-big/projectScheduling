# 基建项目级解决方案项目制交付方案

> 版本：V0.1  
> 日期：2026-07-30  
> 状态：内部讨论稿  
> 适用阶段：领导汇报完成后的项目筛选、售前设计、报价、交付验证与复盘  
> 验证对象：由参数化建模、计划策划、方案比选、动态纠偏、总月周计划、产值统计和形象进度组成的基建项目级解决方案

## 1. 文档目的

本方案用于指导下一阶段从基建版标品转向基建项目级解决方案的验证推进思路，重点验证内容包括：

1. 哪类基建项目存在足够强的计划管理问题。
2. 谁是解决方案的使用者、决策者和付费者。
3. 客户是否愿意为完整解决方案进入报价、预算或采购流程。
4. 解决方案能否进入项目持续计划管理和真实决策，而非只用于展示。
5. 首个项目形成的模型、规则和交付方法能否在第二个项目复用，并覆盖交付成本。

## 2. 验证结果阶段性总结

### 2.1 阶段性决策结论

- 暂停独立基建版标品的持续开发。
- 用户并不缺少计划工具，Excel 等现有方式可以满足基本计划编制。
- 用户的主要问题是前期策划效率较低，以及现场变化后计划需要频繁调整。
- 客户当前更倾向于围绕已有方案讨论和优化，需要持续引导客户，建立精细化管理理念。
- 形象进度存在展示和汇报价值，但属于低频、交付成本较高的场景。
- 下一阶段采用项目解决方案方式，寻找少量强需求项目进行深度产品和商业验证。

### 2.2 解决方案初步思路
- 将参数化建模、计划策划、多方案比选、动态纠偏、总月周计划、产值统计和形象进度组合成一个项目级解决方案。
- 对外销售一个完整解决方案，对内按项目客户需求，设计产品能力分阶段逐步迭代交付。
- 按照意向客户扫描 — 明确客户付费意愿 — FDE项目交付 — 客户验收并确认营收 — 评估产品化沉淀

## 3. 解决方案一页纸

### 基建项目计划策划与动态管控解决方案

### 3.1 目标客户

- 大型基建施工总承包项目。
- 具有明确控制节点、较复杂施工组织和持续计划调整要求的项目。
- 能够提供工程结构、工程量、计划、实际进度和专业校核人员的项目。

### 3.2 关键角色

| 角色 | 主要任务 |
| --- | --- |
| 项目经理 | 确认管理目标、资源投入和最终项目决策 |
| 项目总工 | 确认施工逻辑、方案可实施性和变更影响 |
| 工程部长/计划负责人 | 编制和维护总月周计划，核实现场进度与偏差 |
| 统计/合同相关人员 | 确认工程量、价格和产值统计口径 |
|  |

### 3.3 客户问题

客户可以使用 Excel 和专业软件编制计划，但项目结构、工程量、计划任务、产值、实际进度和现场变化通常分散在不同资料中。计划形成后，持续更新、跨周期拆解、变化影响分析和管理决策仍高度依赖人工经验与重复整理。

### 3.4 价值主张

将工程对象、计划任务、工程量、产值、实际进度和变更事件放在同一条项目数据链上，支持项目持续回答：

- 原来如何策划和安排。
- 当前实际完成多少。
- 总计划如何分解到月、周。
- 计划产值和实际产值如何形成。
- 重大变化影响哪些任务和控制节点。
- 剩余计划需要如何调整。
- 调整结果如何通过形象进度、统计分析和管理清单表达。

### 3.6 业务闭环

```mermaid
flowchart LR
    A["工程结构、工程量、价格口径和控制节点"] --> B["参数化建模"]
    B --> C["前期计划策划"]
    C --> D["客户提出局部备选方案"]
    D --> E["方案影响测算与比选"]
    E --> F["确认基准计划"]
    F --> G["总计划、月计划、周计划拆解"]
    G --> H["计划工程量与计划产值分解"]
    H --> I["实际进度更新与实际产值汇总"]
    I --> J["偏差识别与重大变更事件"]
    J --> K["影响分析、动态纠偏与剩余计划"]
    K --> G
    I --> L["形象进度、统计分析与项目汇报"]
    K --> L
```

## 4. 解决方案范围

### 4.1 能力组成

| 能力域 | 主要输入 | 主要处理 | 主要输出 | 本轮验证重点 |
| --- | --- | --- | --- | --- |
| 参数化建模与形象进度 | 工程结构、构件、工程量、空间位置 | 建立工程对象和展示模型 | 工程结构模型、形象进度、阶段汇报 | 初始化与交付成本是否可控 |
| 前期策划与方案比选 | 控制节点、施工逻辑、工效、资源、客户方案 | 形成基准计划并测算局部方案影响 | 基准计划、方案差异、节点和资源影响 | 能否形成付费决策价值 |
| 总月周计划拆解 | 基准计划、当前状态、周期目标 | 将任务和工程量分解至月、周 | 总计划、月计划、周计划、周期目标 | 是否持续用于项目过程管控 |
| 产值分解与汇总 | 工程量、价格口径、计划任务、实际完成量 | 计算计划产值和实际产值 | 月周计划产值、完成产值、偏差汇总 | 能否替代真实统计工作 |
| 重大变更与动态纠偏 | 基准计划、实际状态、真实变更事件 | 识别影响范围并形成剩余计划建议 | 受影响任务、节点风险、调整方案、版本对比 | 是否进入真实进度纠偏决策 |

### 4.2 关键项目数据

- 项目结构物、构件或工作分解结构。
- 计划任务及任务层级。
- 工程量、单位和来源。
- 单价或产值计算口径。
- 控制节点及外部约束。
- 基准计划版本、当前计划版本和历史版本。
- 总计划、月计划、周计划的来源关系。
- 实际进度状态和统计截止时间。
- 变更事件、影响任务、确认意见和管理动作。

## 5. 目标项目准入与筛选表

### 5.1 项目选择维度

| 维度 | 评分问题 |
| --- | --- |
| 痛点强度 | 存在明确的前期策划、计划拆解或动态调整问题 |
| 事件真实性 | 未来 1—2 个月内存在真实方案决策或重大变更窗口 |
| 数据准备度 | 能提供工程结构、工程量、清单单价和实际进度数据 |
| 责任人完整度 | 决策、校核、维护和统计角色是否齐备 |
| 付费可能性 | 付费决策人参与需求和报价沟通 |
| 复用价值 | 项目类型、数据和规则是否具有跨项目代表性 |


## 6. 客户数据与责任人准备清单

### 6.1 数据清单

| 数据类别 | 最低要求 | 来源责任人 | 验证要求 |
| --- | --- | --- | --- |
| 项目结构 | 标段、单位工程、分部工程、主要结构物 | 工程部门 | 名称和层级可唯一识别 |
| 工程量 | 主要工作项、单位、设计量或控制量 | 工程/合同部门 | 与计划任务能够建立关系 |
| 价格口径 | 用于计划产值统计的单价或折算规则 | 合同/统计人员 | 明确仅用于何种统计口径 |
| 控制节点 | 业主节点、开工、贯通、架梁、交工等 | 项目经理/总工 | 有日期、来源和责任人 |
| 基准计划 | 一版已确认且可解释的项目计划 | 工程部门 | 任务、日期、逻辑关系可读取 |
| 施工逻辑 | 关键先后关系、工作面、工法和外部约束 | 项目总工 | 由专业人员确认 |
| 工效与资源 | 关键工序工效及影响计划的主要资源 | 工程部门 | 记录来源、适用范围和版本 |
| 实际进度 | 已开始、已完成、剩余量和统计日期 | 现场/计划人员 | 与工程对象和计划任务关联 |
| 月周计划 | 当前使用模板、填报频率和责任人 | 计划人员 | 明确总月周之间的来源关系 |
| 变更事件 | 事件事实、发生时间、影响区域和处置状态 | 事件责任人 | 必须是真实且尚未完成处置 |

## 7. 三阶段交付、报价与验收

### 7.1 对外售卖方式

对外统一销售“基建项目计划策划与动态管控解决方案”，合同或报价中可以按以下成本结构拆分：

- 软件使用或许可费用。
- 项目数据初始化与参数化建模费用。
- 计划策划与方案影响测算实施费用。
- 总月周计划及产值规则配置费用。
- 持续进度维护与顾问服务费用。
- 经确认的项目其他扩展费用。

### 7.2 阶段一：项目策划基线

**交付内容**

- 项目结构和参数化工程模型。
- 控制节点、主要约束和数据来源清单。
- 一版可解释、可校核的基准计划。
- 1—2 个局部备选方案的影响对比。
- 计划版形象进度及阶段汇报材料。

**验收条件**

- 项目总工确认施工逻辑和关键约束。
- 工程部门确认基准计划可用于后续月周拆解。
- 项目经理确认选择的方案和决策依据。
- 数据、规则和版本形成书面记录。

### 7.3 阶段二：计划执行与统计

**交付内容**

- 总计划向月计划、周计划的拆解规则。
- 计划工程量和计划产值分解。
- 实际进度更新流程。
- 实际完成量和实际产值汇总。
- 计划偏差、形象进度和周期分析材料。

**验收条件**

- 至少完成两个连续计划周期的数据更新。
- 月周计划进入项目例会、生产协调或公司检查。
- 工程量和产值口径由责任人员确认。
- 记录原方式和新方式的人力投入、耗时和差异。

### 7.4 阶段三：重大变更与动态纠偏

**交付内容**

- 一个真实重大变更事件的事实记录。
- 受影响任务、控制节点和连锁关系。
- 工期、产值和剩余工作影响分析。
- 调整建议、剩余计划和版本对比。
- 专业校核意见、最终决策和管理动作记录。

**验收条件**

- 事件不是我方构造或已完成处置的历史回放。
- 项目总工或工程部门逐项确认影响判断。
- 结果实际触发计划修订、资源协调、施工组织调整或公司督办中的至少一项。
- 记录客户接受、修改和否决的内容及原因。

## 8. 定价原则

重点关注预算、成交和成本三个维度。

| 价格维度 | 需要记录的内容 |
| --- | --- |
| 客户预算 | 预算来源、预算上限、审批角色和采购方式 |
| 初始报价 | 软件、实施、建模、服务和扩展分别报价 |
|  |
| 成交价格 | 合同金额、付款节点和验收条件 |
| 实际成本 | 各角色投入人日、差旅、第三方成本和维护投入 |
| 后续意愿 | 续费、增购、第二项目采购或推荐意愿 |


### 10.1 必须保存的证据

- 客户原始计划和状态快照。
- 方案、变更事件和责任人确认记录。
- 系统输入、输出和版本记录。
- 专业校核意见。
- 项目会议、计划修订、资源协调或督办记录。
- 使用频率和人员投入。
- 报价、商务反馈和成交信息。
- 我方实施、研发和维护投入。
- 第二项目复用差异。
