# 工点级资源作用域与求解规则需求文档

版本：v1.0

日期：2026-07-17

适用范围：桥梁工点资源配置、任务生成、资源候选、命名资源、求解与结果诊断

关联产品 PRD：`03-requirements/product/资源配置页面需求文档_v1.2.md`

关联规格：`03-requirements/specs/047-workpoint-resource-configuration/spec.md`

## 1. 文档定位

本文是工点级资源作用域和数量求解语义的独立权威规则源。PRD 描述用户可见能力，Spec Kit 描述本次研发边界；字段默认、有效配置解析、候选筛选、数量边界和兼容迁移以本文为准。

规则不得依赖桥梁名称、工点 ID 格式、中文关键字或 0/1/10/15 等特殊值。所有判断只读取标准字段和权威项目主数据关系。

## 2. 输入、输出与枚举

### 2.1 输入

- `ScenarioInput.project_data_version_id`：本次配置对应的项目主数据版本。
- `ScenarioInput.project.bridges[].id`：本期桥梁工点稳定 ID，也是任务 `bridge_id` 的权威来源。
- `ScenarioInput.resource_pools[]`：资源类型全局默认、作用域和工点覆盖。
- `Task.bridge_id`：任务所属桥梁工点。
- 工艺库输出的 `Task.compatible_resource_types` 初始资源类型。

### 2.2 作用域枚举

`ResourceScopeMode` 只允许：

- `PROJECT_SHARED`：同一命名资源可成为多个获准工点任务的候选，并由资源互斥约束保证串行。
- `WORKPOINT_EXCLUSIVE`：每个工点生成独立命名资源，只能成为该工点任务候选。

### 2.3 `ResourcePool` 新增规范字段

| 字段 | 类型 | 默认/约束 | 含义 |
| --- | --- | --- | --- |
| `scope_mode` | `ResourceScopeMode` | 旧数据缺失时 `PROJECT_SHARED` | 资源类型的统一作用域模式 |
| `authorized_workpoint_ids` | `string[] \| null` | `null` 表示当前版本全部桥梁工点；显式数组需去重排序 | 可使用该资源的桥梁工点集合 |
| `workpoint_overrides` | `WorkpointResourceOverride[]` | 默认空数组；同一工点最多一条 | 工点对全局默认的显式覆盖 |

`WorkpointResourceOverride` 字段：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `workpoint_id` | string | 必须属于同一 `project_data_version_id` 的桥梁工点 |
| `enabled` | boolean/null | `null` 继承全局 |
| `quantity` | int/null | `null` 继承全局；非负整数 |
| `max_quantity` | int/null | `null` 继承全局；标准化后不小于有效 `quantity` |

不新增 `min_quantity`。

### 2.4 `Resource` 规范字段

命名资源进入 `ScheduleInput.resources[]` 时必须携带：

- `scope_mode`；
- `eligible_workpoint_ids`：该实例可服务的工点集合；
- `exclusive_workpoint_id`：仅独享模式填写；
- 既有 `id/type/pool_id/pool_label/calendar_id` 等字段。

求解器只读这些字段筛选候选，不解析 `Resource.id`。

### 2.5 输出与诊断

`GeneratedScheduleInput.source_summary` 至少记录资源作用域规则版本、共享/独享有效池数量、继承工点数量和 `project_shared_transfer_time_days=0`。求解结果或诊断必须能够说明资源实例的作用域、分配工点及项目共享转场 0 天规则。

## 3. 有效配置解析

### R-001 权威工点集合

本期有效工点集合为当前 `project_data_version_id` 下 `ScenarioInput.project.bridges` 中 `workpoint_type=bridge` 的稳定 ID。非桥梁工点不参与解析。

### R-002 获准范围

- `authorized_workpoint_ids=null`：取 R-001 的全部桥梁工点，用于既有项目兼容和默认配置。
- 显式数组：只取同时存在于 R-001 的 ID；重复项去重并稳定排序。
- 显式引用旧版本或不存在的 ID：输出错误，不静默映射到名称相同的工点。

### R-003 继承

对每个获准工点和资源类型：

1. 找到该工点覆盖记录；
2. 覆盖字段非空时用覆盖值；
3. 覆盖字段为空或无覆盖记录时用 `ResourcePool` 全局值；
4. 标准化有效 `max_quantity = max(effective_quantity, effective_max_quantity)`；
5. 记录来源为 `inherited` 或 `overridden`。

未配置工点执行以上继承流程，禁止转换成 `UNLIMITED` 或空候选。

### R-004 启用和默认充足

- 工点没有覆盖记录时必须先执行 R-003 继承，禁止直接把“未配置工点”归入默认充足。
- `resource_mode=UNLIMITED`、`enabled=false` 或显式有效上限为 0，继续沿用既有统一默认充足 warning 语义；三者都是用户或全局配置的显式状态，不等同于“未配置工点”。
- 对 `enabled=true`、`resource_mode=LIMITED` 且有效上限大于 0 的有效池，任务工点身份缺失、工点不在获准范围或没有合法命名资源时，必须产生错误/不可求解诊断，不得按默认充足继续。
- 本期不改变全局资源类型完全缺失时的既有兼容策略；只修正已存在资源池下的工点继承和作用域。

## 4. 命名资源展开

### R-005 固定资源数量

固定资源求最短工期使用有效 `quantity`：

- `PROJECT_SHARED`：整个资源池只展开 `quantity` 个实例；每个实例的 `eligible_workpoint_ids` 为全部获准工点。
- `WORKPOINT_EXCLUSIVE`：对每个获准工点分别按该工点有效 `quantity` 展开实例；实例的 `eligible_workpoint_ids` 只含自身。

### R-006 最大资源数量

最大资源预检、固定工期求最少资源和增配候选生成使用有效 `max_quantity` 作为每个有效池的上界。共享模式形成一个有效池，独享模式按工点形成多个有效池。

### R-007 稳定命名资源 ID

推荐 ID 结构：

- 共享：`{pool_id}::project::{index}`；
- 独享：`{pool_id}::workpoint::{workpoint_id}::{index}`。

该结构仅保证唯一、稳定和可诊断；任何业务逻辑不得通过字符串拆分 ID 判断作用域。作用域只读规范字段。

## 5. 任务候选

### R-008 类型匹配

任务先按现有统一工艺/构件映射确定资源类型。工点作用域不得改变工艺库资源类型，也不得按桥名、工点名或 ID 补类型。

### R-009 作用域匹配

某命名资源成为任务候选必须同时满足：

1. 资源已启用；
2. 资源类型在任务 `compatible_resource_types` 中；
3. 任务 `bridge_id` 存在且属于资源 `eligible_workpoint_ids`；
4. 独享模式下 `task.bridge_id == exclusive_workpoint_id`。

任务缺少 `bridge_id` 或匹配不到候选时按 R-004 输出阻断诊断。

## 6. 求解规则

### R-010 资源互斥

每个受限任务从合法候选中选择且仅选择一个命名资源。同一命名资源的任务区间建立 `NoOverlap` 或等价容量 1 约束。

结果：项目共享实例可在获准工点间串行；工点独享实例不能跨工点被分配。

### R-011 固定资源求最短工期

- 输入容量为 R-005 展开的 `quantity`。
- 目标函数和既有硬/软约束保持不变。
- 不允许求解器自动增加或减少配置数量。

### R-012 增配建议

- 每个有效池搜索范围为 `[quantity, max_quantity]`。
- 推荐量不得低于当前 `quantity`，不得高于 `max_quantity`。
- 独享模式按工点分别搜索；共享模式按项目共享池搜索。

### R-013 固定工期求最少资源

- 每个有效池容量上界为 `max_quantity`。
- 数学下界从 0 开始，再叠加求解器根据任务覆盖、工期窗口和硬约束推导的必要下界。
- `quantity` 不参与下界计算，故 `recommended_quantity` 可以低于 `quantity`。
- 若目标在最大资源下仍不可行，沿用统一 `max_resources_target_failed`；限时无法证明时沿用 `unconfirmed`。

### R-014 项目共享转场

项目共享资源从工点 A 转到工点 B 时：

- MVP 不增加前置关系、持续时间或成本，转场时间固定为 0 天；
- 仍受同一资源互斥约束，不能并发占用；
- 配置页、结果页和诊断必须显示“跨工点串行、转场时间按 0 天”；
- 非零转场时间属于后续独立规格，不得在本期以名称距离或 ID 顺序估算。

## 7. AI 资源助手规则

### R-015 输入画像

AI 上下文必须包含每个资源类型的 `scope_mode`、获准工点、全局默认和工点有效配置。任务需求按“资源池 + 工点作用域”统计，不得只保留资源类型总数。

### R-016 输出边界

- AI 不得新增资源类型、工点或作用域，不得修改获准范围。
- 共享模式输出项目池数量；独享模式输出各工点数量。
- 每项数量为非负整数且不高于对应 `max_quantity`。
- 旧 `resource_updates: {resource_type: quantity}` 仅兼容项目共享；独享模式必须使用带 `pool_id/workpoint_id` 的结构化更新。
- AI 输出是建议，不直接改变 `quantity`；人工采纳后才写回并触发失效。

## 8. 持久化、版本和失效

### R-017 兼容迁移

- 旧 `ResourcePool` 缺少 `scope_mode`：读取为 `PROJECT_SHARED`。
- 缺少 `authorized_workpoint_ids`：读取为当前版本全部桥梁工点。
- 缺少 `workpoint_overrides`：读取为空数组。
- 迁移发生在统一反序列化/标准化路径；禁止为具体项目或具体 ID 写一次性补丁。

### R-018 指纹

作用域、获准工点、覆盖、数量、上限、启用和日历必须进入场景、AI 方案和计划版本的稳定指纹。集合字段先去重排序，覆盖按 `workpoint_id` 稳定排序，保证相同语义得到相同指纹。

### R-019 结果失效

R-018 任一语义变化后，旧任务图、求解结果、AI 解释和方案对比不得作为当前结果复用。旧持久化快照保留审计，但新计算必须生成新指纹和新结果。

## 9. 可复现规则样例

### 样例 1：独享继承

输入：池 P 为独享，默认 `quantity=1,max_quantity=3`；A 覆盖 `2,4`；B 无覆盖。

输出：固定资源展开 A 两个、B 一个独享实例；A 任务候选只含 A 实例，B 任务候选只含 B 实例；继承计数为 1。

### 样例 2：共享串行

输入：池 P 为共享，`quantity=1,max_quantity=2`，获准 A、B，各有一个持续 5 天且无前置的任务。

输出：固定资源模式只有一个实例；两任务不能重叠，最短资源占用跨度至少 10 天；跨工点转场增加 0 天；结果包含统一提示。

### 样例 3：最少资源低于当前投入

输入：有效池 `quantity=3,max_quantity=5`，固定工期目标在 2 个实例下可行。

输出：固定资源模式使用 3；增配建议范围 3～5；固定工期最少资源可以推荐 2，并记录 `current_quantity=3,recommended_quantity=2`。

### 样例 4：受限资源缺失

输入：任务需要受限类型 X，但当前工点未找到 X 的有效池或合法候选。

输出：在资源池已启用、`LIMITED` 且有效上限大于 0 的前提下，任务候选为空并产生阻断错误；不得记录为 `UNLIMITED`，不得按资源默认充足生成可接受求解结果。显式停用、显式 `UNLIMITED` 或显式零上限仍沿用既有 warning。

## 10. 禁止项

- 禁止新增 `min_quantity` 或把 `quantity`重新解释为固定工期最少资源下界。
- 禁止按工点名称、桥梁名称、ID 前后缀、中文字符串或特殊数量判断作用域。
- 禁止项目共享资源绕过命名资源互斥。
- 禁止未配置工点降级成默认充足。
- 禁止在本期引入非零转场、跨项目共享或审批流程。
