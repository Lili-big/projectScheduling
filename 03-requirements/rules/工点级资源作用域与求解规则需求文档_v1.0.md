# 工点级资源作用域与求解规则需求文档

**版本**：v1.1
**日期**：2026-07-18
**关联规格**：`03-requirements/specs/048-workpoint-first-resource-allocation/`
**演进来源**：047 工点级资源作用域与求解规则

## 1. 规则目标

本规则定义工点独享资源与范围共享资源池的规范数据结构、候选生成、容量互斥、诊断、兼容和迁移语义。规范输入仍为 `ScenarioInput.resource_pools`；资源类型只表达能力类别，资源池标识表达一组独立容量。

## 2. 规范资源池模型

### 2.1 公共字段

每个资源池至少包含：

- `id`：场景内唯一资源池标识；
- `type`：资源类型；
- `quantity`：当前投入，整数且不小于 0；
- `max_quantity`：可增上限，整数且不小于 `quantity`；
- `enabled`：是否启用；
- `scope_mode`：`WORKPOINT_EXCLUSIVE` 或 `PROJECT_SHARED`；
- `workpoint_id`：工点独享记录的所属工点；
- `authorized_workpoint_ids`：共享池允许服务的工点集合；
- 兼容读取所需的旧字段和未知扩展字段。

`id` 必须唯一。同一种 `type` 可以出现多个资源池，禁止以资源类型去重、合并数量或覆盖配置。

### 2.2 工点独享资源不变量

工点独享资源必须同时满足：

- `scope_mode = WORKPOINT_EXCLUSIVE`；
- `workpoint_id` 是场景内已知工点；
- `authorized_workpoint_ids` 为空；
- 不再使用工点覆盖表表达规范数量；
- `(workpoint_id, type)` 在规范输入中唯一。

工点独享池只向 `workpoint_id` 对应工点的任务提供候选。

### 2.3 范围共享资源池不变量

共享池必须同时满足：

- `scope_mode = PROJECT_SHARED`；
- `workpoint_id` 为空；
- `authorized_workpoint_ids` 为空或缺省时表示全项目共享；
- 显式范围必须是已知工点组成的非空集合；
- 每个池的数量、上限和授权集合独立。

同类型多个共享池是合法输入。它们只能共享资源类型语义，不能共享容量、上限或实例身份。

## 3. 任务资源候选生成

对任务 `t`、任务工点 `w` 和所需资源类型 `r`，合法候选集合是下列资源池的并集：

1. `type = r`、启用、`scope_mode = WORKPOINT_EXCLUSIVE` 且 `workpoint_id = w` 的工点资源池；
2. `type = r`、启用、`scope_mode = PROJECT_SHARED`，且授权范围为全项目或包含 `w` 的全部共享池。

候选并集没有“本地优先”或“共享优先”的硬编码顺序。求解器在全部合法候选中决定绑定和使用先后。

在当前资源模式下，只有 `quantity > 0` 的池可以展开实例；`quantity = 0` 表示当前不存在该资源。在允许扩容的规划模式下，可以在不超过 `max_quantity` 的前提下形成增量容量，但不得把 `max_quantity` 偷换为当前数量。

## 4. 容量、互斥与流转

- 每个资源池按自己的池标识独立展开容量实例或建立累计容量约束。
- 同一池、同一实例在任意时刻最多服务一个任务；同类型不同池不得共享实例。
- 工点独享实例不得流转到其他工点。
- 共享实例可以在其授权工点集合内由求解器安排连续任务。
- 本期共享实例跨工点流转时间为 0、费用为 0，不产生额外区间、目标项或人工顺序约束。
- 任务一旦绑定某个池，其容量占用和结果引用必须保留该池标识。

## 5. 不可行与诊断

如果必需资源的合法候选集合为空，求解前检查或求解结果必须阻断，并至少返回：

- `workpoint_id`；
- `task_id`；
- `resource_type`；
- 结构化原因，例如 `LOCAL_QUANTITY_ZERO`、`LOCAL_DISABLED`、`SHARED_SCOPE_EXCLUDED`、`NO_RESOURCE_POOL`。

诊断应区分“存在同类型池但不授权该工点”和“场景中完全没有该类型池”，以支持页面准确修正配置。

## 6. 当前、上限与最小资源模式

### 6.1 当前资源

每个池使用自己的 `quantity`。数量为 0 的池不生成实例；不得回退使用 `max_quantity`。

### 6.2 可增上限

扩容建议和资源调整以资源池标识为键，在 `[quantity, max_quantity]` 内计算。仅当旧输入中的资源类型能够唯一定位一个共享池时，才允许兼容类型键；同类型多池时必须拒绝歧义输入。

### 6.3 最小资源

最小资源结果必须按资源池标识归属。若同一任务可使用多个重叠授权的同类型池，下界估计不得把同一任务需求重复累计到每个池；最终可行性仍以带池级容量约束的求解结果为准。

## 7. 方案控制、AI 与结果契约

- `resource_pool_id` 是方案控制、AI 建议、采用建议、调整方案和求解结果的稳定资源引用。
- 结构化数量结果逐池返回，并对工点独享记录同时携带 `workpoint_id`。
- 同类型仅有一个旧共享池时，可兼容旧的“类型 → 数量”映射；同类型多池时不得默认选择第一条。
- 方案指纹、缓存键和持久化比较必须包含池标识、作用域、工点归属、授权集合、数量与上限，避免不同配置错误复用。
- 镜像调度入口与主后端必须遵循相同的作用域过滤与池标识语义。

## 8. 兼容与迁移规则

### 8.1 旧项目共享池

旧 `PROJECT_SHARED` 配置继续作为一个共享池读取：

- 保留原 `id`、`type`、`quantity` 和 `max_quantity`；
- 保留原授权范围；
- 缺省范围继续解释为全项目共享；
- 不拆分到工点，不按工点数量复制，不自动合并同类型池；
- 未识别扩展字段应往返保留。

### 8.2 047 工点覆盖模型

旧 `WORKPOINT_EXCLUSIVE` 池及其工点数量覆盖只在能无损映射时展开为规范工点资源记录：

- 每个有效工点生成一条独立池记录；
- 数量和上限按原工点覆盖保留；
- 新池标识必须稳定且不冲突；
- 未知工点、重复 `(workpoint_id, type)`、无法归属的数量或可能丢失未知字段时，迁移必须阻断并返回诊断。

迁移不能把旧项目共享配置拆分为工点资源，也不能为了通过校验而静默删除字段。

## 9. 验证矩阵

至少验证以下场景：

1. 工点本地数量为 0，且没有合法共享池时阻断并返回工点、任务、资源诊断。
2. 工点本地数量为 0，但存在授权共享池时可形成共享候选。
3. 同类型两个共享池分别授权不同工点，集合外任务不能获得候选。
4. 同类型两个共享池授权范围重叠时仍保持独立容量与结果标识。
5. 一个共享实例跨工点顺序服务任务但不发生时间重叠，且无转场工期或费用。
6. 旧共享池往返读取后数量、上限、范围和未知字段不丢失且不拆分。
7. 旧工点覆盖能无损展开；存在冲突或未知工点时明确阻断。
8. AI、方案控制、预测调整和镜像入口在同类型多池下使用池标识且拒绝歧义类型键。
