## 用户场景与测试

### 用户故事 1 - 按资源类型配置工点作用域（优先级：P1）

计划工程师为每一种受限资源选择项目共享或工点独享，并查看每个桥梁工点的继承/覆盖状态。未单独配置的工点仍按全局默认形成受限资源。

**优先级理由**：作用域和继承是后续命名资源、候选和求解正确性的输入基础。

**独立测试**：使用两个桥梁工点、一个共享资源类型和一个独享资源类型保存并重载配置，核对权威工点、继承值、覆盖值和标准化结果。

**验收场景**：

1. **假设**资源类型为工点独享且全局默认 `quantity=1,max_quantity=3`，**当**工点 A 覆盖为 `2,4` 而工点 B 不配置，**则**A 显示覆盖值，B 显示继承的 `1,3`，两者均不是默认充足。
2. **假设**既有项目级资源池缺少作用域字段，**当**系统加载它，**则**统一解释为项目共享并覆盖当前项目全部桥梁工点，数量不变。
3. **假设**覆盖引用旧项目主数据版本的工点 ID，**当**用户加载或保存，**则**系统提示版本失配并阻止静默套用。

---

### 用户故事 2 - 生成正确候选并按三类数量语义求解（优先级：P1）

计划工程师生成任务图并运行求解时，共享资源可跨获准工点串行，独享资源不能跨工点；固定资源、增配建议和固定工期最少资源分别使用正确数量边界。

**优先级理由**：这是本功能对排程结果的核心业务价值。

**独立测试**：对固定双工点样例生成 `ScenarioInput → ScheduleInput → ScheduleResult`，核对资源实例、候选、分配、重叠、数量推荐和诊断。

**验收场景**：

1. **假设**一个项目共享资源实例获准服务 A、B，**当**A、B 任务无其他前置，**则**两任务不能同时占用该实例，可跨工点串行且转场增加 0 天。
2. **假设**A、B 各有一个独享资源实例，**当**生成候选，**则**A 任务候选不含 B 实例，B 任务候选不含 A 实例。
3. **假设**有效池 `quantity=3,max_quantity=5`，**当**分别运行固定资源、增配建议和固定工期最少资源，**则**固定资源使用 3，增配只搜索 3～5，最少资源可返回 0～5 内经证明可行且低于 3 的值。
4. **假设**资源池已启用、`LIMITED` 且有效上限大于 0，但受限任务没有合法工点候选，**当**生成或求解，**则**输出阻断诊断，不按资源默认充足继续；显式停用、`UNLIMITED` 或零上限仍沿用既有 warning。

---

### 用户故事 3 - AI、持久化和结果失效保留作用域（优先级：P2）

计划工程师保存配置、使用 AI 资源助手、确认方案或修改资源后，系统在所有快照和结果指纹中保留作用域与工点信息，且不复用过期结论。

**优先级理由**：缺少这一闭环会让正确的配置在助手或持久化路径中丢失。

**独立测试**：保存、重载、生成 AI 方案、修改配置并重新查询结果，核对结构化作用域、稳定指纹和 stale 状态。

**验收场景**：

1. **假设**资源类型为工点独享，**当**AI 生成或更新数量建议，**则**建议按工点输出，不得改变作用域或新增工点。
2. **假设**作用域、获准工点或工点覆盖发生变化，**当**页面或后端比较指纹，**则**旧任务图、求解、AI 解释和方案对比全部失效。
3. **假设**旧本地配置没有新字段，**当**统一迁移并再次保存，**则**得到标准项目共享配置，不修改历史快照原文。

---

### 用户故事 4 - 页面和结果透明说明共享规则（优先级：P2）

计划工程师在配置页和结果页能看清资源作用域、继承来源、分配工点和共享资源转场 0 天限制，不会把系统假设误认为真实调拨时间。

**优先级理由**：共享资源的 0 天转场是 MVP 限制，必须在用户决策处和结果解释处同时可见。

**独立测试**：挂载资源页和结果页，分别覆盖加载、成功、错误、空态、版本切换和项目共享结果，核对文案与无特例分支。

**验收场景**：

1. **假设**资源类型为项目共享且获准多个工点，**当**用户查看配置或结果，**则**两处均明确提示“跨工点串行、转场时间按 0 天”。
2. **假设**工点无覆盖，**当**查看列表，**则**显示“继承全局默认”和有效数量，不显示“默认充足”。
3. **假设**项目主数据为空或加载失败，**当**进入页面，**则**分别展示通用空态或错误/重试态，不根据 ID 或名称补工点。

### 边界与异常场景

- `authorized_workpoint_ids` 为空值、显式空数组、重复 ID、未知 ID 或旧版本 ID 时分别如何标准化和提示。
- 同一工点存在重复覆盖、覆盖 `max_quantity < quantity`、非整数或负数时如何拒绝或标准化。
- 已启用、`LIMITED` 且有效上限大于 0 的资源未找到工点候选时必须阻断；显式停用、`UNLIMITED` 或零上限沿用既有默认充足 warning，未配置工点则先继承而不能被归入这些状态。
- 从独享切换为共享时若存在工点覆盖，不得静默混合两种数量语义。
- 快速切换 `project_data_version_id` 时，旧工点列表和覆盖不得提交到新版本。
- AI 旧格式更新用于独享资源时必须拒绝并提示使用结构化工点更新。
- 项目共享跨工点只建资源互斥，不增加非零转场。

## 需求

### 功能需求

- **FR-001**：系统必须在 `ResourcePool` 统一模型中支持 `PROJECT_SHARED` 与 `WORKPOINT_EXCLUSIVE`，每个资源类型独立选择一种模式。
- **FR-002**：系统必须把缺少作用域字段的既有资源池统一迁移为 `PROJECT_SHARED`，不得为具体项目写手工特例。
- **FR-003**：系统必须以同一 `project_data_version_id` 的桥梁工点为配置范围；非桥梁工点不进入本期。
- **FR-004**：系统必须支持获准工点集合；缺失集合的旧配置兼容为当前版本全部桥梁工点。
- **FR-005**：系统必须支持按工点覆盖 `enabled/quantity/max_quantity`，未覆盖字段继承全局默认。
- **FR-006**：未配置工点必须继承全局默认且继续作为受限资源处理，不得自动转换为 `UNLIMITED` 或默认充足。
- **FR-007**：系统不得新增 `min_quantity`；`quantity` 必须继续表示当前默认投入。
- **FR-008**：配置层必须保持非负整数和 `max_quantity >= quantity` 校验，工点有效值使用相同校验。
- **FR-009**：`ScenarioInput` 必须保存作用域、获准工点和覆盖；`ScheduleInput.resources` 必须保存已解析的作用域及合法工点集合。
- **FR-010**：命名资源 ID 必须在共享/独享范围内稳定且唯一，任何候选或求解逻辑不得解析 ID 判断业务作用域。
- **FR-011**：任务候选必须同时满足资源类型和权威工点作用域；独享资源只能候选给自身工点。
- **FR-012**：对已启用、`LIMITED` 且有效上限大于 0 的有效池，任务缺少合法候选时必须输出阻断诊断；显式停用、`UNLIMITED` 或零上限沿用既有默认充足 warning，未配置工点必须先继承。
- **FR-013**：固定资源求最短工期必须按每个有效池的 `quantity` 展开资源。
- **FR-014**：增配建议必须按每个有效池搜索 `[quantity,max_quantity]`。
- **FR-015**：固定工期求最少资源必须以 `max_quantity` 为上界，允许推荐低于 `quantity`，下界不得由 `quantity` 限制。
- **FR-016**：同一命名资源必须保持互斥；共享资源可在获准工点间串行，独享资源不得跨工点分配。
- **FR-017**：项目共享资源跨工点转场时间本期固定为 0 天，不得通过桥名、ID 或距离推导其他值。
- **FR-018**：配置页和结果页必须同时展示项目共享“跨工点串行、转场 0 天”提示。
- **FR-019**：页面必须展示全局默认、工点有效值及继承/覆盖来源，并支持恢复继承。
- **FR-020**：页面必须使用权威项目主数据加载、空态、错误/重试和版本隔离，不得以名称或 ID 特殊值补工点。
- **FR-021**：AI 资源助手必须保留资源作用域与工点维度，不得改变作用域或新增资源/工点。
- **FR-022**：AI 旧“资源类型→数量”输入只兼容项目共享；独享数量更新必须带资源池和工点身份。
- **FR-023**：本地配置、项目/方案配置、AI 方案和计划快照必须持久化新字段并兼容读取旧字段缺失数据。
- **FR-024**：作用域、工点范围、覆盖、数量、上限、启用或日历变化必须进入稳定指纹并使旧任务图、求解、AI 解释和方案对比失效。
- **FR-025**：集合和覆盖进入指纹前必须去重、排序和标准化，保证等价配置得到相同指纹。
- **FR-026**：系统必须提供正常、异常、空态、版本切换和兼容迁移的可复现样例及自动化验证。
- **FR-027**：前后端不得按桥梁/工点名称、ID 格式、中文字符串、资源特殊数量或具体资源类型硬编码作用域与继承结果。
- **FR-028**：现有工艺映射、同结构资源绑定、桩基机械墩组规则和求解目标不得因本功能被重写；本功能只增加通用工点作用域筛选。
- **FR-029**：共享契约和诊断必须能追溯资源实例的作用域、获准工点、继承来源和项目共享转场 0 天规则。
- **FR-030**：实现不得引入非桥梁工点、非零转场、调拨审批或跨项目共享。

### 关键实体

- **ResourcePool**：资源类型的全局默认配置、作用域模式、获准工点和覆盖集合。
- **WorkpointResourceOverride**：指定桥梁工点对全局默认的可选覆盖，不是第二份资源类型定义。
- **EffectiveResourcePool**：标准化后供展开与求解使用的共享项目池或独享工点池。
- **Resource**：进入 `ScheduleInput` 的命名资源实例，携带显式工点作用域。
- **Task**：带权威 `bridge_id` 和资源类型需求的排程任务。
- **ResourceAssistantPlan**：保留共享项目量或独享工点量的 AI 资源方案。
