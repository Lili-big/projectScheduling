## 用户场景与测试（必填）

### 用户故事 1 - 选择单个工点进行试算（优先级：P1）

计划人员在模拟求解页选择一个桥梁工点，然后使用现有三类求解中的任意一种，只对该工点的任务、关系、适用资源和匹配里程碑进行求解，从而先验证局部可排性并降低模型规模。

**优先级理由**：这是降低一次性求解压力并形成可用闭环的核心能力；没有范围选择和后端真实裁剪，下拉菜单没有业务价值。

**独立测试**：在包含多个桥梁工点的已确认项目版本中选择任务量最大的工点，分别执行固定资源最短工期、固定工期最少资源和资源成本优化，验证输入与结果中不存在其他工点任务，且合法资源条件下能返回可解释结果。

**验收场景**：

1. **假设** 当前项目存在多个桥梁工点且用户已选择其中一个，**当** 用户执行固定资源最短工期求解，**则** 系统只求解该工点任务并在结果中显示所选工点。
2. **假设** 同一工点已有匹配的固定资源最短工期结果或匹配强制里程碑，**当** 用户执行固定工期最少资源或资源成本优化，**则** 后续求解沿用同一个工点范围和对应基准，不读取全项目基准。
3. **假设** 所选工点缺少合法资源、资源数量为 0 或共享资源不覆盖该工点，**当** 用户求解，**则** 系统按现有资源作用域规则阻断并返回包含任务、工点、资源类型和相关池的诊断，不自动补充资源。

---

### 用户故事 2 - 保留全项目求解并隔离结果（优先级：P1）

计划人员仍可选择“全部工点”执行现有全项目求解；当使用单工点试算时，系统必须清楚标识范围，并防止局部结果被误当作全项目正式方案保存或与全项目结果直接比较。

**优先级理由**：范围隔离关系到结果真实性和后续方案决策，必须与单工点求解同时交付。

**独立测试**：先执行全项目求解，再切换到单工点求解，验证两者指纹、基准和展示范围独立；单工点状态下不能保存为全项目方案，也不能与全项目结果进入同一比较集合。

**验收场景**：

1. **假设** 求解范围为“全部工点”，**当** 用户执行任一现有求解，**则** 请求、结果和已有行为与本功能实施前一致。
2. **假设** 当前展示单工点结果，**当** 用户查看摘要、任务、资源、里程碑或诊断，**则** 页面持续显示试算工点名称和 ID，且不出现其他工点的排程结果。
3. **假设** 当前展示单工点结果，**当** 用户尝试保存方案或与全项目结果比较，**则** 系统阻止该动作并说明单工点结果仅用于试算。
4. **假设** 用户从一个范围切换到另一个范围，**当** 新范围尚未完成求解，**则** 旧范围结果不得作为新范围的基准或当前结果继续使用。

### 边界与异常场景

- 当前项目没有已确认主数据版本、没有桥梁工点或工点列表加载失败时，下拉菜单展示明确空态或失败态，求解按钮不得以无效工点范围发起请求。
- 已选择的工点在刷新后被删除、改为非桥梁类型或不属于当前项目版本时，后端返回明确范围校验错误，不回退为全项目求解。
- 所选工点没有可生成的启用任务时，返回“所选工点未生成工作项”的阻断诊断，不提交空模型。
- 单工点范围只保留两端任务均属于该工点的工艺逻辑关系；任何跨工点关系不得以悬空前置或后置进入模型。
- 仅与所选任务匹配的里程碑参与求解；其他工点里程碑不得改变目标、可行性或固定工期基准，也不得产生无关“未匹配”噪声。
- 项目共享资源仍按稳定池 ID 和原授权范围参与所选工点竞争；工点独享资源只能服务其所属工点；筛选不得按资源类型合并同类型独立池。
- 求解进行中切换下拉范围不得产生并发串用；当前请求结束前禁用范围切换，或丢弃与当前范围不一致的迟到响应。
- 旧调用方未提供求解范围时必须继续按“全部工点”处理。

## 需求（必填）

### 功能需求

- **FR-001**：系统必须在模拟求解参数区提供“求解范围”下拉菜单，列出“全部工点”和当前已确认项目版本中的全部桥梁工点；工点选项必须同时可识别名称和稳定 ID。
- **FR-002**：下拉菜单默认选择“全部工点”，保持现有用户路径和旧调用行为兼容。
- **FR-003**：用户选择单个工点时，选择值只能作为本次求解范围，不得修改项目主数据、场景中的项目结构或资源配置，不得作为新的项目配置持久化。
- **FR-004**：固定资源最短工期、固定工期最少资源和资源成本优化三类求解必须使用同一范围语义；同一次后续求解使用的固定工期基准必须来自相同场景指纹和相同工点范围。
- **FR-005**：单工点求解输入必须只包含所选工点的任务，以及前置和后置任务均在该集合内的逻辑关系；不得包含其他工点任务或悬空关系。
- **FR-006**：单工点求解必须先按完整项目事实解析资源作用域，再仅保留对所选任务合法的资源候选；必须保留稳定池 ID、同类型多池独立性、项目共享互斥和工点独享边界。
- **FR-007**：资源缺失、数量为 0、停用或作用域不匹配时，系统必须保留现有阻断语义和结构化诊断，禁止将缺失资源静默视为无限资源。
- **FR-008**：只有能匹配所选工点任务的里程碑才参与单工点求解、目标评估和固定工期基准；其他里程碑必须排除在该次试算之外。
- **FR-009**：单工点求解不得改变现有排程硬约束、软目标、目标权重、时间预算和无解判定；范围裁剪不是新的优化目标。
- **FR-010**：求解结果必须携带并展示范围模式、工点 ID 和工点名称；任务清单、资源作用域结果、里程碑和诊断必须与该范围一致。
- **FR-011**：前端求解指纹和结果有效性判断必须包含范围模式与工点 ID；切换范围后必须失效当前生成输入、求解结果、固定工期基准和比较状态。
- **FR-012**：单工点结果不得保存为全项目正式方案，也不得与全项目结果直接比较；页面必须给出可见说明，不得仅静默禁用。
- **FR-013**：当请求中的工点 ID 不存在、不属于当前项目版本或不是桥梁工点时，系统必须返回明确的范围校验错误，且不得回退到全项目求解。
- **FR-014**：当所选工点没有启用任务时，系统必须返回阻断诊断，不得调用求解器处理空模型。
- **FR-015**：未提供范围的现有 API 请求必须继续执行全项目求解，并保持响应字段和结果语义兼容。
- **FR-016**：工点列表加载中、空态、失败态和求解忙碌态必须有明确页面反馈；求解期间不得产生范围与响应错配。

### 算法规则

- **输入**：完整且已确认的项目主数据版本、场景工艺与逻辑、资源池与日历、里程碑、求解策略、时间预算，以及可选的单个桥梁工点 ID。
- **输出**：与求解范围一致的生成输入、排程结果、里程碑结果、资源分配、范围元数据和诊断；无解或范围非法时返回结构化失败信息。
- **硬约束**：保留所选任务上的全部现有工艺前置、资源互斥/容量、同结构绑定、里程碑硬约束及其他现有硬约束；范围外对象不进入模型。
- **软约束与目标函数**：继续使用场景现有软目标、启用状态、权重和优先级，不因单工点模式新增或改写目标项。
- **冲突处理**：非法工点、空任务、无合法资源或现有模型不可行均按对应诊断返回；禁止自动扩大为全项目范围、自动添加资源或放松业务硬约束。
- **默认值**：未提供范围时为“全部工点”；单工点模式必须显式提供一个当前项目版本中的桥梁工点 ID。

### 关键实体（涉及数据时填写）

- **求解范围**：一次请求的临时上下文，包含范围模式（全部工点或单工点）以及单工点模式下的稳定工点 ID；不持久化到项目主数据或场景配置。
- **范围化求解结果**：现有求解结果及其范围标识，包含范围模式、工点 ID、工点名称和范围化指纹，用于展示、失效和防误用。

## 成功标准（必填）

### 可衡量结果

- **SC-001**：选择任一桥梁工点后，生成输入和求解结果中的任务 100% 属于该工点，跨范围任务和悬空逻辑关系数量均为 0。
- **SC-002**：三类求解的范围、指纹和固定工期基准完全一致；自动化测试中跨范围基准复用和迟到响应覆盖次数均为 0。
- **SC-003**：单工点结果被保存为全项目方案或与全项目结果直接比较的成功次数为 0，用户每次受阻时都能看到原因。
- **SC-004**：在当前参考项目的最大工点样例中，单工点任务量相对全项目至少减少 80%；在合法资源条件和 3 秒求解预算下，端到端 8 秒内返回包含完整任务集合的 `FEASIBLE` 或 `OPTIMAL` 结果。
- **SC-005**：资源数量为 0、资源缺失或范围不匹配的验收样例全部返回现有结构化资源诊断，静默补资源或按无限资源求解的次数为 0。
- **SC-006**：不传求解范围的全项目 API 契约与既有代表性求解测试全部通过，实施前后的任务、关系、目标配置和结果语义无范围功能引入的差异。
- **SC-007**：不存在、过期或非桥梁工点 ID 的测试全部被明确拒绝，回退为全项目求解的次数为 0。

## 默认假设

- 本期只支持“全部工点”或“单个桥梁工点”，不支持多选工点组合。
- 下拉菜单复用当前项目主数据工点列表，默认选择“全部工点”。
- 三类现有求解入口同时支持范围，避免不同按钮产生不一致语义。
- 单工点结果仅作为可行性和局部资源试算，不进入正式方案保存和跨范围比较；未来如需采纳局部结果，应另行定义合并与审批规则。
- 项目共享资源在 MVP 中保持既有零转场时间和零转场成本语义，本功能不新增转场模型。
- 当前资源配置可能因数量为 0 或没有合法候选而阻断，用户需先在资源配置中形成合法资源输入；本功能不绕过该前置条件。
