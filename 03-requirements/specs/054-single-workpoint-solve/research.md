# 研究：单工点模拟求解

## 决策 1：使用可选查询参数承载求解范围

**决策**：四个现有生成/求解端点统一增加可选 `workpoint_id` 查询参数；缺省表示全项目。

**理由**：范围只影响本次计算，不属于 `ScenarioInput` 的持久化场景事实。查询参数不改变三类端点既有请求体，其中最少资源和成本优化仍可保留现有请求包装与固定工期字段，旧调用方无需修改。

**已评估替代方案**：

- 在前端裁剪 `scenario.project.bridges`：后端会按 `project_data_version_id` 重新物化完整项目，筛选会被覆盖；同时容易误改场景指纹和持久化语义，拒绝。
- 给 `ScenarioInput` 增加工点字段：会把临时试算范围混入场景保存、AI、版本和指纹，扩大数据迁移面，拒绝。
- 把三个 solve 端点全部改为新请求包装：会破坏 `/api/solve-scenario` 现有 body 契约，兼容成本更高，拒绝。

## 决策 2：完整项目解析资源，选中工点生成任务

**决策**：项目主数据物化和 `resolve_effective_resource_pools` 仍读取完整项目；任务构建只遍历选中桥梁，随后只展开授权范围包含该工点的有效资源池。

**理由**：项目共享池、工点独享池、授权范围和稳定池 ID 都以完整项目为解释上下文。直接把 `project.bridges` 缩成单工点会把共享池中的其他合法授权误判为未知工点，或迫使代码改写授权集合；完整解析后再裁剪能保持既有资源语义，同时减少求解变量。

**已评估替代方案**：

- 先完整生成 1,586 个任务，再过滤 `ScheduleInput`：求解规模能下降，但会先产生其他工点的资源错误和无关诊断，且需要清理关系、里程碑和 source summary，拒绝。
- 同时裁剪项目和资源授权：会改写用户资源事实并可能合并/拆分共享池，拒绝。

## 决策 3：类型化响应范围，以生成结果为单一权威

**决策**：新增 `SolveScope`，由 `GeneratedScheduleInput.solve_scope` 承载；主结果和备选结果均通过自身 `generated` 获取范围。

**理由**：前端需要稳定判断结果是否属于当前范围、是否允许保存或比较。`source_summary` 是开放统计字典，不适合作为关键安全判断；在 `ScenarioSolveResult` 再复制一份范围又会产生双写不一致。

**已评估替代方案**：

- 仅在 `source_summary` 添加字符串：缺少类型约束和不变量，拒绝。
- 在 `ScenarioSolveResult` 和 `GeneratedScheduleInput` 各放一份：主结果、备选结果和生成预览容易漂移，拒绝。

## 决策 4：生成与 solver 共用里程碑匹配规则

**决策**：把 solver 当前 `_task_ids_for_milestone` 的现有语义无变化地抽取到 `scheduling/domain/milestone_scope.py`，生成阶段据此排除范围外里程碑，solver 继续复用同一函数。

**理由**：固定工期目标是否匹配不能在生成和求解两处使用不同规则。单纯按 `bridge_id` 或 `related_structure_ids` 过滤会遗漏项目、工区、构件类型和任务 ID 等现有范围类型。

**已评估替代方案**：

- 保留所有里程碑让 solver 跳过：不会改变可行性，但会产生大量与所选工点无关的“未匹配”诊断，并可能误导前端“存在强制里程碑”的基准判断，拒绝。
- 在生成层复制匹配实现：存在规则漂移风险，拒绝。

## 决策 5：前后端双重阻止单工点结果被误用

**决策**：前端禁用单工点结果保存并展示原因；比较入口不接收单工点结果。后端 `compare_scenarios` 同时拒绝任何 `WORKPOINT` 结果及混合范围请求。

**理由**：单工点总工期、资源和里程碑口径不能与全项目方案直接比较。仅靠按钮禁用无法保护 API 调用、旧页面或未来调用方。

**已评估替代方案**：

- 允许保存但加“试算”标签：当前保存集合会自动触发方案比较，仍可能产生错误推荐，拒绝。
- 只做前端限制：共享契约缺少兜底，拒绝。

## 决策 6：Netlify 镜像保持契约一致

**决策**：`04-demo/tools/demo-api-mirror/api.mts` 解析同一查询参数、执行同样的任务/关系/里程碑范围裁剪并返回 `solve_scope`；非法工点返回同类 422 错误。

**理由**：镜像虽不是正式 FastAPI 后端，但当前前端可能在静态演示环境调用它。共享字段和交互语义必须一致，算法精度差异仍按现有说明保留。

**已评估替代方案**：只修改 FastAPI 会造成部署环境中下拉看似有效但仍求解全项目，拒绝。

## 研究结论

无剩余阻塞性未知项。设计不需要新依赖、数据库迁移、持久化字段或新的求解器模型。
