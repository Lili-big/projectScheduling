## 1. 定向自动检查

在一个相关修改批次结束后执行一次：

```powershell
node --test --test-concurrency=1 04-demo/frontend/tests/pavementResults.test.mjs 04-demo/frontend/tests/pavementLiveSolve.test.mjs 04-demo/frontend/tests/pavementVisualization.test.mjs
npm run build
```

build已包含TypeScript检查，不再重复同一次typecheck。以下样例使用合成最小数据，预期为行为不变量：

- 同次结果投影不变更原对象；无generated只缺逻辑，不丢已知排程；无方案不泄露旧日期。
- 两个段含同类多层和配套任务，父子层级恰为两级，任务ID无重复，父级无施工条。
- FS/SS/FF/SF、正/零/负lag及max_finish_gap：端点位置和详情跟随真实link；不将显示先后变成箭线。
- 普通等待、零天配套附加等待、同source多任务歧义、零等待：匹配唯一时画原区间，歧义只保留详情；任务间其他空白不画等待。
- 同机组A→A→B→A得到三次到访，最后A为独立序号；未分配任务不进入机组图但保留在计划表。
- K左/K右/AK、逆里程、同桩号、重叠区间、混合前缀、无桩号、非法桩号、同段坐标冲突：只有可比较数据数值定位，其他明确降级；原始桩号不改。
- 真实非零转场、已知零天、没有转场依据：分别显示原区间、0天、未提供；不能把作业空档算作转场。
- started预算保留，终态/异常/输入改变清理显示状态；过期token和单调最好方案等069不变量保持。计时使用可控时钟验证，不以真实sleep拖长单测。
- 静态渲染覆盖当前最好/最终/中断、紧凑摘要、移交列名、层级、图例、未定位区和键盘控件标记。

## 2. 浏览器验收

构建后刷新原有8000页，不新增无关浏览器标签。证据归.local-data/logs/<本次时间>-pavement-visualization/。

1. 使用当前配置发起一次既有有限预算求解，不保存配置。截图首解后仍在运行与结束后两个时点；无改善至少5秒时计时仍更新。若真实改善过密，使用受控流样例验证该区间，不扩展求解预算来制造等待。
2. 核对25段100子任务（配套任务若实际存在按结果计数），父级无施工条；展开/折叠后左右行、箭头和选择仍正确。选中两道工序查看真实关系与7天等待，确认额外排队空档未归为技术等待。
3. 核对4段待移交的日期与本次结果一致，且提示实际日期未定。检查终态未证明最优时文案无误。
4. 选择各机组，以序号前后浏览；核对连续同段合并及返回、跨轴跳转、无法定位段和转场天数。实际当前数据没有覆盖的情况由上述合成测试证明。
5. 在约1992×956和900×956检查布局、内部滚动、长名称、键盘焦点与减少动画。以可用浏览器控制为准，记录实际视口；不可设置目标视口时如实记录未覆盖。
6. 新方案到达后检查折叠/选择尽量保留、时间和详情同时更新。中断/无方案/历史缺字段由受控测试覆盖；不破坏正在使用的服务来制造失败。
7. 页面输入变更沿用历史标记；如需UI验证仅在内存作可逆变更后恢复、不保存；对保存配置和主数据读取前后校验，确保没有持久化写入。桥梁入口只做只读加载冒烟。

一次真实有限求解用于页面验证；不重启不限时任务，不为获得某个工期数字反复求解，不把并行搜索波动认定为界面故障。
