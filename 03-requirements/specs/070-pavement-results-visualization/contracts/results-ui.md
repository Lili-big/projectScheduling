# 路面结果页交互契约

本轮不新增API或共享业务字段；现有同步和流式协议保持069约定。以下是结果阅读界面的可观察契约。

## 信息顺序

1. 主工期行：初步→当前最好/最终＋缩短天数。
2. 运行中活动提示、已等待/预算/已知改善次数；终态移除活动。优化状态与范围用一条紧凑摘要，窄屏允许自然换行。
3. 待移交注意事项和日期表（有待移交时）；施工完成日期与必要假设。
4. “施工计划”两级表格＋横道＋逻辑/等待；“机组施工顺序”里程轴＋到访详情。
5. 保留按需展开的输入来源、实际计算耗时、历史诊断等。

## 状态文案

| 场景 | 必需内容 |
| --- | --- |
| 运行、无方案 | 正在寻找可行方案；活动提示；本地已等待时间 |
| 运行、有方案 | 持续优化中；当前最好；发现更短工期即更新；无改善仍保持运行 |
| 达预算尚未收到终态 | 等待计算结果收尾，保留当前最好；不能宣布最终 |
| 正常终态 | 本次优化结束；真实最终工期及是否已证明最优；停计时/动画 |
| 中断 | 优化未完成；最后收到方案仅供查看；无方案则无图 |
| 输入已变 | 历史结果，不能作为当前计划使用；图内仍用旧快照 |
| 模型异常/无解/未知 | 保留原始诊断区别，不包装成正常可用计划 |

“已等待”是客户端单调时钟时间；计算耗时是后端字段，两者不混称。动画不表示服务器心跳，不展示完成百分比。

## 业务解释

- 待移交：“实际移交日期未定，已安排在正常段全部完成后，请重点关注本方案最晚需移交日。”日期列解释为该日开工前完成移交，不是实际移交承诺或全局最晚优化解。
- 技术等待：“前道工序完成后，为养生、冷却或验收等条件保留的等待时间；期间主机组可安排其他施工段。”具体条件以结果reason为准，不将所有区间统称养生。
- 图例区分实色施工条、浅色虚线等待、工序逻辑箭线；机组轴独立说明“横向位置表示桩号，序号表示实际施工先后”。

## 表图操作

- 左表列为施工段/工序、开始、完成、天数、机组；右图为日历轴。段父级可折叠，只有工序画施工条。
- 默认段展开、逻辑关系显示；支持全展开/全收起、显示关系开关。选择工序显示完整名称、起止、机组、相关关系及等待详情。
- FS/SS/FF/SF及间隔在关系详情中完整显示；选择任务高亮真实入/出边，折叠端点后不接到父级。
- 无generated时文字说明关系数据不可用，不妨碍查看已排程任务。等待无法唯一归属时在按需详情说明。

## 机组轴操作

- 默认第一个可用机组及其第一次到访；可选择其他机组，清楚标识当前机组名称。
- 同坐标系独立轴及日程顺序编号；到访逐行布置避免重复桩号遮挡。选中前后相邻同轴到访显示方向箭线，跨轴用轴名/序号跳转。
- 上一步/下一步按真实机组序号工作，包括跨轴或不可定位到访；首末按钮禁用。
- 详情显示施工段、原始起终桩号、到访序号、作业日期、工序和相邻转场天数。多工序连续施工可展开，返回不去重。
- 无法定位区始终可读，不能把混合桩号放到连续比例轴；不显示推测的道路连通或距离。
- 无机组分配显示空态；零天转场显示0天，缺失事实显示未提供。辅助资源未约束的任务仍在计划表内，不虚构机组路线。

## 可用性与兼容

所有按钮/选择可键盘操作且有可读名称，选中与待移交状态不能只靠颜色；尊重prefers-reduced-motion。图表滚动不撑宽整页。新方案按稳定ID保留有效选择，全部详情随同次快照更新。

继续支持旧结果的blocked_sections、旧交付口径、缺优化字段及失败诊断；桥梁页面不进入本契约。保留既有输入变更/取消隔离，不更改用户保存配置。
