# 快速验证：导航目录与 AI 多方案比选重构

## 前置条件

- 本地前端依赖已经安装。
- 后端服务能够返回默认项目场景并支持 AI 资源方案单方案求解。

## 构建验证

```powershell
cd frontend
npm.cmd run build
```

预期：TypeScript 检查和 Vite 生产构建均成功，源码中不存在 `resultsMvp` 的类型或页面引用。

## 场景 1：导航分组

1. 启动应用并查看左侧导航。
2. 确认两个一级目录默认展开，编号、名称和子项顺序符合 [UI 行为契约](contracts/ui-behavior.md)。
3. 独立收起、展开两个分组，确认已打开工作区标签不受影响。
4. 折叠整个侧栏，通过图标和提示进入所有子页面；恢复侧栏后确认分组状态保留。

## 场景 2：完整模拟求解保留

1. 展开“2. 前期策划”，打开“2.2 模拟求解”。
2. 确认固定资源最短工期、固定工期最少资源和资源成本优化三个入口仍存在。
3. 确认导航和工作区标签中不存在“模拟求解-MVP”。

## 场景 3：单方案下钻

1. 打开“2.1 AI多方案比选”，生成三套方案。
2. 仅求解经济方案。
3. 确认经济方案显示“查看方案详情”，另外两套方案不显示。
4. 进入详情，核对顶部方案信息、资源数量、状态、诊断、里程碑、全量任务、甘特图、资源泳道和资源路径。
5. 返回比选，确认三方案、经济方案结果、对比状态和当前选择均保留，网络面板中没有新增初始化、求解、对比或推荐请求。

## 场景 4：结果失效与异常

1. 修改经济方案任一资源数量，确认详情入口立即消失。
2. 重新求解后确认入口恢复且详情使用新资源数量和新结果。
3. 对返回不可行或未知状态的方案，确认仍可进入详情查看诊断。
4. 模拟请求失败且无结果，确认该方案不显示详情入口。

## 场景 5：跨项目安全

1. 在任一方案详情中切换或重新导入项目场景。
2. 确认页面回到比选态并清空旧方案、结果、对比和推荐，不显示旧项目详情。
