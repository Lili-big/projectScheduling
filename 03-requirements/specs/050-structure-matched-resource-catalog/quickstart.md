# 快速验证：结构物匹配的中文资源目录

## 前置条件

- 已安装仓库现有前端依赖；不需要新增依赖。
- 当前项目主数据存在至少两个已确认的桥梁工点详情。
- 本地服务启动和日志按 `04-demo/runtime/README.md` 执行。
- 验证前确认没有将结构建议写入 `resource_pools`。

## 1. 定向自动化验证

在仓库根目录执行：

```powershell
npm.cmd --workspace 04-demo/frontend test -- --test-name-pattern="resource|workpoint"
npm.cmd run typecheck
npm.cmd run build
python 00-governance/repository-tools/validate_docs.py
```

预期：资源领域和页面契约测试通过，类型检查与生产构建退出码为 0，050 规格文档通过仓库验证。若测试脚本不支持名称过滤，按 `tasks.md` 中的定向文件命令执行，不重复运行全量套件。

## 2. 中文名称场景

1. 打开“资源配置”，选择包含桩基、盖梁和连续梁等结构的工点。
2. 检查资源主名称使用中文，例如“旋挖钻机”“盖梁模板”“连续梁班组”。
3. 检查英文资源类型代码只在次级位置显示。
4. 打开“从资源目录补充”，确认标准选项也使用同一中文名称。
5. 对带自定义中文 `label` 的已配置资源，确认优先显示该名称；对未知且无中文标签的类型，确认主名称为中文未命名提示并保留代码。

## 3. 桩基方法匹配场景

用四个工点样例或领域测试夹具分别配置旋挖、回旋、冲击和人工挖孔工艺：

| 工艺 | 期望唯一桩基资源 |
|---|---|
| 旋挖 | 旋挖钻机 |
| 回旋 | 回旋钻机 |
| 冲击 | 冲击钻机 |
| 人工挖孔 | 人工挖孔班组 |

预期：每个工点只出现实际采用方法对应的桩基资源，不同时追加其他三类。

## 4. 连续梁与普通结构场景

1. 选择包含 `continuous_unit` 的工点，确认显示“连续梁班组”。
2. 选择没有连续梁的工点，确认不因项目工艺库存在连续梁工艺而显示该资源。
3. 对承台、墩柱、盖梁构件，确认分别匹配对应资源。
4. 禁用一个构件，确认其资源从建议集合移除；若该类型已有保存记录，记录仍保留。
5. 同一工点放置多个映射到相同类型的构件，确认只显示一行且重复刷新顺序稳定。

## 5. 建议不等于投入

1. 在没有任何工点资源池的工点打开资源页。
2. 观察匹配建议的当前投入、可增上限均为 0，状态为未配置。
3. 不添加建议，切换页面或保存其他资源配置。
4. 重新载入场景，确认没有隐式新增资源池，也没有求解候选。
5. 明确添加一条建议，确认只创建当前工点、当前类型的 `WORKPOINT_EXCLUSIVE` 记录。

## 6. 权威版本与异常场景

1. 让一个工点详情请求失败，确认页面显示失败和重试，不回退展示全项目目录。
2. 准备无结构或无资源映射的工点，确认显示空态，同时仍允许从完整中文目录补充。
3. 快速切换工点 A → B，或在 A 请求期间切换项目主数据版本，先返回旧请求。
4. 确认页面只显示当前版本当前工点的建议，不被 A 或旧版本响应覆盖。

## 7. 运行时验证

按 `tasks.md` 指定的唯一页面运行时命令执行现有 `resourceWorkpointRuntime.test.mjs`。核心断言应至少证明：

- 详情请求绑定当前版本和工点；
- 中文名称正确；
- 旋挖桩基和连续梁映射正确；
- 无结构工点不展示全目录；
- 建议行不隐式保存；
- 已配置但不再匹配的资源仍可见。

若系统浏览器/CDP 启动属于已证实的环境故障，记录日志和退出结果，并以领域测试、源代码契约、类型检查和构建共同覆盖核心目标；不得因该非核心环境故障撤销已通过的核心验证。
