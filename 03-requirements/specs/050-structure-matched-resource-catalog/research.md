# 研究结论：结构物匹配的中文资源目录

## 决策 1：以当前版本工点详情作为结构匹配权威输入

**决策**：资源页继续使用现有工点分页接口加载桥梁工点导航；选中工点后，调用现有 `GET /api/project-master/versions/{version_id}/workpoints/{workpoint_id}` 懒加载详情，并仅从该详情的启用结构与构件派生建议资源。

**理由**：当前列表数据不保证包含结构详情；`scenario.project` 在页面初始加载时可能仍是 Demo 场景，而 `project_data_version_id` 已指向当前项目主数据版本。按版本读取详情能够避免用旧场景或项目级工艺目录冒充当前工点事实。

**评估的替代方案**：

- 依赖已生成任务的 `compatible_resource_types`：空资源或尚未生成任务时不可用，不满足“空资源也能建议”。
- 一次加载全部工点详情：会形成随工点数增长的 N+1 请求，不符合页面只查看一个工点的实际需要。
- 新增后端资源建议接口：当前已有详情接口和前端工艺映射足以完成只读投影，新增公开契约和镜像改造没有必要。

## 决策 2：在前端领域层实现确定性的结构资源投影

**决策**：在 `domain/resources.ts` 增加纯函数，输入一个 `ProjectMasterWorkpoint` 和当前 `process_library`，输出去重、稳定排序的资源类型。下部结构读取启用构件的 `component_type`；上部结构将现有项目主数据类型映射到排程构件类型，例如 `continuous_unit → cast_in_place_continuous_beam`。工艺选择遵循“显式方法参数 → 唯一默认工艺 → 无匹配”。

**理由**：现有 `defaultResourceTypeForProcess` 已集中处理桩基方法和普通构件的资源类型映射，扩展一个工点投影函数可以复用该规则，且便于用输入/输出样例直接测试。匹配结果不需要通过 API 保存或交给求解器。

**评估的替代方案**：

- 在 React 组件内直接遍历结构：难以独立测试，也会把业务优先级散落到渲染代码。
- 只按 `component_type` 固定映射：无法区分旋挖、回旋、冲击和人工挖孔。
- 没有默认工艺时选择第一条：工艺顺序不是业务选择；仅当现有工艺库唯一默认规则成立时才匹配。

## 决策 3：统一内置资源中文名称，代码只作辅助标识

**决策**：在 `domain/constants.ts` 维护内置可配置资源类型的中文名称；`resourceTypeLabel` 的优先级为“当前类型已配置池的非空中文 `label` → 内置中文名称 → 中文未命名提示”。资源类型代码在页面次级位置保留。`resourceAssistant.ts` 删除私有重复名称表，改用统一解析函数或常量。

**理由**：资源页当前在没有池标签时回退为英文代码，资源助手又维护了另一份中文表，容易出现“旋挖钻/旋挖钻机”等不一致。单一名称表可保证默认列表、补充下拉和资源助手一致。

**评估的替代方案**：

- 修改后端默认配置，为每个资源创建标签池：会重新引入并持久化用户并未配置的资源，不符合数量 0/无资源语义。
- 直接隐藏类型代码：会降低自定义类型的诊断和技术识别能力。

## 决策 4：建议集合与已配置集合分离后合并展示

**决策**：结构匹配得到的类型只形成虚拟建议行，`quantity=0`、`max_quantity=0`、未配置；页面可见集合为“匹配建议类型 ∪ 当前工点已配置类型”。已配置值始终优先且不因结构变化被删除。用户添加建议后才创建 `WORKPOINT_EXCLUSIVE` 记录。

**理由**：结构能证明资源可能使用，不能证明现场投入数量。保留不再匹配的已配置资源可以避免静默数据丢失，并允许用户人工判断和移除。

**评估的替代方案**：

- 自动创建数量 0 的资源池：仍会产生隐式持久化记录，污染项目配置。
- 结构变化时删除旧资源：会覆盖用户决策，违反既有资源配置契约。

## 决策 5：详情请求必须绑定版本和所选工点

**决策**：详情状态以 `versionId + workpointId` 作为请求身份；切换版本或工点时进入加载态，旧请求返回后若身份已变化则丢弃。失败显示当前工点的重试入口，空结构显示空态，不回退到全项目目录。

**理由**：快速切换工点或确认新项目主数据版本时可能出现响应乱序；错误回退到全目录会把网络/数据错误误表现为业务建议。

**评估的替代方案**：

- 保留上一工点建议直到新请求完成：会在导航已切换后短暂展示错误工点资源。
- 失败时使用已生成任务或全目录：掩盖权威数据读取失败，且不满足结构驱动规则。

## 未新增阻塞未知项

当前需求、既有接口和默认工艺规则足以进入任务拆分。项目主数据未携带显式方法参数时按唯一默认工艺处理；将来若新增正式方法字段，可在相同投影入口扩展，不需要本期预建新模型。
