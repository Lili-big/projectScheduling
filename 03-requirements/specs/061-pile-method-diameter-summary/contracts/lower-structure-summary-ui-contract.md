# 桩基、承台与墩身结构摘要 UI 契约

## 1. 目标与边界

本契约定义资源配置页左侧“结构物信息”中桩基、承台和墩身的分组与尺寸文案，以及当前客户矩形墩身尺寸进入主数据的映射。右侧资源配置、页面状态、工期和求解链路继续沿用既有契约。

## 2. 权威输入

页面继续从当前工点详情读取：

- 构件：`component_type`、`quantity`、`unit`、`enabled`、`parameters`；
- 参数：`diameter_m`、`dimensions_m`、`length_m`、`height_m`、`form` 及工艺标识；
- 工艺：当前 `scenario.process_library`。

只统计 `enabled=true` 且数量为有限正数的构件。

## 3. 桩基契约

```text
pile + process identity + diameter_m(value, unit) + component unit
```

- `length_m` 和其他参数不得进入签名或文案。
- 同签名数量相加。
- 规范输出：`旋挖钻-φ1.5m×20根`。
- 缺桩径时显示“桩径未提供”，不得以桩长替代。

## 4. 承台契约

- 分组仍使用 feature 057 的完整参数、工艺和构件单位。
- 可识别的连续米制尺寸文本将乘号统一为 `×`，在尺寸表达式末尾追加一次 `m`。
- 源文本小数精度保留；普通文字形式不追加 `m`。
- 规范输出：`承台施工-16.5×16.5×6.0m×6个`。

## 5. 墩身契约

### 5.1 圆形截面

```text
pier_body + process identity + circular diameter(value, unit) + component unit
```

规范输出：`爬模施工-φ1.5m×10根`。

### 5.2 矩形或变截面

```text
pier_body + process identity + normalized dimensions_m + component unit
```

- 矩形输出：`爬模施工-2.0×1.5m×5根`。
- 变截面可输出：`爬模施工-8.0×6.0/4.0m×2根`。
- 不计算或显示平方米面积。

### 5.3 排除与诊断

- `height_m` 和位置 `form` 不进入墩身签名或文案。
- 直径与尺寸同时有效时显示冲突诊断或由导入预检阻断。
- 两者均缺失时显示“截面尺寸未提供”，不得从高度、位置或名称推断。

## 6. 客户主数据映射契约

《泸古高速TJ-1标桥梁进度统计表4.27(1)》的墩身“直径（m）”源列按值形态映射：

| 原值 | 统一主数据参数 |
|---|---|
| `1.5` | `param.diameter_m = 1.5` |
| `3.0*4.0` | `param.dimensions_m = "3.0*4.0"` |
| `8.0*6.0/4.0` | `param.dimensions_m = "8.0*6.0/4.0"` |

非空非法值必须进入构建/导入诊断，不得静默丢失。位置和墩高继续独立保存。

## 7. 版本与兼容契约

- `dimensions_m` 使用既有 `ProjectMasterParameter` 通用契约，不新增 API 顶层字段或数据库列。
- 重新构建的工作簿必须通过现有导入预检创建新版本；有阻断错误时不得确认。
- 不允许直接更新 SQLite 表；旧版本保持可追溯。
- 历史版本缺少矩形尺寸时只显示缺失诊断，不从其他字段猜测。

## 8. 非回归契约

- 柱系梁、桩系梁和盖梁继续按完整参数、工艺和单位汇总。
- 页面直接渲染领域投影的 `displayText`，不建立第二套合并逻辑。
- 不修改资源目录、资源建议、资源数值、保存载荷、共享资源、工期或求解器。

## 9. 验证契约

定向验证必须覆盖：

1. 桩基同工艺同桩径、不同桩长合并；
2. 承台尺寸乘号、末尾米单位和文本精度；
3. 圆形墩身同工艺同直径、不同高度/位置合并；
4. 矩形墩身同工艺同长宽、不同高度/位置合并；
5. 不同截面拆分、变截面保留、缺失和冲突诊断；
6. 原始非空墩身截面映射零丢失；
7. 新版本导入原子性和旧版本保留；
8. 其他结构与资源语义不变。
