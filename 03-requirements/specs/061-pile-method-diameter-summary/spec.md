# 功能规格：桩基、承台与墩身结构摘要聚合

**功能目录/分支**：`061-pile-method-diameter-summary`

**创建日期**：2026-07-22

**状态**：已实施

**输入**：用户要求资源配置页的结构物信息进一步简化：桩基按施工工艺与桩径聚合；承台尺寸保留米单位；墩身仅按施工工艺与截面尺寸聚合，圆形展示直径，矩形展示长×宽，不再按高度或位置拆分。

## 来源与评审上下文（必填）

- **来源文档**：本轮三次用户请求及截图（2026-07-22）；`03-requirements/specs/057-workpoint-structure-resource-layout/`；当前确认项目主数据；《泸古高速TJ-1标桥梁进度统计表4.27(1)》“永宁河特大桥”原始表。
- **评审结论**：结构摘要用于估算工点资源，桩长、墩高以及内柱/外柱等位置不会改变本页面的设备或模板规格分组。桩基按工艺＋桩径聚合；墩身按工艺＋截面尺寸聚合；承台仍按原尺寸分组，但连续尺寸末尾必须保留 `m`。
- **使用的 Demo/代码事实**：`workpointStructureSummaryProjection` 当前把全部非工艺参数写入签名，导致桩基按桩长、墩身按高度与位置拆行；承台尺寸在当前主数据中以 `form="16.5*16.5*6.0"` 文本保存且没有参数单位。原始桥梁表的墩身“直径（m）”列既含圆形数值，也含 `3.0*3.0`、`3.0*4.0`、`8.0*6.0/4.0` 等矩形或变截面尺寸；当前客户数据构建脚本只接受数值，导致矩形尺寸未进入已确认主数据。
- **不在范围内**：计算矩形截面积；按桩长或墩高继续拆分摘要；改变柱位、墩高等主数据的排程用途；修改柱系梁、桩系梁、盖梁的既有汇总规则；改变资源建议、资源数量、可增上限、启用语义、共享资源、求解器、工期或约束。

## 用户场景与测试（必填）

### 用户故事 1 - 按工艺与桩径查看桩基总量（优先级：P1）

项目策划人员选择桥梁工点后，希望同一施工工艺和桩径的桩基只显示一项，不再因桩长不同占据大量行。

**优先级理由**：这是最直接的页面降噪需求，也是旋挖钻机等资源投入估算的主要结构依据。

**独立测试**：构造同工艺、同桩径、不同桩长的多批桩基，验证只生成一个汇总项且数量正确；不同工艺或桩径仍分别显示。

**验收场景**：

1. **假设** 当前工点有多批旋挖钻桩，桩径均为 1.5m、桩长不同且合计 20 根，**当** 用户查看结构物信息，**则** 桩基分类只显示一个等价于“旋挖钻-φ1.5m×20根”的汇总项。
2. **假设** 当前工点另有桩径 1.8m 的旋挖钻桩，**当** 页面汇总，**则** 1.5m 与 1.8m 分别显示，数量各自累计。
3. **假设** 当前工点存在桩径相同但施工工艺不同的桩基，**当** 页面汇总，**则** 各工艺分别显示，不得合并。

---

### 用户故事 2 - 用带单位的尺寸判断承台与墩身规格（优先级：P1）

项目策划人员希望承台尺寸明确带米单位，同时把墩身按圆形直径或矩形长宽汇总，以便直接判断模板规格和数量。

**优先级理由**：承台单位缺失会造成尺寸含义不完整；墩身按高度和位置逐条展示则无法快速统计同规格模板需求。

**独立测试**：使用文本承台尺寸、同直径不同高度的圆形墩身、同长宽不同高度/位置的矩形墩身，验证单位、分组和数量均符合要求。

**验收场景**：

1. **假设** 当前工点有 6 个尺寸均为 `16.5*16.5*6.0` 的承台，**当** 页面汇总，**则** 显示“承台施工-16.5×16.5×6.0m×6个”或等价文本，并保留尺寸精度和米单位。
2. **假设** 当前工点有 10 根采用爬模施工、直径 1.5m，但高度和内外柱位置不同的圆形墩身，**当** 页面汇总，**则** 只显示一个“爬模施工-φ1.5m×10根”汇总项。
3. **假设** 当前工点有 5 根采用爬模施工、截面均为 2.0m×1.5m，但高度和位置不同的矩形墩身，**当** 页面汇总，**则** 只显示一个“爬模施工-2.0×1.5m×5根”汇总项，不计算 `3.0m²` 面积。
4. **假设** 矩形尺寸分别为 2.0m×1.5m 和 2.0m×1.8m，**当** 页面汇总，**则** 两种截面分别显示，不得合并。

---

### 用户故事 3 - 保留矩形截面数据并维持现有业务语义（优先级：P2）

项目策划人员重新导入当前桥梁主数据后，原始表中的矩形墩身长宽能够进入结构摘要；历史版本和其他结构、资源、排程行为不被静默改写。

**优先级理由**：仅调整前端无法恢复当前导入过程中已丢失的矩形尺寸，必须通过版本化主数据导入建立可追溯的新版本。

**独立测试**：从原始桥梁表构建新导入文件，验证圆形数值进入 `diameter_m`、矩形表达式进入 `dimensions_m`；通过现有导入与确认流程创建新版本，并验证旧版本仍可追溯。

**验收场景**：

1. **假设** 原始墩身截面单元格为数值 `1.5`，**当** 构建统一主数据，**则** 保存为圆形截面直径 1.5m。
2. **假设** 原始墩身截面单元格为 `3.0*4.0`，**当** 构建统一主数据，**则** 原表达式的长宽和精度被保存在 `dimensions_m`，不得丢弃或转为单一数值。
3. **假设** 当前 Demo 已有确认版本，**当** 新工作簿通过现有导入和确认流程生效，**则** 生成新的主数据版本，不直接编辑数据库行；旧版本仍保留审计记录。

### 边界与异常场景

- 桩基只使用 `diameter_m`；桩长、形式及其他参数不得进入桩基摘要签名或文案。
- 圆形墩身以有效 `diameter_m` 作为截面签名；矩形或变截面墩身以 `dimensions_m` 的规范化尺寸表达式作为签名。墩高、内柱/外柱/左柱/右柱/独墩等位置不得参与墩身摘要分组或文案。
- 同一墩身同时存在有效直径与矩形尺寸时视为数据冲突，必须显示可诊断项或在导入验证中阻断，不得任意选择一种截面。
- 墩身缺少有效直径和长宽时显示“截面尺寸未提供”，不得从高度或位置推断。
- 尺寸文本中的 `*`、`x`、`X` 统一显示为 `×`；只在整个尺寸表达式末尾追加一次 `m`。已经带有明确单位时不得重复追加。
- 变截面源值如 `8.0*6.0/4.0` 保留斜线语义并显示为 `8.0×6.0/4.0m`，本功能不解释或计算其面积。
- 承台仅对可识别的纯尺寸前缀追加 `m`；补充方量等括号说明继续保留，不得把普通文字形式误判为米制尺寸。
- 文本尺寸保留源数据的小数表达精度，例如 `6.0` 不得无故变成 `6`；数值型参数继续沿用现有有效精度规则。
- 桩径值、矩形长宽表达式、施工工艺、截面单位或构件计量单位不同不得合并。
- 禁用、数量为 0、负数或非有限数量的构件继续不进入汇总；输入顺序不得改变等价输出。
- 对已确认但缺失矩形尺寸的历史版本不进行原地补写；只有重新构建并导入的新版本获得 `dimensions_m`。

## 需求（必填）

### 功能需求

- **FR-001**：桩基汇总签名必须仅由施工工艺身份、规范化桩径值及单位、构件计量单位组成；桩长及其他非桩径参数不得参与。
- **FR-002**：同签名桩基数量必须累加并显示为“工艺-φ桩径单位×合计数量单位”；不同工艺、桩径或单位必须分别显示。
- **FR-003**：承台尺寸若以 `form` 或等价参数保存为连续米制尺寸，系统必须规范化乘号并在尺寸表达式末尾保留一次 `m`，同时保留源文本有效精度。
- **FR-004**：圆形墩身汇总签名必须仅由施工工艺身份、规范化 `diameter_m` 值及单位、构件计量单位组成；墩高和位置不得参与。
- **FR-005**：矩形或变截面墩身汇总签名必须仅由施工工艺身份、规范化 `dimensions_m` 表达式、构件计量单位组成；展示长宽或原变截面表达式，不得计算截面积。
- **FR-006**：同截面墩身数量必须累加；圆形直径、矩形/变截面表达式、工艺或单位任一不同则分别显示。
- **FR-007**：墩身缺少截面尺寸时必须显示“截面尺寸未提供”或等价诊断；直径与矩形尺寸同时有效时不得静默选择。
- **FR-008**：施工工艺的显式值、唯一默认值、缺失值及未识别值解析必须沿用 feature 057 的规则，不新增工艺选择逻辑。
- **FR-009**：当前客户主数据构建必须区分原始墩身截面单元格：单个有效数字映射到 `diameter_m`，尺寸表达式映射到 `dimensions_m`；位置和高度继续分别保留在 `form`、`height_m`。
- **FR-010**：矩形尺寸的数据补齐必须通过生成新的统一主数据工作簿，并经现有导入/确认流程创建新版本；不得直接更新 `.local-data/state/project-master.db` 表数据或覆盖历史版本。
- **FR-011**：柱系梁、桩系梁和盖梁必须继续按 feature 057 的完整参数、工艺和单位汇总；本功能不得改变它们的签名或文案。
- **FR-012**：本功能不得创建、删除或修改任何资源池、资源数量、可增上限、启用字段、资源建议或保存载荷。
- **FR-013**：本功能不得改变项目主数据公共 API 结构、共享资源、工期计算、求解器目标或约束；`dimensions_m` 继续通过既有通用参数契约传递。

### 关键实体（涉及数据时填写）

- **尺寸表达式**：来自文本参数的米制尺寸值，保留源数值精度，规范化乘号并带单个末尾单位；可表示长×宽×高或包含斜线的变截面。
- **墩身截面标识**：圆形时为直径值/单位，矩形或变截面时为规范化长宽表达式；与工艺和构件单位共同形成只读汇总键。
- **下部结构汇总项**：包含施工工艺、规范化尺寸、累计数量、构件单位和稳定展示文本的前端派生数据，不持久化。
- **项目主数据版本**：由统一工作簿导入产生；新版本可补齐矩形截面参数，旧版本保持可追溯。

## 成功标准（必填）

### 可衡量结果

- **SC-001**：同工艺、同桩径且至少三种不同桩长的 20 根桩基样例只生成 1 项 `旋挖钻-φ1.5m×20根`，文案不含桩长。
- **SC-002**：6 个源尺寸为 `16.5*16.5*6.0` 的承台只生成 1 项 `承台施工-16.5×16.5×6.0m×6个`，小数精度和单位均正确。
- **SC-003**：同工艺、同直径、不同高度和位置的 10 根圆形墩身只生成 1 项 `爬模施工-φ1.5m×10根`。
- **SC-004**：同工艺、同长宽、不同高度和位置的 5 根矩形墩身只生成 1 项 `爬模施工-2.0×1.5m×5根`，页面不显示高度、位置或计算面积。
- **SC-005**：原始表中所有非空墩身截面单元格在新统一工作簿中均映射为 `diameter_m` 或 `dimensions_m`；矩形表达式丢失数为 0，冲突或非法值均有诊断。
- **SC-006**：新工作簿通过现有主数据导入且无阻断错误后创建新确认版本；旧确认版本未被原地改写。
- **SC-007**：柱系梁、桩系梁、盖梁以及资源配置现有定向测试全部通过；前端类型检查、生产构建和文档验证通过，无资源或求解器代码变更。

## 默认假设

- “矩形面积”已由用户澄清为长×宽尺寸展示，不计算平方米。
- 页面统一使用 `-` 和 `×`；桩径与尺寸均保留 `m`，构件数量继续使用主数据单位。
- `dimensions_m` 通过既有通用 `ProjectMasterParameter` 传递，不新增 API 顶层字段或数据库列。
- 当前客户原始表“直径（m）”列中的单个数字表示圆形直径，含乘号的表达式表示矩形或变截面尺寸。
- 新版本导入只补齐源数据已有的截面尺寸，不重算墩高、数量、工艺或资源配置。
