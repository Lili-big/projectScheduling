## 用户场景与测试（必填）

### 用户故事 1 - 快速进入完整任务清单（优先级：P1）

计划工程师打开或硬刷新任务视图时，系统快速取得本次任务所需的权威名称映射，并一次性展示完整任务清单，不再长时间停留在加载提示。

**优先级理由**：当前约 30 秒的等待直接阻断任务查看，是本次调整的首要业务问题。

**独立测试**：使用现有 13 工点、1586 任务运行基线硬刷新任务视图，测量从权威映射加载开始到完整任务 DOM 就绪的时间，并检查名称完整性。

**验收场景**：

1. **假设** 当前任务关联 13 个工点且主数据版本可用，**当** 用户硬刷新任务视图，**则** 5 秒内一次性看到 1586 条任务及其权威工点、桥梁、工区和幅别名称。
2. **假设** 多个任务引用同一工点，**当** 页面加载权威显示映射，**则** 系统按去重后的工点集合取得所需数据，不因任务数量重复加载同一映射。
3. **假设** 当前任务不引用任何工点，**当** 用户打开任务视图，**则** 系统直接进入既有空态或任务态，不发起无意义的主数据详情加载。

---

### 用户故事 2 - 加速后仍保持权威与隔离（优先级：P2）

计划工程师在加载失败、重试、主数据版本切换或任务工点集合快速变化时，仍只看到与当前任务身份一致的完整权威名称，不会看到部分名称、原始 ID 或旧版本数据。

**优先级理由**：性能优化不能破坏已经确立的主数据权威性、原子展示和竞态隔离。

**独立测试**：在真实 React 页面中分别模拟成功、失败后重试、版本切换、工点集合切换和旧响应晚到，验证页面状态和最终名称集合。

**验收场景**：

1. **假设** 当前映射请求仍未完成，**当** 页面已取得规范任务，**则** 页面保持通用加载态且不显示部分任务名称或原始 ID。
2. **假设** 映射加载失败，**当** 用户查看页面并点击重试，**则** 页面先显示既有错误/重试态，并在重试成功后原子展示完整任务。
3. **假设** 用户快速切换主数据版本或任务工点集合，**当** 旧请求晚于新请求返回，**则** 旧响应不覆盖当前映射。
4. **假设** 请求中的任一工点不属于指定版本或无法取得，**当** 加载结束，**则** 整体进入错误态，不以其他版本、名称猜测或原始 ID 补齐。

### 边界与异常场景

- 工点 ID 输入包含重复项、空字符串或不同顺序时，必须归一化为同一请求身份和稳定结果。
- 映射响应为空、缺少请求工点或包含未请求工点时，必须拒绝作为完整映射提交，并进入可重试错误态。
- 主数据版本为空时，沿用既有非权威映射路径，不伪造版本请求。
- 网络超时、服务不可用或响应格式无效时，必须结束加载态并显示既有通用错误/重试入口。
- 已成功加载的相同版本和相同规范化工点集合可复用缓存；版本或集合变化时不得复用不匹配缓存。
- 单个工点包含大量结构物或构件时，任务视图加载量只随其显示所需信息增长，不携带任务视图不使用的构件、参数或来源证据。

## 需求（必填）

### 功能需求

- **FR-001**：系统必须根据当前规范任务提取、去空、去重并稳定排序所需工点 ID，并与 `project_data_version_id` 共同形成显示映射请求身份。
- **FR-002**：系统必须通过一次逻辑批量加载取得当前请求身份所需的全部任务视图主数据映射，不得按每个工点重复加载或重建同一完整版本快照。
- **FR-003**：批量结果必须只包含任务视图显示所需的工点、桥梁、工区、幅别及其稳定身份和层级关系；不得携带任务视图未使用的构件、参数、来源证据等重型明细。
- **FR-004**：系统必须验证返回版本与请求版本一致、所有请求工点均有且仅有一份有效映射；缺失、重复或版本不匹配时不得提交部分结果。
- **FR-005**：当前请求身份的全部映射成功并通过完整性校验后，系统必须原子提交映射并一次性渲染任务清单。
- **FR-006**：映射未就绪时必须保持通用加载态，不得显示 `bridge_id`、`work_section_id`、占位符或部分权威名称冒充最终名称。
- **FR-007**：加载失败、超时或响应无效时必须结束加载态，显示通用错误和重试入口；重试不得改变当前请求身份或回退到猜测名称。
- **FR-008**：版本或规范化工点集合切换时，系统必须隔离缓存与在途请求，旧响应不得覆盖当前映射。
- **FR-009**：相同请求身份的成功结果可在当前页面生命周期内复用，失败结果不得作为成功缓存复用。
- **FR-010**：既有逐工点详情能力仍须保持现有业务响应语义；本功能不得改变项目主数据导入、确认、版本状态或其他页面的详情展示行为。
- **FR-011**：共享契约必须明确批量请求、成功响应、请求工点缺失、版本不存在和通用服务失败的状态及前端处理，不得依赖错误文本解析业务状态。
- **FR-012**：系统必须提供后端精确读取/批量投影、前端协调器和真实浏览器 DOM 行为验证，覆盖正常、空集合、缺失工点、失败重试、缓存命中、版本/集合切换及旧响应晚到。
- **FR-013**：现有任务名称权威来源、原子展示、错误/重试、版本隔离和原始 ID 零泄漏验收必须保持通过。

### 关键实体（涉及数据时填写）

- **任务视图主数据请求身份**：由项目主数据版本 ID 与规范化工点 ID 集合组成，用于请求、缓存和竞态隔离。
- **任务视图显示映射**：当前请求身份下，任务视图展示工点、桥梁、工区和幅别名称所需的最小权威数据集合。
- **显示映射加载状态**：加载中、就绪或失败；就绪状态只承载通过完整性校验的完整映射。

## 成功标准（必填）

### 可衡量结果

- **SC-001**：在现有本地运行基线（13 工点、1586 任务、服务已启动）下，连续 3 次硬刷新从显示映射加载开始到完整权威任务 DOM 就绪均不超过 5 秒。
- **SC-002**：同一基线的一次任务视图加载最多发起 1 次权威显示映射业务请求，返回体不超过当前 13 个逐工点详情响应合计 2.21 MB 的 20%。
- **SC-003**：成功加载时 1586 条任务一次性提交，页面中原始 `bridge_id`、`work_section_id`、章节代码和占位符冒充最终名称的次数均为 0。
- **SC-004**：失败重试、版本切换、工点集合切换和旧响应晚到的自动化场景全部通过，部分映射提交次数为 0，旧身份覆盖当前结果次数为 0。
- **SC-005**：项目主数据现有导入、版本、列表、单工点详情，以及任务视图既有正常/异常浏览器行为回归全部通过。

## 默认假设

- 性能验收复用仓库现有任务视图运行基线、同一开发机和已启动的本地服务，以降低环境差异；不把公网网络延迟计入本期指标。
- 本期允许新增或调整任务视图专用共享读取契约，但不改变持久化结构和主数据内容。
- 现有逐工点详情接口可能被其他页面使用，因此默认保留其对外业务语义；内部查询可按最小范围优化。
- 任务视图仍采用“全部权威名称就绪后一次性展示”，不采用渐进渲染作为性能替代方案。
