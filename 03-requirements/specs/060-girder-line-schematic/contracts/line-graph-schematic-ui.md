# 契约：架梁线路示意图派生与展示

## 范围

本契约约束现有线路图 API 输出在后端派生和前端展示中的行为。不新增 API 路径、请求字段、响应字段或持久化结构。

## 后端输出契约

1. 有效连续梁每幅输出三个有序节点：
   - `bridge_segment_kind=approach_small`
   - `bridge_segment_kind=continuous`
   - `bridge_segment_kind=approach_large`
2. 三个节点保留既有字段：`node_id`、`project_master_workpoint_id`、`side`、`alignment_code`、`start_mileage_m`、`end_mileage_m`、`spatial_group_id`、`display_order`、`source_refs`、`beam_demands`。
3. 三段边界是本幅归一化示意投影；不得生成 `BRIDGE_SEGMENT_LENGTH_MISMATCH` 或等价诊断。
4. 长度差异不得使 `LineGraphSnapshot.status` 变为 `blocking`。
5. 缺失跨序、无效结构长度、多连续区块、缺失前后引桥、连续结构预制梁冲突和无效起终里程继续使用现有诊断代码和严重级别。
6. 节点或边变化继续进入既有线路图指纹；旧方案失效行为不变。

## 前端输入分类契约

| 分类 | 条件 | 展示角色 |
|---|---|---|
| 左幅主线 | `side=left` 且标准化前缀为 `ZK` | 左幅连续线路 |
| 右幅主线 | `side=right` 且标准化前缀为 `K` | 右幅连续线路 |
| 互通支线 | 标准化前缀不是 `ZK` 或 `K` | 空间组内支线层 |
| 兼容主线 | 前缀缺失且已有 `side` | 暂留对应主线并显示既有数据诊断 |
| 梁场 | 方案梁场存在有效部署节点 | 线路外场站标记 |

## 前端展示契约

- 主体只有 ZK 左幅和 K 右幅两条连续水平主线。
- 路基使用基线，不显示圆形图标或独立卡片。
- 桥梁、隧道使用不同的粗线区段；连续梁三段在桥梁区段内部可区分。
- AK、BK、B1K 等支线不得叠加为主线普通区段，必须显示前缀并由连接线锚定空间组。
- 梁场在线路外展示名称与中心里程，不占据线路区段。
- 工点名称无边框；密集时上下错行、省略，原生悬浮提示展示完整名称。
- 单幅缺少对应工点时不渲染占位框。
- 页面不显示长度不一致提示，也不显示三段示意边界的精确工程里程声明。

## 空态与失败态

- 没有可展示节点时沿用现有线路图空态。
- 支线为空时不渲染支线层。
- 梁场为空时不保留额外垂直空间。
- 其他 blocking 诊断继续显示，不因本契约隐藏。

## 兼容性

- 现有 API 客户端和前端 TypeScript 类型无需迁移。
- 已保存方案中的节点引用如果因三段节点变化失效，必须通过现有指纹和方案失效流程要求用户重新保存与计算。
- 不恢复方案级人工连接选择入口；后端历史字段仅按既有兼容行为保留。
