# 项目资源清理契约

## GET `/api/demo-scenario`

### 响应

- `ScenarioInput.resource_pools` 允许为空。
- 返回数组只包含当前有效的工点独享池。
- bundled 默认配置和本地配置中的共享记录均不得出现在响应中。
- 本地配置若包含共享记录，服务在成功响应前完成限定清理和原子写回。

### 失败

- 本地配置无法解析、校验或原子写回时返回 HTTP 503，`detail` 使用现有 `LocalScenarioConfigError` 文本。
- 失败时不得返回仍含共享记录的项目场景作为成功结果。

## PUT `/api/local-scenario-config`

### 请求

- `resource_pools` 必填但允许 `[]`。
- 为兼容旧客户端，请求仍可解析 `PROJECT_SHARED` 记录。

### 成功响应

- 服务删除请求中的全部共享记录并保存剩余工点独享池。
- `response.resource_pools` 只包含工点独享池，允许为空。
- 不把被删除共享记录的数量、上限、范围或其他字段转移到工点资源。
- 重复提交清理后的同一请求保持幂等。

### 失败

- 工点独享记录自身不合法、ID/工点类型键重复或原子写入失败时返回 HTTP 503。

## 正常项目计算输入

- 前端对 `/api/demo-scenario` 响应和保存响应执行资源标准化后，只向任务生成、固定资源求解、增配、最少资源和 AI 参数流程传递工点独享池。
- 本功能不改变求解 API schema，也不要求求解器拒绝或忽略调用方显式构造的共享池。

## Demo API 参考镜像

- `04-demo/tools/demo-api-mirror/api.mts` 的默认场景、缓存合并、保存响应和正常生成输入遵守同一“项目资源只含工点独享池”契约。
- 镜像底层共享匹配函数保留，不作为当前项目数据来源。
