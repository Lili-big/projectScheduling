**功能目录/分支**：`048-workpoint-first-resource-allocation`

**创建日期**：2026-07-18

**状态**：已实施，R3 收口受外部仓库门禁阻断

**输入**：将资源配置主轴改为按工点维护资源数量，并支持同一种资源类型建立多个范围共享资源池；共享实例在各自选定工点集合内以零转场时间和零转场成本互斥流转，同时兼容既有项目共享配置。

## 用户场景与测试

### 用户故事 1 - 按工点维护当前资源（优先级：P1）

计划工程师先选择桥梁工点，再维护该工点可以投入的资源。每条工点资源记录只表达该工点的当前投入、可增上限和启用状态，不再反向勾选“该资源适用于哪些工点”。页面默认列出该工点任务可能使用的资源，也允许从统一资源目录补充其他资源类型。

**优先级理由**：工点主轴是本功能的核心产品改变，也是后续候选生成、共享补位和诊断的输入基础。

**独立测试**：选取两个桥梁工点，分别维护不同资源及数量，保存并重载后核对工点、资源类型、当前投入、可增上限和启用状态均保持，且页面不存在资源适用工点勾选。

**验收场景**：

1. **假设**工点 A 的任务可能使用旋挖钻和汽车吊，**当**用户进入 A 的资源配置，**则**默认看到这两类资源，并可直接维护各自的 `quantity`、`max_quantity` 和启用状态。
2. **假设**资源目录中存在发电机但 A 的当前任务未自动推导出该类型，**当**用户从资源目录补充发电机，**则**A 新增一条工点资源记录，不改变其他工点。
3. **假设**用户把 A 的旋挖钻 `quantity` 设为 0，**当**保存并重新加载，**则**系统仍保留该记录及其上限，但当前投入明确显示为“没有该资源”，不得解释为默认充足或项目共享。
4. **假设**当前项目主数据版本没有桥梁工点，**当**用户进入页面，**则**系统展示空态，不创建虚构工点，也不展示架桥机或梁场配置。

---

### 用户故事 2 - 只为任务提供合法资源候选（优先级：P1）

计划工程师生成任务和排程时，系统先使用任务所属工点的本地资源，再合并所有允许该工点使用的共享池实例。没有本地资源且没有合法共享资源的受限任务必须被阻断，并准确指出缺口所在工点、任务和资源类型。

**优先级理由**：候选正确性决定排程是否真实可执行；把数量 0 当成默认充足会直接形成错误计划。

**独立测试**：构造一个有本地资源、一个仅有共享资源、一个两者都没有的三工点样例，核对候选集合、阻断状态和诊断实体引用。

**验收场景**：

1. **假设**A 的资源 X 当前投入大于 0，且 A 同时属于两个 X 共享池，**当**生成候选，**则**A 的 X 任务可获得 A 本地实例和两个共享池的合法实例，候选不包含其他工点本地实例。
2. **假设**B 的资源 X `quantity=0`，但 B 属于一个当前投入大于 0 的 X 共享池，**当**生成候选，**则**B 只能获得该共享池实例，不得生成 B 本地实例。
3. **假设**C 的资源 X `quantity=0`，且没有任何启用、范围匹配且当前投入大于 0 的 X 共享池，**当**生成当前资源排程，**则**系统阻断并给出 C、具体任务和 X 的诊断。
4. **假设**任务所属工点身份缺失或已不属于当前项目主数据版本，**当**生成候选，**则**系统阻断并指出身份问题，不按名称或 ID 格式猜测归属。

---

### 用户故事 3 - 建立多个独立范围共享池（优先级：P1）

计划工程师在独立的共享资源池区域中，可以为同一种资源类型建立多个池。每个池单独维护名称、当前投入、可增上限、启用状态和可流转工点集合；集合可以重叠。“全部工点”表示面向当前项目全部桥梁工点的全项目共享语义。

**优先级理由**：多池和范围共享是相对 047 的关键新增能力，直接决定资源能否按施工组织边界复用。

**独立测试**：为同一资源类型建立两个范围不同且部分重叠的共享池，运行无前置的跨工点任务，核对候选、实例互斥、自动顺序和零转场。

**验收场景**：

1. **假设**同类型资源有共享池 P1（A、B）和 P2（B、C），**当**生成候选，**则**A 只可用 P1，B 可用 P1 和 P2，C 只可用 P2，各池数量和上限互不覆盖。
2. **假设**P1 只有一个实例且 A、B 各有一个可用该实例的任务，**当**求解，**则**两个任务不能同时占用该实例，使用先后由求解器确定。
3. **假设**共享实例从 A 的任务转到 B 的任务，**当**计算计划，**则**不增加转场持续时间或费用，结果明确记录本期二者均为 0。
4. **假设**工点 C 不在 P1 的范围内，**当**生成 C 的任务候选，**则**P1 的任何实例都不得成为候选。
5. **假设**用户选择“全部工点”，**当**当前项目主数据中的桥梁工点集合变化，**则**该池继续表达全项目共享，不因保存时的列表快照丢失语义。

---

### 用户故事 4 - 兼容旧配置并保持下游一致（优先级：P2）

计划工程师打开旧项目、使用 AI 资源助手、保存方案或查看计划结果时，系统在配置、快照、指纹、建议和诊断中保持新的工点资源与多共享池语义。旧项目共享配置继续作为一个共享池读取，不拆成各工点资源，也不丢失数量、上限或已有限定范围。

**优先级理由**：兼容和下游一致性避免新页面正确、旧数据或后续计划错误的割裂状态。

**独立测试**：加载旧项目共享配置，保存、生成任务、生成 AI 建议、形成计划快照并修改共享池范围，核对迁移结果、稳定指纹、旧结果失效和历史快照保留。

**验收场景**：

1. **假设**旧项目资源 X 为项目共享且数量为 2、上限为 4、范围为 A/B，**当**新版本读取，**则**得到一个 X 共享池，仍为 2/4、仍只覆盖 A/B，不生成 A/B 两份工点资源。
2. **假设**旧项目共享配置没有显式范围，**当**读取，**则**按“当前项目全部桥梁工点”的全项目共享语义处理。
3. **假设**资源助手提出数量建议，**当**建议对应工点资源或某个共享池，**则**建议必须携带唯一目标身份，不得只按资源类型合并同类型多个池。
4. **假设**工点资源、共享池数量或共享范围变化，**当**系统判断旧任务图、求解结果、AI 解释、方案比较或计划快照是否仍为当前结果，**则**旧结果全部失效但历史记录保留。

### 边界与异常场景

- 同一工点同一资源类型最多有一条本地资源记录；重复输入必须被拒绝或确定性合并并给出诊断，不能静默累加。
- 同一资源类型允许多个共享池；共享池以独立稳定身份区分，池名称重复时不得据名称合并。
- 同一工点可以同时属于同类型多个共享池；任务获得所有合法候选，但每个池的实例和容量独立。
- `quantity`、`max_quantity` 必须为非负整数，且标准化后 `max_quantity >= quantity`；数量 0 只表示当前无实例，不得表示 `UNLIMITED`。
- 处于停用状态的工点资源或共享池不生成当前候选；它与数量 0、范围不匹配和资源类型不存在必须使用不同诊断原因。
- 工点被删除、项目主数据版本切换或旧响应晚到时，旧工点资源和共享范围不得静默应用到新版本。
- 共享池范围显式为空时不得保存为可用池；“全部工点”必须是独立语义，不得与显式空集合混淆。
- 共享池实例之间、共享池与工点本地实例之间互不替代数量；求解器只能在任务合法候选中选择实例。
- 当前资源排程中数量为 0 且无合法共享候选必须阻断；增配或最少资源分析可以在 `max_quantity` 范围内形成建议，但建议未被采纳前不得把当前计划标记为可执行。
- 047 已存在但不属于“既有项目共享配置”的其他历史形态不得静默丢弃或改写；若无法无损映射到工点资源或共享池，必须保留原数据并给出迁移阻断诊断。

## 需求

### 功能需求

- **FR-001**：系统必须以当前项目主数据版本的桥梁工点作为资源配置一级对象。
- **FR-002**：每个工点资源记录必须包含工点身份、资源类型、`quantity`、`max_quantity` 和启用状态；同一工点同一资源类型最多一条。
- **FR-003**：工点资源页面必须默认展示该工点任务根据现有工艺和任务需求可能使用的资源类型。
- **FR-004**：用户必须能够从统一资源目录向当前工点补充资源类型；补充操作不得修改其他工点或共享池。
- **FR-005**：工点资源页面不得提供“该资源适用于哪些工点”的勾选或等价反向范围配置。
- **FR-006**：工点资源 `quantity=0` 必须表示当前没有该资源，不生成当前本地实例，也不得被解释为默认充足、无限资源或共享资源。
- **FR-007**：工点资源的 `max_quantity` 必须表示该工点该资源允许建议或增配的上限，并保持不小于 `quantity`。
- **FR-008**：系统必须在独立共享池区域维护共享池，而不是把共享范围混入工点资源记录。
- **FR-009**：每个共享池必须具有稳定唯一身份、资源类型、显示名称、`quantity`、`max_quantity`、启用状态和可流转工点范围。
- **FR-010**：系统必须允许同一种资源类型建立多个共享池；各池数量、上限、状态和工点范围必须互相独立。
- **FR-011**：同一工点必须允许同时属于同类型多个共享池，且任务获得所有范围匹配池的合法候选。
- **FR-012**：共享池的“全部工点”必须表达当前项目全部桥梁工点的动态全项目共享语义；显式工点集合只允许集合内工点使用。
- **FR-013**：共享池范围外的工点不得获得该池任何资源实例作为候选。
- **FR-014**：任务候选必须由任务资源类型、权威工点身份、该工点当前本地实例和所有合法共享池实例共同决定，不得解析名称或 ID 格式推断归属。
- **FR-015**：受限任务没有任何当前合法候选时必须阻断任务生成或求解，并在诊断中同时标识工点、任务和资源类型。
- **FR-016**：诊断必须区分本地数量为 0、资源停用、共享池停用、共享范围不匹配、工点身份失配和资源类型未配置。
- **FR-017**：每个工点本地实例只能服务所属工点；不得成为其他工点任务候选。
- **FR-018**：同一共享实例同一时间最多服务一个任务，跨工点使用必须保持容量互斥。
- **FR-019**：共享实例在合法工点之间的使用顺序必须由求解器在现有目标和约束下决定，不提供人工指定顺序配置。
- **FR-020**：本期共享资源跨工点转场时间和转场成本必须均为 0，且不得根据距离、名称或 ID 推导非零值。
- **FR-021**：配置页、生成诊断和结果解释必须明确展示共享池身份、允许工点范围以及零转场时间和成本限制。
- **FR-022**：固定资源的当前排程必须按各工点资源和共享池的 `quantity` 展开实例；数量为 0 的记录不展开当前实例。
- **FR-023**：增配或最少资源分析必须以对应记录的 `max_quantity` 为上界并保留目标身份；建议不得在未采纳时自动改写当前投入或解除当前计划阻断状态。
- **FR-024**：既有项目共享配置必须统一读取为一个共享池，不拆分到工点，并保留 `quantity`、`max_quantity`、启用状态、日历、成本和已有工点范围。
- **FR-025**：既有项目共享配置缺少显式工点范围时，必须按当前项目全部桥梁工点的全项目共享语义读取。
- **FR-026**：无法无损映射的其他历史资源形态不得被静默丢弃或改写；系统必须保留原数据并输出迁移阻断诊断。
- **FR-027**：工点资源、共享池及其范围必须进入标准持久化、方案快照、AI 资源方案、计划快照和稳定指纹。
- **FR-028**：工点资源或共享池的身份、数量、上限、状态、范围或日历变化后，旧任务图、求解结果、AI 解释、方案比较和计划当前性必须失效。
- **FR-029**：AI 资源助手可以建议已有工点资源或已有共享池的数量，但不得新增工点、改变共享范围、合并同类型多个池或自动改变资源归属。
- **FR-030**：前后端、求解、持久化和助手必须使用同一组工点资源与共享池语义，不得各自维护平行权威模型。
- **FR-031**：项目主数据版本切换后，旧版本工点资源、共享范围和晚到响应不得应用到新版本。
- **FR-032**：系统必须为工点主轴、目录补充、数量 0 阻断、多共享池重叠范围、共享互斥、零转场和旧项目共享兼容提供可复现验收样例。
- **FR-033**：系统不得在本功能中引入架桥机、梁场、非零转场、人工流转顺序、调拨审批、跨项目共享、单机台账、维修或班次管理。

### 关键实体

- **资源目录项**：项目可配置的标准资源类型及展示信息，是工点补充资源的来源，不代表实际投入或共享范围。
- **工点资源配置**：某一桥梁工点对某一资源类型的本地投入，包含当前数量、可增上限和启用状态。
- **范围共享资源池**：具有独立身份、数量、上限和获准工点范围的共享容量；同类型可以存在多个池。
- **命名资源实例**：由工点资源配置或共享池当前数量展开的可互斥分配实例，携带明确来源和合法工点范围。
- **任务资源需求**：任务所需资源类型与权威工点身份，用于筛选本地及共享候选。
- **资源缺口诊断**：描述受阻任务、所属工点、所需资源以及缺失原因的可追溯结果。
- **旧项目共享配置**：缺少新结构但仍表达项目共享总量及范围的历史配置，迁移后保持单一共享池语义。

## 成功标准

### 可衡量结果
