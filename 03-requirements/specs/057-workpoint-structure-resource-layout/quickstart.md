# 快速验证：工点结构物与资源左右分栏配置

## 前置条件

- 使用仓库现有前端依赖，不安装新包。
- 准备一个已确认桥梁工点详情，至少包含桩基、承台和墩身；推荐再包含两种桩径或工艺。
- 本地服务如需启动，严格按 `04-demo/runtime/README.md` 操作。
- 验证前记录当前工点 `resource_pools`，用于确认只读结构汇总不会隐式写入。

## 1. 定向自动化验证

在仓库根目录依次执行：

```powershell
node --test 04-demo/frontend/tests/resourceWorkpointScope.test.mjs
node --test 04-demo/frontend/tests/resourceWorkpointRuntime.test.mjs
npm.cmd --prefix 04-demo/frontend run typecheck
npm.cmd --prefix 04-demo/frontend run build
python 00-governance/repository-tools/validate_docs.py
```

运行时测试只尝试一次。若业务断言失败，修正后在同一任务范围内复验；若证据证明仅为页面加载前的系统浏览器/CDP 环境故障，则记录日志并以领域测试、源码契约、类型检查和构建覆盖核心目标。

## 2. 结构物汇总场景

准备以下样例并选择对应工点：

| 构件 | 参数/工艺 | 数量 | 预期 |
|---|---|---:|---|
| 桩基 | 旋挖钻、直径 1.8m | 3 根 + 2 根 | 合并为一项，总数 5 根 |
| 桩基 | 冲击钻、直径 1.8m | 2 根 | 与旋挖钻分开 |
| 承台 | 3m、4m、12m | 1 个 + 1 个 | 合并为 `3×4×12m×2个` 等价文本 |
| 墩身 | 高 12m / 高 18m | 各 1 个 | 同分类下两项 |
| 柱系梁、桩系梁、盖梁 | 任意有效参数 | 各一项 | 按固定顺序落在各自分类 |

同时验证：禁用构件、数量 0 构件和非六类构件不显示；参数或工艺缺失时不编造数值，仍保留有效数量的诊断性汇总。

## 3. 左右布局与资源简化

1. 打开“资源配置”并选择有结构的桥梁工点。
2. 在桌面宽度下确认左侧为“结构物信息”，右侧为“资源配置”。
3. 缩窄窗口，确认结构物信息先于资源配置纵向排列，无横向 900px 表格滚动要求。
4. 检查右侧不显示资源类型代码、资源字段表头、状态列或启用开关。
5. 检查资源仍使用中文名称；两个数字控件可由读屏名称或悬浮提示区分当前投入和可增上限。
6. 检查从目录补充和显式删除仍作用于当前工点。

## 4. 数量派生启用状态

对同一当前工点资源执行：

1. 当前投入设为 0、可增上限设为正数并保存，确认保存数据中 `enabled=false`。
2. 当前投入改为 2 并保存，确认 `enabled=true` 且 `max_quantity>=2`。
3. 当前投入再改回 0 并保存，确认 `enabled=false`，记录仍保留直到显式删除。
4. 构造历史矛盾记录（`quantity=2, enabled=false` 或 `quantity=0, enabled=true`），确认页面按数量解释，并在相关保存后收敛为一致字段。

## 5. 建议不自动配置

1. 打开一个没有工点资源池但有结构匹配建议的工点。
2. 确认建议资源显示 0 当前投入和 0 可增上限。
3. 只查看左侧汇总并切换工点，不编辑资源。
4. 重新加载场景，确认没有新增资源池，也没有因结构数量自动填充资源数量。

## 6. 当前详情身份与异常

1. 快速切换工点 A → B，并让 A 的详情后返回；左右两块都必须保持 B 的数据。
2. 模拟详情失败，确认错误和重试入口出现，且不显示全项目资源建议。
3. 选择没有六类有效构件的工点，确认左侧显示结构空态；若该工点已有资源记录，右侧继续显示并可编辑。

## 7. 非回归边界

- 不出现共享资源配置区，也不创建 `PROJECT_SHARED`。
- 不出现预制梁班组；架梁班组等既有非本次目标资源行为不被结构汇总改写。
- 不新增后端 API、持久化字段、项目主数据变更或求解器规则。
- `git diff` 只包含 tasks 明确列出的规格、前端源码和测试路径；无关脏工作树改动保持原样。
