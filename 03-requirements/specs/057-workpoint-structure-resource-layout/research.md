# 研究结论：工点结构物与资源左右分栏配置

## 1. 工点结构汇总的数据来源

**决策**：复用当前资源页已经请求的单工点详情，不新增接口或全项目扫描。

**依据**：`ProjectMasterWorkpoint.structures[].components[]` 已包含构件类型、名称、数量、单位、启用状态与参数；结构本身也包含参数。`ResourcesTab` 已用当前 `project_data_version_id + workpoint_id + 请求序号` 管理详情状态。

**替代方案**：从已生成排程任务反推结构数量。未采用，因为任务可能尚未生成或因配置失败而缺失，且会让主数据汇总依赖求解链路。

## 2. 汇总维度和目标类型

**决策**：只处理用户点名的六类有效构件，并按以下页面名称和顺序显示：

| 构件类型 | 页面名称 | 顺序 |
|---|---|---:|
| `pile` | 桩基 | 1 |
| `cap` | 承台 | 2 |
| `middle_tie_beam` | 柱系梁 | 3 |
| `pier_body` | 墩身 | 4 |
| `ground_tie_beam` | 桩系梁 | 5 |
| `cap_beam` | 盖梁 | 6 |

只统计 `enabled=true` 且 `quantity>0` 的构件。汇总键为“构件类型 + 规范化参数 + 解析工艺 + 单位”，相同键累加数量。

**理由**：类型先分类满足用户阅读顺序；参数、工艺或单位不同会影响资源判断，不能合并。零数量或禁用构件不代表实际结构规模。

**替代方案**：按结构 ID 或构件名称逐条展示。未采用，因为无法提供用户要求的汇总，且会重复项目主数据页面。

## 3. 参数规范化与紧凑显示

**决策**：参数签名使用稳定的 `parameter_code + 规范化值 + unit`，忽略参数输入顺序。施工方法参数不重复进入结构参数签名。展示优先处理 `diameter_m`、`length_m`、`width_m`、`height_m`、`dimensions_m`、`form` 等现有物理/形式参数：

- 桩径显示为 `φ{数值}`，同为米时不重复尾随单位；
- 连续尺寸按稳定顺序使用 `×` 连接，并合并相同单位后缀；
- 文本形式作为单独片段；
- 数值去掉无意义尾零，单位使用主数据提供值或参数代码中可确认的既有单位；
- 其他非空参数仍进入签名，展示时以值和单位形成可读片段；缺失值不编造。

**理由**：签名需要确定性以保证正确合并；展示需要接近“旋挖钻-φ1.8×5根”“3×4×12m×2个”的业务速读方式。

**替代方案**：直接拼接参数 JSON 或英文代码。未采用，因为会暴露技术结构且不适合业务估算。

## 4. 施工工艺解析

**决策**：复用 feature 050 的边界：构件显式工艺优先，其次结构显式工艺；都缺失时仅允许使用同构件类型唯一默认工艺。显式标识无法匹配时保留原值或显示“工艺未识别”，不替换为任意工艺。

**理由**：左右两块必须对同一构件采用一致工艺认知，并避免多默认工艺时猜测。

**替代方案**：只显示资源类型名称或直接取工艺库第一项。未采用，因为资源名称不等于施工工艺，任意第一项会制造错误汇总。

## 5. 资源启用语义

**决策**：保留 `ResourcePool.enabled` 公共字段，但在 `normalizeResourcePoolForWorkspace` 对带明确 `workpoint_id` 的 `WORKPOINT_EXCLUSIVE` 记录设置 `enabled = normalizedQuantity > 0`。共享/旧兼容范围不应用该派生规则。页面删除启用开关，所有新增和编辑也由数量产生一致状态。

**理由**：用户明确数量 0 即不启用、非 0 即启用；集中在现有规范化入口可覆盖新增、编辑、载入和送往后续流程的工点资源，避免只在一个输入事件中修正。

**替代方案**：删除 `enabled` 字段。未采用，因为会破坏现有前后端、演示镜像和求解输入兼容契约。

## 6. 页面布局与字段简化

**决策**：工点导航和目录补充保持在双栏上方；详情就绪后，左侧为结构物汇总，右侧为资源列表。桌面左右并排，窄屏结构在前、资源在后。资源项不再使用可见表头或状态列，不显示类型代码；保留中文名称、两个数字输入、添加/删除动作和非可见无障碍说明。

**理由**：满足同屏对照，同时不牺牲键盘/读屏识别和现有人工补充能力。

**替代方案**：保留表格并只删启用列。未采用，因为仍保留用户明确不需要的字段表头，左右并排时也会造成不必要横向滚动。

## 7. 验证策略

**决策**：核心证据为纯领域样例、页面源码契约、类型检查和生产构建；现有真实浏览器运行时场景更新后只尝试一次。业务相关失败必须修正；仅当证据证明失败发生在业务页面加载前的系统浏览器/CDP 环境时，记录为剩余风险而不偏离核心目标。

**理由**：结构分组和数量语义可确定重复验证；真实浏览器仍有布局与交互价值，但已有环境故障历史，不能无限深究非核心设施。

## 8. 未决项

无阻断实施的未决项。具体视觉间距、左右宽度比例和断点沿用当前页面设计系统，在不改变上述信息层级和验收语义的前提下由实施确定。
