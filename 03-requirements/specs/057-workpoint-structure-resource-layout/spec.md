# 功能规格：工点结构物与资源左右分栏配置

**功能目录/分支**：`057-workpoint-structure-resource-layout`

**创建日期**：2026-07-21

**状态**：已实施

**输入**：用户要求在选择工点后，以左右分栏同时展示结构物汇总和资源配置；结构物按类型、参数与施工工艺汇总，资源区去掉可见字段表头、技术代码和启用开关，并以数量是否为 0 判定启用状态。

## 来源与评审上下文（必填）

- **来源文档**：本次用户请求及截图（2026-07-21）；`03-requirements/specs/048-workpoint-first-resource-allocation/`；`03-requirements/specs/049-remove-shared-resource-mode/`；`03-requirements/specs/050-structure-matched-resource-catalog/`；`03-requirements/specs/052-exclude-precast-beam-team/`。
- **评审结论**：需求目标与范围明确；结构物汇总用于辅助人工估算资源，不自动推导资源数量。现有工点详情已提供构件类型、数量、单位、参数和工艺标识，无需新增后端读取接口。
- **使用的 Demo/代码事实**：`ResourcesTab.tsx` 已按当前版本和所选工点加载详情；`ProjectMasterWorkpoint` 已包含结构、构件、数量、单位和参数；`resources.ts` 已实现结构工艺到资源类型的建议投影；工点资源仍保存为 `WORKPOINT_EXCLUSIVE` 资源池，并保留 `quantity`、`max_quantity` 与兼容字段 `enabled`。
- **不在范围内**：自动计算或推荐具体资源数量；修改工艺库、项目主数据结构、后端 API 或求解目标/约束；恢复共享资源；展示上部结构、桥台、扩大基础、梁场或预制梁生产班组的结构汇总；新增资源字段或迁移历史记录。

## 用户场景与测试（必填）

### 用户故事 1 - 结合结构物汇总估算资源（优先级：P1）

项目策划人员选择一个桥梁工点后，在页面左侧直接看到该工点下与下部结构施工有关的汇总信息，不必回到项目主数据逐条统计构件，即可结合结构规模判断右侧资源投入是否合理。

**优先级理由**：这是本次改版的核心业务价值，也是用户估算资源数量所需的直接依据。

**独立测试**：构造包含不同桩径、不同桩基工艺、相同承台尺寸和多类下部结构的工点，验证页面按固定类型顺序展示，并只合并“类型、参数、工艺、单位”均相同的构件数量。

**验收场景**：

1. **假设** 当前工点存在 5 根直径 1.8m 且采用旋挖钻工艺的桩基，**当** 用户选择该工点，**则** 左侧桩基分类显示等价于“旋挖钻-φ1.8×5根”的汇总项。
2. **假设** 当前工点存在 2 个尺寸相同的承台，**当** 用户查看结构物信息，**则** 左侧承台分类显示等价于“3×4×12m×2个”的汇总项。
3. **假设** 同一工点存在参数或工艺不同的同类构件，**当** 页面汇总，**则** 不同组合分行展示，不得把数量错误相加。
4. **假设** 工点不存在某一目标结构类型，**当** 页面展示，**则** 不显示该类型的空分类。

---

### 用户故事 2 - 简化工点资源录入（优先级：P1）

项目策划人员在右侧紧邻结构物汇总的位置维护资源当前投入和可增上限。页面只保留中文资源名称与必要的数字输入，不再要求单独理解或操作启用状态。

**优先级理由**：资源录入必须与结构物判断同时完成；去除重复状态能降低配置复杂度并消除数量与启用开关互相矛盾的情况。

**独立测试**：对一个建议资源和一个已配置资源分别输入 0 与正整数，验证可见界面没有状态开关、技术类型代码和资源字段表头，并验证保存后的兼容启用字段始终与当前投入数量一致。

**验收场景**：

1. **假设** 工点资源当前投入为 0，**当** 用户保存配置，**则** 该资源被视为未启用，且不会因独立启用状态而进入有效资源配置。
2. **假设** 工点资源当前投入从 0 改为正整数，**当** 用户保存配置，**则** 该资源被视为已启用，无需额外勾选开关。
3. **假设** 页面显示建议或已配置资源，**当** 用户查看右侧资源区，**则** 主界面只显示中文资源名称和数字控件，不显示资源类型代码、状态列或启用开关。
4. **假设** 用户需要目录中未自动匹配的资源，**当** 用户从资源目录补充，**则** 该资源加入当前工点，仍遵循数量派生启用状态的规则。

---

### 用户故事 3 - 稳定切换与异常识别（优先级：P2）

项目策划人员快速切换工点或遇到详情加载失败时，始终看到与当前选择相符的结构和资源信息，且能明确重试或识别空数据。

**优先级理由**：左右两块共用同一工点详情，必须避免旧响应造成结构物与资源错配。

**独立测试**：模拟快速切换、详情加载失败和无目标构件三种状态，验证旧响应被丢弃、失败可重试、空态可辨识，且不退化为全项目资源建议。

**验收场景**：

1. **假设** 用户在前一个工点详情返回前切换到新工点，**当** 两个请求乱序返回，**则** 左右两块只展示新工点的数据。
2. **假设** 当前工点详情加载失败，**当** 页面进入失败态，**则** 显示错误和重试入口，不用全项目目录伪造结构汇总或默认资源建议。
3. **假设** 当前工点没有可汇总的目标构件，**当** 详情加载成功，**则** 左侧显示明确空态，右侧仍按既有规则保留当前工点已配置资源及人工补充能力。

### 边界与异常场景

- 只统计 `enabled=true` 且 `quantity>0` 的目标构件；禁用、零数量和非目标类型不进入结构汇总。
- 目标类型固定为桩基、承台、柱系梁、墩身、桩系梁、盖梁；页面名称分别对应 `pile`、`cap`、`middle_tie_beam`、`pier_body`、`ground_tie_beam`、`cap_beam`。
- 参数缺失时不得编造尺寸；保留已知工艺、已知参数和数量，完全没有可展示参数或工艺时使用“参数/工艺未提供”的可诊断文案。
- 工艺标识存在但无法匹配工艺库时显示原始非空标识或“工艺未识别”，不得任意选择另一种工艺。
- 相同汇总签名但单位不同的构件不得合并；小数数量和参数按现有有效精度展示，不增加无意义尾零。
- `max_quantity` 小于当前投入时仍按既有规则收敛到不小于当前投入；当前投入不得为负数。
- 数量为 0 只表示未启用，不等于删除资源记录；显式删除仍沿用既有操作和保留规则。
- 窄屏无法稳定左右并排时，结构物信息在前、资源信息在后纵向排列，不丢失字段和操作。

## 需求（必填）

### 功能需求

- **FR-001**：选择桥梁工点后，系统必须在同一内容区以左侧“结构物信息”和右侧“资源配置”两个区块展示当前工点信息；桌面宽度下左右并排，窄屏按结构物在前、资源在后排列。
- **FR-002**：结构物信息必须只读，并仅汇总桩基、承台、柱系梁、墩身、桩系梁和盖梁六类已启用且数量大于 0 的构件。
- **FR-003**：六类结构必须按桩基、承台、柱系梁、墩身、桩系梁、盖梁的固定顺序展示，仅在该分类有数据时显示分类。
- **FR-004**：系统必须按“结构物类型 + 规范化结构参数 + 施工工艺 + 单位”形成汇总签名；签名相同的构件数量相加，任一项不同则分别展示。
- **FR-005**：结构汇总必须以紧凑中文表达展示工艺、关键物理参数和合计数量；桩径使用 `φ` 表达，连续尺寸使用乘号连接，数量末尾保留原构件单位。
- **FR-006**：施工工艺优先读取构件的显式工艺参数，其次读取所属结构的显式工艺参数；没有显式值时可沿用当前资源建议的唯一默认工艺规则，但不得在多候选中任意选择。
- **FR-007**：系统不得因缺失参数或未识别工艺而丢弃仍有有效数量的目标构件；必须以省略缺失段或诊断文案的方式继续展示。
- **FR-008**：资源区必须继续展示结构匹配建议与当前工点已配置资源的并集，并保留从资源目录补充、当前投入、可增上限、保存和显式移除能力。
- **FR-009**：资源区不得显示资源技术类型代码、状态列、启用开关或资源字段表头；资源中文名称必须继续使用统一名称解析规则。
- **FR-010**：资源数字控件可以保留无障碍名称、提示或悬浮说明，以便区分当前投入和可增上限，但这些说明不得作为可见表格字段标题重复占用页面空间。
- **FR-011**：对 `WORKPOINT_EXCLUSIVE` 工点资源，业务启用状态必须由当前投入派生：`quantity=0` 时未启用，`quantity>0` 时启用；用户不得再独立修改启用状态。
- **FR-012**：保存或编辑工点资源时，系统必须将底层兼容字段 `enabled` 规范化为 `quantity>0` 的结果，避免数量与状态矛盾；不得删除该兼容字段或改变现有共享输入读取契约。
- **FR-013**：建议资源在用户未编辑或添加前仍是只读派生项，默认 `quantity=0`、`max_quantity=0`，不得仅因查看或切换工点而持久化。
- **FR-014**：结构汇总只为人工配置提供依据，不得自动填充、增加或修改资源的 `quantity` 或 `max_quantity`。
- **FR-015**：左右区块必须共用当前版本、当前工点的同一详情身份；加载、失败、空态、重试和乱序响应处理必须保持一致，旧版本或旧工点响应不得覆盖当前页面。
- **FR-016**：本功能不得创建 `PROJECT_SHARED` 资源，不得恢复共享资源页面，不得修改求解器目标、约束或资源候选规则；求解器只按保存后的一致工点资源配置执行既有逻辑。
- **FR-017**：历史工点资源记录必须保留；读取到 `quantity` 与 `enabled` 不一致的工点独享记录时，页面以 `quantity` 为业务真值，并在下一次相关编辑或保存时按 FR-012 收敛，不进行批量迁移或静默删除。

### 关键实体（涉及数据时填写）

- **结构物汇总分类**：当前工点的一类目标下部结构，包含固定中文名称、排序和若干汇总项。
- **结构物汇总项**：由构件类型、规范化参数、解析后的施工工艺和单位共同标识，包含合计数量和紧凑展示文本；仅为页面派生数据。
- **工点资源配置项**：当前工点下某一资源类型的中文展示名称、当前投入和可增上限；启用状态由当前投入派生，底层仍兼容现有资源池结构。
- **工点详情身份**：`project_data_version_id + workpoint_id + 最新请求序号`，用于保证结构汇总与资源建议来自同一当前选择。

## 成功标准（必填）

### 可衡量结果

- **SC-001**：在包含六类目标构件、重复参数组合和不同工艺组合的验收样例中，100% 汇总项的分类、签名、数量与预期一致。
- **SC-002**：用户选择任一有详情的桥梁工点后，可在一个页面视区内同时查看结构物依据和对应资源配置，无需切换功能页。
- **SC-003**：资源区可见界面中资源技术代码、状态列、启用开关和字段表头的出现次数均为 0；所有资源主名称均为既有统一中文名称。
- **SC-004**：针对数量从 0 改为正数、从正数改为 0，以及读取历史矛盾状态三个样例，保存后的 `enabled === (quantity > 0)` 通过率为 100%。
- **SC-005**：快速切换、加载失败、空结构三类页面状态均不会显示旧工点结构或用全项目目录伪造当前工点建议，定向回归测试全部通过。
- **SC-006**：实施不新增后端 API、持久化字段或求解器规则，现有工点资源定向测试、前端类型检查和生产构建通过。

## 默认假设

- “结构物信息”指所选桥梁工点下六类下部结构构件的汇总，不包含上部结构和非桥梁工点。
- 用户示例中的显示分隔符可按页面视觉规范使用 `×` 或等价紧凑符号；验收关注信息含义、顺序和合计正确性，不绑定单一字体字形。
- 施工工艺名称复用现有工艺库；缺失显式工艺时复用 feature 050 的唯一默认工艺判定，不新增第二套选择规则。
- “不展示资源字段名称”解释为不显示表格列标题或每项重复的可见字段标签；为可访问性保留 `aria-label`、`title` 或等价非占位语义。
- 本期只调整工点资源配置页面与前端派生/规范化逻辑，不进行历史数据批量迁移。
