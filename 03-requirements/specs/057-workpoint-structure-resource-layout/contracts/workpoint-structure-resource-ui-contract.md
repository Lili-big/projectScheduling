# 工点结构物与资源配置 UI 契约

## 1. 目标与边界

本契约定义资源配置页如何从当前工点详情派生结构物汇总、如何与工点资源并排展示，以及数量如何唯一决定工点资源启用状态。契约不新增公共 API，不修改项目主数据或求解器 schema。

## 2. 权威读取

继续使用：

```http
GET /api/project-master/versions/{version_id}/workpoints/{workpoint_id}
```

只有响应的 `version_id`、`workpoint_id` 和最新请求身份均与当前选择一致时，页面才可同时更新结构物汇总与资源建议。工点列表接口只用于导航，不能替代详情。

使用的既有字段：

- 结构：`structure_type`、`parameters`、`components`；
- 构件：`component_type`、`quantity`、`unit`、`enabled`、`parameters`；
- 参数：`parameter_code`、`value_type`、`value`、`unit`、`sort_order`；
- 工艺：当前 `scenario.process_library` 的 `id`、`method_id`、`process_name`、`component_type`、`is_default`。

## 3. 结构物汇总

### 3.1 分类映射

| `component_type` | 页面分类 | 顺序 |
|---|---|---:|
| `pile` | 桩基 | 1 |
| `cap` | 承台 | 2 |
| `middle_tie_beam` | 柱系梁 | 3 |
| `pier_body` | 墩身 | 4 |
| `ground_tie_beam` | 桩系梁 | 5 |
| `cap_beam` | 盖梁 | 6 |

只接受 `enabled=true` 且 `quantity>0` 的构件。其他构件、上部结构和空分类不展示。

### 3.2 工艺解析

1. 读取构件参数中的显式工艺标识；
2. 构件没有显式值时读取结构参数；
3. 都没有时，只选择同构件类型唯一默认工艺；
4. 显式值无法匹配时保留未知身份，不选择默认工艺；
5. 多个默认工艺时显示工艺未指定，不任意取第一项。

### 3.3 分组键

```text
component_type
+ normalized(non-method parameters)
+ resolved process identity
+ component unit
```

参数数组顺序、结构数组顺序和构件数组顺序不得改变等价输出。不同分组键不得合并；同一键的 `quantity` 相加。

### 3.4 展示格式

- 顺序为：工艺片段（若有）→ 参数片段（若有）→ 合计数量和单位；
- 工艺与参数可用短横线分隔，参数内部尺寸用 `×`；
- `diameter_m=1.8` 显示为 `φ1.8`，单位为米时可省略重复 `m`；
- 相同单位的连续尺寸只保留一个尾部单位，例如 `3×4×12m`；
- 数值去掉无意义尾零；文本形式保留非空业务值；
- 缺失参数不补零，完全缺失时显示诊断文案。

规范示例：

| 输入摘要 | 输出含义 |
|---|---|
| 桩基，旋挖钻，直径 1.8m，5 根 | `旋挖钻-φ1.8×5根` |
| 承台，尺寸 3m/4m/12m，2 个 | `3×4×12m×2个` |
| 墩身，高 12m 和 18m，各 1 个 | 同一“墩身”分类下两条不同汇总项 |

## 4. 页面布局

1. 工点导航保持在页面上方。
2. “从资源目录补充”保持在所选工点上下文内，并位于详情双栏上方或右侧顶部，不得脱离当前工点身份。
3. 桌面布局：左侧“结构物信息”，右侧“资源配置”；两侧分别滚动或自然增长，不要求资源表格的 900px 最小宽度。
4. 窄屏布局：结构物信息在前，资源配置在后纵向排列。
5. 加载和失败状态作用于同一当前详情；空结构只显示左侧空态，不删除右侧已配置资源。

## 5. 资源显示与编辑

- 可见资源为结构匹配建议和当前工点已配置资源的并集。
- 每项显示统一中文资源名称、当前投入数字控件、可增上限数字控件和适用的添加/删除操作。
- 不显示资源类型代码、表格列标题、状态列或启用复选框。
- 当前投入和可增上限必须通过 `aria-label`、`title` 或等价非可见语义保持可识别。
- 目录补充仍只创建当前工点、当前类型的唯一 `WORKPOINT_EXCLUSIVE` 资源。
- 只查看结构汇总、切换工点或加载建议不得创建资源池。

## 6. 数量与兼容启用字段

对规范工点独享资源：

```text
quantity = 0  => enabled = false
quantity > 0  => enabled = true
```

- 页面不得提供独立状态输入。
- 编辑当前投入时同步产生一致 `enabled`；统一资源池规范化再次保证该不变量。
- `max_quantity` 不决定启用状态，但不得小于 `quantity`。
- 数量为 0 不删除记录；显式删除沿用既有操作。
- 兼容字段 `enabled` 继续出现在现有前后端/演示镜像数据结构中。
- `PROJECT_SHARED` 的兼容读取不在本契约中改变。

## 7. 状态与异常

- **加载**：显示当前工点详情加载态；不保留上一工点结构汇总。
- **失败**：显示错误和重试；不使用全项目目录伪造当前工点建议。
- **结构空态**：显示“当前工点没有可汇总的下部结构信息”或等价文案；已配置资源与目录补充仍可用。
- **资源空态**：显示现有无匹配资源提示；不得自动写入 0 数量资源。
- **乱序响应**：旧版本或旧工点响应同时不得更新左、右区块。
- **历史矛盾状态**：若工点独享池 `quantity` 与 `enabled` 不一致，页面以数量派生值展示并在相关保存时收敛；不删除历史记录。

## 8. 验证契约

领域样例必须覆盖：六类顺序、相同签名累加、参数/工艺/单位差异分组、桩径、连续尺寸、禁用/零数量过滤、未知工艺、缺失参数、输入乱序确定性，以及三种数量/启用状态转换。

页面契约必须覆盖：双栏和窄屏类名/结构、无资源字段表头和技术代码、无启用控件、中文名称、无障碍输入语义、目录补充、显式删除、详情请求身份、失败/空态和建议不持久化。
