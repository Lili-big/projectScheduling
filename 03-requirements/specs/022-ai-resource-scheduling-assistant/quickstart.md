# 快速验证指南：AI资源配置与排程优化助手

## 前置条件

- 已安装后端和前端依赖。
- 当前仓库能运行默认桥梁施工排程 Demo。
- 本功能实现后，助手能读取当前 `ScenarioInput`，通过外部 LLM 或本地回退生成 A/B/C 资源方案。

## 本地启动

后端：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --app-dir backend --reload
```

前端：

```powershell
npm.cmd run frontend:dev
```

访问：

```text
http://127.0.0.1:5173/
```

## 验证场景 1：默认闭环

步骤：
1. 打开 Demo。
2. 使用当前项目样例或导入本地结构参数。
3. 进入 AI资源配置与排程优化助手。
4. 查看工程画像和 A/B/C 三张方案卡片。
5. 点击开始方案对比。

期望：
- 工程画像展示项目范围、控制墩候选、资源类型、连续梁相关结构。
- 三方案资源数量由 LLM 或本地回退一次性生成，且符合经济、平衡、抢工定位。
- 原 A/B/C 数值只作为参考样例影响生成，不要求输出完全等于参考样例。
- 每张方案卡展示生成来源、生成依据和施工组织策略。
- 三方案分别显示求解状态。
- 求解完成后展示指标对比表。
- 推荐解释引用至少 3 个指标证据。

## 验证场景 2：桩机按类型分类

步骤：
1. 使用包含多种桩基工艺资源的项目。
2. 查看 A/B/C 方案资源配置和生成依据。

期望：
- 旋挖钻、冲击钻、回旋钻等资源按类型分别显示 AI 生成或本地回退生成的数量。
- 资源利用率按类型分别统计。
- 不存在“桩机总数”覆盖所有工艺资源的展示。

## 验证场景 2a：参考样例不是固定方案

步骤：
1. 进入助手并触发三方案生成。
2. 查看 A/B/C 方案卡片的生成依据。

期望：
- 页面显示原 A/B/C 数值为参考样例或生成参考，不展示为正式固定方案。
- LLM 输出可以与参考样例不同，但必须有生成依据和校验提示。
- 用户确认前，任何 AI 初始方案都不得进入 CP-SAT 求解。

## 验证场景 3：控制墩专项视图

步骤：
1. 完成三方案求解。
2. 切换至控制墩专项视图。
3. 在 A/B/C 之间切换。

期望：
- 视图展示控制墩下部结构到连续梁相关任务的链路。
- 能看到控制墩释放时间和连续梁开工时间。
- 切换方案后视图刷新，不沿用上一方案数据。

## 验证场景 4：资源调整与结果失效

步骤：
1. 完成三方案求解。
2. 修改方案 B 的连续梁班组数量。
3. 查看对比表和推荐区域。
4. 重新求解方案 B。

期望：
- 方案 B 旧结果被标记为待重新求解。
- 推荐解释标记待更新。
- 重新求解后，方案 B 指标刷新，方案 A/C 不被错误覆盖。

## 验证场景 5：外部大模型回退

步骤：
1. 不配置资源方案生成和推荐解释相关外部大模型环境变量。
2. 进入助手并生成三方案。
3. 完成三方案求解并生成推荐解释。

期望：
- 系统使用本地回退生成三方案，并明确标识来源。
- 系统使用本地解释生成推荐说明。
- 推荐结论仍基于指标规则。
- 页面不要求用户配置密钥即可完成闭环。

## 验证场景 6：外部大模型启用

步骤：
1. 在 `.local.env` 中配置统一的 `PROCESS_NL_LLM_PROVIDER`、`PROCESS_NL_LLM_ENDPOINT`、`PROCESS_NL_LLM_MODEL`、`PROCESS_NL_LLM_API_KEY` 等变量；AI 资源助手默认复用这套配置。
2. 重启后端。
3. 完成三方案求解并生成推荐解释。

期望：
- 系统显示外部大模型已配置。
- A/B/C 初始资源方案和施工组织策略由外部大模型生成或增强。
- AI 解释由外部大模型生成或增强。
- 推荐方案仍由系统规则决定。
- 页面和日志不展示真实密钥。

补充：
- `AI_RESOURCE_ASSISTANT_*` 只作为可选覆盖项；留空或不设置时，继续使用 `PROCESS_NL_LLM_*`。

## 通过标准

- AI 三方案生成、资源配置校验、求解状态、指标对比和推荐解释形成完整闭环。
- 不可行、未知、失效和大模型失败均有清晰提示。
- 演示成本与转场惩罚均明确标识为演示/诊断口径。
- AI 不生成最终施工计划，不直接决定最优方案。
