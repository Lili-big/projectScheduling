# 功能规格：进度锁定重排三步闭环

**功能目录/分支**：`040-progress-forecast-closed-loop`

**创建日期**：2026-07-15

**状态**：草稿

**输入**：用户反馈在填写实际进度后，没有看到基于实绩的“锁定＋动态重排”能力，也没有看到关键节点预警；需要把页面完善为“保存实际进度 → 锁定实绩并重排剩余计划 → 查看关键节点预警与调整建议”的三步闭环。

## 来源与评审上下文（必填）

- **来源文档**：`AGENTS.md`、`agent.md`、`specs/027-baseline-progress-forecast/spec.md`、`specs/027-baseline-progress-forecast/plan.md`、`specs/039-progress-actual-date-defaults/`。
- **评审结论**：现有能力不是完全缺失，而是“保存成功后才解锁”的交互门槛不明显，当前趋势预测的锁定边界没有业务化表达，关键节点只以泛化风险文字出现。建议在复用既有计划版本、进度快照、滚动预测和调整方案实体的前提下补齐三步闭环。
- **使用的 Demo/代码事实**：当前页面只有在存在有效进度快照时才显示“滚动预测与按期风险”；后端已能冻结已完成任务、对进行中和未开始任务构造剩余计划、计算项目完工偏差和里程碑迟延，但前端没有结构化关键节点清单。当前错误只在顶部显示，日期与状态错误缺少行级阻断提示；未成功保存时不会产生可用于预测的进度快照。
- **不在范围内**：不重做基准计划确认流程；不新增第三方进度系统接入、移动端填报、正式审批权限、跨项目资源调拨；不改变 AI 三方案生成和基于 LLM 推荐资源的初始求解；不增加新的调整策略；不允许 LLM 改写实绩、排程结果或预警结论。

## 用户场景与测试（必填）

### 用户故事 1 - 保存可用于预测的实际进度（优先级：P1）

计划工程师在第一步填写任务状态、工程量和实际日期时，能够立即知道哪些内容有效、哪些内容会阻断保存。保存成功后，页面明确显示本次进度快照及下一步操作，不再让用户误以为表格中已填写的数据已经进入预测。

**优先级理由**：没有成功保存的进度快照，后续锁定、重排和预警都没有可信输入。

**独立测试**：分别填写有效进度、晚于状态日期的实际日期、缺少进行中任务剩余工期、同日更正四类数据，验证行级提示、保存结果、快照版本和第二步解锁状态。

**验收场景**：

1. **假设** 实际日期晚于状态日期，**当** 用户准备保存，**则** 对应任务行立即显示阻断原因，第一步不得标记完成。
2. **假设** 所有必填信息有效，**当** 用户保存进度，**则** 页面显示状态日期、修订号和保存成功状态，并解锁“锁定实绩并重排剩余计划”。
3. **假设** 保存请求失败，**当** 页面仍保留用户输入，**则** 系统必须明确说明“尚未形成进度快照”，不得展示或沿用上一轮预测作为本次结论。
4. **假设** 用户修改了已保存快照对应的页面数据但尚未再次保存，**当** 查看后续步骤，**则** 系统提示存在未保存变更并将既有预测标记为待更新。

---

### 用户故事 2 - 锁定实绩并重排剩余计划（优先级：P1）

计划工程师基于第一步保存的进度快照，主动发起一次当前趋势重排。系统清楚说明哪些任务已锁定、哪些任务只排剩余工作、哪些任务可以重新安排，并返回历史实际与未来预测组成的完整计划。

**优先级理由**：这是把现场实绩转化为未来计划的核心业务动作，也是用户当前最难感知的能力。

**独立测试**：构造包含已完成、进行中、暂停、未开始和取消任务的进度快照，执行重排后逐项核对历史日期、剩余工期、资源、恢复日期、未来开始日期和依赖诊断。

**验收场景**：

1. **假设** 已完成任务具有有效实际起止日期，**当** 执行重排，**则** 这些日期和实际状态保持不变，求解不得改写。
2. **假设** 任务正在进行，**当** 执行重排，**则** 系统保留其实际开始事实和已使用资源，仅从状态日期起安排剩余工作。
3. **假设** 暂停任务设置了恢复日期，**当** 执行重排，**则** 剩余工作不得早于恢复日期开始；缺少恢复条件时不得静默按正常任务立即开工。
4. **假设** 任务尚未开始，**当** 执行重排，**则** 其预测开始不得早于状态日期，并继续满足有效工艺逻辑、资源容量和既定当前趋势顺序。
5. **假设** 取消任务仍被后续任务依赖，**当** 执行重排，**则** 系统明确标出受影响任务和需人工确认的依赖，不得静默删除影响。
6. **假设** 剩余计划未得到可行结果，**当** 重排结束，**则** 页面保留已锁定实绩并说明未获得未来可行排程的原因，不生成虚假的预测日期。

---

### 用户故事 3 - 查看关键节点预警并进入调整（优先级：P1）

重排成功后，计划工程师能够查看项目完工节点和强制里程碑的目标日期、实际或预测日期、偏差、剩余缓冲、风险等级和主要影响原因，并从具体风险进入任务明细或调整方案比选。

**优先级理由**：只有把重排结果转换为明确的节点风险和行动入口，进度反馈才形成决策闭环。

**独立测试**：分别使用节点已完成、预测按期、缓冲不足、预测延期、无法评估五类数据，验证节点日期来源、风险状态、原因证据、排序和调整入口。

**验收场景**：

1. **假设** 强制里程碑范围已经全部完成，**当** 查看预警，**则** 节点使用实际完成日期判断，不再用剩余任务预测或显示“未评估”。
2. **假设** 节点预测日期超过目标日期，**当** 展示预警，**则** 系统显示“预计延期”、延期天数及主要影响任务或瓶颈资源。
3. **假设** 节点尚未延期但剩余缓冲不超过预警阈值，**当** 展示预警，**则** 系统显示“临近风险”及剩余缓冲天数。
4. **假设** 节点有充足缓冲，**当** 展示预警，**则** 系统显示“预计按期”，并保留目标与预测日期供核查。
5. **假设** 节点缺少匹配任务或剩余排程不可用，**当** 展示预警，**则** 系统显示“无法判断”及缺失原因，不误报为按期。
6. **假设** 存在多个风险节点，**当** 页面展示预警列表，**则** 已延期节点优先于临近风险节点，强制节点优先于一般节点。
7. **假设** 用户选择某个风险节点，**当** 查看详情或调整，**则** 能定位相关任务，并可继续进入既有调整方案比选流程。

### 边界与异常场景

- 状态日期不能早于项目计划开始日期或晚于当天；任何实际日期不能晚于状态日期。
- 页面填写态、已保存快照和已生成预测必须具有明确区别；浏览器中存在输入不代表后端已保存。
- 同一计划版本同一状态日期的再次保存继续走带原因的修订流程；新修订必须使旧预测失效。
- 当前生效计划版本变化后，旧进度快照、旧预测和旧预警不得继续作为当前结论展示。
- 已完成任务缺少实际起止日期、进行中任务缺少剩余工期依据时必须阻断保存；暂停任务缺少恢复日期时允许保存现场事实，但必须产生数据质量警告，并阻止输出确定性未来排程。
- 关键节点范围同时包含历史已完成任务和未来剩余任务时，节点日期必须由历史实际与未来预测共同计算。
- 节点目标早于状态日期但实际仍未完成时，必须显示已逾期，不得仅以未来预测日期计算风险。
- 求解超时、无解、服务不可达和存储失败必须分别表达；服务错误不得只显示无上下文的 `Failed to fetch`。
- 用户修改进度但未保存时，不自动发起耗时重排；只有明确操作后才生成新的预测。
- 项目没有配置强制里程碑时，仍展示项目计划完工节点，并说明没有可评估的强制里程碑。

## 需求（必填）

### 功能需求

- **FR-001**：页面必须以连续三步展示“保存实际进度”“锁定实绩并重排剩余计划”“查看关键节点预警与调整”，并为每一步显示未开始、可执行、执行中、已完成、失败或已过期状态。
- **FR-002**：第一步必须在保存前校验任务状态、完成比例、工程量、实际日期、剩余工期依据、恢复日期和原因，并将可定位到任务的问题显示在对应任务行。
- **FR-003**：第一步的页面校验规则必须与最终保存规则一致；实际日期晚于状态日期、完成日期早于开始日期等阻断错误不得等到生成预测时才暴露。
- **FR-004**：只有成功保存并返回当前有效进度快照后，第二步才可执行；页面必须展示快照的状态日期和修订号。
- **FR-005**：保存失败时必须明确区分网络不可达、字段校验、修订冲突和存储失败，并说明当前输入尚未进入重排。
- **FR-006**：第二步的主要操作名称必须直接表达业务动作“锁定实绩并重排剩余计划”，不得只使用“滚动预测”等需要用户自行理解的术语。
- **FR-007**：每次重排必须绑定当前活动计划版本和最新有效进度快照；任一输入变化后原预测与预警必须立即标记为已过期。
- **FR-008**：重排必须将已完成任务作为不可修改的历史事实，将进行中和暂停任务作为带实际状态的剩余工作，将未开始任务作为状态日期之后的未来工作。
- **FR-009**：进行中任务必须保留实际开始事实和已使用资源，并仅安排剩余工期；暂停任务必须遵守有效恢复日期，缺少恢复日期时保存为警告但预测结论必须为“无法判断”；未开始任务不得早于状态日期。
- **FR-010**：当前趋势重排必须保持原资源数量，继续执行剩余任务的工艺逻辑、资源容量、日历、合法并行限制和既定未来执行顺序，不得通过自动增配资源制造改善。
- **FR-011**：取消任务及其依赖影响必须形成可定位诊断；系统不得因为任务被取消就无提示地解除后续工艺条件。
- **FR-012**：重排结果必须同时包含历史实际任务和未来预测任务，并明确区分实际日期、基准日期和预测日期。
- **FR-013**：第三步必须至少对项目完工节点和全部强制里程碑生成结构化节点结果；其他里程碑可以作为次级信息展示。
- **FR-014**：每个节点结果必须包含节点标识、名称、级别、目标日期、日期来源、实际或预测日期、偏差天数、剩余缓冲、风险状态和原因证据。
- **FR-015**：关键节点风险状态必须包含“预计按期”“临近风险”“预计延期”“无法判断”，且同一输入必须得到确定一致的状态。
- **FR-016**：已经完成的节点必须优先使用实际进度计算；包含历史与未来任务的节点必须综合实际和预测计算；不得只基于剩余任务判断。
- **FR-017**：默认预警阈值沿用当前 3 天缓冲口径；预测未超过目标但剩余缓冲不超过 3 天时标记为“临近风险”。
- **FR-017A**：项目完工节点的目标日期必须使用当前活动计划快照的基准完成日期，不从状态日期或预测结果反推新目标。
- **FR-018**：节点原因证据必须优先关联造成偏差的关键任务、前后置等待、瓶颈资源或数据质量问题；缺少证据时必须明确说明而不是生成推测性原因。
- **FR-019**：第三步必须支持从节点预警定位相关任务，并在存在可调整风险时进入既有调整方案比选，不新增第四种调整策略。
- **FR-020**：进度输入、活动计划或预测输入发生变化后，页面不得继续把旧节点预警显示为当前结论；可以保留历史记录但必须清晰标注过期。
- **FR-021**：页面必须覆盖无活动计划、无快照、存在未保存修改、保存失败、重排中、重排无解、节点无法判断、结果过期和重试状态。
- **FR-022**：系统不得在保存进度后自动执行耗时重排；保存成功后应明确引导用户主动执行第二步。
- **FR-023**：本功能必须保持既有基准计划、进度快照、历史修订、调整方案和执行版本可继续读取，不重写历史文件。
- **FR-024**：新增节点预警信息必须采用向后兼容方式提供，现有三方案生成、方案求解、基准确认和调整方案接口行为保持不变。
- **FR-025**：LLM不得参与进度校验、锁定边界、重排结果、节点风险状态或推荐结论计算；LLM可用时仍只承担解释性文字。

### 关键实体（涉及数据时填写）

- **三步闭环状态**：描述每一步当前是否可执行、执行中、已完成、失败或因输入变化而过期，并指向使用的计划版本、进度快照和预测。
- **进度快照**：某状态日期下经校验并成功保存的任务实绩集合，是重排的唯一实际进度输入。
- **任务执行状态**：任务在重排中的历史实际、剩余工作或未来预测状态，以及相应的锁定边界。
- **滚动预测**：以活动计划和最新有效进度快照为输入形成的完整历史加未来计划。
- **关键节点预测**：项目完工节点或里程碑的目标、实际/预测日期、偏差、缓冲和风险状态。
- **节点风险证据**：支撑节点结论的任务、逻辑等待、资源瓶颈、求解状态或数据质量事实。

## 成功标准（必填）

### 可衡量结果

- **SC-001**：首次进入页面的计划工程师能在 10 秒内识别当前所处步骤和唯一下一步操作。
- **SC-002**：晚于状态日期、日期倒置和状态必填缺失等阻断错误在保存前识别率为 100%，并能定位到具体任务。
- **SC-003**：保存成功后第二步解锁率为 100%；保存失败或没有有效快照时错误解锁次数为 0。
- **SC-004**：可复现样例中，已完成任务实际日期被重排改写的次数为 0，未开始任务早于状态日期的次数为 0，暂停任务早于恢复日期的次数为 0。
- **SC-005**：每次获得可行预测后，项目完工节点和全部强制里程碑的结构化结果覆盖率为 100%。
- **SC-006**：节点已完成样例中，系统使用实际日期判断的准确率为 100%；包含历史与未来任务的节点使用合并日期判断的准确率为 100%。
- **SC-007**：预测延期、缓冲 0–3 天、缓冲大于 3 天和无法评估四类样例的风险状态准确率为 100%。
- **SC-008**：活动计划、进度修订或预测输入变化后，旧预测和旧预警被标记过期的覆盖率为 100%，作为当前结论继续展示的次数为 0。
- **SC-009**：用户可以从任一延期或临近风险节点在 2 次操作内定位相关任务或进入调整方案比选。
- **SC-010**：网络不可达、业务校验失败、求解无可行结果三类错误均显示业务可理解的不同提示，不再只显示无上下文的通用错误。

## 默认假设

- “散步闭环”按上下文理解为“三步闭环”。
- MVP 继续面向单机 Demo 和本地计划工程师，不新增权限模型。
- 当前趋势重排仍保持基准资源数量和既定未来顺序；自由重排只属于既有“关键任务优先”调整策略，不混入第二步的当前趋势预测。
- 关键节点主列表包括项目计划完工节点和强制里程碑；软性或内部里程碑作为次级信息展示。
- 关键节点“临近风险”默认沿用 3 天缓冲阈值，本期不增加按节点自定义阈值。
- 项目完工节点目标日期使用当前活动计划的基准完成日期；强制里程碑继续使用各自配置的目标日期。
- 用户保存有效进度后需要主动触发重排，避免每次编辑都启动耗时计算。
- 复用现有本地持久化、计划版本和历史修订，不迁移或重写已有版本文件。
