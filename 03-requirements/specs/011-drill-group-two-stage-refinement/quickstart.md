# 快速验证：桩基钻机墩组两阶段精排

> 当前实现校正（2026-07-09）：`resource_path_continuity` 已从当前目标项体系中移除；旧输入字段仅作为废弃兼容字段被忽略。当前目标项为 `control_node_late`、`makespan_and_soft_milestone`、`resource_idle`。第一阶段路径连续性、无窗口候选路径和资源路径罚分均为历史设计，不再建路径 circuit 或产生路径罚分；机械钻组聚合、组内升序和同组同资源保留为基础规则。

## 后端自动验证

实施后运行：

```powershell
.\.venv\Scripts\python.exe -m pytest backend\tests\test_scheduler.py -q
```

重点期望：

- 同一机械钻机墩组内的原任务最终使用同一台对应类型桩机。
- 机械钻机墩组聚合不依赖 `same_structure_parallel_limit = 1`。
- 人工挖孔桩不进入机械钻机墩组聚合。
- 人工挖孔桩不受组内单资源规则限制，可保持多资源并行。
- 固定资源主链路直接进入第一阶段精排，不再先跑池级最短工期排序。
- 第一阶段精排不可行或超时时，当前资源主结果保持失败语义，并尝试资源建议。
- 第一阶段不产生全量路径转移弧。
- 资源路径连续性开启且第一阶段可行时，结果诊断为 `stage1_final`，不再常规运行第二阶段 `refined` 排程。
- 第二阶段节点和弧数量通常为 0；`stage2_refined` / `stage2_fallback` 仅作为历史兼容或显式诊断路径。
- 关闭资源路径连续性目标时路径节点和路径弧为 0 或未评价。

## 规模验证场景

构造至少包含以下数据的后端测试场景：

- 30 个机械钻机墩组。
- 至少 3 台同类桩机。
- 每个墩组至少 2 个原桩基任务。
- 资源池不依赖 `same_structure_parallel_limit = 1`，至少覆盖未配置、配置为 0 或配置为大于 1 的一种场景。

期望结果：

- `coarse_group_count >= 30`。
- `coarse_child_task_count >= 60`。
- 第一阶段候选路径弧受窗口约束，不再全量连接所有候选路径节点。
- `drill_group_refinement.status = "stage1_final"`。
- 最终 `ScheduleResult.tasks` 数量等于原任务数量，不包含虚拟墩组。
- 同一机械桩基墩组内所有原任务最终继承同一台命名钻机。

## 固定资源主链路验证场景

构造一个当前资源足够、硬里程碑可满足的固定资源场景。

期望结果：

- 主求解入口直接调用命名资源精排，不先调用池级最短工期排序。
- `schedule_source`、`performance_path` 或等价诊断能表明当前资源精排成功。
- 精排失败或硬里程碑迟延时，当前资源主结果保持失败语义；如需测算增量资源，才进入资源建议分支。
- 池级最短工期不得作为当前资源失败后的兜底展示结果。

## 跳墩偏好验证场景

构造同一幅别、同一工艺、同一钻机资源组的墩组序列：

```text
1#墩、2#墩、3#墩
```

或稀疏序列：

```text
1#墩、3#墩、5#墩
```

期望结果：

- 相邻换资源惩罚能区分相邻墩组是否分配给同一桩机。
- `1-0-1` 洞洞惩罚能识别同一桩机承担前后墩组但跳过中间实际存在墩组的模式。
- 稀疏序列只按实际存在墩组判断相邻，不补造缺失墩号。

## 硬里程碑验证场景

构造一个硬里程碑命中某个机械钻机墩组内原任务的场景。

期望结果：

- 粗排成功时该墩组在硬里程碑日期前完成。
- 第一阶段最终排程展开出的原任务保留目标达成诊断；目标未达成时不得伪装成功。
- 若当前固定资源无法满足硬里程碑，结果进入失败语义并尝试资源建议，不伪造成功。

## 手工场景验证

1. 启动本地后端和前端。
2. 打开默认场景或导入本地 Excel 样例。
3. 确认旋挖钻、冲击钻、回旋钻资源池启用；无需依赖同结构同工艺并行上限为 1。
4. 运行固定资源精排。
5. 检查结果：
   - 任务列表仍是每根桩或每个原任务。
   - 同墩同工艺机械钻机任务使用同一台对应类型桩机。
   - 连续性诊断中能看到第一阶段路径窗口、候选弧和 `stage1_final` 状态。
   - 目标未达成时显示当前资源目标未满足，不伪装为成功。
