# 设计依据：路面实际进度统计

没有剩余的阻塞业务问题。超量行为已由用户选择；以下为影响本次设计的代码核对结论，不新增独立研究阶段。

| 决策 | 当前证据与理由 | 已评估替代方案 |
| --- | --- | --- |
| 复用施工段/结构层身份和任务投影 | `04-demo/frontend/src/domain/pavement.ts` 的 `pavementTaskGroups` 在 generated=null 时可组织行；结构层 ID 稳定 | 从求解结果生成表会使未求解项目不能填报，且可能丢未生成工序 |
| 施工长度作为每道工序设计量 | `app/project_master/definitions.py` 的 construction_length_m/width_m 属施工段，thickness_m 属结构层；`withPavementMaster` 将参数投影到构件属性 | 求解 quantity 随工效单位变化；桩号相减不等于用户维护的施工长度，均不采用 |
| 新增独立日记录，沿用主数据库 | `project_master/repository.py` 已有 WAL、连接及事务边界；schema 当前为2 | 桥梁 `plan_control_repository.py` 存按计划版本关联的累计快照；强行复用会引入错误身份与计划依赖。scheduler-config也不适合独立并发台账 |
| 原子差量写入＋双版本令牌 | 当前主数据每次确认版本可能变化，台账也会跨页面修改 | 整月覆盖会抹掉别人的录入；只比对主数据版本不能识别两个填报页面冲突 |
| 只保留一份每日事实 | 精度默认0.001 m，累计和剩余由每日事实导出；Decimal避免0.1+0.2误差 | 同时持久化累计量会产生双事实源；直接浮点相加容易显示残差 |
| 普通表格及面板保留草稿 | 当前规模约100行；Workspace菜单条件渲染会卸载子面板 | 不引入复杂表格库或全局状态框架；首次访问后保持面板挂载即可满足菜单返回保留草稿 |

缺失宽厚不阻止填报、不同月份累计不截断、停用记录不删除、负剩余不归零均已在 [spec.md](./spec.md) 定义。无需要另行请用户选择的技术方案。
