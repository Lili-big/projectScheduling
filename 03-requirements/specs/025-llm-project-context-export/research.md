# 研究结论：三方案生成前 LLM 项目信息下载

## 决策 1：后端返回真实上下文，不由前端重建

- **决策**：初始化流程只调用一次上下文构造函数，把所得对象同时传给 `generate_resource_plan_payload` 并写入初始化响应。
- **理由**：当前上下文包含工程画像派生结果、参考样例和固定规则，前端无法可靠复刻；同源对象可以直接证明下载内容与生成调用一致。
- **已评估的替代方案**：前端基于 `ScenarioInput` 和初始化响应拼装，存在字段遗漏和规则漂移；新增独立预览接口会多一次请求并可能与实际生成时点不一致。

## 决策 2：只导出 generation context

- **决策**：下载对象严格等于当前 `_llm_generation_context` 的六个分区，不包含外层 `task`、`output_schema`、system instruction、Provider 配置或 HTTP 请求体。
- **理由**：用户已确认关注的是输入模型前用于生成三方案的项目信息数据；排除传输和模型配置可减少敏感信息风险并保持文件聚焦。
- **已评估的替代方案**：完整请求快照包含非项目数据且扩大安全审查范围；完整 `ScenarioInput` 并不是当前实际提供给 LLM 的内容。

## 决策 3：响应字段使用向后兼容增量

- **决策**：在 `ResourceAssistantInitialResponse` 增加 `llm_generation_context`，不修改现有字段语义和端点路径。
- **理由**：初始化响应天然对应一次三方案生成会话；新增响应字段不会破坏现有调用方，并可复用现有加载与错误处理。
- **已评估的替代方案**：用 `plan_generation` 塞入上下文会混淆生成审计摘要与完整输入；新建下载端点需要保存或重算上下文。

## 决策 4：浏览器临时文件，不落服务端

- **决策**：前端收到上下文后生成 UTF-8 JSON Blob 和临时对象 URL；场景变化、再次生成或组件卸载时失效和回收。
- **理由**：满足单次核查需求，不引入文件存储、清理、权限和共享 URL 生命周期。
- **已评估的替代方案**：服务端临时文件和长期留档均超出当前范围。

## 决策 5：失败与回退按响应是否成功区分

- **决策**：本地 Provider 或外部调用失败回退只要初始化响应成功，就提供下载；初始化请求整体失败时先清除本轮下载状态且不沿用旧链接。
- **理由**：回退前上下文已经形成，仍是有价值的预备输入；整体失败则无法证明旧上下文属于当前请求。
- **已评估的替代方案**：仅外部调用成功时下载会丢失最需要排查的回退场景；保留旧链接容易误认。
