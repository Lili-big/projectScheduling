## 用户场景与测试

### 用户故事 1 - 未使用工艺不分配资源（优先级：P1）

计划工程师生成三版方案时，只希望看到项目真实使用的施工工艺获得资源；人工挖孔、冲击钻、回旋钻等任何工艺没有实际任务工作量时，对应资源均为 0。

**独立测试**：构造仅含旋挖钻任务、其他桩基工艺工作量为零的项目，生成三版方案，验证未使用工艺全部为 0，旋挖钻按三方案策略获得非零数量。

**验收场景**：

1. **假设** 项目只有旋挖钻任务，**当** 生成三版资源方案，**则** 人工挖孔、冲击钻、回旋钻在经济、平衡、抢工方案中均为 0。
2. **假设** 某资源池已配置非零当前数量但没有任何匹配任务，**当** 生成方案，**则** 不得因当前数量或参考样例为其分配资源。
3. **假设** 某工艺存在真实匹配任务，**当** 生成方案，**则** 该资源按项目工作量和方案定位分配，不被误判为未使用。

---

### 用户故事 2 - 三版方案有稳定、可解释的项目基线（优先级：P1）

计划工程师希望经济、平衡、抢工方案先基于项目任务、控制墩、连续梁和当前资源形成稳定基线，再由 LLM 输出组织策略与有限调整，避免只复制固定样例。

**独立测试**：使用当前默认项目生成确定性基线，验证三版同类有效资源满足经济不高于平衡、平衡不高于抢工，并验证控制墩、连续梁主墩和实际任务工作量参与计算。

**验收场景**：

1. **假设** 项目存在墩柱、承台、盖梁及控制墩任务，**当** 生成三版基线，**则** 三版数量体现经济、平衡、抢工的递增投入定位。
2. **假设** 项目含连续梁组，**当** 计算连续梁班组基线，**则** 使用真实主墩关系和连续梁组数量，且不得超过可施工组数。
3. **假设** 项目工作量或控制墩数量变化，**当** 再次生成，**则** 基线随当前项目变化，不沿用固定项目数值。

---

### 用户故事 3 - LLM 输出可控且失败可回退（优先级：P2）

计划工程师希望外部 LLM 的三版方案始终符合资源类型、上限、单调性和零工作量等硬规则；输出不合法时系统自动纠错，仍不合法则使用确定性基线完成生成。

**独立测试**：分别模拟合法输出、首次非法后重试成功、持续非法、本地 Provider 和外部调用失败，验证最终总能获得符合规则的三版方案，并保留正确生成来源。

**验收场景**：

1. **假设** LLM 为零工作量资源输出正数，**当** 系统校验，**则** 该输出不被直接采用，并触发一次带错误信息的纠错重试。
2. **假设** 重试后仍违反规则或外部调用失败，**当** 系统回退，**则** 返回确定性三版基线而不是失败或放宽资源上限。
3. **假设** LLM 输出求解前的 `recommended_profile` 或未知资源类型，**当** 系统解析，**则** 不采用该推荐或未知类型，且不得影响最终三版有效资源方案。

### 边界与异常场景

- “实际工作量”以当前场景生成任务中对资源类型的真实匹配需求为准，而不是资源池当前数量、固定参考样例或结构物名称猜测。
- 资源存在任务但被禁用时，三版均为 0；无法映射或数据异常时不得伪造正数，并保留可诊断原因。
- `max_quantity` 为有效上限；LLM 数量不得反向扩大上限。
- 无上限资源仍受工作量状态、三方案定位和非负整数约束。
- 连续梁主墩字段使用当前项目真实字段；无连续梁任务时连续梁班组为 0。
- 三方案生成阶段不输出最终推荐；推荐只能在存在可比较 CP-SAT 结果后产生。

## 需求

### 功能需求

- **FR-001**：系统必须在调用 LLM 前，根据当前生成任务计算每种资源类型的实际工作量状态。
- **FR-002**：任何资源类型实际工作量为零时，经济、平衡、抢工三版数量必须均为 0，不得被当前资源数量、参考样例或 LLM 输出扩充。
- **FR-003**：系统必须区分至少 `ACTIVE`、`UNUSED_OR_UNMAPPED`、`DISABLED`、`UNLIMITED`、`DATA_INVALID` 五类资源状态，并让数量计算与诊断使用同一状态结果。
- **FR-004**：对 `ACTIVE` 资源，系统必须结合当前项目工作量、控制墩、连续梁主墩关系、当前资源数量和原始上限形成经济、平衡、抢工三版确定性基线。
- **FR-005**：同类有效资源的基线必须满足经济方案数量不高于平衡方案、平衡方案不高于抢工方案；所有数量为非负整数。
- **FR-006**：桩基资源必须按人工挖孔、旋挖钻、冲击钻、回旋钻等实际工艺分别计算，不得合并为“桩机总数”。
- **FR-007**：连续梁班组必须按真实连续梁组及其 `main_support_indices` / `main_support_refs` 计算；无连续梁工作量时三版为 0。
- **FR-008**：LLM 必须一次生成 `economy`、`balanced`、`crash` 三版方案，且仅能使用允许的资源类型和当前项目基线进行有限调整与策略说明。
- **FR-009**：LLM 输出必须保持现有方案字段契约：`profile`、`positioning`、`resource_quantities`、字符串型 `organization_strategy`、`generation_rationale`、`applicable_scenarios`、`expected_risks`。
- **FR-010**：后端必须校验方案数量、方案标识、资源类型、非负整数、零工作量归零、禁用资源归零、原始上限、三方案单调性和连续梁班组边界。
- **FR-011**：校验失败时系统必须最多执行一次带结构化错误原因的 LLM 纠错重试；重试仍失败或调用异常时使用本次确定性基线回退。
- **FR-012**：系统不得通过修改 `max_quantity` 来接纳 LLM 超限数量，不得静默丢弃未知资源后继续将整体输出标记为有效。
- **FR-013**：三方案生成阶段不得接受或展示 LLM 的最终方案推荐，最终推荐仍由 CP-SAT 求解结果、指标对比和确定性推荐规则产生。
- **FR-014**：现有外部 LLM 成功、本地 Provider、未配置和外部失败回退路径必须保持可用，且使用同一确定性规则保证最终方案合法。
- **FR-015**：本功能不得改变 `ResourceAssistantInitialResponse.llm_generation_context` 下载口径或新增前端共享字段。

### 关键实体

- **资源工作量状态**：资源类型在当前生成任务中的实际使用判定、匹配任务数、累计需求工期、启用状态、上限状态和诊断原因。
- **三方案确定性基线**：基于当前项目事实计算的经济、平衡、抢工资源数量及计算依据，是 LLM 输入约束和失败回退结果。
- **LLM 三方案草案**：外部模型返回的三个方案对象，必须通过后端校验后才能转为页面方案。
- **方案校验结果**：包含是否合法、错误代码、资源类型、方案标识和期望边界，用于一次纠错重试及诊断。

## 成功标准

### 可衡量结果

- **SC-001**：在所有零工作量测试场景中，对应资源三版输出为 0 的准确率为 100%。
- **SC-002**：在当前默认项目中，人工挖孔、冲击钻、回旋钻三版均为 0；旋挖钻等实际使用资源保持非零并符合项目基线。
- **SC-003**：所有有效输出中，未知资源、负数、非整数、原始上限越界和三方案单调性违规的通过次数均为 0。
- **SC-004**：外部 LLM 合法输出、一次纠错成功、持续非法回退、本地 Provider 和外部调用失败五类场景均能返回三版合法方案。
- **SC-005**：同一项目输入重复构建确定性基线时，资源数量与计算依据一致率为 100%。
- **SC-006**：三方案生成前输出最终推荐的次数为 0，现有 CP-SAT 后推荐流程行为不变。

## 默认假设

- “工作量为零”以任务生成后的资源需求映射为唯一业务判断口径。
- 本次只优化后端三方案生成策略与提示约束；现有方案卡已能展示数量、策略、依据、场景和风险，无需新增页面字段。
- 方案倍率与专项公式属于可测试的 Demo 基线策略，不等同于 CP-SAT 最优解，也不替代后续求解验证。
- 第一次实现优先复用现有服务和测试文件，不新增依赖、数据库表或持久化记录。
