## 用户场景与测试（必填）

### 用户故事 1 - 给定资源统一求解工期（优先级：P1）

计划工程师在模拟求解页使用当前资源，或在 AI 多方案比选中使用 LLM 推荐/人工调整后的资源时，系统都严格按本次输入数量执行同一种单阶段工期求解，使两个入口的排程目标、状态和诊断含义一致。

**优先级理由**：这是减少重复算法、缩短固定资源求解链和消除入口间结果口径差异的核心价值。

**独立测试**：构造同一任务、里程碑和资源数量，通过模拟求解与 AI 单方案入口分别求解，核对命名资源快照、排程调用次数、目标优先级、状态判定及是否扩资源。

**验收场景**：

1. **假设** 两个入口提交完全相同的任务、范围、里程碑和资源数量，**当** 分别求解，**则** 两者都只执行一次固定资源排程，使用的命名资源数量与输入 100% 一致，且遵循同一目标和状态规则。
2. **假设** 当前固定资源能形成排程但目标延期，**当** 任一入口求解完成，**则** 系统保留排程与延期信息，不生成最大资源场景、不搜索新增资源、不输出增配方案。
3. **假设** 资源数量为 0、资源类型缺失或作用域不合法，**当** 求解，**则** 系统在进入排程前返回现有结构化资源阻断诊断，不按默认充足降级。
4. **假设** 用户选择单工点范围，**当** 从模拟入口求解，**则** 统一算法只读取该工点已生成的任务、里程碑和合法资源，结果范围隔离规则保持不变。

### 用户故事 2 - 全局搜索最少资源后生成详细排程（优先级：P1）

计划工程师给定固定工期或强制里程碑后，系统先在所有有效资源池的上限范围内联合寻找资源总数最少的组合，再严格按该组合执行一次与用户故事 1 相同的固定资源工期求解，使资源建议与详细排程来源清楚可核查。

**优先级理由**：固定工期入口必须形成“数量搜索—详细排程”的最小闭环，同时删除多轮回退造成的耗时、状态混淆和隐式增配。

**独立测试**：使用两个可并行任务、当前数量 3、最大数量 5、目标工期 5 天的样例，验证全局搜索可以推荐 2；随后只以 2 个命名资源求一次工期，并分别覆盖目标满足、目标未确认和全局无解场景。

**验收场景**：

1. **假设** 多个资源池存在多种满足目标的组合，**当** 执行固定工期最少资源求解，**则** 系统先最小化所有资源池数量之和，数量相同时再选择总工期更短的组合。
2. **假设** 当前 `quantity=3`、搜索上限 `max_quantity=5`，而满足目标只需 2，**当** 全局搜索完成，**则** 推荐数量允许为 2，不把当前数量作为搜索下限。
3. **假设** 全局搜索得到候选数量且详细固定资源排程满足目标，**当** 返回结果，**则** 该组合标记为已验证的全局最少资源方案，并展示实际命名资源和详细排程。
4. **假设** 全局搜索得到候选数量但详细排程未满足或未确认目标，**当** 返回结果，**则** 系统保留候选数量和真实排程状态，但不得标记为已验证成功，也不得增加资源重试。
5. **假设** 全局搜索在资源上限内证明无解或限时内未确认，**当** 返回结果，**则** 系统分别报告上限内无解或未确认，不执行逐池二分、压力循环或其他资源搜索回退。

### 用户故事 3 - 页面准确展示统一目标和结果来源（优先级：P2）

计划工程师在模拟求解和 AI 比选页面能够清楚看到固定资源只优化最大目标延期与总工期，资源空闲和连续性仅为诊断；固定工期结果能够区分全局数量搜索与后续详细排程是否验证成功。

**优先级理由**：算法简化后若页面仍展示旧的三个可选目标或自动增配含义，用户会误解求解事实并错误使用结果。

**独立测试**：分别查看固定资源成功、延期、未确认、不可行，以及最少资源已验证/未验证结果，确认页面目标说明、资源数量、结果来源、禁用状态和诊断入口与响应事实一致。

**验收场景**：

1. **假设** 用户进入模拟求解页，**当** 查看固定资源和固定工期入口，**则** 页面明确展示“最大目标延期优先、总工期其次”，不得将资源空闲或连续性显示为本次优化目标。
2. **假设** 固定工期全局搜索成功但详细排程未确认，**当** 用户查看结果，**则** 页面同时显示候选资源数量和“尚未通过详细排程确认”，不显示为正式成功方案。
3. **假设** 用户打开历史结果，**当** 历史结果包含旧目标贡献、方案 2 或多阶段来源，**则** 页面继续按历史事实可读，不迁移、不重写；只有新结果使用统一算法口径。

### 边界与异常场景

- 固定资源输入没有可评估目标时，物理可行结果保持 `unconfirmed`，原因是目标缺失，不得自动假定目标已满足。
- 固定工期入口既没有匹配的强制里程碑，也没有同一求解范围的固定资源工期基准时，必须阻止搜索并说明缺少目标工期。
- `OPTIMAL` 且目标延期时返回 `not_met`；`FEASIBLE` 且目标延期时返回 `unconfirmed`，不得断言当前资源必然不足。
- 全局最少资源候选的某个资源池数量可以为 0；只有实际任务没有任何合法资源候选时才阻断，不能为了避免 0 自动补资源。
- 同类型多个独立资源池必须保持稳定池身份，不能为减少变量而按资源类型合并数量。
- 项目共享和工点独享资源继续遵守现有候选范围与互斥规则；共享资源跨工点转场时间和成本保持 0。
- 求解范围、资源数量、任务、工艺逻辑、里程碑或项目版本变化后，旧生成结果、工期基准、最少资源结果、比较和推荐必须按现有指纹规则失效。
- 求解超时、OR-Tools 缺失、输入格式错误和模型构建错误必须保留各自真实原因，不得通过重试或旧结果伪装成功。
- Netlify 演示镜像如继续承担相同页面流程，必须与 FastAPI 的调用次数、状态和禁止重试边界一致。

## 需求（必填）

### 功能需求

- **FR-001**：系统必须提供一个由模拟固定资源求工期和 AI 资源方案求工期共同使用的权威固定资源单阶段求解行为。
- **FR-002**：统一固定资源求解必须严格使用本次输入的有效资源数量展开命名资源，实际使用数量不得超过或自动补足输入 `quantity`。
- **FR-003**：统一固定资源求解每次请求必须只执行一次排程调用，不得先求基础排程再求完整排程。
- **FR-004**：统一固定资源求解的第一目标必须是最小化所有可评估目标中的最大延期，第二目标必须是在第一目标不劣的前提下最小化总工期。
- **FR-005**：资源空闲、资源连续性、跳墩、换幅、方向反转、路径组切换和负载均衡必须只作为求解后诊断，不得影响统一固定资源模型的目标、阶段选择或结果取舍。
- **FR-006**：统一固定资源求解必须保留现有任务工期、工艺逻辑、资源分配与互斥、执行约束、连续梁、同结构、工作面、资源作用域和里程碑匹配硬规则。
- **FR-007**：统一固定资源求解不得生成最大资源输入、调用最少资源搜索、执行资源压力搜索、自动增配或输出新增资源方案。
- **FR-008**：统一固定资源结果必须同时保留原始求解器状态和 `met`、`not_met`、`unconfirmed`、`infeasible` 四种业务状态及其目标偏差。
- **FR-009**：`OPTIMAL` 或 `FEASIBLE` 且目标满足时业务状态必须为 `met`；`OPTIMAL` 且目标延期时必须为 `not_met`；`FEASIBLE` 且目标延期时必须为 `unconfirmed`；资源覆盖错误或已证明物理无解时必须为 `infeasible`。
- **FR-010**：固定资源结果存在可用排程时必须保留任务日期、命名资源分配、里程碑偏差和诊断，不得因业务目标未满足而丢弃排程。
- **FR-011**：固定工期最少资源入口必须先在每个有效池 `0..max_quantity` 范围执行一次全局联合数量搜索，且不得将当前 `quantity` 作为默认下限。
- **FR-012**：全局数量搜索必须以资源总数最少为第一目标，以资源总数相同下总工期更短为第二目标，不得引入资源成本或资源空闲作为该搜索目标。
- **FR-013**：全局数量搜索必须保持稳定资源池身份、资源类型兼容、资源作用域、容量、工艺逻辑、施工硬规则及强制里程碑/固定工期约束。
- **FR-014**：全局数量搜索得到候选后，系统必须按候选数量展开命名资源，并只调用一次 FR-001 定义的统一固定资源求解生成详细排程。
- **FR-015**：详细排程只有在业务状态为 `met` 时，候选数量才能标记为“已验证的全局最少资源方案”。
- **FR-016**：详细排程为 `not_met`、`unconfirmed` 或 `infeasible` 时，系统必须保留全局候选和真实状态，不得增加资源、改变下限、重新搜索或发起第二次详细排程。
- **FR-017**：全局数量搜索返回 `UNKNOWN` 时必须直接返回未确认；返回 `INFEASIBLE` 时必须直接返回当前上限内无解，不得执行逐资源池二分、最大资源独立求解或压力搜索回退。
- **FR-018**：固定工期目标必须来自匹配的强制里程碑；没有匹配强制里程碑时，才允许使用同一范围下当前有效的固定资源求工期结果作为总工期目标。
- **FR-019**：全部工点和单工点求解必须共用相同算法规则，同时保持各自任务、里程碑、资源、指纹、保存和比较隔离。
- **FR-020**：模拟求解页面必须准确展示统一目标顺序，不得继续把资源空闲或连续性作为固定资源/固定工期当前求解的可选优化目标。
- **FR-021**：固定工期结果必须分别展示全局候选数量、详细排程业务状态和是否通过验证，不得用容量候选状态替代详细排程结论。
- **FR-022**：AI 方案比较和推荐必须继续只允许 `met` 方案进入正式推荐候选；模拟单工点结果继续不得保存为全项目方案或参与全项目比较。
- **FR-023**：现有接口路径和共享响应结构应保持兼容；被取消的新结果阶段必须明确标记为未执行或不适用，旧结果继续可读且不重写。
- **FR-024**：前后端共享类型、FastAPI、前端请求、Netlify 演示镜像、结果展示和契约测试必须使用一致的求解来源、调用次数和状态语义。
- **FR-025**：资源成本优化、LLM 资源生成、人工资源调整、项目主数据和架梁专项不得因本功能改变现有业务行为。

### 关键实体（涉及数据时填写）

- **统一固定资源求解输入**：求解范围内的任务、逻辑、里程碑、策略和按输入 `quantity` 固化的命名资源快照；请求内资源数量不可被求解器改写。
- **统一固定资源结果**：包含原始求解器状态、四态业务结论、最大目标延期、总工期、任务排程、资源分配、里程碑偏差、诊断和一次求解事实。
- **全局最少资源候选**：按稳定有效池标识记录的推荐数量集合；每个数量在 `0..max_quantity` 内，并记录全局搜索状态。
- **候选验证结果**：以全局最少资源候选作为固定资源得到的统一固定资源结果，以及候选是否达到 `met` 的验证结论。
- **历史求解来源**：旧结果中已有的基础排程、方案 2、多阶段或最佳努力来源，只用于兼容读取，不参与新请求。

## 成功标准（必填）

### 可衡量结果

- **SC-001**：同一输入通过模拟固定资源入口和 AI 方案入口求解时，每个请求的排程调用次数均为 1，自动扩资源、最少资源搜索和方案 2 输出次数均为 0。
- **SC-002**：两个入口使用的资源数量与各自提交 `quantity` 的一致率为 100%，资源数量为 0 或无合法候选时静默补足次数为 0。
- **SC-003**：统一固定资源所有可行结果的目标顺序均为最大目标延期优先、总工期其次；资源空闲和连续性影响最终排程选择的次数为 0。
- **SC-004**：固定资源四态矩阵样例全部通过，尤其 `OPTIMAL+延期` 100% 为 `not_met`、`FEASIBLE+延期` 100% 为 `unconfirmed`，两者均保留可用排程。
- **SC-005**：固定工期入口每个请求最多执行 1 次全局数量搜索和 1 次统一固定资源排程；二分、压力、增配和第二次详细排程调用次数均为 0。
- **SC-006**：全局搜索正常样例中推荐数量等于满足目标的全局最小资源总数；数量相同的候选中所选总工期不大于其他候选。
- **SC-007**：当前数量大于必要数量的样例中，推荐数量低于当前 `quantity` 的合法结果能够返回，默认下限被提升到当前数量的次数为 0。
- **SC-008**：详细排程非 `met` 的所有样例中，候选被标记为已验证成功或触发增加资源重试的次数均为 0。
- **SC-009**：全部工点、单工点、共享池、工点独享池、数量 0、目标缺失、全局无解、超时和历史结果兼容样例均有可复现结果，跨范围结果错误复用次数为 0。
- **SC-010**：现有 API 路径、历史结果读取、AI 推荐门禁、资源成本优化和架梁专项相关兼容测试全部通过；前端类型检查和生产构建通过。

## 默认假设

- “同一个算法”指共享一个不包含 AI 推荐、页面范围或结果包装的固定资源求解内核；模拟和 AI 入口保留各自范围、快照、推荐和展示职责。
- 最大目标延期取所有可评估强制目标和固定工期偏差中的最大值；没有目标时结果为 `unconfirmed`。
- 资源空闲和连续性仍有人工审核价值，继续从最终排程派生，但不再消耗额外求解阶段或参与平局裁决。
- 统一算法只作用于新请求；历史结果中的旧来源和目标贡献按原始事实展示。
- 多阶段取消后不删除共享兼容字段，使用“未执行/不适用”表达新结果，避免无必要的数据迁移。
