# 快速验证：AI 第二阶段仅优化资源空闲

## 1. 验证目标

验证 AI 固定资源排程第二阶段：

- 只构建和优化累计资源空闲；
- 不构建资源路径连续性目标；
- 不恶化第一阶段最大延期和总工期；
- 只有空闲严格下降才采用第二阶段；
- 连续性诊断变化不影响采用；
- 失败或无改善时完整回退第一阶段；
- 三套方案资源数量不变且不自动增配。

## 2. 后端针对性测试

在仓库根目录执行：

```powershell
python -m pytest backend/tests/test_scheduler.py -q
python -m pytest backend/tests/test_ai_resource_scheduling_assistant.py -q
python -m pytest backend/tests/test_plan_control_api.py -q
```

重点断言：

- 第一阶段 `resource_idle` 建模关闭；
- 第二阶段 `resource_idle` 建模开启；
- 第二阶段连续性路径建模关闭，路径节点和转移弧数量为 0 或状态为未建模；
- 第二阶段目标只等于累计资源空闲；
- 空闲下降但连续性变差的结果可采用；
- 空闲相同但连续性改善的结果回退；
- 第一阶段空闲为 0 时第二阶段不启动；
- `resource_expansion_attempted=false`。

## 3. 前端验证

在 `frontend/` 目录执行：

```powershell
npm.cmd run typecheck
npm.cmd run build
```

页面检查：

1. AI 多方案比选顶部说明只描述第二阶段减少资源空闲；
2. 阶段详情不再声明连续性是优化目标；
3. 连续性指标仍可查看，并明确为诊断；
4. 历史结果缺少新说明时页面不报错。

## 4. 可复现小样例

构造第一阶段结果：

```text
最大延期：0 天
总工期：20 天
累计资源空闲：5 天
连续性诊断：2
```

验证两组第二阶段结果：

| 样例 | 最大延期 | 总工期 | 空闲 | 连续性诊断 | 期望 |
|---|---:|---:|---:|---:|---|
| A | 0 | 20 | 4 | 10 | 采用第二阶段 |
| B | 0 | 20 | 5 | 0 | 回退第一阶段 |
| C | 0 | 21 | 4 | 0 | 因工期越界回退 |

## 5. 真实 Excel 三方案验证

1. 导入当前真实桥梁 Excel 案例；
2. 生成经济、平衡、抢工三套 LLM 资源方案；
3. 逐个点击求解；
4. 记录每案：固定资源数量、第一阶段状态/工期/最大延期/空闲、第二阶段状态/空闲、最终选用阶段、总耗时和连续性诊断；
5. 检查第二阶段被采用时空闲严格下降，最大延期和总工期不恶化；
6. 检查连续性诊断只随最终排程变化，不出现在第二阶段目标或采用原因中；
7. 检查三案自动增配次数均为 0。

## 6. 预期结果

- 第二阶段模型规模低于包含路径连续性时的模型规模；
- 被采用的第二阶段结果空闲严格下降；
- 连续性变化不影响阶段选择；
- 工期三态、推荐、基准计划和进度反馈链路保持可用；
- 所有测试和生产构建通过。
