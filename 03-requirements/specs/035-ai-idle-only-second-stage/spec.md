# 功能规格：AI 第二阶段仅优化资源空闲

**功能目录/分支**：`035-ai-idle-only-second-stage`

**状态**：草稿

## 来源与评审上下文（必填）

- **来源文档**：`AGENTS.md`、`agent.md`、`README.md`、`docs/AI资源配置与排程优化助手验证说明.md`、`specs/033-ai-two-stage-resource-optimization/`、`specs/034-ai-resource-solve-60s-budget/`
- **评审结论**：用户已明确要求收窄 AI 固定资源排程第二阶段目标；本次属于目标函数调整，按项目门禁进入完整 Spec Kit。
- **使用的 Demo/代码事实**：当前 AI 单方案排程严格使用 LLM 推荐或用户调整后的固定资源，两阶段共享 60 秒预算；第一阶段优化最大延期和总工期，第二阶段在第一阶段工期上限内按累计资源空闲、资源路径连续性两级目标优化，并在无改进、越界或失败时回退第一阶段。
- **不在范围内**：不修改第一阶段工期目标，不调整 60 秒共享预算，不改变任务工期、工艺逻辑、里程碑、固定资源数量或自动增配规则；不删除求解后的资源路径连续性诊断，不修改 LLM 三方案生成规则，不影响通用模拟求解、最少资源求解和资源成本求解。

## 用户场景与测试（必填）

### 用户故事 1 - 第二阶段只压缩资源内部空闲（优先级：P1）

计划工程师对经济、平衡或抢工方案执行固定资源排程时，希望第二阶段只减少已使用资源执行期间的内部空档，不再为跳墩、换幅或路径组切换增加求解复杂度，从而让有限的剩余预算集中用于更明确的资源紧凑性目标。

**优先级理由**：这是本次变更的核心价值，直接决定第二阶段的目标、结果采用规则和求解规模。

**独立测试**：给定第一阶段排程及其最大延期、总工期和累计资源空闲，执行第二阶段，验证第二阶段只按累计资源空闲判断改善，且被采用结果的最大延期和总工期均不恶化。

**验收场景**：

1. **假设** 第一阶段最大延期为 0 天、总工期为 579 天、累计资源空闲为 120 天，**当** 第二阶段获得最大延期 0 天、总工期不超过 579 天、累计资源空闲 100 天的排程，**则** 系统采用第二阶段排程，不因其资源路径连续性诊断变差而拒绝。
2. **假设** 第二阶段累计资源空闲与第一阶段相同，**当** 连续性诊断更好，**则** 系统仍判定第二阶段没有资源空闲改善并返回第一阶段排程。
3. **假设** 第二阶段累计资源空闲更少但最大延期或总工期超过第一阶段，**当** 系统校验结果，**则** 拒绝第二阶段并返回第一阶段排程。

---

### 用户故事 2 - 保留连续性诊断但不影响排程选择（优先级：P2）

计划工程师仍需要在方案详情中查看跳墩、换幅、跨幅跳墩、方向反转和路径组切换等资源路径信息，用于人工审核施工组织，但这些指标不再参与第二阶段求解或最终阶段选择。

**优先级理由**：保留诊断可以避免目标函数收窄后丢失现场审核信息，并保持历史结果和页面解释可读。

**独立测试**：构造第二阶段资源空闲改善但连续性诊断变差的结果，验证结果仍可采用，同时页面继续显示连续性诊断并明确其为求解后指标。

**验收场景**：

1. **假设** 第二阶段累计资源空闲严格下降且工期边界不恶化，**当** 跳墩或换幅次数上升，**则** 系统采用第二阶段排程并保留对应诊断，不把连续性变化作为失败原因。
2. **假设** 用户查看阶段详情，**当** 第二阶段已执行，**则** 页面说明第二阶段只优化资源空闲，连续性数据仅供诊断。

---

### 用户故事 3 - 保持现有回退和兼容链路（优先级：P3）

计划工程师希望目标收窄后，原有两阶段预算、固定资源、状态三态、推荐、基准计划和历史结果读取继续稳定工作。

**优先级理由**：该变更不能破坏已完成的三方案求解和计划执行链路。

**独立测试**：覆盖第二阶段未启动、超时、无排程、工期越界、任务或资源异常、空闲未改善等情况，验证均返回第一阶段结果，历史包含连续性字段的结果仍可读取。

**验收场景**：

1. **假设** 第一阶段已获得可行排程，**当** 第二阶段失败或累计资源空闲没有严格下降，**则** 系统完整返回第一阶段排程和明确回退原因。
2. **假设** 历史结果包含第二阶段连续性罚分，**当** 页面加载该结果，**则** 继续按诊断字段展示，不要求数据迁移。
3. **假设** 第一阶段累计资源空闲为 0，**当** 系统判断第二阶段没有可改善空间，**则** 可以跳过第二阶段并保留第一阶段排程。

### 边界与异常场景

- 第一阶段没有获得 `OPTIMAL` 或 `FEASIBLE` 排程时，不启动第二阶段。
- 第一阶段耗尽 60 秒共享预算或剩余预算不足时，跳过第二阶段。
- 第一阶段累计资源空闲为 0 时，第二阶段没有严格改善空间，可直接跳过。
- 第二阶段返回 `UNKNOWN`、`INFEASIBLE`、模型异常、任务集合变化、使用方案外资源或工期边界恶化时，必须回退第一阶段。
- 第二阶段空闲减少但连续性诊断变差时，只记录诊断，不得据此拒绝结果。
- 第二阶段空闲与第一阶段相同但连续性更好时，不构成可采用的严格改善。
- 完全未使用资源、首个任务前和最后任务后的等待继续不计入累计资源空闲。
- 历史响应缺少新阶段说明或仍包含连续性优化字段时，前端必须兼容解析。

## 需求（必填）

### 功能需求

- **FR-001**：AI 固定资源排程第二阶段必须仅以累计资源空闲最少作为优化目标，不得再以资源路径连续性作为次级目标或并列目标。
- **FR-002**：第二阶段不得为了优化跳墩、换幅、跨幅跳墩、方向反转、路径组切换或同结构拆分而建立额外的求解目标。
- **FR-003**：第二阶段必须继续将第一阶段最大延期和总工期作为不可恶化上限，被采用结果必须同时满足两个上限。
- **FR-004**：第二阶段必须继续使用第一阶段排程作为可行起点，并严格保持当前方案的资源类型、资源数量、任务集合、工艺逻辑和资源兼容范围。
- **FR-005**：第二阶段结果只有在累计资源空闲严格小于第一阶段时才可被采用；空闲相同即视为无改进，不得因连续性诊断更好而采用。
- **FR-006**：第二阶段累计资源空闲严格下降且工期边界不恶化时，即使连续性诊断变差也不得据此拒绝结果。
- **FR-007**：系统必须继续在求解完成后计算并返回资源路径连续性诊断，但必须明确其不参与第二阶段求解、结果采用或推荐门禁。
- **FR-008**：现有连续性诊断字段必须保持向后兼容；历史结果无需迁移或重写，新增结果可继续返回诊断值但不得将其标记为第二阶段优化目标。
- **FR-009**：第二阶段无排程、超时、模型异常、空闲未改善、工期越界、任务变化或资源越界时，必须返回第一阶段排程并记录准确原因。
- **FR-010**：第一阶段累计资源空闲为 0 时，系统可以直接跳过第二阶段，并以“资源空闲已无改善空间”说明原因。
- **FR-011**：单方案两阶段必须继续共享 60 秒总预算，第二阶段仅使用第一阶段结束后的剩余预算。
- **FR-012**：两阶段均不得触发自动资源扩充、资源替换或候选资源搜索，最终资源数量必须与 LLM 推荐或用户调整后的方案完全一致。
- **FR-013**：方案卡、方案详情和阶段说明必须将第二阶段描述统一为“资源空闲优化”，不得再描述为“资源空闲与连续性优化”。
- **FR-014**：工期三态、三方案推荐、设为基准计划和进度反馈读取规则不得因本次目标收窄发生变化。
- **FR-015**：通用模拟求解、最少资源求解、资源成本求解和其他非 AI 固定资源入口不得因本次变更改变目标函数或结果口径。

### 关键实体（涉及数据时填写）

- **第一阶段排程摘要**：包含最大延期、总工期、累计资源空闲、状态和耗时，是第二阶段工期上限、空闲改善基线及回退结果。
- **第二阶段排程摘要**：包含累计资源空闲、求解状态、耗时和诊断信息；连续性字段仅代表求解后诊断，不代表优化目标。
- **阶段选择记录**：说明最终采用第一阶段还是第二阶段，以及预算不足、无排程、工期越界、资源空闲未改善等原因。
- **资源路径连续性诊断**：求解后根据最终任务路径计算的跳墩、换幅、跨幅跳墩、方向反转和路径组切换信息，仅用于人工复核。

## 成功标准（必填）

### 可衡量结果

- **SC-001**：所有被采用的第二阶段排程，其累计资源空闲均严格小于第一阶段，且最大延期和总工期不超过第一阶段，验证通过率为 100%。
- **SC-002**：连续性诊断改善但累计资源空闲未下降的第二阶段结果，回退第一阶段的准确率为 100%。
- **SC-003**：累计资源空闲下降且工期边界满足的第二阶段结果，不因连续性诊断变差而被拒绝，验证通过率为 100%。
- **SC-004**：第二阶段的用户可见说明中不再出现“优化连续性”口径，连续性信息均明确为求解后诊断。
- **SC-005**：第二阶段失败、超时、越界或空闲无改善时，第一阶段可行排程保留率为 100%。
- **SC-006**：经济、平衡、抢工三套方案求解均保持固定资源数量，自动增配发生次数为 0。
- **SC-007**：现有 AI 方案状态、推荐、基准计划、进度反馈和历史结果兼容验证全部通过。

## 默认假设

- 用户所说“不求解资源连续性”指从第二阶段目标函数、候选改善约束和阶段采用判断中移除连续性，不是删除求解后的路径诊断。
- 第二阶段继续保留，因为累计资源空闲仍需要在第一阶段工期边界内单独优化。
- 累计资源空闲继续沿用现有口径：只统计已使用命名资源从首项任务开始到末项任务结束之间的内部空档。
- 连续性相关响应字段暂不删除，以保持历史数据和前端兼容；其含义调整为诊断值。
- 第二阶段只有累计资源空闲严格下降才算成功改善，不使用连续性作为空闲相同时的平局裁决项。
- 不新增依赖，不修改 LLM 提示词，不扩大为施工路径硬约束调整。
