# 快速验证：实际进度工程量一致性

## 1. 前置条件

1. 本地 FastAPI 服务和前端依赖可用。
2. 项目已经从 AI 多方案比选确认一个带求解结果的活动执行计划。
3. 活动计划中至少存在一个总工程量为 `10m` 的任务；若样例没有，可在测试夹具中构造。
4. 备份或使用临时 `PlanControlRepository`，避免页面验证污染需要保留的本地进度记录。

## 2. 后端验证

运行进度、API 和持久化相关测试：

```powershell
python -m pytest backend/tests/test_progress_forecast.py backend/tests/test_plan_control_api.py backend/tests/test_plan_control_repository.py -q
```

重点断言：

- `10m + 40%` 得到已完 `4m`、剩余 `6m`。
- `10m + 已完4m` 得到 `40%`、剩余 `6m`。
- 剩余 `6m`、实际工效 `2m/天` 得到 3 天剩余工期。
- 未开始返回 `0% / 0 / 10m`，已完成返回 `100% / 10m / 0`。
- 暂停保留实绩并使用人工剩余天数；取消保留物理剩余量但剩余工期为 0。
- 超总量、负值、比例冲突、数量和不等于总量、无效总量均被阻断。
- 新快照使旧预测过期；历史缺失字段和冲突字段读取时不改写文件。

## 3. 前端构建

```powershell
cd frontend
npm.cmd run build
```

期望 TypeScript 和 Vite 生产构建成功，不新增依赖。

## 4. 页面验证

打开“计划执行 → 进度反馈与预测”：

1. 验证表头在“状态”之后依次为“总工程量、实际完成比例、实际已完工程量、剩余工程量”。
2. 验证总工程量和剩余工程量为只读展示，实际完成比例和实际已完工程量按状态启用。
3. 对总量 `10m` 的进行中任务输入 `40%`，确认同一行立即显示 `4m / 6m`。
4. 将已完工程量改为 `2.5m`，确认比例变为 `25%`、剩余量变为 `7.5m`。
5. 填写有效实际开始日期和实际工效，保存后刷新，确认服务器回显与保存前一致。
6. 分别切换未开始、已完成、暂停、取消，核对 [data-model.md](./data-model.md) 的状态矩阵。
7. 筛选和翻页后再次返回任务，确认行级进度没有丢失；保存失败时原错误提示可见。

## 5. 历史兼容验证

构造一个旧快照：

- 缺少 `completed_quantity` 和 `remaining_quantity`；或
- 两个数量与计划总量不一致。

确认：

1. 项目和进度页面可以打开。
2. 缺失值按总量和比例派生展示，并标记派生来源。
3. 冲突值显示数据质量提示，不静默覆盖。
4. 只读加载前后的存储文件哈希相同。
5. 用户填写更正原因并保存后形成新修订，原快照仍可追溯。
