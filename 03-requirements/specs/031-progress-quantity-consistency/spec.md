# 功能规格：实际进度工程量一致性

**功能目录/分支**：`031-progress-quantity-consistency`

**创建日期**：2026-07-13

**状态**：草稿

**输入**：用户要求在“实际进度反馈”中提供总工程量、实际完成比例、实际已完工程量和剩余工程量四列数据，并基于当前基准计划与进度预测链路保持数据一致。

## 来源与评审上下文（必填）

- **来源文档**：`AGENTS.md`、`agent.md`、`README.md`、`docs/基建智能计划管控中枢整体产品方案_v1.0.md`、`specs/027-baseline-progress-forecast/spec.md`、`specs/027-baseline-progress-forecast/data-model.md`、`specs/030-task-parameter-quantity-split/spec.md`。
- **评审结论**：需求成立，建议作为进度数据一致性改造推进，而不是只增加一个页面表头。总工程量应来自当前执行计划，实际完成比例和实际已完工程量可以互相驱动，剩余工程量必须由统一公式得到，避免三个可编辑字段互相矛盾并污染滚动预测。
- **使用的 Demo/代码事实**：当前页面已有“完成比例、已完工程量、剩余工程量”，缺少总工程量；三个进度字段可独立填写；保存时已完工程量可以覆盖完成比例，但系统没有保证“已完工程量 + 剩余工程量 = 总工程量”；滚动预测使用剩余工程量和实际工效计算剩余工期；基准计划任务已经保存稳定的工程量数值和工程量文本。
- **不在范围内**：不修改基准计划任务工程量；不重新计算结构物工程量；不修改工效库、资源约束、里程碑、CP-SAT 目标函数或调整策略；不新增正式权限、审批、移动端填报或外部计量系统；不迁移和重写历史进度快照。

## 用户场景与测试（必填）

### 用户故事 1 - 查看完整工程量进度（优先级：P1）

计划工程师在实际进度反馈页面核验任务时，可以同时看到计划总工程量、实际完成比例、实际已完工程量和剩余工程量，并明确三项数量使用同一任务单位。

**优先级理由**：总工程量是判断实际完成和剩余数据是否合理的基准；缺少该列时，用户无法在当前页面完成工程量闭环核验。

**独立测试**：打开已确认基准计划的进度反馈页面，选择一个总工程量为 `10m` 的任务，确认四列同时展示为可理解的完整数据，且总工程量来自当前执行计划。

**验收场景**：

1. **假设** 当前执行计划任务总工程量为 `10m`，**当** 用户打开实际进度反馈，**则** 页面在状态之后依次展示总工程量、实际完成比例、实际已完工程量和剩余工程量，并在数量数据中保持米单位口径。
2. **假设** 当前执行计划任务以 `个`、`根`、`块`、`段` 或 `联`为工程量单位，**当** 页面展示进度数据，**则** 总量、已完和剩余量使用同一任务单位，不混入结构物参数。
3. **假设** 没有活动执行计划，**当** 用户进入页面，**则** 继续展示现有“尚未确认基准计划”空态，不出现没有来源的总工程量。

---

### 用户故事 2 - 一致地填报完成进度（优先级：P1）

计划工程师可以按实际完成比例或实际已完工程量任一口径填报进行中任务，系统立即同步另外两项进度数据，并将一致的剩余工程量用于剩余工期预测。

**优先级理由**：这是消除当前三个进度字段互相矛盾的核心能力，会直接影响剩余工期和未来排程预测是否可信。

**独立测试**：对总工程量 `10m` 的进行中任务分别输入 `40%` 和 `4m`，确认两种输入均得到 `40% / 4m / 6m`；输入实际工效 `2m/天` 后，剩余工期为 3 天。

**验收场景**：

1. **假设** 任务总工程量为 `10m` 且状态为进行中，**当** 用户把实际完成比例改为 `40%`，**则** 实际已完工程量同步为 `4m`，剩余工程量同步为 `6m`。
2. **假设** 同一任务状态为进行中，**当** 用户把实际已完工程量改为 `4m`，**则** 实际完成比例同步为 `40%`，剩余工程量同步为 `6m`。
3. **假设** 剩余工程量为 `6m`、实际工效为 `2m/天`，**当** 保存进度，**则** 系统采用 3 天作为计算得到的剩余工期。
4. **假设** 输入值导致已完工程量超出总工程量、完成比例超出 0–100% 或数量关系不一致，**当** 保存进度，**则** 系统拒绝该记录并指出具体任务及错误关系。

---

### 用户故事 3 - 按任务状态与历史快照安全兼容（优先级：P2）

计划工程师切换任务状态或打开历史进度时，可以看到符合状态含义的四项工程量数据；历史快照继续可读且不会被系统静默改写。

**优先级理由**：进度快照承担审计和未来预测输入，状态切换与历史兼容必须避免丢失真实实绩或破坏既有记录。

**独立测试**：分别设置未开始、进行中、已完成、暂停和取消状态，再加载缺少工程量字段或数量关系不一致的旧快照，检查状态规则、提示、修订和文件不改写行为。

**验收场景**：

1. **假设** 任务状态为未开始，**当** 页面展示该任务，**则** 实际完成比例为 0%、实际已完工程量为 0、剩余工程量等于总工程量。
2. **假设** 任务状态切换为已完成，**当** 用户填写有效实际起止日期，**则** 实际完成比例为 100%、实际已完工程量等于总工程量、剩余工程量为 0。
3. **假设** 进行中任务切换为暂停，**当** 保存暂停进度，**则** 已发生的完成比例和实际已完工程量被保留，剩余工程量仍按总量减已完量展示，剩余工期继续走暂停任务的人工填报规则。
4. **假设** 任务被取消，**当** 保存带原因的取消记录，**则** 系统保留取消前实际完成数据和物理剩余工程量，但该任务不再产生预测剩余工期。
5. **假设** 历史快照缺少已完或剩余工程量，**当** 用户打开该快照，**则** 页面可根据执行计划总工程量和历史完成比例派生展示；原快照不被改写，下一次保存形成新的可追溯修订。

### 边界与异常场景

- 当前执行计划中的任务总工程量是本功能唯一计划基准，不从结构物参数摘要、旧混合工程量文本或当前页面重新计算。
- 总工程量为 0、缺失或无法确认时，数量联动不可用；页面显示明确诊断，并保留完成比例与人工剩余工期的兼容填报路径。
- 用户清空实际完成比例或实际已完工程量时，不得把空值静默解释为 0；进行中或暂停任务保存前必须形成有效进度口径。
- 小数工程量允许表示等效完成工作量；页面显示值可以按统一精度格式化，但计算和保存不得使用显示舍入值反复累计。
- 历史快照中的已完量和剩余量与总量不一致时，页面必须提示数据质量问题，不得静默覆盖历史值；用户更正后生成带原因的新修订。
- 状态日期、实际日期倒序、完成比例倒退、更正原因和并发修订继续沿用现有校验与审计规则。
- 修改并保存实际进度后，已有滚动预测和调整方案继续按现有规则失效。

## 需求（必填）

### 功能需求

- **FR-001**：实际进度反馈必须在任务状态之后依次展示“总工程量”“实际完成比例”“实际已完工程量”“剩余工程量”。
- **FR-002**：总工程量必须只读，并来自当前活动执行计划中对应任务的计划工程量。
- **FR-003**：总工程量、实际已完工程量和剩余工程量必须使用同一任务工程量单位，且不得混入结构物参数。
- **FR-004**：实际完成比例和实际已完工程量必须支持用户按任一口径填报；修改其中一项时，另外两项进度数据必须在同一行立即同步。
- **FR-005**：剩余工程量必须只读，并始终等于总工程量减实际已完工程量。
- **FR-006**：实际完成比例必须等于实际已完工程量除以总工程量后乘以 100%；显示比例保留至多两位小数，业务计算使用未因显示而重复舍入的值。
- **FR-007**：系统必须保证 `0 ≤ 实际已完工程量 ≤ 总工程量`、`0 ≤ 剩余工程量 ≤ 总工程量`、`0% ≤ 实际完成比例 ≤ 100%`。
- **FR-008**：新保存的进度记录必须满足“实际已完工程量 + 剩余工程量 = 总工程量”；不一致时不得进入滚动预测。
- **FR-009**：未开始任务必须自动形成 `0% / 0 / 总工程量`，且不可填写实际工程量。
- **FR-010**：已完成任务必须自动形成 `100% / 总工程量 / 0`，并继续要求有效的实际开始和实际完成日期。
- **FR-011**：进行中任务必须允许填报实际完成比例或实际已完工程量，并继续要求实际开始日期以及可计算或人工提供的剩余工期数据。
- **FR-012**：暂停任务必须保留实际完成比例、实际已完工程量和物理剩余工程量，并继续使用人工剩余工期和暂停原因规则。
- **FR-013**：取消任务必须保留取消前的实际完成数据和物理剩余工程量，但预测剩余工期必须为 0，并继续要求取消原因。
- **FR-014**：剩余工期按工程量计算时，必须使用本功能归一后的剩余工程量和实际工效。
- **FR-015**：总工程量无效时，系统必须禁用工程量联动并明确提示；完成比例和人工剩余工期兼容路径仍可用于进行中或暂停任务。
- **FR-016**：历史进度快照缺少已完或剩余工程量时必须继续可读；系统可以派生展示，但不得静默改写原快照。
- **FR-017**：历史快照数量关系不一致时必须展示数据质量提示；更正必须沿用现有更正原因、修订号和字段级审计记录。
- **FR-018**：新进度快照保存后，系统返回的完成比例、已完工程量和剩余工程量必须已经归一并可直接回显。
- **FR-019**：保存实际进度后，基于旧进度生成的滚动预测和调整方案必须继续失效。
- **FR-020**：页面筛选、分页、加载、保存中、保存失败、空态和刷新行为必须保持现有交互能力。
- **FR-021**：本功能不得改变基准计划任务工程量、任务工期、工效库、资源约束、里程碑、求解目标或调整策略。

### 关键实体（涉及数据时填写）

- **计划任务工程量**：活动执行计划中任务的稳定总工程量及单位，是进度数量计算的唯一计划基准。
- **进度填报项**：某任务在状态日期下的状态、实际完成比例、实际已完工程量、剩余工程量、实际日期、实际工效、剩余工期和备注。
- **进度快照**：同一状态日期下所有进度填报项的可审计集合，保存归一后的进度数据并支持修订。
- **历史进度修订**：对既有状态日期的进度更正，保留原快照、字段变化、更正原因、人员和时间。
- **滚动预测输入**：活动计划和当前进度快照形成的未来排程输入，其中进行中任务使用一致的剩余工程量计算剩余工期。

## 成功标准（必填）

### 可衡量结果

- **SC-001**：拥有活动执行计划时，100% 的任务行同时展示四个约定工程量进度字段，且总工程量与执行计划任务一致。
- **SC-002**：对总工程量 `10m` 的任务输入 `40%` 或 `4m`，两种操作均在一次编辑后得到 `40% / 4m / 6m`。
- **SC-003**：所有新保存的有效进度项均满足“已完工程量 + 剩余工程量 = 总工程量”，不一致记录进入预测的数量为 0。
- **SC-004**：未开始和已完成任务的自动进度值准确率为 100%；暂停和取消任务不会丢失已发生的实际完成数据。
- **SC-005**：剩余工程量 `6m`、实际工效 `2m/天` 的样例得到 3 天剩余工期，且预测使用的数值与页面保存结果一致。
- **SC-006**：缺少新增工程量实绩的历史快照可直接打开，原文件或原快照被静默改写的次数为 0。
- **SC-007**：超总量、负数、完成比例越界、数量关系冲突和总工程量无效五类样例均产生可定位到任务的明确结果，不出现 `NaN`、负剩余量或静默修正。
- **SC-008**：保存有效进度后，用户刷新页面仍看到同一组归一数据，且旧滚动预测不可继续作为当前结果使用。

## 默认假设

- 总工程量取自活动执行计划的任务快照，不在进度反馈页面编辑，也不复制到进度填报项中。
- 用户可以编辑实际完成比例或实际已完工程量；页面保证两者同步，新保存请求中的三项进度值必须一致。
- 小数数量表示等效完成工程量，适用于 `个`、`根`、`块`、`段`、`联`等离散单位的任务过程进度。
- 取消任务的“剩余工程量”表示尚未完成的物理工作量，但该数量不参与取消任务的剩余排程。
- 历史快照只读加载时允许派生缺失展示值；只有用户主动保存更正时才创建新修订。
- 当前单机 Demo 不新增角色权限；沿用现有填报人和更正原因机制。
