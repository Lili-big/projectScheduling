# 研究决策

仅核对本次目标所需的既有实现，无依赖调研或独立代理。

| 决策 | 依据与理由 | 未采用方案 |
| --- | --- | --- |
| 手动独立优化 | 用户已选择在当前结果点击“优化窝工” | 不在每次常规求解后自动耗费第二轮预算 |
| 当前工期为上限、窝工合计最小 | 符合“已求解工期基础上”；不要求此前证明全局最短 | 不用工期与窝工加权和，避免为少空闲延期；不用 makespan = D 强制拖到原末日 |
| 统计机组自身作业期内部空档 | 资源图已有同一口径；项目全周期空闲常会变成固定量、不能有效指导连续施工 | 不把未进场/退场时段算窝工，不把必要转场算窝工 |
| 复用路线首尾和弧变量 | add_pavement_fleet_paths 已返回 first/last/empty 和真实相邻弧 | 不新增成对先后模型或每条弧的间隔变量 |
| 基准重新核验 | 当前结果由浏览器提交，前端 stale 标记不能替代服务端权威输入和数值约束 | 不只相信 objective_days/客户端工期上限或仅比较任务数量 |
| 独立新增目标元数据 | 旧工期阶段结果字段及展示已存在，窝工最优不代表工期最优 | 不复用 objective_days 存窝工，不覆写第一阶段耗时/证明证据 |
| 沿用有限预算与流式通道 | 既有 mailbox、取消控制、线程/LNS 可复用；改动集中在候选比较和显示 | 不开新后台任务、不无限优化、不增加通用协议层 |

需显式说明的目标局限：允许延后首次作业以缩短占用期；机组等权合计不保证每套各自改善，必要转场可能随路线变化。转场前后值展示，但本期不新增转场总量上限或成本目标。所有转场常量仍来自真实配置，不能人为延长来冲掉空闲。

无未解决的阻塞技术问题。实施时的模型/数值一致性由针对性测试证明，不预先宣称真实项目能改善多少。
