# 功能规格：现浇连续梁联级班组占用

**功能目录/分支**：`016-continuous-beam-team-span`

**创建日期**：2026-07-08

**状态**：草稿

**输入**：用户要求按“联”聚合现浇连续梁任务，连续梁班组按联占用；同一联内任务不因班组空闲而互斥，跨联受连续梁班组数量限制。

## 来源与评审上下文（必填）

- **来源文档**：`AGENTS.md`、`agent.md`、`docs/CP-SAT固定资源算法实现需求文档_v1.0.md`、`docs/资源配置页面需求文档_v1.0.md`、本次用户确认的联级资源规则。
- **评审结论**：用户已确认直接进入规格化开发。该变更涉及 CP-SAT、资源模型、排程结果和前后端共享口径，按项目契约必须进入 Spec Kit，未确认 `tasks.md` 与 `$speckit-analyze` 结果前不进入实现。
- **使用的 Demo/代码事实**：
  - 当前连续梁任务由 `backend/app/scenario.py` 根据上部结构参数生成，任务属性中已有 `group_index`，且左右幅位于不同 `work_section_id`。
  - 当前求解器对命名资源建立任务级互斥；若连续梁任务逐个占用同一个班组，会让同一联内任务也被班组空闲状态限制。
  - 当前求解器已有连续梁左右悬臂标准段同步、合龙前置完成间隔等连续梁专用硬约束，这些规则应继续保留。
  - 当前资源池默认包含 `cast_in_place_continuous_beam_team`，资源数量代表可投入的连续梁班组数。
- **不在范围内**：
  - 不改变连续梁 0 号块、标准段、边跨连续段、边跨合龙段、中跨合龙段的任务拆分口径。
  - 不改变连续梁既有工艺前后置、下部结构完成约束、左右悬臂同步和合龙间隔规则。
  - 不新增连续梁路径连续性目标、转场成本目标或班组路线优化目标。
  - 不改变桩基墩组两阶段精排规则。

## 用户场景与测试（必填）

### 用户故事 1 - 一个班组按联串行施工（优先级：P1）

计划工程师将现浇连续梁班组数量设置为 1 后，希望系统把左幅、右幅或多联连续梁视为争用同一个班组的联级对象，避免结果显示同一班组同时负责两个联。

**优先级理由**：这是本次变更的核心业务口径。若一个班组仍能跨联并行，固定资源测算会高估现场施工能力。

**独立测试**：使用包含左幅一联、右幅一联的连续梁场景，将连续梁班组数量设置为 1，求解后验证两个联的联级占用时间不重叠。

**验收场景**：

1. **假设** 左幅和右幅各有一个相同 `group_index` 的现浇连续梁联，且连续梁班组数量为 1，**当** 用户执行固定资源排程，**则** 左幅联和右幅联不能在联级占用时间上重叠。
2. **假设** 多个联的下部结构都已具备连续梁施工条件，且连续梁班组数量为 1，**当** 系统生成排程结果，**则** 系统只能选择一个联先施工，其他联等待该班组释放。

---

### 用户故事 2 - 两个班组允许两联并行（优先级：P1）

计划工程师将现浇连续梁班组数量设置为 2 后，希望系统允许最多两个联同时进入连续梁施工，体现两个班组可以分别负责不同联。

**优先级理由**：该场景验证 `cast_in_place_continuous_beam_team.quantity` 的资源组织含义，直接影响资源增配建议和工期测算。

**独立测试**：在同一连续梁场景中将连续梁班组数量从 1 调整为 2，验证左幅和右幅可被不同班组并行占用，且任一时刻并行占用的联数不超过 2。

**验收场景**：

1. **假设** 左幅和右幅连续梁均已具备施工条件，且连续梁班组数量为 2，**当** 用户执行固定资源排程，**则** 左幅联与右幅联可以在时间上重叠，并分别归属不同连续梁班组。
2. **假设** 场景中存在 3 个可施工的连续梁联，且连续梁班组数量为 2，**当** 系统生成排程结果，**则** 任意日期最多只有 2 个联处于班组占用状态。

---

### 用户故事 3 - 同一联内任务不因班组互斥被串行化（优先级：P1）

计划工程师希望一个联获得连续梁班组后，联内 0 号块、标准段、边跨段、合龙段等任务只受工艺条件控制，而不是因为它们都属于同一班组就被逐个串行安排。

**优先级理由**：这是本次规则区别于普通命名资源互斥的关键。如果联内仍按任务级班组互斥，规则会退化为原有模型，无法表达用户期望。

**独立测试**：构造一个联内存在多个已具备施工条件任务的连续梁场景，验证同一联内任务可以根据既有工艺约束并行或同步，不会仅因使用同一连续梁班组而被强制错开。

**验收场景**：

1. **假设** 同一联内左右悬臂标准段按既有规则需要同步，且该联已占用一个连续梁班组，**当** 系统求解，**则** 左右标准段仍可同日开始和完成。
2. **假设** 同一联内两个任务之间没有工艺前后置或连续梁专用间隔限制，**当** 这些任务都满足开工条件，**则** 系统不得仅因为它们属于同一个连续梁班组而强制排成先后顺序。

---

### 用户故事 4 - 结果可解释为联级班组组织（优先级：P2）

计划工程师查看排程结果时，需要知道每个连续梁联由哪个连续梁班组负责，以及为什么某些联等待另一个联完成后才开始。

**优先级理由**：联级占用改变了资源解释口径。若结果只显示任务未分配资源或继续显示任务级互斥，会造成现场组织理解错误。

**独立测试**：求解后查看连续梁任务、资源分配和诊断信息，验证结果能说明联级班组归属、联级占用起止和跨联等待原因。

**验收场景**：

1. **假设** 某联被连续梁班组 1 负责，**当** 用户查看该联下任一连续梁任务，**则** 结果能追溯该任务所属联的班组归属。
2. **假设** 连续梁班组数量不足导致某联等待，**当** 用户查看诊断或资源组织信息，**则** 系统能说明等待来自跨联班组占用，而不是提示联内任务缺少资源。

### 边界与异常场景

- 当连续梁任务缺少 `bridge_id`、`work_section_id` 或 `group_index` 导致无法识别联时，系统应保留可解释诊断，不得静默把多个联合并为一个错误对象。
- 当连续梁班组资源池被禁用、数量为 0 或配置为不受限资源时，系统应按项目既有资源规则给出明确诊断，并避免把联级班组约束错误套用到无限资源。
- 当一个联只有部分连续梁任务生成时，联级占用范围应覆盖该联实际生成的连续梁任务。
- 当连续梁任务中存在既有 `resource_neutral` 任务时，该任务仍应纳入联级占用范围，但不应恢复为任务级班组互斥。
- 当求解进入最少资源或资源建议分支时，连续梁班组数量上限应继续代表最多可并行施工的连续梁联数。
- 当旧结果或旧配置不包含联级资源信息时，前端展示应保持兼容，不得将历史结果误判为求解失败。

## 需求（必填）

### 功能需求

- **FR-001**：系统必须将现浇连续梁任务按 `bridge_id + work_section_id + continuous_beam.group_index` 识别为联级施工对象；左幅和右幅因 `work_section_id` 不同，应默认识别为不同联。
- **FR-002**：系统必须将 `cast_in_place_continuous_beam_team.quantity` 解释为最多可同时施工的连续梁联数；数量为 1 时跨联串行，数量为 2 时最多两联并行。
- **FR-003**：系统必须让每个连续梁联在排程中选择一个连续梁班组归属，并确保同一个连续梁班组在同一时间最多占用一个联。
- **FR-004**：系统必须以该联内所有已生成连续梁任务的最早开始和最晚完成作为联级占用窗口，用于判断跨联班组是否冲突。
- **FR-005**：系统不得把同一联内每个连续梁任务逐个纳入连续梁班组的任务级互斥；联内任务是否并行仅由工艺前后置、下部结构约束、左右悬臂同步、合龙间隔、里程碑和其他既有约束决定。
- **FR-006**：系统必须保留既有连续梁专用约束，包括左右悬臂标准段同步和合龙前置完成间隔，不得因联级资源占用而放松。
- **FR-007**：系统必须在固定资源排程、最少资源建议和资源成本相关求解中保持一致的连续梁班组数量语义。
- **FR-008**：系统必须在结果中提供可解释的联级班组归属和联级占用信息，使用户能够理解连续梁任务对应的班组组织。
- **FR-009**：系统必须在资源不足、联识别失败、资源池禁用或无兼容班组时输出明确诊断，不得返回看似正常但资源语义错误的结果。
- **FR-010**：系统必须保持非连续梁任务的资源互斥、同结构同工序规则和桩基墩组规则不变。
- **FR-011**：系统必须保持现有任务粒度展示，不得把联内任务合并成一个粗任务替代原任务视图。
- **FR-012**：系统必须支持基于同一输入样例比较连续梁班组数量为 1 和 2 的排程差异，且差异应主要体现为跨联并行能力变化。

### 关键实体（涉及数据时填写）

- **连续梁联**：由同一桥梁、同一工区或幅别、同一连续梁组号下的现浇连续梁任务组成，是连续梁班组占用的业务单位。
- **连续梁班组资源池**：类型为 `cast_in_place_continuous_beam_team` 的资源组织，数量表示可同时承担多少个连续梁联。
- **联级占用窗口**：一个连续梁联从首个联内任务开始到最后一个联内任务完成的时间范围，用于跨联班组冲突判断。
- **联内连续梁任务**：0 号块、标准段、边跨连续段、边跨合龙段、中跨合龙段等原有任务，继续作为排程和展示的基本任务粒度。
- **联级班组归属**：某个连续梁联选择或占用的连续梁班组，用于解释资源组织和跨联等待。

## 成功标准（必填）

### 可衡量结果

- **SC-001**：在包含左幅和右幅各一联的可复现场景中，连续梁班组数量为 1 时，两个联的联级占用窗口重叠次数为 0。
- **SC-002**：在同一场景中，连续梁班组数量为 2 时，左幅和右幅连续梁联允许并行，且任一时间并行占用联数不超过 2。
- **SC-003**：同一联内左右悬臂标准段同步验收继续通过，且不会因为同属一个连续梁班组而被强制错开。
- **SC-004**：连续梁联级资源规则的新增自动化测试覆盖 1 个班组串行、2 个班组并行、联内不任务级互斥、联识别失败诊断四类场景。
- **SC-005**：现有非连续梁资源互斥和桩基墩组相关回归测试继续通过。
- **SC-006**：排程结果中每个连续梁任务都能追溯到所属连续梁联；每个已占用连续梁班组的联级起止时间可被检查。

## 默认假设

- 默认同一 `bridge_id + work_section_id + group_index` 代表一个连续梁联；若后续结构参数出现更细的“联号”字段，再通过兼容策略映射到同一口径。
- 默认连续梁班组资源池仍使用 `cast_in_place_continuous_beam_team`，不新增新的资源类型。
- 默认联级占用只控制跨联班组并发，不表达联内劳动力人数、挂篮套数、模板周转或材料供应能力。
- 默认旧结果可以缺少联级资源字段，前端需要以兼容方式展示历史结果。
- 默认第一阶段只覆盖本地 Python 后端和 React 前端的主排程链路；Netlify 演示 API 如存在同类逻辑，应在计划阶段判断是否同步。
