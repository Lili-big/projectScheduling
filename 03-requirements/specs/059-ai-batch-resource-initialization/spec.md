# 功能规格：AI 批量初始化工点工装资源

**功能目录/分支**：`059-ai-batch-resource-initialization`

**创建日期**：2026-07-21

**状态**：规格已确认，待计划

**输入**：在工点资源配置页面增加“AI快速配置工装”按钮，调用真实 LLM，根据当前项目各桥梁工点的结构物汇总和可选资源批量推荐初始化资源；密钥由用户填写在本地环境文件中。

## 来源与评审上下文（必填）

- **来源文档**：本次用户请求与两次规则确认；`03-requirements/specs/048-workpoint-first-resource-allocation/spec.md`；`03-requirements/specs/053-ai-workpoint-resource-comparison/spec.md`。
- **评审结论**：AI 推荐结果继续使用现有逐工点资源配置页面展示，不新增全项目推荐预览；用户自行切换工点逐项检查，点击现有“保存”后一次性保存全部资源。AI 只补充尚未配置的工点本地资源，已有资源及其数量、上限、状态和作用域保持不变。
- **使用的 Demo/代码事实**：`ResourcesTab` 已按当前项目主数据版本展示完整桥梁工点，能够从工点结构推导候选资源并在页面状态中增删 `WORKPOINT_EXCLUSIVE` 资源；现有保存操作一次提交完整 `resource_pools`。后端已具备 OpenAI-compatible LLM 配置、JSON 输出校验与 `.local.env` 加载能力，真实密钥不进入前端或仓库。
- **不在范围内**：不新增全量推荐预览页；不自动保存；不修改或删除任何已有资源；不创建项目共享池；不推荐非桥梁工点资源；不触发 CP-SAT 求解或 AI 多方案比选；不把本地确定性回退伪装成真实 LLM 推荐。

## 用户场景与测试（必填）

### 用户故事 1 - 一键生成全部桥梁工点的初始化资源（优先级：P1）

计划工程师在“工点资源配置”页面点击“AI快速配置工装”，系统汇总当前项目主数据版本下所有可排程桥梁工点的结构物信息及其合法可选资源，调用已配置的真实 LLM，为各工点批量推荐尚未配置的本地资源及初始化数量。

**优先级理由**：减少逐工点、逐资源手工建立初始配置的重复工作，是本功能的核心价值。

**独立测试**：使用至少两个结构类型不同的桥梁工点且均无资源的项目，点击按钮后验证每个工点只新增与其结构和资源目录匹配的本地资源，推荐数量均合法且没有自动保存。

**验收场景**：

1. **假设** 当前项目版本包含多个可排程桥梁工点且真实 LLM 配置有效，**当** 用户点击“AI快速配置工装”，**则** 系统为所有有结构资料的桥梁工点生成合法初始化资源并填入当前页面状态。
2. **假设** 某工点仅允许一组候选资源类型，**当** LLM 返回推荐，**则** 系统只接受该工点候选集合内的资源，不接受其他工点、共享资源或未知资源类型。
3. **假设** 推荐正在生成，**当** 用户再次点击按钮，**则** 系统不得发起重复批次，并清楚展示处理中状态。

---

### 用户故事 2 - 在现有逐工点页面检查并统一保存（优先级：P1）

推荐完成后，用户继续使用现有工点标签逐个查看和调整 AI 填入的资源，无需面对新的全量预览页面；确认完毕后点击现有“保存”，一次性保存当前页面中的全部资源配置。

**优先级理由**：保留用户最终决策权，并复用已经熟悉的逐工点资源检查和保存流程。

**独立测试**：完成一次 AI 推荐后依次切换所有工点，确认推荐资源均出现在对应工点；保存前刷新不得视为已持久化，点击保存后重新加载则恢复整批配置。

**验收场景**：

1. **假设** AI 已返回多个工点的推荐，**当** 用户切换工点标签，**则** 每个工点只展示其自己的资源，现有编辑、启停和移除能力保持可用。
2. **假设** 推荐已填入但尚未保存，**当** 用户继续人工修改数量或上限并点击“保存”，**则** 系统一次保存推荐与人工修改后的完整资源配置。
3. **假设** 推荐已填入但用户未点击保存，**当** 页面重新加载，**则** 未保存推荐不得被当作持久化配置恢复。

---

### 用户故事 3 - 保护已有配置和真实模型边界（优先级：P1）

对已经配置过资源的工点，AI 快速配置只补充缺失资源，不覆盖任何已有记录；未配置真实 LLM、模型不可用或输出不合法时，系统明确失败且不改变当前资源状态。

**优先级理由**：已有配置属于用户数据，真实模型能力和失败原子性是避免误覆盖与伪推荐的必要边界。

**独立测试**：在部分工点已有资源、部分工点为空的场景下分别模拟成功、缺少密钥、超时、返回越界数量和返回未知资源；验证已有资源逐字段不变，失败时整个批次零写入。

**验收场景**：

1. **假设** 某工点已有一个本地资源池，**当** AI 推荐包含同类型资源，**则** 系统保留原资源全部字段，不以 AI 值覆盖。
2. **假设** LLM 环境变量缺失或服务调用失败，**当** 用户点击快速配置，**则** 页面显示可行动错误，所有工点资源保持点击前状态。
3. **假设** LLM 输出存在未知资源、错误工点、非整数、负数或上限小于投入等非法数据，**当** 后端完成校验，**则** 整批推荐不进入页面状态并返回明确诊断。

### 边界与异常场景

- 当前项目没有已确认的项目主数据版本、没有可排程桥梁工点或所有桥梁均无结构资料时，不调用 LLM，并提示缺失条件。
- 工点结构资料加载不完整时，该批次不得用空结构或猜测数据生成正式推荐；系统应指出缺失工点。
- 某工点所有候选资源都已配置时，AI 不得重复创建资源，该工点结果标记为无需补充。
- 用户在点击前已有未保存的手工资源修改时，这些修改视同当前配置并必须保留；AI 只补充仍缺失的资源。
- 项目主数据版本或资源配置在调用期间发生变化时，迟到结果不得写入新状态，用户需重新发起推荐。
- LLM 返回部分有效、部分无效工点时，整批保持原子性：任何非法记录都会导致本批次零应用。
- LLM 响应不得携带或回显 API Key；错误信息和日志不得包含密钥、认证头或完整敏感请求。
- 候选资源为空的工点不生成占位资源，必须返回对应诊断。

## 需求（必填）

### 功能需求

- **FR-001**：系统必须在现有“工点资源配置”页面提供“AI快速配置工装”按钮，并展示空闲、处理中、成功和失败状态。
- **FR-002**：系统必须以当前 `project_data_version_id` 对应的完整项目主数据快照作为桥梁工点和结构物信息的唯一权威来源。
- **FR-003**：系统必须为每个可排程桥梁工点形成结构物汇总，至少包含稳定工点身份、工点名称、结构物/构件类型及数量、关键工艺或结构特征。
- **FR-004**：系统必须为每个工点形成合法候选资源集合；候选项至少包含稳定资源类型、中文名称、适用工艺、默认日历和允许的数量规则。
- **FR-005**：发送给 LLM 的内容必须仅包含推荐所需的项目、工点、结构汇总、候选资源和输出约束，不得包含 API Key 或无关本地敏感信息。
- **FR-006**：系统必须调用由本地环境变量配置的真实 OpenAI-compatible LLM；所需 provider、endpoint、model、API Key、超时和结构化输出配置必须有无密钥模板。
- **FR-007**：真实 LLM 配置缺失、不可达、超时或鉴权失败时，系统必须返回明确错误并保持全部资源不变，不得自动采用本地推荐冒充 LLM 结果。
- **FR-008**：LLM 必须按稳定工点 ID 返回每个工点的资源推荐；每条推荐包含候选资源类型、正整数当前投入和不小于当前投入的正整数可增上限。
- **FR-009**：后端必须校验工点属于当前版本、资源属于该工点候选集合、数量为整数且满足边界；禁止共享池、未知资源、跨工点资源和任意属性写入。
- **FR-010**：推荐必须仅创建 `WORKPOINT_EXCLUSIVE`、`LIMITED`、已启用的工点本地资源，使用稳定且可重复生成的资源池身份，并保留候选资源的适用工艺与默认日历。
- **FR-011**：AI 快速配置必须只补充当前页面状态中尚不存在的 `工点 ID + 资源类型`；任何已有资源池及其 ID、数量、上限、启用状态、日历、作用域和适用工艺必须逐字段保持不变。
- **FR-012**：批量结果必须先完成整体验证再进入前端状态；任一非法记录、版本过期或响应不完整时，本批次不得应用任何资源变更。
- **FR-013**：成功结果必须直接合并到现有逐工点资源页面状态，不新增全量预览页；用户可通过现有工点标签逐个确认和调整。
- **FR-014**：AI 推荐成功不得自动持久化；只有用户点击现有“保存”操作时，系统才一次性保存当前完整资源配置。
- **FR-015**：保存成功后必须沿用现有场景失效规则，使旧任务图、求解结果、对比结果和 AI 多方案会话不再被当作当前结果。
- **FR-016**：调用期间按钮必须防重复提交；项目版本或资源输入变化后，旧响应必须被丢弃并提示重新生成。
- **FR-017**：系统必须返回逐工点处理摘要，包括新增资源数量、无需补充工点和未能处理的工点诊断，但不要求新增集中式编辑预览。
- **FR-018**：真实密钥必须只存在于被 Git 忽略的本地 `.local.env`，不得写入前端代码、API 响应、日志、规格、测试夹具或已跟踪文件。
- **FR-019**：历史资源配置和不使用 AI 按钮的现有手工配置、逐工点编辑及保存流程必须保持兼容。

### 关键实体（涉及数据时填写）

- **AI 工点资源初始化请求**：当前项目主数据版本、当前资源快照以及本批次调用身份；用于建立可复现、可失效的推荐输入。
- **工点结构汇总**：一个桥梁工点的稳定身份、结构物与构件分类数量、关键特征和相关工艺摘要。
- **工点候选资源**：由当前工艺库和资源目录限定的合法资源类型、显示名称、适用工艺、默认日历及数量约束。
- **AI 工点资源推荐**：按工点分组的缺失资源初始化数量和上限；通过后端确定性校验后才能进入页面状态。
- **批量推荐摘要**：本次模型与验证状态、各工点新增数量、无需补充项、失败诊断和输入版本身份，不包含密钥。

## 成功标准（必填）

### 可衡量结果

- **SC-001**：在包含至少 10 个桥梁工点的验证项目中，用户一次点击即可为全部具备完整结构资料且存在缺失资源的工点生成初始化建议，无需逐工点发起模型请求。
- **SC-002**：对点击前已存在的所有资源池进行逐字段比较，AI 推荐后的非用户编辑差异数量为 0。
- **SC-003**：LLM 返回的 100% 推荐记录都通过工点、候选资源、作用域和数量边界校验后才进入页面；非法批次进入页面的记录数为 0。
- **SC-004**：推荐完成后，用户可以在现有工点标签中查看全部新增资源，并通过一次现有“保存”操作持久化整批资源。
- **SC-005**：在缺少密钥、鉴权失败、超时、非法 JSON、部分非法记录和项目版本切换测试中，资源状态变化数均为 0，且页面均提供可行动错误。
- **SC-006**：仓库跟踪文件、前端产物、API 响应和测试输出中的真实 API Key 暴露次数为 0。

## 默认假设

- v1 只处理当前已确认项目主数据版本中的 `bridge_supported` 桥梁工点。
- 真实模型通过现有 OpenAI-compatible HTTP 能力接入，并优先复用 `AI_RESOURCE_ASSISTANT_*` 配置族；规划阶段确认是否需要独立前缀。
- AI 仅建议工点独享受限资源的初始投入与可增上限；共享池仍由人工配置。
- 一个批次只调用一次模型；模型上下文超过限制时可以确定性分批传输，但对用户仍表现为一次原子操作，且不得因分批允许部分应用。
- 用户在 AI 推荐后可以继续使用现有页面人工修改或删除新增资源，最终保存内容以点击“保存”时的页面状态为准。
