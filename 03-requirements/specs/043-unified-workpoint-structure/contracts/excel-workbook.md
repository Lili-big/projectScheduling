# Excel 契约：统一工点与结构物完整快照

## 1. 文件级规则

- 文件格式：`.xlsx`；模板版本写在“填写说明”表的固定单元格中，首版为 `1.0`。
- 每次上传都表示该项目的**完整主数据快照**，不是增量追加。文件中缺少但当前确认版本存在的稳定 ID 将显示为待删除。
- 固定工作表：`填写说明`、`工点信息`、`结构物信息`、`构件参数`。工作表名称不得修改；允许调整列宽和冻结窗格，不允许合并数据区单元格。
- 第 1 行为字段代码，第 2 行为中文说明，第 3 行起为数据。导出文件保持相同结构，可再次导入。
- 空白行忽略；公式单元格按已计算值读取，缺少缓存值时报错。日期使用 `YYYY-MM-DD`，布尔使用 `是/否`，里程和工程量使用数值。
- 稳定 ID 只允许字母、数字、短横线、下划线和点，项目内不区分大小写后必须唯一；建议格式分别为 `WP-*`、`ST-*`、`CP-*`。
- 标准列之外的类型特有参数使用 `param.<parameter_code>` 列；不得在单元格中嵌套 JSON。参数定义为列表时使用半角竖线 `|` 分隔。

## 2. `工点信息`

| 字段代码 | 中文名 | 必填 | 规则 |
|---|---|---|---|
| `workpoint_id` | 工点ID | 是 | 项目内稳定且唯一；跨版本保持不变 |
| `workpoint_name` | 工点名称 | 是 | 一座桥/一段路基/一座隧道只填一行 |
| `workpoint_type` | 工点类型 | 是 | 见工点类型枚举 |
| `alignment_code` | 线路编码 | 否 | 线路或线别稳定编码 |
| `start_mileage_m` | 起点里程(m) | 否 | 数值；与终点同时填写 |
| `end_mileage_m` | 终点里程(m) | 否 | 数值且不小于起点 |
| `sort_order` | 排序号 | 是 | 非负整数 |
| `remark` | 备注 | 否 | 最长 500 字 |

工点类型：`bridge` 桥梁、`roadbed` 路基、`tunnel` 隧道、`culvert` 涵洞、`interchange` 互通、`service_area` 服务区、`station_yard` 场站、`access_road` 便道、`other` 其他。

## 3. `结构物信息`

| 字段代码 | 中文名 | 必填 | 规则 |
|---|---|---|---|
| `structure_id` | 结构物ID | 是 | 项目内稳定且唯一 |
| `workpoint_id` | 所属工点ID | 是 | 必须存在于“工点信息” |
| `structure_name` | 结构物名称 | 是 | 业务可读名称 |
| `structure_category` | 结构类别 | 是 | `substructure`、`superstructure`、`earthwork`、`tunnel_body`、`drainage`、`ancillary`、`other` |
| `structure_type` | 结构类型 | 是 | 按模板“填写说明”中的定义目录 |
| `side` | 幅别 | 是 | `left`、`right`、`shared`、`none` |
| `section_code` | 工区编码 | 条件必填 | 桥梁排程结构物必填；同一工区保持稳定 |
| `section_name` | 工区名称 | 否 | 展示名称 |
| `control_level` | 受控级别 | 否 | 按类型目录枚举 |
| `sort_order` | 排序号 | 是 | 同工点下稳定的非负整数 |
| `remark` | 备注 | 否 | 最长 500 字 |
| `param.<code>` | 结构参数 | 条件必填 | 由结构类型决定；例如跨径、支座范围、联跨表达式、主墩、节段数量 |

幅别定义：

- `left`：只属于左幅的正式结构物。
- `right`：只属于右幅的正式结构物。
- `shared`：左右幅共用且在物理上只维护一次的结构物。
- `none`：幅别不适用，仅用于非桥或明确无需幅别的结构物；不得用于应区分左右幅的桥梁结构。

桥梁首期至少支持：`bridge_abutment` 桥台、`bridge_pier` 桥墩、`simple_span` 简支梁跨、`cast_in_place_unit` 现浇梁联、`continuous_unit` 连续梁/连续刚构联。参数定义由模板版本固定，不允许用自由文本代替结构类型。

## 4. `构件参数`

一行表示一个构件。相同类型的扩展参数使用 `param.<parameter_code>` 列，不使用“键值对字符串”。

| 字段代码 | 中文名 | 必填 | 规则 |
|---|---|---|---|
| `component_id` | 构件ID | 是 | 项目内稳定且唯一 |
| `structure_id` | 所属结构物ID | 是 | 必须存在于“结构物信息” |
| `component_name` | 构件名称 | 是 | 业务可读名称 |
| `component_type` | 构件类型 | 是 | 按结构类型定义目录校验 |
| `quantity` | 工程量 | 是 | 数值且不小于 0 |
| `unit` | 单位 | 是 | 必须属于该构件类型允许单位 |
| `enabled` | 是否启用 | 是 | `是` 或 `否` |
| `sort_order` | 排序号 | 是 | 同结构物下稳定的非负整数 |
| `remark` | 备注 | 否 | 最长 500 字 |
| `param.<code>` | 构件参数 | 条件必填 | 如直径、长度、混凝土方量、梁型、节段类型 |

## 5. 参数示例

| 所属类型 | 参数列 | 值示例 | 含义 |
|---|---|---|---|
| `simple_span` | `param.span_length_m` | `40` | 跨径，米 |
| `simple_span` | `param.bearing_from` / `param.bearing_to` | `A0` / `P1` | 起止支座/墩台引用 |
| `cast_in_place_unit` | `param.span_expression` | `32+48+32` | 联跨表达式 |
| `continuous_unit` | `param.main_pier_ids` | `ST-P12|ST-P13` | 主墩结构物 ID 列表 |
| `continuous_unit` | `param.segment_count` | `17` | 节段数量 |
| 桩基构件 | `param.diameter_m` / `param.length_m` | `2.0` / `45` | 桩径/桩长 |

## 6. 校验和问题定位

导入器按以下顺序校验：

1. 文件可读、模板版本、工作表和表头。
2. 字段类型、必填、枚举、长度和数值范围。
3. 稳定 ID 唯一性与父子关系。
4. 工点类型、结构类型、幅别、构件类型和参数定义组合。
5. 桥梁排程所需参数的完整性与引用关系。
6. 相对当前确认版本的新增、修改、删除及下游引用影响。

每个问题返回：严重级别、问题代码、工作表、Excel 行号、字段代码、对象 ID、说明和修正建议。`error` 阻断草稿版本创建或确认；`warning` 必须在确认前显式知悉。

## 7. 幂等与差异规则

- 解析器统一修剪文本、规范枚举大小写、按定义规范数值精度和空值，再计算业务指纹。
- 文件名、工作表样式、列宽、行顺序变化不构成业务变更；`sort_order` 变化构成业务字段修改。
- 相同项目和相同业务指纹必须保存新的 `unchanged` 导入批次并引用已有版本，不得创建重复业务版本。
- 差异按稳定 ID 分类：ID 只在新快照存在为新增，只在当前确认版本存在为删除，两边存在但字段/参数不同为修改。
- 首次导入以空版本为基线，所有对象均为新增。

## 8. 不兼容边界

- 不解析旧桥梁结构导入文件、旧架梁工点导入文件或任意工作表智能识别格式。
- 不读取或迁移旧 JSON 中的项目结构和工点。
- 旧文件必须由用户按新模板整理后重新上传；系统不提供后台自动转换和双写。
