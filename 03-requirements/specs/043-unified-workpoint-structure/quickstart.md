# 快速验证：统一工点与结构物主数据

## 1. 验证前提

- 使用仓库现有 Python、Node 和依赖，不新增 ORM。
- 测试数据库使用临时目录；手工本地验证默认使用 `.local-data/project-master.db`。
- 不复制、导入或读取旧 `.local-data/*.json` 作为主数据来源。
- 准备一个新模板样例：1 座左右幅桥梁、1 段路基、1 座隧道。桥梁只有 1 个工点，左右幅分别有墩台和上部结构，另含 1 个共用结构。

## 2. 后端自动验证

从仓库根目录运行：

```powershell
python -m pytest -q backend
$env:RUN_PROJECT_MASTER_PERFORMANCE='1'
python -m pytest -q backend/tests/test_project_master_performance.py
```

必须覆盖：

- 空库建表、schema 版本、外键和唯一索引。
- 合法工作簿创建导入批次与完整草稿；非法工作簿只保存阻断批次和问题。
- 同内容幂等且保存新的 `unchanged` 批次、稳定 ID 差异、漏行删除、批次取消、乐观并发冲突。
- 确认版本不可修改，同项目仅一个当前确认版本。
- 服务/仓储重建后，批次、问题、草稿、确认版本、差异和来源均可恢复。
- 固定桥梁样例的任务归属、幅别、工区、构件、工程量和业务前后置关系与现行规则一致。
- 路基和隧道可查询但生成桥梁任务数为 0。
- 原旧接口回归测试通过，但新主数据路径不读取或双写旧存储。

## 3. 前端自动验证

```powershell
Set-Location frontend
npm.cmd test
npm.cmd run build
```

至少验证以下页面状态：无版本空态、上传校验中、阻断问题、差异预览、告警确认、确认成功、历史版本、分页工点列表、工点明细和 API 失败重试。

## 4. 单服务冒烟

```powershell
python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

另一个终端依次检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
Invoke-WebRequest http://127.0.0.1:8000/api/project-master/template -OutFile $env:TEMP\project-master-template.xlsx
```

然后使用统一页面完成：

1. 首次打开显示“尚未建立首个主数据版本”，不出现旧结构/旧工点迁移提示。
2. 下载模板，填入样例并上传。
3. 校验结果显示 3 个工点；桥梁左右幅均为该桥梁工点的子结构，不生成两个桥梁工点。
4. 预览首次导入的全量新增并确认。
5. 刷新页面并重启后端，确认当前版本与完整层级仍可读取。
6. 导出当前版本，重新上传；系统保存新的 `unchanged` 批次并通过 `existing_version_id` 指向已有版本，业务版本数不增加。
7. 从工作簿删除一个结构物再上传；差异明确显示待删除。调用批次取消后，批次状态为 `cancelled`、取消审计保留、未确认草稿业务行被清理、当前版本不变。
8. 使用错误父 ID、重复结构物 ID、桥梁非法 `none` 幅别各制造一条错误；页面精确显示工作表、行号和字段，且不能确认。
9. 随机抽查不少于 20 个工点及其结构物，逐个从确认版本追溯到导入批次、源工作表和行号，成功率必须达到 100%。

## 5. 版本与并发验收

1. 客户端 A、B 同时基于版本 V1 上传不同完整快照，均得到草稿。
2. A 确认 V2：V1 变为 `superseded`，V2 为唯一 `confirmed`。
3. B 用 `expected_current_version_id=V1` 确认时返回 `409 CURRENT_VERSION_CHANGED`；不得覆盖 V2。
4. B 重新基于 V2 导入后方可确认 V3。
5. 查询 V1/V2/V3，历史层级和来源均保持可读，任何已确认版本都没有原地修改接口。

## 6. 桥梁排程接入验收

1. 使用固定旧结构模型样例记录现有任务业务快照：任务业务键、工点、幅别、工区、结构物、构件、工程量、单位和业务前后置边集合。
2. 把同一业务数据整理到新模板并确认。
3. 通过 `ProjectMasterScheduleAdapter` 生成现有排程投影和任务。
4. 对比业务快照，以上字段和边集合 100% 一致；任务内部随机 ID 和无业务意义的序列化顺序不参与比较。
5. 验证路基、隧道不进入桥梁任务生成，诊断中明确标注“当前排程不支持”。
6. 确认包含桥梁结构变化的新版本，旧任务图、求解结果、方案比较和专项状态被标记为 `stale`，未变化引用仍可审计但不得冒充基于新版本。

## 7. 性能与恢复验收

- 生成 500 个工点、10,000 个结构物、50,000 个构件的合法模板，在目标开发机记录上传到完整校验/差异结果可见时间，必须不超过 30 秒。
- 工点列表分页查询不得加载全项目构件；单工点明细只加载该工点子树。
- 在创建草稿事务中注入异常，验证版本、对象、来源和差异全部回滚，当前确认版本不变，批次留下失败记录。
- 在确认事务中注入异常，验证旧确认版本与新草稿状态均保持事务前状态。
- 在取消 `ready` 批次事务中注入异常，验证批次状态与草稿业务行同时回滚，当前确认版本不变。
