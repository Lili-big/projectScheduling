# 实际研究与决策

本次只核对共享资源所需实现，没有外部调研或新增依赖。

| 问题 | 当前证据 | 采用方案与替代方案 |
| --- | --- | --- |
| 一组多工艺怎么保存 | ResourcePool已含compatible_process_ids；当前生成器禁止不同类别ID | 复用此字段；不增加另一份池能力列表 |
| 工艺如何精确识别 | 工艺库可存在同类不同工艺，Task仅保留工效方案ID | 在路面任务上下文增加实际process_id；不用工效ID字符串猜测工艺，也不把某类全部方法自动授权 |
| 实例怎么传递能力 | Resource没有能力字段，作用域解析已有source_pool_id | 实例增加可选compatible_process_ids，生成器按解析结果映射来源池；不为每种工艺重复展开实例 |
| 同一机组能否跨工艺互斥 | add_pavement_fleet_paths以资源ID建立Circuit及NoOverlap；区间仅含施工工期 | 保留算法，扩展候选集即可；不重写求解器，不按资源类型复制路径 |
| 旧数据如何读 | 现有类型代表三种专用组，样例中存在空工艺列表 | 旧专用空列表回退本类；新保存要求有效组有工艺；新增通用组无推断。具体兼容边界见契约 |
| 实际项目如何更新 | 只读API确认水稳组1套、转场1天，另两组0套 | 原组稳定ID上扩展碎石能力；禁止新增一个也为1套的碎石组冒充共享 |
| 无资源行为什么阻塞 | 生成器对所有启用行要求转场，包括quantity=0 | 只要求实际可用实例的转场已确认，数量0无需补造转场参数 |

研究结论已覆盖plan的D1—D10，无待澄清问题。桥梁逻辑、064路床状态及养生页面改造均独立。
