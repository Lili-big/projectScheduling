# 模拟求解-MVP页面需求文档

版本：v1.2

日期：2026-07-03

适用范围：桥梁施工自动排程系统“模拟求解-MVP”页面

面向对象：产品经理、前端研发、后端研发、算法研发、测试、计划工程师

## 1. 页面定位

### 1.1 页面目标

“模拟求解-MVP”页面是面向计划工程师的轻量求解入口。用户不需要进入完整模拟结果页，只需选择工点、确认计划开始日期，即可完成两类核心测算：

1. 固定资源条件下，推算最短工期。
2. 固定工期条件下，推算最少资源。

页面重点回答三个业务问题：


| 业务问题                         | 页面回答                                       |
| -------------------------------- | ---------------------------------------------- |
| 当前资源能不能形成可执行计划     | 展示计划状态、总工期、工作项数量和节点达成情况 |
| 当前计划具体怎么排               | 展示里程碑结果、计划表和资源泳道               |
| 如果按目标工期倒推，需要多少资源 | 展示最少资源测算结果、候选方案或不可行诊断     |

本页面不是完整精排分析页。MVP 阶段只保留用户决策所需的主结果，不展示精排诊断、甘特图、资源路径图、罚分列和复杂方案对比。

### 1.2 使用角色


| 角色         | 主要诉求                                                                   |
| ------------ | -------------------------------------------------------------------------- |
| 计划工程师   | 快速判断单个工点在当前资源下的预计工期、关键节点是否满足、资源是否连续占用 |
| 项目管理人员 | 了解当前工点计划是否可行、是否存在节点风险、是否需要追加资源               |
| 产品和测试   | 按页面可见字段、交互状态和验收口径确认 MVP 是否闭环                        |
| 研发和算法   | 按统一的数据输入输出和页面状态完成开发与联调                               |

### 1.3 MVP 范围

本页面纳入 MVP 的能力：

- 选择一个工点。
- 设置计划开始日期。
- 发起“固定资源条件下，推算最短工期”。
- 发起“固定工期条件下，推算最少资源”。
- 展示四个摘要指标：计划状态、总工期、工作项、资源 / 里程碑。
- 展示里程碑结果。
- 展示计划表，并支持按时间、按墩台、按工艺排序。
- 展示资源泳道，用于查看各资源在计划时间轴上的占用连续性。
- 展示必要的约束诊断和资源建议诊断。

## 2. 页面布局

### 2.1 页面整体结构

页面从上到下分为六个区域：


| 区域       | 页面内容                                | 说明                                          |
| ---------- | --------------------------------------- | --------------------------------------------- |
| 顶部操作区 | 页面标题、页面副标题、两个求解按钮      | 让用户明确当前是 MVP 求解入口，并快速发起测算 |
| 参数区     | 工点选择、计划开始                      | 用户发起求解前必须确认的两个输入              |
| 指标摘要区 | 计划状态、总工期、工作项、资源 / 里程碑 | 求解后第一眼判断结果是否可用                  |
| 约束诊断区 | 生成、求解、里程碑和资源相关提示        | 帮助用户理解结果为什么可行、迟延或不可行      |
| 结果表格区 | 里程碑结果、计划表                      | 查看节点是否满足、任务如何排布                |
| 资源泳道区 | 资源名称、资源类型、时间轴占用条        | 查看资源是否连续投入、是否存在明显空档        |

页面背景为浅灰色，主要内容以白色面板承载。面板之间保持清晰分隔，避免用户把摘要、表格和资源泳道误认为同一类信息。

### 2.2 顶部操作区

顶部操作区左侧展示：

- 标题：模拟求解-MVP
- 副标题：工点和计划开始时间

顶部操作区右侧展示两个按钮：


| 按钮                         | 视觉优先级 | 业务含义                                   |
| ---------------------------- | ---------- | ------------------------------------------ |
| 固定资源条件下，推算最短工期 | 主按钮     | 使用当前资源数量，测算该工点最短可完成时间 |
| 固定工期条件下，推算最少资源 | 次按钮     | 在目标工期约束下，倒推需要投入的资源数量   |

主按钮应使用更强的强调色。两个按钮均应支持加载中状态，加载中时不可重复点击。

### 2.3 参数区

参数区位于标题下方，包含两个输入项：


| 控件     | 类型     | 展示示例     | 交互要求                                       |
| -------- | -------- | ------------ | ---------------------------------------------- |
| 工点选择 | 下拉选择 | 渠溪河特大桥 | 默认选中当前项目可求解的第一个工点；用户可切换 |
| 计划开始 | 日期选择 | 2026/07/03   | 默认使用当前计划开始日期；用户可手动调整       |

工点选择和计划开始是本页面的核心输入。用户修改任一输入后，页面下一次求解必须使用新的输入；旧结果不得继续被解释为当前结果。

### 2.4 指标摘要区

指标摘要区展示四张指标卡：


| 指标卡        | 展示示例 | 说明                                          |
| ------------- | -------- | --------------------------------------------- |
| 计划状态      | 可行     | 当前结果是否形成可用计划                      |
| 总工期        | 1013 天  | 从计划开始到计划完成的总天数                  |
| 工作项        | 351 项   | 本次求解纳入排程的任务数量                    |
| 资源 / 里程碑 | 31 / 1   | 当前结果使用的资源数量 / 参与检查的里程碑数量 |

计划状态为“可行”时，指标卡可使用成功色突出。状态异常时，应使用提醒或错误色，避免用户误读为可执行计划。

### 2.5 约束诊断区

约束诊断区标题为“约束诊断”，副标题为“生成层、求解层和里程碑检查的摘要”。

诊断区用于承接用户对结果的追问：


| 用户追问             | 诊断区应回答                                           |
| -------------------- | ------------------------------------------------------ |
| 为什么当前计划可行   | 说明任务生成、资源约束和里程碑检查均通过               |
| 为什么节点迟延       | 说明实际完成日期晚于目标日期，必要时提示资源或逻辑原因 |
| 为什么最少资源不可行 | 说明资源上限、关键路径或求解确认状态                   |
| 为什么还没有诊断     | 尚未求解时展示等待状态                                 |

诊断信息应使用简短业务语言，诊断内容由后端统一返回，前端展示即可。

### 2.6 结果表格区

结果表格区至少包含两个面板：


| 面板       | 标题       | 副标题                                      | 主要内容                                                               |
| ---------- | ---------- | ------------------------------------------- | ---------------------------------------------------------------------- |
| 里程碑结果 | 里程碑结果 | 节点完成情况和迟延天数                      | 节点、约束、目标、实际、迟延、状态                                     |
| 计划表     | 计划表     | 计划起止日期，例如 2026-07-03 至 2029-04-10 | 工作项、幅别、构件、计划表达式、工期、计划开始、计划完成、资源、前置数 |

计划表右上角提供三个排序按钮：按时间、按墩台、按工艺。排序只改变当前表格展示顺序，不重新求解。

### 2.7 资源泳道区

资源泳道区标题为“资源泳道”，副标题为“横轴按计划时间展示每条资源的占用连续性”。

资源泳道每一行展示一条资源：

- 左侧展示资源名称。
- 资源名称右侧展示资源类型标签。
- 右侧时间轴展示该资源被任务占用的时间段。
- 深色条表示资源占用区间。
- 空白区域表示该资源在对应时间段未被安排任务。

资源泳道用于辅助用户查看资源投入节奏，不承担精排诊断、资源路径诊断或跳墩分析职责。

## 3. 数据口径

### 3.1 用户输入数据


| 数据项       | 来源         | 是否必填 | 页面规则                           |
| ------------ | ------------ | -------- | ---------------------------------- |
| 工点         | 工点下拉     | 是       | 决定本次 MVP 求解范围              |
| 计划开始日期 | 日期选择器   | 是       | 决定本次计划的起算日期             |
| 求解方式     | 用户点击按钮 | 是       | 固定资源最短工期或固定工期最少资源 |

当工点为空或场景尚未加载完成时，两个求解按钮应禁用。

### 3.2 上游配置数据

本页面不直接维护项目基础配置，但依赖以下上游数据：


| 上游数据           | 对本页面的影响                           |
| ------------------ | ---------------------------------------- |
| 项目结构和工点清单 | 决定工点下拉、任务来源、构件和墩台信息   |
| 工艺工效库         | 决定任务名称、构件工艺、计划表达式和工期 |
| 工艺逻辑           | 决定任务前置关系和计划顺序               |
| 资源配置           | 决定可用资源数量、资源类型和资源泳道     |
| 里程碑配置         | 决定目标日期、节点状态和固定工期倒推依据 |

若上游配置发生变化，本页面已有求解结果应视为过期。用户再次查看时，应重新求解或清空旧结果。

### 3.3 摘要指标数据


| 字段          | 展示格式     | 取值说明                         |
| ------------- | ------------ | -------------------------------- |
| 计划状态      | 中文状态标签 | 可行、不可行、模型无效、未知等   |
| 总工期        | X 天         | 以自然日天数展示                 |
| 工作项        | X 项         | 本次求解纳入计划表的任务数量     |
| 资源 / 里程碑 | X / Y        | X 为使用资源数，Y 为检查里程碑数 |

无结果时，摘要指标展示“-”或等待状态，不展示上一轮不匹配结果。

### 3.4 里程碑结果数据


| 字段 | 展示规则                                   |
| ---- | ------------------------------------------ |
| 节点 | 里程碑名称，例如“下部及现浇结构施工完成” |
| 约束 | 强制目标或提醒目标                         |
| 目标 | 目标日期，格式为 YYYY-MM-DD                |
| 实际 | 实际完成日期；无法评估时展示“-”          |
| 迟延 | 迟延天数，格式为 X 天；未迟延展示 0 天     |
| 状态 | 已满足、已迟延、未评估                     |

MVP 页面不展示“罚分”字段。罚分属于完整模拟结果或算法诊断信息，不进入当前页面主表格。

### 3.5 计划表数据


| 字段       | 展示规则                                         |
| ---------- | ------------------------------------------------ |
| 工作项     | 任务名称，需能定位到具体墩台、构件和工艺         |
| 幅别       | 左幅、右幅或“-”                                |
| 构件       | 构件中文标签，例如桩基、承台、墩柱、盖梁         |
| 计划表达式 | 用业务可读方式解释工期来源，例如“3天/根 = 3天” |
| 工期       | X 天                                             |
| 计划开始   | YYYY-MM-DD                                       |
| 计划完成   | YYYY-MM-DD                                       |
| 资源       | 资源名称；未分配时展示“-”                      |
| 前置数     | 前置任务数量                                     |

计划表是本页面最主要的明细结果。表头应固定清晰，滚动时不应影响用户识别列含义。

### 3.6 资源泳道数据


| 数据项   | 展示规则                                   |
| -------- | ------------------------------------------ |
| 资源名称 | 例如“墩柱模板1”“旋挖钻1”               |
| 资源类型 | 以标签展示，例如墩柱模板、旋挖钻           |
| 占用区间 | 按任务开始和完成日期绘制为时间轴上的深色条 |
| 空闲区间 | 保持空白，用于直观看到资源空档             |

资源泳道应与当前计划表使用同一份求解结果。切换方案或重新求解后，资源泳道必须同步刷新。

### 3.7 约束诊断数据

约束诊断用于解释为什么结果可行、不可行或需要追加资源。诊断内容应以业务用户能理解的方式展示，避免直接暴露求解器内部术语。

诊断信息至少包含：

- 任务生成是否成功。
- 求解是否成功。
- 里程碑是否满足。
- 当前资源是否不足。
- 若固定工期最少资源不可行，应说明是资源上限不足、关键路径不可压缩，还是求解暂未确认。

## 4. 页面交互

### 4.1 初始进入

用户进入页面后，系统应完成以下动作：

1. 加载当前项目场景。
2. 初始化工点下拉。
3. 初始化计划开始日期。
4. 清空与当前输入不匹配的历史结果。
5. 展示可点击的求解按钮。

若场景加载中，页面应展示加载状态，求解按钮不可点击。

### 4.2 切换工点

用户切换工点后：

1. 工点下拉立即展示新选项。
2. 指标摘要、里程碑结果、计划表和资源泳道应清空或标记为等待重新求解。
3. 用户点击任一求解按钮时，应基于新工点计算。

切换工点不应自动发起求解，避免用户误以为页面已经使用新工点完成测算。

### 4.3 修改计划开始日期

用户修改计划开始日期后：

1. 日期输入框展示新日期。
2. 旧求解结果失效。
3. 下一次求解的计划表起止日期应随新日期变化。

日期为空或格式非法时，求解按钮应禁用或给出明确提示。

### 4.4 固定资源条件下，推算最短工期

用户点击主按钮后：

1. 按钮进入加载状态。
2. 页面防止重复点击。
3. 系统基于当前工点、计划开始日期和当前资源配置进行测算。
4. 求解成功后刷新摘要指标、里程碑结果、计划表、资源泳道和诊断。
5. 求解失败时展示错误提示，不保留旧结果冒充当前结果。

该入口的产品含义是：在当前资源不增加的前提下，看这个工点最早能排到什么时候。

### 4.5 固定工期条件下，推算最少资源

用户点击次按钮后：

1. 系统优先使用当前工点的强制里程碑作为目标工期。
2. 若没有可用强制里程碑，但已有同一工点同一日期的最短工期结果，可用上一轮结果作为测算参考。
3. 若没有目标依据，页面提示用户先运行固定资源最短工期，或先配置强制里程碑。
4. 求解成功后展示最少资源结果、候选方案或资源不足诊断。

该入口的产品含义是：在目标工期已确定的前提下，估算至少需要多少资源投入。

### 4.6 查看里程碑结果

里程碑结果用于判断计划是否满足节点要求。

交互要求：

- 状态为“已满足”时使用成功标签。
- 状态为“已迟延”时使用提醒或错误标签。
- 实际日期早于或等于目标日期时，迟延展示 0 天。
- 实际日期晚于目标日期时，迟延展示实际迟延天数。
- MVP 表格不展示罚分列。

### 4.7 查看计划表

计划表用于查看任务级排程明细。

交互要求：

- 默认按时间排序。
- 用户点击“按时间”“按墩台”“按工艺”后，按钮高亮当前排序。
- 排序切换只影响表格展示，不重新求解。
- 表格内容较多时支持滚动查看。
- 计划表副标题展示当前计划起止日期。

排序规则：


| 排序   | 聚合方式                                                   | 排序优先级                                                                           | 适用场景                     |
| ------ | ---------------------------------------------------------- | ------------------------------------------------------------------------------------ | ---------------------------- |
| 按时间 | 不做业务分组，以计划时间为主线连续展示任务                 | 计划开始日期、计划完成日期、墩台顺序、构件顺序、任务名称                             | 快速检查总体计划推进节奏     |
| 按墩台 | 将同一桥梁 / 幅别 / 墩台下的任务排在相邻行，形成墩台聚合   | 桥梁或工点顺序、幅别顺序、墩台编号或结构物顺序、构件施工顺序、计划开始日期、任务名称 | 检查同一墩台下各构件施工顺序 |
| 按工艺 | 将同一构件类型、同一施工工艺的任务排在相邻行，形成工艺聚合 | 构件施工顺序、施工工艺名称、计划开始日期、墩台顺序、任务名称                         | 检查同类工艺的连续施工情况   |

按墩台排序的产品规则：

- “墩台”聚合以计划表中的结构物归属为准。同一墩台或同一台身下的桩基、承台、墩柱、盖梁等任务应连续展示。
- 若存在左右幅，先按幅别形成稳定顺序，再在同一幅别内按墩台编号从小到大排列。
- 同一墩台内，任务按构件施工顺序排列。默认顺序为桩基、承台 / 扩大基础、系梁、墩柱 / 台身、盖梁、上部现浇相关任务；具体构件名称以系统构件标签为准。
- 同一墩台、同一构件下若有多条任务，再按计划开始日期由早到晚排序。
- 如果墩台编号或结构物顺序无法识别，应排在可识别结构物之后，并按任务名称保持稳定顺序。

按工艺排序的产品规则：

- “工艺”聚合以“构件类型 + 施工工艺”共同确定。例如桩基-旋挖钻、桩基-冲击钻、承台-承台模板、墩柱-墩柱模板应分别形成相邻任务段。
- 首先按构件施工顺序排列，使同一类构件任务集中查看。
- 同一构件内，再按施工工艺名称聚合；工艺名称为空或未配置时，应作为该构件下的独立聚合段展示。
- 同一构件、同一工艺下，任务按计划开始日期由早到晚排列。
- 如果计划开始日期相同，再按墩台或结构物顺序排列；仍相同时按任务名称稳定排序。

聚合展示说明：

- 当前 MVP 计划表通过“排序后相邻展示”表达聚合，不要求新增分组标题、合并单元格或折叠分组。
- 三种排序只改变计划表的行顺序，不改变任务数据、不触发重新求解，也不影响里程碑结果和资源泳道数据。

### 4.8 查看前置关系

计划表“前置数”用于提示该任务依赖多少前置任务。

交互要求：

- 前置数为 0 时，展示普通数字 0。
- 前置数大于 0 时，应提供可悬停或可聚焦的明细入口。
- 明细中展示前置任务名称、幅别、结构物和逻辑关系。
- 鼠标移出或失焦后，明细自动关闭。

### 4.9 查看资源泳道

资源泳道用于查看每条资源的占用情况。

交互要求：

- 每条资源单独成行。
- 同类资源通过资源类型标签识别。
- 时间轴上的任务条应能体现开始、结束和空档。
- 鼠标悬停任务条时，可展示任务名称、计划起止日期和资源信息。
- 无资源分配时展示空态，不展示空白大面板。

资源泳道只回答“资源什么时候被占用”，不回答“资源路径是否合理”。资源路径分析不在 MVP 中实现。

## 5. 页面状态和提示


| 场景           | 页面状态                 | 提示或处理                   |
| -------------- | ------------------------ | ---------------------------- |
| 场景加载中     | 输入和按钮不可用         | 展示加载状态                 |
| 无工点         | 工点下拉为空，按钮禁用   | 提示暂无可求解工点           |
| 尚未求解       | 摘要和表格为空态         | 提示等待生成或求解           |
| 求解中         | 按钮加载中，禁止重复点击 | 展示求解中提示               |
| 求解成功       | 展示完整结果             | 刷新摘要、表格和泳道         |
| 求解失败       | 保留输入，清空不匹配结果 | 展示错误信息                 |
| 输入变化后     | 旧结果失效               | 提示或清空结果，等待重新求解 |
| 资源不足       | 展示诊断                 | 说明不足原因和建议资源方向   |
| 目标工期不可达 | 展示不可行诊断           | 不展示未经验证的候选方案     |

错误提示应尽量使用业务语言，例如“当前资源上限仍无法满足目标工期”，避免只展示技术错误。

## 6. 前后端职责

### 6.1 前端职责

前端负责：

- 渲染页面布局、按钮、输入框、指标卡、表格和资源泳道。
- 管理工点和计划开始日期输入。
- 控制按钮加载中、禁用和错误状态。
- 在输入变化后清空或标记旧结果失效。
- 根据结果展示摘要、里程碑、计划表、资源泳道和诊断。
- 在计划表内完成三种排序切换。
- 在前置数和资源任务条上提供轻量明细查看。

### 6.2 后端和算法职责

后端和算法负责：

- 接收当前工点、计划开始日期及上游配置形成的求解输入。
- 生成任务、前置关系和资源约束。
- 完成固定资源最短工期测算。
- 完成固定工期最少资源测算。
- 返回统一的计划状态、总工期、任务明细、资源占用、里程碑结果和诊断信息。
- 当结果不可行时，返回业务可解释的原因。
- 当存在资源建议时，保证候选方案经过可行性验证后再返回页面。

文档不要求前端直接暴露接口路径或求解器内部字段；研发联调时以统一数据对象和页面展示结果为准。

## 7. 与其他页面的联动


| 上游页面            | 影响内容                                   |
| ------------------- | ------------------------------------------ |
| 项目参数 / 结构参数 | 改变工点、墩台、构件和任务来源             |
| 工艺工效库          | 改变计划表达式、任务工期和默认资源         |
| 工艺逻辑            | 改变前置关系和任务先后顺序                 |
| 资源配置            | 改变资源数量、资源类型、资源上限和资源泳道 |
| 里程碑              | 改变目标日期、节点状态和最少资源测算依据   |

当上述页面的关键配置发生变化后，“模拟求解-MVP”页面已有结果应失效。用户需要重新点击求解按钮获取新结果。

## 8. 验收标准

### 8.1 页面基础展示

1. 页面标题展示为“模拟求解-MVP”。
2. 页面副标题展示为“工点和计划开始时间”。
3. 顶部展示两个按钮：“固定资源条件下，推算最短工期”“固定工期条件下，推算最少资源”。
4. 页面展示工点选择和计划开始两个输入项。
5. 页面不展示甘特图、资源路径图、精排诊断和罚分列。

### 8.2 求解输入

1. 工点下拉应展示当前项目可求解工点。
2. 工点为空时，两个求解按钮不可点击。
3. 计划开始日期可修改。
4. 修改工点或计划开始日期后，旧结果不得继续作为当前结果展示。

### 8.3 固定资源最短工期

1. 点击主按钮后，按钮进入加载状态。
2. 加载期间重复点击无效。
3. 求解成功后，摘要指标展示计划状态、总工期、工作项和资源 / 里程碑。
4. 求解成功后，里程碑结果、计划表和资源泳道均刷新。
5. 求解失败时，页面展示错误提示，不展示不匹配的旧结果。

### 8.4 固定工期最少资源

1. 有强制里程碑时，用户可直接点击次按钮求解。
2. 没有强制里程碑且没有可参考结果时，页面提示先运行固定资源最短工期或配置强制里程碑。
3. 返回候选方案时，页面应使用“最少资源候选”口径，不使用“精排”作为主文案。
4. 目标工期不可达时，页面展示不可行原因，不展示未经验证的候选方案。

### 8.5 里程碑结果

1. 表头为：节点、约束、目标、实际、迟延、状态。
2. 不出现“罚分”列。
3. 已满足节点展示成功状态。
4. 已迟延节点展示迟延天数。
5. 未评估节点应展示清晰空态或未评估状态。

### 8.6 计划表

1. 表头为：工作项、幅别、构件、计划表达式、工期、计划开始、计划完成、资源、前置数。
2. 表格默认按时间排序。
3. 右上角展示“按时间”“按墩台”“按工艺”三个排序按钮。
4. 点击排序按钮后，仅改变表格顺序，不重新发起求解。
5. 点击“按墩台”后，同一桥梁 / 幅别 / 墩台下的任务应在相邻行展示；组内按构件施工顺序和计划开始日期排序。
6. 点击“按工艺”后，同一构件类型、同一施工工艺的任务应在相邻行展示；组内按计划开始日期和墩台顺序排序。
7. 当前 MVP 不要求计划表出现分组标题、合并单元格或折叠分组。
8. 前置数大于 0 时，可查看前置任务明细。

### 8.7 资源泳道

1. 资源泳道标题展示为“资源泳道”。
2. 每行展示资源名称和资源类型标签。
3. 时间轴以深色条展示资源占用区间。
4. 无资源分配时展示空态。
5. 资源泳道不展示资源路径诊断信息。

## 9. 后续扩展建议

MVP 验收通过后，可按以下顺序扩展：

1. 增加计划表筛选能力，例如按构件、资源、日期范围筛选。
2. 增加资源泳道按资源类型分组和折叠。
3. 增加结果导出能力。
4. 增加当前资源方案与最少资源候选方案的轻量对比。
5. 若业务确认需要，再将精排诊断、甘特图、资源路径图纳入完整模拟结果页，而不是混入 MVP 页面。
