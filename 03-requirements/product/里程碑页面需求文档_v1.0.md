# 里程碑页面需求文档

版本：v1.0

日期：2026-06-16

适用范围：桥梁施工自动排程系统工程化版本里程碑页面

面向对象：产品、前端研发、后端研发、测试、计划工程师

## 1. 功能模块核心定位

### 1.1 模块定位

里程碑页面用于维护当前项目或当前排程方案的关键工期控制节点。系统将里程碑配置纳入任务图生成和求解过程，用于判断固定资源方案是否满足控制工期，并为资源增量建议、固定工期最少资源、资源成本优化和方案对比提供目标依据。

本期页面聚焦“按桥梁/工点维护里程碑完成节点”。页面入口为功能导航中的“里程碑”，页面标题为“关键里程碑节点约束”，副标题为“按桥梁/工点维护里程碑完成节点，用于固定工期和资源建议测算”。

### 1.2 当前页面效果和业务场景

用户进入里程碑页面后，系统以表格展示当前项目或当前方案下的桥梁 / 工点完成节点。页面按桥梁分组，每个分组展示桥梁名称和工点类型标签，并在分组下展示对应里程碑的节点名称、作用范围、事件类型和目标日期。

典型业务场景包括：

- 技术负责人根据合同节点或项目控制目标，录入每座桥梁 / 工点的下部及现浇结构完成目标日期。
- 技术负责人调整目标日期后，重新求解固定资源条件下的最短工期，判断当前资源组织是否满足强制节点。
- 项目团队基于同一目标日期执行固定工期最少资源或资源成本优化，获取资源增量或低成本资源配置建议。
- 用户保存多个求解方案后，通过方案对比查看总工期、硬节点偏差和软节点罚分对推荐方案的影响。

### 1.3 模块边界

本期覆盖：

- 查看桥梁 / 工点级里程碑。
- 编辑目标日期。
- 只读展示节点名称。
- 展示范围和事件类型。
- 桥梁结构变化后的默认里程碑同步。
- 里程碑配置参与任务图生成、求解、资源建议和方案对比。

本期不覆盖：

- 新增任意层级里程碑。
- 删除里程碑。
- 编辑约束模式。
- 编辑作用范围。
- 编辑罚分权重。
- 编辑合同节点、强控节点和内部节点的层级分类。

## 2. 数据定义

### 2.1 主数据对象

页面主数据来源为 `ScenarioInput.milestones`，每条里程碑对应 `MilestoneConstraint`。实际工程版本中，系统应支持从里程碑模板初始化到项目级或方案级配置，用户后续修改只影响当前项目或当前方案，不直接修改系统默认模板。

| 数据对象 | 说明 | 页面用途 |
| --- | --- | --- |
| `ScenarioInput` | 项目排程场景输入，聚合项目结构、工艺工效、逻辑规则、资源、里程碑和求解配置 | 里程碑页面的输入上下文 |
| `ProjectModel` | 项目结构主数据，包含项目、桥梁、工区、下部结构和上部结构 | 提供桥梁 / 工点清单和范围标签来源 |
| `ProjectBridge` | 桥梁或工点对象，包含桥梁名称、排序和工点类型 | 页面分组和默认里程碑同步依据 |
| `MilestoneConstraint` | 里程碑约束配置 | 页面主要查看和编辑对象 |
| `MilestoneResult` | 求解后的里程碑达成结果 | 结果页展示目标、实际、迟延、罚分和状态 |

### 2.2 里程碑字段

| 字段 | 类型 | 必填 | 页面状态 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | string | 是 | 内部使用 | 稳定 ID，建议按桥梁生成 |
| `name` | string | 是 | 只读展示 | 节点名称，默认“下部及现浇结构施工完成” |
| `level` | enum | 是 | 不展示 | 本期桥梁完成节点默认 `control` |
| `mode` | enum | 是 | 不展示 | 本期桥梁完成节点默认 `hard` |
| `scope_type` | enum | 是 | 只读派生 | 本期默认 `bridge` |
| `scope_id` | string | 是 | 只读派生 | 关联桥梁 / 工点 ID |
| `target_event` | enum | 是 | 只读展示 | `finish` 展示“完成”，`start` 展示“开始” |
| `target_date` | date | 是 | 可编辑 | 目标日期 |
| `penalty_per_day` | number | 是 | 不展示 | 硬约束默认为 0，软约束用于罚分 |
| `related_structure_ids` | string[] | 否 | 不展示 | 扩展关联结构物 |

### 2.3 枚举、状态和标签

| 类别 | 值 | 展示或含义 |
| --- | --- | --- |
| 里程碑层级 | `contract` | 合同节点 |
| 里程碑层级 | `control` | 强控节点 |
| 里程碑层级 | `internal` | 内部节点 |
| 约束模式 | `hard` | 强制目标 |
| 约束模式 | `soft` | 提醒目标 |
| 作用范围 | `project` | 项目范围 |
| 作用范围 | `bridge` | 桥梁 / 工点范围 |
| 作用范围 | `work_section` | 工区范围 |
| 作用范围 | `structure` | 墩台或结构物范围 |
| 作用范围 | `component` | 构件类型或单构件范围 |
| 目标事件 | `start` | 开始 |
| 目标事件 | `finish` | 完成 |
| 求解状态 | `met` | 已满足 |
| 求解状态 | `late` | 已迟延 |
| 求解状态 | `not_evaluated` | 未评估 |

里程碑范围标签按当前项目结构派生。本期桥梁级范围展示为“桥梁名称 · 全部下部结构及上部现浇结构”。底层模型保留项目、工区、结构物、构件类型、单构件等范围扩展能力，但页面一期不开放配置。

## 3. 默认数据初始化

### 3.1 初始化原则

系统应在项目首次进入排程配置或创建排程方案时，将里程碑模板初始化为项目级或方案级配置。初始化后的里程碑属于当前项目或当前方案，用户编辑后应持久化，不影响系统默认模板和其他项目。

如果项目已有保存过的里程碑配置，应优先加载项目级或方案级配置；如果没有已保存配置，则使用系统模板初始化。

### 3.2 当前默认数据清单

每个桥梁 / 工点默认生成 1 条完成类强制里程碑。

| 默认项 | 规则 |
| --- | --- |
| 名称 | 下部及现浇结构施工完成 |
| 层级 | `control` |
| 模式 | `hard` |
| 范围 | 当前桥梁 / 工点 |
| 事件 | `finish` |
| 默认目标日期 | 项目开工年份 + 2 年的 12 月 31 日 |
| 同步规则 | 导入或更新桥梁结构后，应按桥梁清单补齐一桥一节点；已有目标日期优先保留 |

### 3.3 数据归属

里程碑配置分为三层：

- 系统模板：由平台维护，用于新项目或新方案初始化。
- 项目级配置：由项目用户维护，作为项目排程配置默认值。
- 方案级配置：当系统支持多排程方案时，可在项目级配置基础上复制形成方案独立里程碑配置。

页面编辑应作用于当前项目或当前方案，不应直接修改系统模板。

## 4. 页面功能交互

### 4.1 进入页面

用户点击功能导航中的“里程碑”后，系统打开里程碑页面。页面标题为“关键里程碑节点约束”，副标题为“按桥梁/工点维护里程碑完成节点，用于固定工期和资源建议测算”。

页面加载时，前端应读取当前项目或当前方案的里程碑配置，并与桥梁 / 工点清单同步。桥梁级里程碑应按桥梁 `order` 升序展示，`order` 相同时按桥梁名称兜底排序。

### 4.2 查看里程碑

页面以表格展示里程碑，表头为：

- 节点名称。
- 范围。
- 事件。
- 目标日期。

表格按桥梁 / 工点分组展示。分组行展示桥梁名称和工点类型标签；里程碑明细行展示对应节点名称、范围、事件和目标日期。

当没有桥梁级里程碑时，页面展示空态“暂无桥梁/工点里程碑”。实际工程版本应优先尝试初始化或同步默认里程碑；初始化失败时应提示用户，不能静默进入无约束状态。

### 4.3 编辑里程碑

用户可直接编辑目标日期。节点名称只读展示，不提供页面编辑入口。

范围由系统根据 `scope_type`、`scope_id` 和项目结构计算，只读展示。事件以标签展示“开始”或“完成”，本期默认展示“完成”。

本期不提供新增、删除、范围切换、约束模式切换和罚分配置入口。

### 4.4 保存和失效

工程化版本应支持保存项目级或方案级里程碑配置。用户修改目标日期后，系统应将当前配置标记为已变更，并在保存后持久化到当前项目或当前方案。

里程碑变更属于影响求解的配置变更。用户修改目标日期后，旧任务图、旧求解结果和旧方案对比结果应失效，需重新生成或重新求解。

## 5. 前后端接口

### 5.1 查询能力

后端应提供查询当前项目或当前方案里程碑配置的能力，并返回标准化的 `MilestoneConstraint[]` 或包含 `milestones` 的 `ScenarioInput`。如果当前项目尚未初始化里程碑配置，应按系统模板生成默认配置后返回。

### 5.2 保存能力

后端应提供保存当前项目或当前方案里程碑配置的能力。保存时应校验里程碑字段合法性、作用范围是否存在、当前用户是否有配置权限，并返回保存后的标准化数据。

### 5.3 初始化和重置能力

后端应支持以下初始化和同步能力：

- 新项目或新方案按系统模板初始化一桥一节点。
- 桥梁结构导入或更新后，按最新桥梁清单补齐默认里程碑。
- 已存在的桥梁级里程碑优先保留用户编辑后的目标日期。
- 当用户执行重置时，可按系统模板重新生成当前项目或当前方案里程碑配置。

接口不要求固定为 demo 路径，但必须支持返回当前项目场景、保存项目或方案级里程碑配置，并在结构参数导入后同步一桥一节点。

## 6. 联动规则

### 6.1 上游输入

里程碑页面依赖以下上游输入：

- 当前项目或方案的桥梁 / 工点清单。
- 项目开工日期。
- 已保存的里程碑配置。
- 系统里程碑模板。

桥梁 / 工点清单变化时，系统应重新同步桥梁级里程碑，确保每个桥梁 / 工点有且只有一条默认完成节点。

### 6.2 下游影响

里程碑配置影响以下下游模块：

- 任务图生成：`ScenarioInput.milestones` 应传入 `ScheduleInput`。
- 固定资源最短工期求解：用于输出强制节点偏差诊断和软节点罚分。
- 固定工期最少资源求解：匹配到的强制里程碑可作为目标工期依据。
- 资源成本优化：匹配到的强制里程碑可作为目标工期约束，软节点迟延可形成罚分。
- 模拟结果页面：展示里程碑结果、迟延天数、罚分和状态。
- 资源增量建议：固定资源方案无法满足强制里程碑时，系统可测算资源增量建议。
- 方案对比：软节点罚分、硬节点偏差和总工期共同影响方案摘要和推荐口径。

### 6.3 匹配和计算规则

桥梁级里程碑匹配范围为该桥梁下部结构任务及上部现浇类任务，包括现浇连续梁、现浇箱梁；不包含简支梁架梁等未纳入该控制目标的任务。

完成类里程碑取范围内任务最大完成时间。开始类里程碑取范围内任务最早开始时间。

`hard` 里程碑用于强制目标或偏差诊断：固定资源最短工期下输出迟延诊断并触发资源增量建议；固定工期最少资源和资源成本优化下作为目标工期依据。

`soft` 里程碑允许超期，迟延天数按 `penalty_per_day` 进入目标函数罚分。

## 7. 校验与异常处理

目标日期必须为合法日期。范围未匹配到任务时，求解结果应标记为未评估或给出诊断；未匹配的强制里程碑不能作为固定工期目标。

保存或求解前，系统应校验：

- `id` 不能为空且在当前配置中唯一。
- `name` 不能为空。
- `scope_type` 必须为支持的范围类型。
- 本期桥梁级里程碑的 `scope_id` 必须能匹配到当前项目桥梁 / 工点。
- `target_event` 必须为 `start` 或 `finish`。
- `target_date` 必须为合法日期。
- `penalty_per_day` 必须为非负数。

如果强制里程碑迟延，结果页应展示严重诊断，并在“里程碑结果”表中展示节点、约束、目标、实际、迟延、罚分和状态。状态包括“已满足”“已迟延”“未评估”。

## 8. 验收标准

1. 进入里程碑页面后，按桥梁顺序展示一桥一条里程碑，并显示桥梁分组、工点类型、节点名称、范围、事件、目标日期。
2. 节点名称以只读文本展示，不出现可输入控件，用户不能在页面直接修改节点名称。
3. 修改目标日期后，旧任务图、旧求解结果和旧方案对比失效，重新求解后按新日期计算迟延。
4. 导入或更新桥梁结构后，系统为新增桥梁补齐默认完成里程碑，并保留已有桥梁目标日期。
5. 固定资源求解不满足强制里程碑时，结果页展示迟延天数、严重诊断和资源建议相关信息。
6. 固定工期最少资源或资源成本优化时，系统可使用匹配到的强制里程碑作为目标工期依据。
7. 软里程碑迟延时，结果页展示罚分，且方案对比可纳入软里程碑罚分。
8. 无里程碑数据时展示明确空态或初始化失败提示。

## 9. 后续扩展建议

后续可开放新增、删除、批量编辑、约束模式切换、范围选择器、软节点罚分配置、合同节点与内部节点区分、里程碑模板库和多方案版本对比。
