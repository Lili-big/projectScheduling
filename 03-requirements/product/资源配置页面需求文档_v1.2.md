# 资源配置页面需求文档

**版本**：v1.4
**日期**：2026-07-18
**关联规格**：`03-requirements/specs/048-workpoint-first-resource-allocation/`
**演进来源**：047 工点级资源配置规格

## 1. 目标与范围

资源配置以“工点”为独享资源的一级维护对象，同时提供独立的“范围共享资源池”配置区。用户应能直接回答两个问题：

1. 每个工点当前拥有哪些资源、当前投入多少、最多可增至多少、是否启用。
2. 哪些共享资源池可以在选定工点集合内互斥流转。

本期支持同一种资源类型建立多个相互独立的共享池。共享实例的使用先后由求解器决定，转场时间和转场成本均按 0 处理。

本期不包含架桥机资源配置、梁场资源配置、非零转场时间或费用、人工指定共享流转顺序、资源调拨审批、跨项目共享，以及单机编号、维修和班次管理。

## 2. 页面信息架构

### 2.1 工点资源

工点资源页面以工点为一级对象。用户先选择或展开工点，再维护该工点的资源记录。

每条工点资源记录至少展示：

- 资源名称与资源类型；
- 当前投入 `quantity`；
- 可增上限 `max_quantity`；
- 启用状态；
- 数据来源或兼容状态（需要提示时）。

页面默认展示该工点任务可能使用的资源。用户还可以从资源目录补充添加资源类型。已添加的同一资源类型在同一工点只保留一条工点独享记录。

工点资源页不提供“该资源适用于哪些工点”的反向勾选。工点归属由当前页面上下文和记录本身确定，不再通过项目级默认值、适用范围与工点覆盖共同推导。

### 2.2 范围共享资源池

共享资源池在独立区域维护，不混入工点独享资源列表。每个共享池至少维护：

- 唯一共享池标识；
- 资源名称与资源类型；
- 当前投入 `quantity`；
- 可增上限 `max_quantity`；
- 启用状态；
- 允许流转的工点集合。

“选中全部工点”表示全项目共享；否则必须选择一个非空工点集合。集合外工点不得获得该共享池候选。

同一种资源类型允许建立多个共享池。每个共享池的数量、上限、启用状态和工点集合互相独立，页面不得因资源类型相同而合并或覆盖记录。

## 3. 数量、启用与校验规则

### 3.1 工点独享资源

- `quantity` 表示该工点当前已投入数量。
- `max_quantity` 表示规划时允许增加后的数量上限，且不得小于 `quantity`。
- `quantity = 0` 表示该工点当前没有该资源，不得在当前资源模式中被当作一台可用资源。
- 禁用记录不提供候选。
- 删除工点资源记录与将数量设为 0 均会使该工点失去该本地资源候选，但删除前应提示其对已有方案或任务可行性的影响。

### 3.2 共享资源池

- 每个共享池独立计算 `quantity` 和 `max_quantity`。
- 同一共享实例不得同时服务多个任务。
- 共享池可以按求解结果在授权工点之间连续服务任务，本期不增加转场工期或费用。
- 同类型的不同共享池互不借用数量或上限。

### 3.3 阻断诊断

当任务需要某种资源，但任务所在工点既没有可用的工点独享资源，也没有任何合法共享池候选时，排程必须阻断。诊断至少包含：

- 工点；
- 任务；
- 所需资源类型；
- 未形成候选的原因，例如本地数量为 0、记录被禁用、共享池未授权该工点或不存在相应共享池。

页面不得把该场景降级为静默忽略、自动补齐资源或仅给出笼统的“不可排程”提示。

## 4. 操作流程

### 4.1 配置工点资源

1. 用户进入“工点资源”。
2. 选择一个工点。
3. 页面展示根据该工点任务推导的可能使用资源，以及已经配置的资源记录。
4. 用户维护当前投入、可增上限和启用状态，或从资源目录补充资源。
5. 保存时校验数量、上限、同工点同类型唯一性和引用完整性。

### 4.2 配置共享资源池

1. 用户进入“共享资源池”。
2. 新建共享池并选择资源类型。
3. 维护当前投入、可增上限和启用状态。
4. 选择“全部工点”或一个非空工点集合。
5. 保存后，该共享池只向授权工点提供候选。

## 5. 方案、AI 与结果展示

- 方案控制、AI 建议、采用建议和资源结果均以共享池或工点资源记录的唯一标识为主要引用，不以资源类型作为唯一键。
- 当同类型仅有一个可兼容的旧共享池时，可继续读取旧的“资源类型 → 数量”输入；一旦同类型存在多个池，必须要求明确池标识，不得默认修改第一条。
- 结果展示应区分工点独享资源与共享池，并能识别同类型的多个独立池。
- 共享池的任务使用顺序是求解输出，不是用户输入项。

## 6. 兼容与迁移

### 6.1 既有项目共享配置

旧项目中按项目共享保存的资源继续作为共享资源读取：

- 保留原数量与可增上限；
- 保留原适用工点范围；
- 不拆分到各工点；
- 全项目共享仍解释为允许全部工点；
- 不因迁移生成额外共享池。

### 6.2 047 工点覆盖配置

既有的工点独享覆盖配置仅在能够无损确定工点、资源类型、数量和上限时展开为工点资源记录。若缺少工点、引用未知工点、同工点同类型冲突或会丢失未知字段，必须阻断并给出迁移诊断，不得静默选择一个解释。

## 7. 验收要点

- 能以工点为一级对象维护独享资源，页面无反向适用工点勾选。
- 默认资源来自该工点任务可能使用的类型，并允许从资源目录补充。
- 工点数量为 0 时不产生当前资源候选。
- 同类型可创建多个独立共享池，且授权范围互不影响。
- 授权集合外工点无法使用共享池。
- 同一共享实例不重叠服务多个任务，流转由求解器决定且本期转场时间、成本均为 0。
- 无合法候选时，以工点、任务、资源维度阻断并诊断。
- 旧共享配置保留数量、上限和范围，不拆分、不丢失。
