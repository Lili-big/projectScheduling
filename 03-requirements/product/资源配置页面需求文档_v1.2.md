# 资源配置页面需求文档

版本：v1.3（沿用稳定文件路径，避免既有引用失效）

日期：2026-07-17

适用范围：桥梁自动排程系统工程化版本资源配置页面

面向对象：产品、前端研发、后端研发、测试

关联规格：`03-requirements/specs/047-workpoint-resource-configuration/spec.md`

独立规则口径：`03-requirements/rules/工点级资源作用域与求解规则需求文档_v1.0.md`

## 1. 产品目标

资源配置页面用于维护当前项目或排程方案的受限资源容量，并把每一种资源类型配置为“项目共享”或“工点独享”。系统必须基于统一资源模型生成任务候选、命名资源和求解约束，不得由前端或后端按桥梁名称、工点 ID 格式、中文字符串或特殊数量硬编码作用域。

本期解决三个问题：

- 同一资源类型可以按项目共享，也可以在各桥梁工点内独享，避免项目级总量被错误地跨工点或重复使用。
- 工点没有单独配置时，自动继承该资源类型的全局默认配置，不得被解释为“资源默认充足”。
- `quantity`、`max_quantity` 在三类求解中的含义保持一致，不新增 `min_quantity`。

## 2. 已确认产品口径

1. 每个资源类型独立选择 `PROJECT_SHARED`（项目共享）或 `WORKPOINT_EXCLUSIVE`（工点独享）。
2. 既有项目级资源池缺少作用域字段时，兼容迁移为 `PROJECT_SHARED`，保持现有跨工点串行使用语义。
3. 工点没有显式覆盖配置时，继承该资源类型的全局 `enabled`、`quantity`、`max_quantity`、日历和并行规则；“未配置”不等于 `UNLIMITED`，也不等于禁用。
4. 不新增 `min_quantity`。`quantity` 始终表示当前默认投入：项目共享时表示项目共享总量，工点独享时表示每个未覆盖工点的默认投入。
5. 固定资源求最短工期按有效配置的 `quantity` 展开资源。
6. 当前资源未满足目标时，增配建议只在 `[quantity, max_quantity]` 搜索。
7. 固定工期求最少资源以 `max_quantity` 为上界，但推荐数量可以低于 `quantity`；其下界由 0、任务可行性和求解器证明共同决定，不由 `quantity` 限制。
8. 项目共享资源可在获准桥梁工点间串行使用；MVP 跨工点转场时间固定按 0 天处理，配置页和结果页都必须明确提示。
9. 本期只覆盖桥梁工点，不覆盖非桥梁工点、非零转场时间、资源调拨审批或跨项目共享。

## 3. 数据与页面对象

### 3.1 全局默认资源池

`ScenarioInput.resource_pools` 继续承载每种资源类型的全局默认配置。既有字段含义保持不变，并增加作用域和工点覆盖信息。完整字段、默认值和校验以独立规则文档为准。

| 配置项 | 页面标签 | 产品含义 |
| --- | --- | --- |
| `type` / `label` | 资源类型 / 名称 | 统一工艺资源类型及其展示名称，只读 |
| `scope_mode` | 使用范围 | `PROJECT_SHARED` 或 `WORKPOINT_EXCLUSIVE` |
| `quantity` | 默认投入 | 当前默认投入；共享模式是项目总量，独享模式是每个未覆盖工点的默认量 |
| `max_quantity` | 可增上限 | 对应有效资源池的推荐上限，且不小于 `quantity` |
| `enabled` | 启用 | 是否作为受限资源参与候选和求解 |
| `authorized_workpoint_ids` | 获准工点 | 可使用该资源类型的桥梁工点集合；兼容空值表示当前项目全部桥梁工点 |
| `workpoint_overrides` | 工点覆盖 | 仅对指定工点覆盖默认投入、可增上限或启用状态；缺失即继承 |

### 3.2 工点范围

- 页面工点列表只来自当前 `project_data_version_id` 的权威项目主数据。
- 本期工点身份使用桥梁工点稳定 ID；名称、工区和幅别只用于展示，不参与规则判断。
- 非桥梁工点不进入本期配置列表，也不被自动转换为桥梁工点。
- 项目主数据版本切换后，旧版本工点覆盖不得应用到新版本；失配项应提示并阻止静默保存。

### 3.3 继承与覆盖

- “继承全局默认”是工点没有显式覆盖记录时的正常状态。
- 工点显式覆盖只修改该工点对应的有效值，不复制另一份资源类型定义。
- 工点被删除或版本切换后，无法匹配的覆盖记录保留迁移诊断，但不得参与新任务候选。
- 用户应能将覆盖恢复为“继承全局默认”。

## 4. 页面信息架构与交互

### 4.1 资源类型列表

每种资源类型展示：名称、编码、作用域模式、默认投入、可增上限、启用状态、日历说明、并行规则说明和工点配置摘要。

页面必须明确区分：

- `PROJECT_SHARED`：同一批命名资源供多个获准工点串行使用。
- `WORKPOINT_EXCLUSIVE`：每个工点生成独立命名资源，不能被其他工点任务使用。
- `UNLIMITED`：显式资源默认充足模式。它与“工点未配置并继承全局默认”是不同状态。
- 显式停用或显式有效上限为 0：沿用既有统一默认充足 warning 语义；它们同样不得与“未配置工点”混为一谈。

### 4.2 项目共享模式

- 用户为资源类型设置项目共享后，配置项目总 `quantity` 和 `max_quantity`。
- 页面展示获准桥梁工点范围；未设置显式范围的既有资源池默认覆盖当前项目全部桥梁工点。
- 页面固定提示：“项目共享资源可跨获准工点串行使用；本期转场时间按 0 天计算。”
- 项目共享模式不允许录入互相矛盾的工点独享数量；若存在历史独享覆盖，切换前必须由用户确认清理或转换。

### 4.3 工点独享模式

- 用户为资源类型设置工点独享后，页面按桥梁工点展示有效 `quantity`、`max_quantity` 和“继承/已覆盖”状态。
- 未配置工点自动显示从全局默认继承的有效值，不显示“默认充足”。
- 用户可以覆盖单个工点的默认投入和可增上限，也可以恢复继承。
- 不同工点生成的命名资源彼此隔离；页面不按名称或 ID 形式推测归属。

### 4.4 数量编辑

- `quantity`、`max_quantity` 必须为非负整数，且配置层仍要求 `max_quantity >= quantity`。
- 提高 `quantity` 超过 `max_quantity` 时，页面可同步提高上限，或阻止保存并明确提示。
- 固定工期求最少资源的结果允许 `recommended_quantity < quantity`；页面必须用“当前投入”和“推荐投入”分别展示，不得自动把推荐值抬高到 `quantity`。
- 推荐结果只有在用户明确采纳后才回写配置；采纳后该值成为新的 `quantity`，同时触发结果失效。

### 4.5 状态、保存与失效

- 查询、保存、任务生成和求解期间避免重复提交。
- 保存失败保留用户输入并展示通用错误及重试入口。
- 作用域、获准工点、工点覆盖、数量、上限、启用状态或资源日历任一变化，都必须使基于旧指纹的任务图、求解结果、AI 方案和方案对比失效。
- 保存成功后以前后端返回的标准化配置刷新页面，不保留前端私有补值。

## 5. 任务生成与求解联动

本节只说明产品可观察结果，算法细节以独立规则文档为唯一权威源。

- `ScenarioInput` 保存配置意图；`ScheduleInput` 保存已解析的命名资源作用域，求解器不再回读页面状态。
- 任务先按工艺库获得资源类型，再按任务所属桥梁工点与资源作用域筛选候选。
- 共享资源候选只对获准工点开放；独享资源候选只对其所属工点开放。
- 对已启用、`LIMITED` 且有效上限大于 0 的资源池，若工点身份失配或没有合法候选，必须输出明确错误或阻断诊断，不得降级成资源默认充足。显式 `UNLIMITED`、显式停用或显式有效上限为 0 沿用既有统一默认充足 warning；工点未配置则先继承，不能借用这些状态。
- 同一命名资源同一时间最多执行一个任务。项目共享资源因此可跨工点串行，工点独享资源不能跨工点分配。
- 结果必须展示资源作用域、分配工点、当前投入、推荐投入和项目共享转场时间 0 天的提示。

## 6. AI 资源助手

- AI 助手读取标准化后的资源作用域和各工点有效配置，不得只按资源类型汇总后丢失工点范围。
- AI 可以建议数量，但不得自行改变 `scope_mode`、获准工点或工点继承关系。
- 项目共享资源输出项目级数量建议；工点独享资源按工点输出建议。
- AI 输出必须受对应 `max_quantity` 约束，且只能引用当前项目已有的资源类型和桥梁工点。
- AI 方案被人工修改后，既有求解和解释标记为失效；重新求解前不得展示旧结论为当前结论。
- 兼容旧的“资源类型→数量”输入时，只能应用于迁移后仍为项目共享的资源；工点独享必须使用带工点身份的结构化输入。

## 7. 持久化与兼容迁移

- 既有资源池缺少 `scope_mode` 时按 `PROJECT_SHARED` 读取，数量和命名资源总量保持兼容。
- 既有配置缺少工点范围时，按当前项目全部桥梁工点读取；该行为是统一迁移规则，不是一次性数据补丁。
- 新字段必须进入本地/项目/方案配置、AI 资源方案和计划快照的标准序列化及指纹。
- 旧快照可按兼容默认读取；新配置保存后必须使用新指纹，旧生成或求解结果不可复用。
- 不直接改历史快照；需要重新计算时生成新结果并保留旧结果的审计状态。

## 8. 异常、空态与提示

| 场景 | 预期 |
| --- | --- |
| 当前版本没有桥梁工点 | 展示空态并禁止工点独享配置；不创建虚构工点 |
| 工点覆盖引用旧版本 ID | 标记失配，阻止静默应用并提示重新确认 |
| 未配置某工点 | 继承全局默认，明确展示继承来源 |
| 显式 `UNLIMITED` | 按资源默认充足处理，并与继承状态区分 |
| 显式停用或有效上限为 0 | 沿用既有默认充足 warning，并与继承状态区分 |
| 已启用、`LIMITED`、正上限的有效池没有合法候选 | 输出阻断错误，不按默认充足排程 |
| 项目共享跨工点分配 | 允许串行使用，并提示转场时间按 0 天 |
| 保存或加载失败 | 保留编辑内容，展示通用错误和重试 |
| 旧配置缺少新字段 | 按统一迁移默认读取并在保存时标准化 |

## 9. 可复现验收样例

### 样例 A：工点独享与继承

资源类型“旋挖钻”设置为工点独享，全局 `quantity=1`、`max_quantity=3`；工点 A 覆盖为 `quantity=2`、`max_quantity=4`，工点 B 无覆盖。

预期：A 展开 2 台仅可服务 A 的旋挖钻；B 继承全局并展开 1 台仅可服务 B 的旋挖钻；B 不得显示或按“默认充足”处理。

### 样例 B：项目共享与转场 0 天

资源类型“盖梁模板”设置为项目共享，`quantity=1`、`max_quantity=2`，获准工点为 A、B。

预期：固定资源求最短工期只展开 1 套共享模板；A、B 任务不能同时占用它，可连续串行且两工点间不增加转场天数；配置页和结果页均显示 0 天提示。

### 样例 C：三类数量语义

某有效资源池 `quantity=3`、`max_quantity=5`。

预期：固定资源求最短工期使用 3；增配建议只搜索 3～5；固定工期求最少资源可返回 0～5 内经求解证明可行的数量，例如 2，且不得因 `quantity=3` 抬高结果。

### 样例 D：旧项目兼容

旧配置只有 `id/type/quantity/max_quantity`，无作用域和工点字段。

预期：统一读取为项目共享并覆盖当前项目全部桥梁工点；固定资源命名资源数量与旧版本一致；不执行手工数据特例补丁。

## 10. 验收标准

- 页面可按资源类型选择项目共享或工点独享，并正确显示继承与覆盖。
- 未配置工点始终继承全局默认，0 次被误判为资源默认充足。
- 既有项目级资源池迁移为项目共享，原有项目共享容量语义保持一致。
- 固定资源、增配建议、固定工期最少资源三类数量语义分别符合第 2 节，且系统中不存在 `min_quantity`。
- 共享资源可跨获准工点串行，独享资源候选只属于自身工点。
- 配置页、任务/结果诊断均明确项目共享转场时间按 0 天。
- AI 助手、持久化、结果指纹和失效判断保留作用域与工点信息。
- 正常、异常、空态、兼容和版本切换场景均有自动化或可复现验证。
- 前后端不存在依据桥梁名称、工点 ID 格式、中文字符串或特殊数量决定作用域的业务分支。

## 11. 非本期范围

- 非桥梁工点资源配置。
- 非零转场时间、路径或费用建模。
- 资源调拨申请、审批、到离场流程。
- 跨项目资源共享与全局占用看板。
- 单机台账、人员技能、班次和维修日历的新增建模。
