# `<workpackage-id>` 工作包

复制本目录到目标阶段后，先替换所有占位说明，再添加业务资产。工作包应能让不熟悉上下文的人在 60 秒内说明输入、运行方式、成果和清理边界。

## 目的（必填）

说明本工作包只解决什么问题，以及不负责什么。

## 输入（必填）

- 列出相对路径、来源、是否含客户/敏感数据。
- 用户输入默认 `local-only`；批准样例才可 `tracked`。

## 运行（必填）

给出从仓库根目录可执行的命令。没有可复现命令时，状态必须使用 `orphaned`，不得编造脚本。

## 成果（必填）

列出正式成果和可再生成成果，并说明哪个是当前版本。

## 跟踪与保留（必填）

分别说明 README/脚本、用户输入、正式成果、日志、缓存和临时文件的 tracking/retention 策略。

## 关联工作包（可选）

只登记引用或上下游关系；每个资产仍只能有一个主归属。
