# 公路路面工程排程产品实现方案

版本：v1.0  
日期：2026-09-24  
适用范围：公路路面 Demo 的客户试算与后续能力适配  
文档状态：产品方案；待确认事项见第八节

## 一、目标与使用流程

围绕“一台关键设备的路面排程与人工对比”，让软件在路床移交、段内工序和养生条件下安排跨段施工，并让客户检查设备流转和计划结果。

客户已有 Excel 计算工期、Project 维护逻辑的工作方式。本方案重点承接跨段安排、参数变化后的重新计算以及结果对比。

使用流程：

**维护主数据 → 匹配工效 → 确认工艺关系 → 配置共享机组 → 自动排程 → 查看设备安排 → 对比人工计划。**

## 二、现有 Demo 能力与补齐范围

| 能力 | 当前路面 Demo | 实现方向 |
| --- | --- | --- |
| 项目主数据 | 分段及其结构层、厚度密度、路床移交日期、本地保存 | 沿用现有15段及结构层，补入客户修订数据 |
| 工效与工期 | 工效配置、任务匹配、按数量计算工期 | 本案例使用施工长度和日工效计算 |
| 工艺逻辑 | 统一关系、分段覆盖、FS/SS/FF/SF及技术间歇 | 配置客户四层工序及养生规则 |
| 资源排程 | 固定机组跨段作业、养生期间释放机组；工艺机组相互独立 | 增加一套机组承担多个工艺的共享配置 |
| 结果表达 | 任务日期、等待信息、设备流转文字及分段可用日期 | 增加任务甘特图、设备时间轴和空闲统计 |
| 人工计划对比 | 路面页面尚无完整入口 | 增加人工计划录入、校验和同条件对比 |
| 日历与动态进度 | 路面使用连续日历天，进度管控尚未接入路面流程 | 第二批增加工作日历与剩余计划重排 |

本节仅用于识别复用和补齐范围，不代表新增能力已经实现。

## 三、客户试算的业务口径

| 项目 | 方案口径 |
| --- | --- |
| 施工范围 | 沿用现有15个施工段及左右幅划分 |
| 结构层 | 默认启用碎石垫层和三层水稳；沥青层保留数据并停用 |
| 层厚 | 碎石垫层0.16m，各水稳层0.20m；保留按段、按层编辑 |
| 施工数量 | 使用施工长度（m）计算工期；结构层工程量（t）用于工程量展示 |
| 工效 | 按工艺维护，允许任务选择适用工效；最终值采用客户修订表，不将800—900m/天的讨论值固化为定值 |
| 开工条件 | 不早于本段路床移交日期，并满足前置关系 |
| 默认工序 | 碎石垫层 → 水稳底基层 → 水稳下基层 → 水稳上基层 |
| 默认关系 | 碎石至首层水稳为FS＋0天，水稳相邻层为FS＋7天；末层水稳保留7天养生后的可用日期 |
| 设备 | 本次试算固定一套关键施工机组，求解不自动增加设备 |
| 共享假设 | 方案按该机组可承担碎石、水稳设计；具体设备及适用工艺需客户核对 |
| 转场 | 本次试算设0天，表示暂不另占生产时间，不代表现场转场没有工作量 |
| 日历 | 第一批按每周7天连续试算；双方对比使用相同假设。工作日历由第二批补齐 |
| 配套资源 | 第一批只约束关键机组，养生管理及配套资源不单独排程 |

第一批不包含沥青排程、自动增配设备、双班方案优化、天气预测和机械成本优化。

## 四、第一批：单机排程与人工对比

### 4.1 项目主数据

- 沿用“施工段下面展开结构层”的页面，维护施工长度、宽度、路床移交日期，以及每层的名称、厚度、密度和启用状态。
- 结构层工程量（t）＝施工长度（m）×宽度（m）×厚度（m）×密度（t/m³），按整数吨展示。密度缺失时提示待补齐，不伪造吨位；长度排程仍按其必要参数校验。
- 修改后结构化保存到本地。影响任务或排程的数据变化后，已有任务和结果标记为过期。

### 4.2 工艺工效与任务视图

- 工艺工效库维护标准日工效，任务视图负责匹配具体工效方案。
- 本案例施工天数＝施工长度÷所选日工效，按整数天向上取整。
- 任务行展示施工段、结构层、施工长度、所选工效、计算天数及前置关系，便于客户核对。
- 缺失工效、工效不大于0或数量与工效单位不一致时，提示具体任务并阻止采用该输入求解。

### 4.3 工艺逻辑与养生

- 保留统一关系和单段覆盖，表达为“前置任务、后续任务、关系类型、技术间歇”。客户试算使用第三节的默认关系。
- 保留现有其他关系类型的维护能力；修改后按生效配置重新生成任务并检查关系循环和失效引用。
- 同一段相邻层的默认FS＋7天已包含水稳养生，不重复叠加另一份7天等待。
- 养生约束后续工序的开工，不占关键施工机组；末层养生用于计算分段可用日期。

典型效果：A段水稳施工3天后开始7天养生。设备可在施工结束后安排到满足条件的B段，A段下一层仍需等待养生完成。

### 4.4 共享机组

- 资源配置增加“可承担工艺”，一套机组可关联碎石、水稳等多个适用工艺。
- 关联工艺的任务共同占用该机组，同一时段只能执行一个施工任务。
- 本案例配置一套关键机组，数量为1。碎石、水稳不能各建一套独立机组后当作“一台设备”。
- 保留现有独立机组配置的含义；将已有任务改用共享机组时，必须明确其资源归属，避免重复计入能力。
- 已启用任务没有可用机组时，提示任务及缺失资源，不默认无限资源或替换施工方式。

### 4.5 模拟求解

- 计划开始日期、求解范围及求解操作集中在模拟求解页面。
- 在移交、前置关系、技术间歇和资源互斥条件下，自动决定跨段作业顺序。
- 第一批以尽早整体可用为求解目标，同时展示施工完成日期和设备空闲指标；不把展示指标宣称为已独立优化的目标。
- 不以增加设备或违反业务条件换取更早日期。没有可施工工作面时允许等待，不承诺一定零窝工。
- 输入缺项或冲突时定位到具体对象；无可行计划和限时内未找到计划分别提示。仅得到可行解时，不标为最优解。

### 4.6 结果视图

在模拟求解结果中提供三个视图，不增加独立一级导航。

| 视图 | 内容 | 客户要判断的问题 |
| --- | --- | --- |
| 施工计划 | 按施工段显示各层施工条、养生等待条及日期 | 每段什么时候做、什么时候具备后续施工条件 |
| 设备安排 | 一台设备一条时间轴，显示作业段、工序、空闲区间及完整作业顺序 | 设备怎么走、哪里在等待 |
| 方案对比 | 人工与自动计划的日期、空闲指标及任务顺序差异 | 两份计划差在哪里、是否适合现场 |

保持表格紧凑、表头单位同行；结果说明只保留业务条件和必要提示。

### 4.7 人工计划录入与调整

提供可从Excel粘贴的人工计划表，使用当前任务清单匹配任务。

| 字段 | 含义 |
| --- | --- |
| 任务 | 对应施工段及结构层，匹配唯一任务 |
| 开始日期 | 人工计划的施工开始日期 |
| 完成日期 | 人工计划的施工完成日期 |
| 使用机组 | 该任务占用的机组 |

- 对比记录关联同一版主数据及工效、资源、逻辑、日历条件，保留人工填写日期。
- 检查缺漏或重复任务、提前开工、施工时长不匹配、养生不足和设备冲突。存在问题时列出差异，不将其作为同条件的有效优劣结论。
- 自动结果需要现场调整时，允许指定任务先后顺序，再重新求解；不采用绕过约束的自由日期拖动。
- 第一批通过表格承接人工计划；向斑马计划交付的导出格式，取得目标模板后确定，不承诺直接解析Project原生文件或自动同步。

## 五、结果指标口径

| 指标 | 含义 |
| --- | --- |
| 施工完成日期 | 本次范围内最后一个施工任务的完成日期 |
| 整体可用日期 | 全部施工段末层均满足养生及已配置可用条件后的日期 |
| 设备作业天数 | 统计范围内该设备承担施工任务的天数 |
| 设备空闲天数 | 统计窗口内可作业天数减去设备作业天数；不直接等同于可消除的窝工 |
| 设备利用率 | 设备作业天数÷统计窗口内可作业天数，显示统计窗口；分母为0时不计算 |
| 计划差异 | 人工与自动计划的日期差、空闲天数差，以及具体任务顺序和时间差异 |

第一批按“统一计划开始日期至该计划施工完成日期”统计设备指标，采用连续日历天；不通过推迟统计起点美化利用率。对比同时展示各自统计窗口和完工日期。末层施工结束后的纯养生等待不计为设备空闲。

第二批引入工作日历后，停工日和休息日不计入可作业天数，并与养生、设备空闲分开显示。

## 六、后续批次

| 批次 | 内容 | 期望效果与边界 |
| --- | --- | --- |
| 第二批：工作日历 | 每周5/6/7工作日、指定停工日 | 保持作业天数口径，按日历推算开始及完成日期；养生是否按自然日计数须先确认 |
| 第二批：动态进度 | 按结构层维护总施工长度、已完成长度、剩余长度及统计日期 | 计算剩余施工天数，保留已完成事实和实际日期，只重排剩余工作 |
| 第三批：产值联动 | 完成工程量×单价 | 按明确的计量口径形成产值，不混同于机械成本 |
| 第三批：资料与报表 | 综合日报和独立资料来源，按已有模板填报 | 在数据权限、来源映射和模板明确后，减少重复整理 |

双班方案的工效换算和对比，在客户明确班制与产能口径后再安排，不直接按单班工效翻倍。

## 七、第一批验收

| 场景 | 预期结果 |
| --- | --- |
| 同一机组关联碎石和水稳任务 | 各工艺共同受该机组约束，不出现同一时段跨段或跨工艺重复占用 |
| A段施工3天、养生7天，B段已经可施工 | A段施工结束后资源可安排B段；A段下一层仍满足其养生条件 |
| 施工段尚未移交 | 本段施工任务不早于移交日期开始 |
| 默认碎石及水稳关系 | 碎石后无额外养生，水稳间歇按配置计一次；末层等待体现在可用日期 |
| 修改移交日期、工效、资源或技术间歇 | 旧结果标记过期，重新计算后使用最新输入 |
| 任务缺少工效、资源或关系存在循环 | 提示具体问题并阻止无效输入求解，不补造资源或参数 |
| 录入人工计划 | 完成任务匹配与业务条件检查，保留原人工日期并展示问题 |
| 对比两份有效计划 | 能查看完工日期、设备空闲、作业顺序及任务日期差异，显示统计窗口 |
| 添加人工指定的任务先后顺序 | 重新求解并满足新增约束；冲突时明确提示 |
| 求解仅返回可行结果或没有找到结果 | 展示真实求解状态，不宣称最优或静默放宽业务条件 |

## 八、实施前待确认事项

| 事项 | 需要确认的内容 | 影响范围 |
| --- | --- | --- |
| 关键设备与队伍 | “一台设备”具体是什么、可承担哪些工艺，与“两个队伍”的关系 | 共享机组适用范围及是否还有其他资源限制 |
| 最终工效 | 客户修订值、各工艺是否相同、对应单班还是双班 | 工期计算及人工对比基准 |
| 计划起点 | 使用哪一天起算，是否包含已经完成或正在施工的任务 | 第一批试算输入；有实绩时需明确试算范围或接入第二批 |
| 完成口径 | 客户主要考核施工完成还是养生后可用 | 第一批显示两项日期，采用整体可用目标；正式验收目标需核对 |
| 养生日历 | 7天是否按自然日连续计算，雨天和休息日是否继续计入 | 第二批日历规则 |
| 交付格式 | 斑马计划接收的模板、字段和任务标识方式 | 结果导出与交付 |

本方案依据2026-09-23客户沟通记录、现有路面Demo能力及本轮产品方案讨论整理，用于明确产品范围和验收效果。后续开发按项目既定需求与实施流程推进。
