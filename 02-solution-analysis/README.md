# 02 · 过程方案分析

## 目的

承接调研证据，比较产品方向、算法融合、工程化路径和 MVP 边界，并保留关键决策依据。

## 进入条件

- `01-discovery` 已说明真实业务问题和证据。
- 存在两个以上可选路径，或需要评估价值、可行性、风险与范围。

## 退出条件

- 推荐方案、未选方案、边界、风险和待决事项明确。
- 决策可以转化为 `03-requirements` 的正式产品口径。

## 权威资产

- `proposals/`：长期目标、融合方案、MVP 与工程化方案。
- `decisions/`：后续新增的正式决策记录。

## 工作包索引

当前方案按主题直接维护在 `proposals/`；需要独立输入、脚本和成果闭环时再创建 workpackage。

## 相邻阶段

- 上一阶段：[01-discovery](../01-discovery/README.md)。
- 下一阶段：[03-requirements](../03-requirements/README.md)。治理入口位于 `00-governance`。

## 禁止内容

- 把 Demo 临时实现直接定义为正式产品规则。
- 未完成评审就生成实现任务或正式交付物。

## 维护触发条件

方案范围、推荐结论、MVP 边界或关键技术取舍变化时，必须同步相关决策和被引用需求。
