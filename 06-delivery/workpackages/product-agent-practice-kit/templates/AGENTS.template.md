# [项目名称] Agent 工作契约

本文件是项目执行流程的唯一来源。项目事实见 `[项目事实文件]`，实际命令以 `[命令权威文件]` 为准。

## 默认执行

1. 读取目标文件、邻近证据和完成任务所需的最少上下文。
2. 保护无关改动，在现有结构内完成最小操作。
3. 对相关修改运行一次与风险匹配的最小验证。
4. 报告实际产物、证据、未覆盖风险和下一门禁，然后停止。

不得把截图、产品宣传、Demo临时行为或Agent推断写成已确认产品规则。

## 阶段路由

- 收到资料：归档到 `01-inputs/raw/`，更新 `01-inputs/source-index.md`；本阶段不设计新功能。
- 还原现状：更新 `02-product-baseline/product-baseline.md`，分开事实、用户表达、推断、冲突和待验证。
- 模糊需求或Demo业务反馈：使用 `$requirement-discovery`；本阶段不修改业务代码、不创建正式Feature。
- 产品口径确认：使用项目本地 `$speckit-specify → $speckit-plan → $speckit-tasks`，完成一致性检查后停在实施授权门禁。
- 用户明确确认 `tasks.md` 和一致性结果后：使用项目本地 `$speckit-implement`。
- Demo评审反馈：先分类；业务变化回需求发现，契约变化回规格，缺陷才直接修复。
- 研发交底：使用 `$write-prd`，只保留当前有效口径和验证证据。

## 人工确认门禁

以下操作不得自动越过：

1. 产品目标、核心规则、范围和成功标准的确认。
2. `tasks.md` 和一致性结果的实施授权。
3. 安全、权限、客户数据、迁移、不可逆操作和外部发布。

## 资产规则

- 客户原件和敏感输入按项目政策处理；默认不得跨项目复制。
- 正式结论必须能追溯到来源ID、用户确认或机器证据。
- 新口径替代旧决策时显式记录，不静默改写历史。
- 日志、缓存和临时提取物不得进入正式交付目录。
