# Skill 路由与人工门禁

本文件供初始化 Agent 生成项目 `AGENTS.md` 时读取。

## 路由规则

| 用户意图或项目状态 | 调用能力 | 预期产物 | 必须停止在哪里 |
|---|---|---|---|
| 收到Word/PDF/Excel/截图/访谈 | 对应资料处理Skill + 项目证据规则 | 原件、来源索引、提取物 | 资料入库完成 |
| “还原当前产品” | 普通项目分析 | 产品基线 | 事实与未知项说明完成 |
| “先分析需求，不要实现” | `requirement-discovery` | 需求发现文档、确认快照 | 高影响口径待用户确认 |
| “口径确认，进入正式规格” | 项目本地 `speckit-specify` | `spec.md` | 规格完成 |
| “继续形成方案和任务” | `speckit-plan` → `speckit-tasks` | `plan.md`、`tasks.md`、一致性结果 | 实施授权门禁 |
| “tasks确认，可以实现” | `speckit-implement` | Demo修改、测试和证据 | 相关验收完成 |
| “这是Demo反馈” | 先分类，再回流对应阶段 | 新决策、规格修订或缺陷修复 | 对应阶段完成条件 |
| “形成研发交底” | `write-prd` | 当前有效PRD | 交付检查完成 |

## 两个必须独立确认的门禁

### 产品口径门禁

确认目标、角色、场景、核心规则、范围、非范围和成功标准。通过后才允许生成正式Spec。

### 实施授权门禁

确认Tasks覆盖的范围、数据与兼容策略、验证方式和不应进入当前版本的内容。通过后才允许修改Demo。

“认可方向”不等于“授权实施”。

## Demo反馈回流

```text
业务目标/规则/范围变化 → requirement-discovery → 新确认 → 更新Spec
数据或共享契约变化     → 更新Spec/Plan/Tasks → 新实施授权
信息架构变化           → 判断是新Feature还是现有Feature修订
纯视觉变化             → 项目UI Skill → 视觉证据
实现缺陷               → 直接修复 → 定向验证
证据不足               → 记录待验证，不升级为规则
```

## AGENTS.md 中的最小路由片段

```markdown
- 模糊想法、页面反馈或尚未确认的产品语义使用 `$requirement-discovery`；本阶段不得修改业务代码。
- 产品口径确认后，执行项目本地 `$speckit-specify → $speckit-plan → $speckit-tasks`，并停在实施授权门禁。
- 只有用户明确确认 `tasks.md` 和一致性结果后，才使用 `$speckit-implement`。
- Demo评审反馈先分类；业务变化回到需求发现，缺陷才直接修复。
- 形成研发交底时使用 `$write-prd`；Demo实现只能作为行为证据，不能成为正式工程约束。
```
