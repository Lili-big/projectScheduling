# 产品经理最小意图表达

这些语句用于初始化完成后的日常任务，不承担项目初始化职责。

这些语句只表达“要做什么、推进到哪一步”。执行方法、输出合同和质量检查由 `AGENTS.md` 与 Skill 负责，不要把本文件扩展成庞大的万能 Prompt。

| 场景 | 建议表达 |
|---|---|
| 资料入库 | “请先归档并还原这些资料，不要直接形成新需求。” |
| 当前产品还原 | “基于资料、代码和测试还原当前产品，事实、推断、冲突和待验证分开。” |
| 模糊需求分析 | “先把这个需求分析清楚，不要实现。” |
| 方案比较 | “比较真实可行方案，说明推荐、代价和不选理由。” |
| 产品口径确认 | “以上产品口径确认，进入正式规格，先不要实施。” |
| 形成任务 | “继续生成plan和tasks，完成一致性检查后停下。” |
| 实施授权 | “tasks和一致性结果确认，可以进入Demo实现。” |
| Demo反馈 | “这是Demo评审反馈，先判断是业务变化、UI变化、证据不足还是实现缺陷。” |
| UI校准 | “按真实系统证据校准页面，保持已确认业务规则不变。” |
| 算法解释 | “基于当前代码、测试和运行样例解释规则，不要只引用需求文档。” |
| 研发交底 | “按当前有效口径和验证证据输出正式研发交底PRD。” |

## 每次最好补充四项信息

```text
1. 当前要解决的问题
2. 可用资料、现有页面或反馈
3. 已经确认的业务口径
4. 本次允许推进到哪个阶段
```
