# 产品 Agent 项目初始化协议

本文件是初始化 Agent 的执行合同。初始化只建立产品 AI Coding 工作环境，不处理具体需求，不修改 Demo 业务代码。

## 1. 识别目标

1. 读取 `toolkit-manifest.json` 并校验 `id`。
2. 工具包目录的父目录默认为目标项目根目录。
3. 若目标目录是磁盘根、用户主目录、工具包自身或包含多个候选项目，停止并说明。
4. 优先读取目标项目已有的 `AGENTS.md`；其规则高于本工具包。

## 2. 预检

检查并记录：

- 新项目还是已有项目。
- 当前目录、文档、代码、测试和 Demo 入口。
- 已有 `AGENTS.md`、Constitution、`.agents/skills` 和 `specs`。
- 工作树中的已有改动。
- 可确认的产品目标、用户、场景和正式研发边界。
- 缺失、冲突或不能从材料推出的信息。

预检不写文件。若存在覆盖、删除、迁移、敏感资料外移或业务规则冲突风险，停止对应操作。

## 3. 安全初始化

从工具包目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File scripts/init-product-agent-project.ps1 `
  -ProjectRoot <目标项目绝对路径> `
  -Write `
  -InitializeProjectSkills
```

脚本只能：

- 创建缺失目录。
- 从模板创建缺失文件。
- 安装缺失的项目本地 Skill。
- 跳过所有已有目标。

脚本不得覆盖、合并或删除已有文件。

## 4. 项目适配

初始化后：

1. 根据真实项目证据填写 `.product-agent/project-profile.md`。
2. 新建的 `AGENTS.md` 可以替换模板占位符；已有 `AGENTS.md` 不得被工具包覆盖。
3. 新建的 Constitution 可以填写已确认不变量；无法证明的内容保留为待确认。
4. 登记真实验证命令；没有可执行命令时明确写“尚未配置”。
5. 检查 `.agents/skills` 中的项目副本是否可发现。
6. 不在初始化阶段形成具体 Feature、Spec、Demo 修改或 PRD。

## 5. 验证

至少验证：

- 必需目录和模板存在。
- 重复运行初始化脚本会跳过已有文件。
- 项目本地 `requirement-discovery`、`write-prd`、`project-skill-template` 和六个 `speckit-*` Skill 存在。
- `AGENTS.md` 明确需求分析、产品确认、实施授权、反馈回流和研发交接路由。
- 项目概况没有把推断写成事实。

## 6. 初始化报告

填写 `.product-agent/setup-report.md`，并给出以下状态之一：

- `可开始`：核心结构、Skill、项目概况和路由均可用。
- `部分可用`：可以开始需求分析，但仍缺少验证命令、研发边界或非关键事实。
- `已阻塞`：目标目录不明确、现有规则冲突、初始化失败或缺少关键权限。

报告必须包含下一条可直接发送的产品任务。

## 7. 停止条件

遇到以下情况立即停止相关操作：

- 需要覆盖或删除已有文件。
- 需要安装全局 Skill。
- 需要修改业务代码或正式研发工程。
- 需要移动客户资料或改变敏感性策略。
- 需要替产品经理确认业务规则、范围或实施授权。
- 目标项目规则与工具包冲突。
