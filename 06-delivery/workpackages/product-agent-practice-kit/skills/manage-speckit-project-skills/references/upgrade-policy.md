# Spec Kit Skill 升级策略

## 权威关系

工具包模板是可复用基线。目标项目的 `AGENTS.md`、`.specify/memory/constitution.md`、脚本和本地验收门禁仍是权威。Feature 执行始终调用 `.agents/skills/` 下的项目副本。

## 状态含义

- `缺失`：项目没有对应副本，可以初始化。
- `一致`：项目副本与工具包模板哈希一致。
- `存在差异`：项目副本与模板不同，可能是项目适配，也可能是旧版本。

`存在差异` 只说明需要审查，不代表允许覆盖。

## 升级步骤

1. 先执行只读 `status`。
2. 比较模板与项目副本。
3. 将差异分为通用改进、项目规则和未知差异。
4. 确认通用改进不会破坏项目规则。
5. 获得明确授权后再执行写入升级。
6. 验证升级后的 Skill，并记录模板版本、备份位置和保留的项目适配。

## 禁止事项

- 不自动升级。
- 不删除项目特有门禁。
- 不把工具包模板声明为业务事实权威。
- 不在升级过程中执行 Feature 工作流。
