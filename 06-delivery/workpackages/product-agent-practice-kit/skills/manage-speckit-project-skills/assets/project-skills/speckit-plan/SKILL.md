# 实施规划

## 工作流

1. 在仓库根目录运行：

   ```powershell
   .specify/scripts/powershell/setup-plan.ps1 -Json
   ```

   使用返回的 `FEATURE_SPEC`、`IMPL_PLAN`、`SPECS_DIR` 和 `BRANCH`。

2. 读取 `FEATURE_SPEC`、`.specify/memory/constitution.md` 和已复制的 `IMPL_PLAN` 模板。
3. 填写技术上下文和 Constitution 检查：

   - 只把真正阻断设计的未知项标为“需要澄清”。
   - Constitution 门禁未满足且没有明确理由时停止。
   - 不为熟悉的项目模式或未来设想制造研究任务。

## 阶段 0：研究

1. 从技术上下文提取阻断性未知项。
2. 收集解决未知项所需的最小证据。只有问题可独立调查且并行确有价值时才使用子 Agent。
3. 用简体中文写入 `research.md`，记录决定、理由和实际比较过的替代方案。
4. 没有新增未知项时，简要记录“无新增研究决策”。

## 阶段 1：设计与契约

按适用性生成：

- `data-model.md`：仅当功能新增或改变实体时，记录字段、关系、校验和状态变化。
- `contracts/`：仅当项目存在对用户或其他系统暴露的接口时，记录 API、命令、语法或 UI 契约。
- `quickstart.md`：记录可运行的端到端验证场景、前置条件、命令和预期结果。

`quickstart.md` 不包含完整实现代码、迁移、服务主体或完整测试套件；实现细节留给 `tasks.md` 和实施阶段。

如项目提供 Agent 上下文更新脚本，按模板要求运行一次。设计完成后重新检查 Constitution 门禁。

## 关键规则

- 文件操作使用绝对路径，文档引用使用项目相对路径。
- 不生成与当前功能无关的设计产物。
- 门禁失败或仍有阻断性未知项时停止。

## 完成

规划阶段结束后，报告分支、`IMPL_PLAN` 路径、生成的适用产物和剩余阻塞项。不得继续生成任务或实施。
