# 正式规格

## 工作流

1. 将触发请求作为功能描述；描述为空时停止并请求补充。
2. 生成简短的 `SHORT_NAME`，在仓库根目录只运行一次：

   ```powershell
   .specify/scripts/powershell/create-new-feature.ps1 -Json -ShortName "<SHORT_NAME>" "<功能描述>"
   ```

   使用返回的 `SPEC_FILE`、`FEATURE_NUM` 和功能目录。不得自行扫描编号、创建目录、复制模板或修改 `.specify/feature.json`。

3. 读取已解析的规格模板和 `.specify/memory/constitution.md`。
4. 用业务意图编写规格，不写实现设计。只保留适用内容：

   - 用户故事和场景。
   - 可测试的功能需求。
   - 可度量的成功标准。
   - 范围与非范围。
   - 边界、空态和错误。
   - 假设、实体和来源。

5. 非关键缺口采用合理且明确记录的默认值。若没有安全默认值，且答案会改变范围、安全隐私、数据含义或验收，一次只问一个问题，总计最多三个；每次答复后直接更新对应需求，不创建独立澄清阶段。
6. 对照模板和 Constitution 验证一次，并修复有来源支持的遗漏。仍存在阻断性歧义或冲突时记录并停止，不进入规划。
7. 除非用户明确调用 `$speckit-checklist`，不得自行创建检查表。

## 完成

报告功能目录、`SPEC_FILE`、已采用的假设或问答、剩余阻塞项，以及是否可以进入 `$speckit-plan`。规格完成并验证后立即停止。
