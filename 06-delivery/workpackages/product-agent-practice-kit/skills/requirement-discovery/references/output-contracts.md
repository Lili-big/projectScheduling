# 分级输出契约

按实际需求删除不适用部分。不要为了模板完整制造事实、角色、异常或后续功能。

## 小型需求：需求快照

```markdown
# 需求快照：<名称>

## 需求分级
- 级别：小型
- 判断依据：
- 升级条件：

## 当前与目标
- 当前行为：
- 目标行为：
- 修改原因：

## 边界
- 包含：
- 不包含：
- 默认假设：

## 验收
- 正常场景：
- 必要边界/失败场景：
```

完成后，如果用户已要求实施且项目规则允许，进入项目默认最小执行路径。

## 中型需求：紧凑功能设计

```markdown
# Feature Design：<名称>

## 1. 需求分级
## 2. 问题与证据
## 3. 用户、场景和现有方式
## 4. 目标、MVP和非范围
## 5. 方案比较与推荐
## 6. 用户流程和状态
## 7. 数据、接口或规则影响
## 8. 异常、兼容与回退
## 9. 验收与反证标准
## 10. 默认假设和待验证问题
## 11. 下一步路由
```

下一步：

- 需要正式研发交底：交给 `write-prd`。
- 项目规则要求正式规格：升级为复杂流程。
- 用户已确认且项目允许直接实施：把本设计作为实施输入。

## 复杂需求：需求发现结论

```markdown
# 需求发现结论：<名称>

## 1. 总体判断
- 是否存在真实问题：
- 当前是否值得推进：
- 推荐验证或建设范围：
- 最大不确定性：

## 2. 需求分级与拆分
- 级别和依据：
- 强制门禁：
- 子需求、依赖和顺序：

## 3. 业务现状还原
## 4. 角色、任务和决策
## 5. 证据账本与冲突
## 6. 核心矛盾和产品机会
## 7. 方案比较与推荐
## 8. MVP、非范围和后续阶段
## 9. 业务、算法、数据与交互规则
## 10. 异常、无解、兼容和回退
## 11. 成功标准、反证和验证计划
## 12. 默认假设、待验证和阻塞问题
## 13. PRD或正式规格输入摘要
```

复杂需求未解决关键冲突或没有可验证证据时，不输出伪完整规格；明确写出阻塞项和下一轮验证。

## 路由矩阵

| 当前结果 | 下一步 |
| --- | --- |
| 客户材料或访谈需要结构化分析 | `research-summary` |
| 产品口径已确认，需要研发交底 | `write-prd` |
| 项目要求正式规格化 | 项目指定的 Spec Kit 或同类流程 |
| 目标、范围、行为和验收已经明确且风险低 | 项目默认实施路径 |
| 关键语义、数据、安全或验收仍冲突 | 停止并请求用户决策 |

## 输出自检

- 是否写清了采用哪一级流程以及省略了什么。
- 是否将用户提出的解法与真实问题分开。
- 是否存在无来源的价值结论。
- 中型/复杂需求是否有真实方案比较和明确推荐。
- 是否同时定义成功证据和停止/改方向的证据。
- 是否只路由下一步，没有提前创建后续阶段产物。
